Cyclic Sort (Циклическая сортировка)

Описание шаблона

Шаблон Cyclic Sort используется для сортировки массивов, содержащих числа в определенном диапазоне (обычно от 1 до N). Алгоритм работает на месте, используя тот факт, что каждое число должно находиться на позиции, равной его значению минус один (для диапазона 1..N).

Исторический контекст

Cyclic Sort является специализированным алгоритмом сортировки, оптимизированным для массивов с ограниченным диапазоном значений. Он основан на идее циклических перестановок и особенно эффективен когда известно, что каждое число от 1 до N встречается ровно один раз (или с дубликатами).

Основная идея

Ключевое наблюдение: если массив содержит числа от 1 до N, то число x должно находиться на позиции x - 1. Алгоритм использует это свойство для размещения каждого элемента на правильной позиции за один цикл перестановок.

Когда применять

Используйте этот шаблон, когда:

  • Массив содержит числа в диапазоне от 1 до N (или от 0 до N-1)
  • Нужно отсортировать массив на месте с минимальными затратами памяти
  • Требуется найти отсутствующие, дублирующиеся или неправильно расположенные числа
  • Задача связана с массивами, где каждое число должно быть на определенной позиции

Алгоритм/Подход

Предусловия

Базовый цикл ниже предполагает, что каждый nums[i] лежит в диапазоне от 1 до N (где N = len(nums)), иначе correctPos := nums[i]-1 выходит за границы слайса или алгоритм зацикливается. В задачах с числами вне диапазона или без гарантии перестановки 1..N нужен guard (пропуск таких индексов) или другой вариант цикла — см. код.

Базовый алгоритм:

func cyclicSort(nums []int) {
    i := 0
    n := len(nums)

    // Шаг 1: Итерация по массиву
    // Используем while вместо for, так как не всегда увеличиваем i
    for i < n {
        v := nums[i]
        // Guard: значение вне [1, n] нельзя поставить на «свою» позицию — пропускаем
        if v < 1 || v > n {
            i++
            continue
        }

        // Шаг 2: Проверка позиции - вычисляем правильную позицию для текущего элемента
        // Для массива с числами от 1 до N: число x должно быть на индексе x-1
        // Например, число 3 должно быть на индексе 2 (3-1=2)
        correctPos := v - 1

        // Проверяем, находится ли элемент на правильной позиции
        // Если nums[i] уже на правильной позиции, переходим к следующему элементу
        if nums[i] != nums[correctPos] {
            // Шаг 3: Циклическая замена - элемент не на правильной позиции
            // Меняем текущий элемент с элементом на правильной позиции
            // Это гарантирует, что элемент на правильной позиции попадет на свое место
            nums[i], nums[correctPos] = nums[correctPos], nums[i]
            
            // После замены на позиции i находится новый элемент
            // НЕ увеличиваем i - нужно проверить этот новый элемент
            // Повторяем проверку для нового элемента на текущей позиции
        } else {
            // Шаг 4: Продолжение - элемент на правильной позиции
            // Только теперь переходим к следующему индексу
            // Это гарантирует, что все элементы до индекса i находятся на правильных позициях
            i++
        }
    }
}

Правильная позиция:

Для массива с числами от 1 до N:

  • Число x должно находиться на индексе x - 1
  • Для массива с числами от 0 до N-1: число x на индексе x

Схема алгоритма:

flowchart TD
    A[i = 0] --> B{i < n?}
    B -->|Нет| C[Конец]
    B -->|Да| D{arr[i] на месте?}
    D -->|Да| E[i++]
    D -->|Нет| F[swap arr[i], arr[correctPos]]
    E --> B
    F --> B

Математическое обоснование

Почему алгоритм работает?

Инвариант: После обработки позиции i, все элементы на позициях [0..i-1] находятся на своих правильных позициях.

Доказательство корректности:

  1. Базовый случай: Пустой массив уже отсортирован
  2. Индуктивный шаг: Предположим, элементы [0..i-1] на правильных позициях
    • Рассмотрим элемент на позиции i
    • Если он на правильной позиции, переходим к i+1
    • Если нет, меняем его с элементом на правильной позиции
    • Новый элемент на позиции i также будет обработан (циклически)
    • После конечного числа перестановок элемент попадет на правильную позицию

Почему сложность O(n)?

Каждый элемент перемещается максимум один раз на свою правильную позицию. После размещения элемента на правильной позиции, он больше не перемещается. Всего n элементов → максимум n перестановок → O(n).

Временная и пространственная сложность

Детальный анализ:

  • Временная сложность: O(n)
    • Каждый элемент обрабатывается максимум один раз
    • Каждая перестановка занимает O(1)
    • Итого: O(n)
  • Пространственная сложность: O(1)
    • Сортировка на месте, только константная память

Амортизированная сложность

Амортизированный анализ для циклической сортировки:

  • Амортизированная временная сложность: O(1) на элемент
    • Каждый элемент перемещается максимум один раз на правильную позицию
    • Амортизированная стоимость: O(n) / n = O(1) на элемент

Граничные случаи

При работе с циклической сортировкой важно обрабатывать следующие граничные случаи:

1. Пустой массив

Проблема: Если массив пуст, алгоритм может упасть или вернуть неверный результат.

Решение:

Go:

func cyclicSort(nums []int) {
    if len(nums) == 0 {
        return
    }
    // ... остальной код
}

2. Массив из одного элемента

Проблема: Если массив содержит только один элемент, он уже на правильной позиции.

Решение:

if len(nums) == 1 {
    return // Уже отсортирован
}

3. Массив уже отсортирован

Проблема: Если массив уже отсортирован, алгоритм все равно должен работать корректно.

Решение: Алгоритм корректно обрабатывает этот случай, просто пропуская элементы, которые уже на правильных позициях.

4. Все элементы одинаковые

Проблема: Если все элементы одинаковые, алгоритм может работать неоптимально.

Решение: Алгоритм корректно обрабатывает этот случай, так как каждый элемент уже на правильной позиции.

5. Элементы вне диапазона [1, n]

Проблема: Если элементы не в диапазоне [1, n], алгоритм может работать некорректно.

Решение:

// Валидация диапазона
for _, num := range nums {
    if num < 1 || num > len(nums) {
        // Обработка элемента вне диапазона
        // Например, пропустить или обработать отдельно
    }
}

6. Дубликаты

Проблема: Если есть дубликаты, алгоритм может зациклиться.

Решение:

// Проверка перед обменом
if nums[i] != nums[nums[i]-1] {
    // Обмениваем только если элементы разные
    nums[i], nums[nums[i]-1] = nums[nums[i]-1], nums[i]
} else {
    // Дубликат найден, пропускаем
    i++
}

7. Очень большой массив

Проблема: При очень больших массивах может быть проблема с производительностью.

Решение: Алгоритм имеет O(n) сложность, что оптимально. Убедитесь, что используете эффективные структуры данных.

8. Отрицательные числа

Проблема: Если массив содержит отрицательные числа, стандартный алгоритм не работает.

Решение:

// Сдвиг всех чисел в положительный диапазон
minVal := findMin(nums)
for i := range nums {
    nums[i] -= minVal - 1 // Сдвигаем в диапазон [1, n]
}
// Применяем cyclic sort
// Затем сдвигаем обратно

9. Поиск отсутствующего числа: все числа присутствуют

Проблема: Если все числа от 1 до n присутствуют, отсутствующего числа нет.

Решение:

func findMissingNumber(nums []int) int {
    cyclicSort(nums)
    // Проверяем, есть ли отсутствующее число
    for i := 0; i < len(nums); i++ {
        if nums[i] != i+1 {
            return i + 1
        }
    }
    return len(nums) + 1 // Все числа присутствуют
}

10. Поиск дубликатов: нет дубликатов

Проблема: Если дубликатов нет, алгоритм должен вернуть пустой результат.

Решение:

func findDuplicates(nums []int) []int {
    result := []int{}
    cyclicSort(nums)
    for i := 0; i < len(nums); i++ {
        if nums[i] != i+1 {
            result = append(result, nums[i])
        }
    }
    return result
}

Типичные ошибки

  1. Неправильное определение правильной позиции: Для диапазона 0..N-1 используйте x, для 1..N используйте x-1
  2. Бесконечный цикл: Убедитесь, что элемент действительно не на правильной позиции перед перестановкой
  3. Выход за границы: Проверяйте границы массива перед доступом

Практические советы

  1. Определите диапазон значений перед применением алгоритма
  2. Используйте правильную формулу для вычисления правильной позиции
  3. Обрабатывайте дубликаты отдельно (пропускайте их или обрабатывайте специально)

Когда использовать:

Используйте Cyclic Sort когда:

  • Массив содержит числа от 1 до n (или известный диапазон)
  • Нужна in-place сортировка
  • Важна экономия памяти

Не используйте когда:

  • Диапазон значений неизвестен
  • Нужна стабильная сортировка
  • Элементы не уникальны (нужна специальная обработка)

Отладка и диагностика

Отладка циклической сортировки требует отслеживания позиций элементов и циклов перестановок:

1. Логирование перестановок

Go:

func cyclicSortDebug(nums []int) {
    log.Printf("Начало сортировки: %v", nums)
    
    i := 0
    swaps := 0
    
    for i < len(nums) {
        correctPos := nums[i] - 1
        
        log.Printf("Шаг %d: i=%d, nums[i]=%d, correctPos=%d", i, i, nums[i], correctPos)
        
        if nums[i] != nums[correctPos] {
            log.Printf("Перестановка: nums[%d]=%d <-> nums[%d]=%d",
                i, nums[i], correctPos, nums[correctPos])
            nums[i], nums[correctPos] = nums[correctPos], nums[i]
            swaps++
            log.Printf("После перестановки: %v", nums)
        } else {
            log.Printf("Элемент на правильной позиции, переходим к следующему")
            i++
        }
    }
    
    log.Printf("Сортировка завершена за %d перестановок: %v", swaps, nums)
}

2. Обнаружение циклов перестановок

Go:

func detectCycles(nums []int) [][]int {
    cycles := [][]int{}
    visited := make([]bool, len(nums))
    
    for i := 0; i < len(nums); i++ {
        if !visited[i] && nums[i] != i+1 {
            cycle := []int{}
            current := i
            
            for !visited[current] {
                visited[current] = true
                cycle = append(cycle, current)
                current = nums[current] - 1
            }
            
            if len(cycle) > 1 {
                cycles = append(cycles, cycle)
                log.Printf("Обнаружен цикл: %v", cycle)
            }
        }
    }
    
    return cycles
}

Эволюция решения: от наивного к оптимизированному

Наивный подход (O(n²)):

Go:

// ❌ Наивный подход: используем дополнительный массив
func cyclicSortNaive(nums []int) {
    result := make([]int, len(nums))
    
    for _, num := range nums {
        if num >= 1 && num <= len(nums) {
            result[num-1] = num  // Размещаем на правильной позиции
        }
    }
    
    copy(nums, result)
}
// Проблемы: O(n) дополнительная память, не in-place

Оптимизированный подход (O(n), O(1) память):

Go:

// ✅ Оптимизированный подход: in-place сортировка
func cyclicSortOptimized(nums []int) {
    i := 0
    for i < len(nums) {
        correctPos := nums[i] - 1
        
        // Если элемент не на правильной позиции, перемещаем его
        if nums[i] != nums[correctPos] {
            nums[i], nums[correctPos] = nums[correctPos], nums[i]
        } else {
            i++  // Элемент на месте, переходим к следующему
        }
    }
}
// Преимущества: O(1) память, O(n) время, in-place

Идиоматичный Go код:

// ✅ Идиоматичный Go: используем именованные возвращаемые значения
func cyclicSortIdiomatic(nums []int) {
    for i := range nums {
        // Продолжаем перемещать элемент, пока он не окажется на правильной позиции
        for nums[i] != nums[nums[i]-1] {
            nums[i], nums[nums[i]-1] = nums[nums[i]-1], nums[i]
        }
    }
}

// Поиск отсутствующих чисел в диапазоне [1, n]
func findMissingNumbers(nums []int) []int {
    n := len(nums)
    i := 0
    
    // Cyclic sort
    for i < n {
        correctPos := nums[i] - 1
        if nums[i] != nums[correctPos] {
            nums[i], nums[correctPos] = nums[correctPos], nums[i]
        } else {
            i++
        }
    }
    
    // Находим отсутствующие числа
    missing := []int{}
    for i := 0; i < n; i++ {
        if nums[i] != i+1 {
            missing = append(missing, i+1)
        }
    }
    
    return missing
}

Алгоритмические шаблоны для решения задач на собеседованиях

Dynamic Programming (Динамическое программирование)

Описание шаблона

Динамическое программирование (ДП) — это техника решения задач путём разбиения их на перекрывающиеся подзадачи и сохранения результатов уже решённых подзадач, чтобы не вычислять их повторно. Если backtracking перебирает все варианты, то ДП превращает экспоненциальный перебор в полиномиальное решение за счёт запоминания.

Задача поддаётся ДП, когда есть два свойства:

  1. Перекрывающиеся подзадачи (overlapping subproblems) — одни и те же подзадачи встречаются многократно. Наивная рекурсия Фибоначчи пересчитывает fib(2) десятки раз.
  2. Оптимальная подструктура (optimal substructure) — оптимальное решение задачи строится из оптимальных решений её подзадач.

Когда применять

Признаки-маркеры в условии:

  • «Сколькими способами…» (подсчёт вариантов).
  • «Найдите минимум / максимум / самый длинный…» при последовательности выборов.
  • «Можно ли достичь…» (достижимость через комбинацию шагов).
  • Каждый шаг — выбор с последствиями, и варианты перекрываются.

Если же все подзадачи уникальны (не повторяются) — это обычная рекурсия или backtracking, а не ДП.

Два подхода

Мемоизация (сверху вниз)

Обычная рекурсия + кэш уже посчитанных значений. Пишется естественно, считает только нужные подзадачи.

func fibMemo(n int) int {
    memo := make(map[int]int)
    var f func(int) int
    f = func(k int) int {
        if k < 2 {
            return k
        }
        if v, ok := memo[k]; ok {
            return v // подзадача уже решена
        }
        memo[k] = f(k-1) + f(k-2)
        return memo[k]
    }
    return f(n)
}

Табуляция (снизу вверх)

Заполняем таблицу от базовых случаев к ответу, без рекурсии. Обычно эффективнее по памяти и без риска переполнения стека.

func fibTab(n int) int {
    if n < 2 {
        return n
    }
    prev, cur := 0, 1
    for i := 2; i <= n; i++ {
        prev, cur = cur, prev+cur // храним только два последних значения
    }
    return cur
}

Здесь видна и оптимизация памяти: вместо массива на n элементов достаточно двух переменных — O(1) памяти.

Как построить ДП-решение

  1. Состояние — что описывает подзадачу? (например, dp[i] = ответ для префикса длины i).
  2. Переход — как ответ для состояния выражается через меньшие состояния? (рекуррента).
  3. База — тривиальные случаи (dp[0], dp[1]).
  4. Порядок вычисления — такой, чтобы нужные подзадачи были посчитаны раньше.

Примеры

1D ДП: Climbing Stairs / House Robber

«На сколько ступеней можно подняться, делая шаги по 1 или 2?» — это Фибоначчи: dp[i] = dp[i-1] + dp[i-2]. Тот же приём — в House Robber, где dp[i] = max(dp[i-1], dp[i-2] + nums[i]).

Coin Change (минимум монет)

Состояние dp[a] — минимум монет, чтобы набрать сумму a. Переход: пробуем каждую монету c: dp[a] = min(dp[a], dp[a-c] + 1).

func coinChange(coins []int, amount int) int {
    const INF = 1 << 30
    dp := make([]int, amount+1)
    for i := 1; i <= amount; i++ {
        dp[i] = INF
        for _, c := range coins {
            if c <= i && dp[i-c]+1 < dp[i] {
                dp[i] = dp[i-c] + 1
            }
        }
    }
    if dp[amount] >= INF {
        return -1 // сумму набрать нельзя
    }
    return dp[amount]
}

2D ДП: Longest Common Subsequence (LCS)

Состояние dp[i][j] — длина наибольшей общей подпоследовательности префиксов a[:i] и b[:j]. Если символы совпали — берём диагональ +1, иначе — лучшее из двух соседей.

func lcs(a, b string) int {
    m, n := len(a), len(b)
    dp := make([][]int, m+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
    }
    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            if a[i-1] == b[j-1] {
                dp[i][j] = dp[i-1][j-1] + 1
            } else {
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
            }
        }
    }
    return dp[m][n]
}

0/1 Рюкзак (knapsack)

Состояние dp[i][w] — максимальная ценность из первых i предметов при вместимости w. Для каждого предмета выбор «взять / не взять»: dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i]). Часто сворачивается до 1D-массива по w (идём по w в обратную сторону).

Временная и пространственная сложность

ЗадачаСостоянийПереходВремяПамять (после оптимизации)
Фибоначчи / лестницаO(n)O(1)O(n)O(1)
Coin ChangeO(amount)O(монет)O(amount·k)O(amount)

0/1 РюкзакO(n·W)O(1)O(n·W)O(W)

Общая формула: время ≈ (число состояний) × (стоимость перехода).

Типичные ошибки

  1. Неправильная база — забыли dp[0] или задали неверно; вся таблица «съезжает».
  2. Неверный порядок обхода — состояние используется раньше, чем посчитано.
  3. Путаница индексов строк и таблицы — для строк длины m таблица размера m+1, символ a[i-1] соответствует dp[i].
  4. Мемоизация без кэша на самом деле — забыли записать результат перед return, экспонента осталась.
  5. 0/1-рюкзак: проход по w в прямом порядке при свёрнутом массиве — предмет ошибочно берётся несколько раз (это уже unbounded knapsack).

Связанные шаблоны

  • Backtracking — когда подзадачи перекрываются, перебор с возвратом превращается в ДП добавлением мемоизации.
  • Modified Binary Search — ускоряет некоторые ДП (например, Longest Increasing Subsequence до O(n log n)).

Алгоритмические шаблоны для решения задач на собеседованиях

Этот репозиторий содержит подробное изучение 15 основных алгоритмических шаблонов, которые помогут решить большинство задач на технических собеседованиях.

  • Путь обучения - Рекомендуемая последовательность изучения

Шаблоны

Группа 1: Базовые техники (массивы и строки)

  1. Sliding Window (Скользящее окно) - Операции с подмассивами фиксированного размера
  2. Two Pointers (Два указателя) - Поиск пар элементов в отсортированных массивах
  3. Fast & Slow Pointers (Быстрые и медленные указатели) - Обнаружение циклов и поиск середины списка

Группа 2: Работа с данными

  1. Merge Intervals (Слияние интервалов) - Работа с перекрывающимися интервалами
  2. Cyclic Sort (Циклическая сортировка) - Сортировка массивов с числами от 1 до N
  3. Modified Binary Search (Модифицированный бинарный поиск) - Вариации бинарного поиска
  4. Bit Manipulation (Битовые операции) - Побитовые операции, XOR, маски

Группа 3: Структуры данных - списки

  1. Reverse Linked List (Разворот связанного списка) - Инвертирование списков на месте

Группа 4: Структуры данных - деревья

  1. Tree BFS (Обход дерева в ширину) - Поуровневый обход деревьев
  2. Tree DFS (Обход дерева в глубину) - Рекурсивный обход деревьев

Группа 5: Продвинутые структуры данных

  1. Two Heaps (Две кучи) - Поддержание медианы и разделение данных
  2. Top K Elements (Топ K элементов) - Поиск K наибольших/наименьших элементов
  3. K-way Merge (K-way слияние) - Слияние K отсортированных массивов

Группа 6: Комбинаторика и графы

  1. Subsets (Подмножества) - Генерация всех подмножеств множества
  2. Topological Sort (Топологическая сортировка) - Линейный порядок зависимых элементов

Предварительные знания

Для комфортного изучения шаблонов желательно иметь базовое понимание:

  • Асимптотическая сложность (Big-O) — O(n), O(log n), O(n²) и т.д.; см. Глоссарий
  • Массивы и слайсы — индексация, обход, основные операции
  • Рекурсия — базовый случай, рекурсивный вызов
  • Базовые структуры данных — связанный список, дерево (узлы, дети, корень), граф (вершины, рёбра)

Если какой-то термин неясен, обратитесь к Глоссарию.

Как выбрать между похожими шаблонами?

Sliding Window vs Two Pointers

  • Sliding Window: Используйте для подмассивов/подстрок фиксированного или переменного размера
  • Two Pointers: Используйте для поиска пар/троек в отсортированных массивах или палиндромов

Tree BFS vs Tree DFS

  • Tree BFS: Используйте для обхода по уровням, поиска кратчайшего пути
  • Tree DFS: Используйте для обхода в глубину, валидации, построения дерева

Two Heaps vs Top K Elements

  • Two Heaps: Используйте для поддержания медианы потока данных
  • Top K Elements: Используйте для поиска K наибольших/наименьших элементов

Modified Binary Search vs Two Pointers

  • Modified Binary Search: Используйте для поиска в отсортированных данных (O(log n))
  • Two Pointers: Используйте для поиска пар в отсортированных массивах (O(n))

Что делать, если решение не проходит по времени?

  1. Проверьте сложность: Убедитесь, что временная сложность соответствует ограничениям
  2. Используйте правильный шаблон: Возможно, выбран неоптимальный подход
  3. Оптимизируйте операции: Избегайте дорогих операций в циклах
  4. Используйте кэширование: Сохраняйте результаты повторяющихся вычислений
  5. Рассмотрите альтернативные структуры данных: HashMap вместо линейного поиска, Heap вместо сортировки

Как оптимизировать решение дальше?

  1. Анализируйте сложность: Определите узкие места (bottlenecks)
  2. Используйте профилирование: Измерьте реальную производительность
  3. Оптимизируйте память: Используйте in-place алгоритмы, переиспользуйте структуры данных
  4. Используйте идиоматичный код: Компилятор может лучше оптимизировать идиоматичный код
  5. Рассмотрите параллелизм: Для подходящих задач используйте параллельную обработку

Как выбрать между рекурсивным и итеративным подходом?

  • Рекурсивный: Используйте для простоты кода, когда глубина рекурсии невелика
  • Итеративный: Используйте для больших данных, когда рекурсия может вызвать переполнение стека

Когда использовать кучу вместо сортировки?

  • Куча: Используйте когда нужны только K элементов, а не полная сортировка (O(n log k) vs O(n log n))
  • Сортировка: Используйте когда нужны все элементы в отсортированном порядке

Как работать с дубликатами в алгоритмах?

  • Сначала отсортируйте: Для многих алгоритмов сортировка помогает обработать дубликаты
  • Используйте Set/Map: Для отслеживания уже обработанных элементов
  • Пропускайте дубликаты: В циклах пропускайте элементы, которые уже были обработаны

Как обрабатывать очень большие данные?

  1. Используйте streaming: Обрабатывайте данные порциями
  2. Используйте внешнюю сортировку: Для данных, которые не помещаются в память
  3. Используйте индексы: Для быстрого доступа к данным
  4. Рассмотрите распределенную обработку: Для очень больших объемов данных

Как отлаживать алгоритмы?

  1. Используйте отладчик: Пошаговое выполнение помогает найти ошибки
  2. Добавляйте логирование: Выводите промежуточные состояния
  3. Тестируйте на маленьких данных: Убедитесь, что алгоритм работает корректно
  4. Проверяйте граничные случаи: Пустые данные, один элемент, максимальные значения
  5. Визуализируйте: Рисуйте диаграммы для понимания работы алгоритма

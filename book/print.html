Алгоритмические шаблоны для решения задач на собеседованиях

Шаблоны

Группа 1: Базовые техники (массивы и строки)

  1. Sliding Window (Скользящее окно) - Операции с подмассивами фиксированного размера
  2. Two Pointers (Два указателя) - Поиск пар элементов в отсортированных массивах
  3. Fast & Slow Pointers (Быстрые и медленные указатели) - Обнаружение циклов и поиск середины списка

Группа 2: Работа с данными

  1. Merge Intervals (Слияние интервалов) - Работа с перекрывающимися интервалами
  2. Cyclic Sort (Циклическая сортировка) - Сортировка массивов с числами от 1 до N
  3. Modified Binary Search (Модифицированный бинарный поиск) - Вариации бинарного поиска
  4. Bit Manipulation (Битовые операции) - Побитовые операции, XOR, маски

Группа 3: Структуры данных - списки

  1. Reverse Linked List (Разворот связанного списка) - Инвертирование списков на месте

Группа 4: Структуры данных - деревья

  1. Tree BFS (Обход дерева в ширину) - Поуровневый обход деревьев
  2. Tree DFS (Обход дерева в глубину) - Рекурсивный обход деревьев

Группа 5: Продвинутые структуры данных

  1. Two Heaps (Две кучи) - Поддержание медианы и разделение данных
  2. Top K Elements (Топ K элементов) - Поиск K наибольших/наименьших элементов
  3. K-way Merge (K-way слияние) - Слияние K отсортированных массивов

Группа 6: Комбинаторика и графы

  1. Subsets (Подмножества) - Генерация всех подмножеств множества
  2. Topological Sort (Топологическая сортировка) - Линейный порядок зависимых элементов

Для комфортного изучения шаблонов желательно иметь базовое понимание:

  • Асимптотическая сложность (Big-O) — O(n), O(log n), O(n²) и т.д.; см. Глоссарий
  • Массивы и слайсы — индексация, обход, основные операции
  • Рекурсия — базовый случай, рекурсивный вызов
  • Базовые структуры данных — связанный список, дерево (узлы, дети, корень), граф (вершины, рёбра)

Как выбрать между похожими шаблонами?

Sliding Window vs Two Pointers

  • Sliding Window: Используйте для подмассивов/подстрок фиксированного или переменного размера
  • Two Pointers: Используйте для поиска пар/троек в отсортированных массивах или палиндромов

Tree BFS vs Tree DFS

  • Tree BFS: Используйте для обхода по уровням, поиска кратчайшего пути
  • Tree DFS: Используйте для обхода в глубину, валидации, построения дерева

Two Heaps vs Top K Elements

  • Two Heaps: Используйте для поддержания медианы потока данных
  • Top K Elements: Используйте для поиска K наибольших/наименьших элементов

Modified Binary Search vs Two Pointers

  • Modified Binary Search: Используйте для поиска в отсортированных данных (O(log n))
  • Two Pointers: Используйте для поиска пар в отсортированных массивах (O(n))

Что делать, если решение не проходит по времени?

  1. Проверьте сложность: Убедитесь, что временная сложность соответствует ограничениям
  2. Используйте правильный шаблон: Возможно, выбран неоптимальный подход
  3. Оптимизируйте операции: Избегайте дорогих операций в циклах
  4. Используйте кэширование: Сохраняйте результаты повторяющихся вычислений
  5. Рассмотрите альтернативные структуры данных: HashMap вместо линейного поиска, Heap вместо сортировки

Как оптимизировать решение дальше?

  1. Анализируйте сложность: Определите узкие места (bottlenecks)
  2. Используйте профилирование: Измерьте реальную производительность
  3. Оптимизируйте память: Используйте in-place алгоритмы, переиспользуйте структуры данных
  4. Используйте идиоматичный код: Компилятор может лучше оптимизировать идиоматичный код
  5. Рассмотрите параллелизм: Для подходящих задач используйте параллельную обработку

Как выбрать между рекурсивным и итеративным подходом?

  • Рекурсивный: Используйте для простоты кода, когда глубина рекурсии невелика
  • Итеративный: Используйте для больших данных, когда рекурсия может вызвать переполнение стека

Когда использовать кучу вместо сортировки?

  • Куча: Используйте когда нужны только K элементов, а не полная сортировка (O(n log k) vs O(n log n))
  • Сортировка: Используйте когда нужны все элементы в отсортированном порядке

Как работать с дубликатами в алгоритмах?

  • Сначала отсортируйте: Для многих алгоритмов сортировка помогает обработать дубликаты
  • Используйте Set/Map: Для отслеживания уже обработанных элементов
  • Пропускайте дубликаты: В циклах пропускайте элементы, которые уже были обработаны

Как обрабатывать очень большие данные?

  1. Используйте streaming: Обрабатывайте данные порциями
  2. Используйте внешнюю сортировку: Для данных, которые не помещаются в память
  3. Используйте индексы: Для быстрого доступа к данным
  4. Рассмотрите распределенную обработку: Для очень больших объемов данных

Как отлаживать алгоритмы?

  1. Используйте отладчик: Пошаговое выполнение помогает найти ошибки
  2. Добавляйте логирование: Выводите промежуточные состояния
  3. Тестируйте на маленьких данных: Убедитесь, что алгоритм работает корректно
  4. Проверяйте граничные случаи: Пустые данные, один элемент, максимальные значения
  5. Визуализируйте: Рисуйте диаграммы для понимания работы алгоритма

Детальное описание по типам задач

Работа с массивами и строками

Sliding Window

Используйте, когда:

  • Нужно найти подмассив/подстроку определенного размера
  • Нужно найти подмассив/подстроку, удовлетворяющую условию
  • Задача связана с “окном” фиксированного или переменного размера

Примеры задач:

  • Найти максимальную сумму подмассива размера k
  • Найти минимальную подстроку, содержащую все символы
  • Найти все анаграммы в строке

Two Pointers

Используйте, когда:

  • Массив отсортирован
  • Нужно найти пару/тройку элементов с определенным свойством
  • Нужно удалить дубликаты из отсортированного массива
  • Нужно проверить палиндром

Примеры задач:

  • Найти два числа с заданной суммой
  • Удалить дубликаты из отсортированного массива
  • Проверить, является ли строка палиндромом

Cyclic Sort

Используйте, когда:

  • Массив содержит числа в диапазоне [1, n] или [0, n-1]
  • Нужно найти отсутствующие числа
  • Нужно найти дубликаты
  • Можно использовать индексы как хеш-таблицу

Примеры задач:

  • Найти отсутствующее число
  • Найти все дубликаты
  • Найти первое отсутствующее положительное число

Modified Binary Search

Используйте, когда:

  • Массив отсортирован (или частично отсортирован)
  • Нужно найти элемент или границу
  • Нужно найти в повернутом отсортированном массиве
  • Нужно найти в 2D отсортированной матрице

Примеры задач:

  • Найти элемент в отсортированном массиве
  • Найти первую/последнюю позицию элемента
  • Найти минимум в повернутом массиве

Bit Manipulation

Используйте, когда:

  • Нужно найти единственный элемент среди пар (каждый элемент встречается дважды)
  • Работа с отдельными битами числа (проверка, установка, сброс)
  • Задача связана с флагами, степенями двойки, чётностью
  • Требуется O(1) дополнительной памяти

Примеры задач:

  • Single Number — найти единственный элемент
  • Missing Number — XOR-решение
  • Power of Two — проверка степени двойки
  • Number of 1 Bits — подсчёт единичных битов
  • Hamming Distance — расстояние Хэмминга

Работа со связанными списками

Fast & Slow Pointers

Используйте, когда:

  • Нужно обнаружить цикл в списке
  • Нужно найти середину списка
  • Нужно найти K-й элемент с конца
  • Нужно проверить палиндром в списке

Примеры задач:

  • Обнаружить цикл в связанном списке
  • Найти середину связанного списка
  • Проверить, является ли список палиндромом

Reverse Linked List

Используйте, когда:

  • Нужно развернуть весь список
  • Нужно развернуть часть списка
  • Нужно развернуть список группами

Примеры задач:

  • Развернуть связанный список
  • Развернуть список между позициями m и n
  • Развернуть узлы группами по k

Работа с деревьями

Tree BFS

Используйте, когда:

  • Нужен обход дерева по уровням
  • Нужно найти кратчайший путь
  • Нужно обработать все узлы на одном уровне перед переходом к следующему

Примеры задач:

  • Обход дерева по уровням
  • Найти среднее значение каждого уровня
  • Найти вид дерева справа

Tree DFS

Используйте, когда:

Sliding Window (Скользящее окно)

Теория

Скользящее окно — техника для операций над подмассивами или подстроками фиксированного или переменного размера в линейной структуре (массив, строка).

Ключевая идея — инкрементальное обновление: переходя к следующему окну, мы добавляем один новый элемент и убираем один старый, вместо полного пересчёта. Это снижает сложность с O(n·k) (наивный пересчёт каждого окна) до O(n).

Когда применять:

  • данные линейны (массив, строка, список);
  • нужно найти самый длинный/короткий/оптимальный подмассив или подстроку;
  • задача о подмассиве фиксированного размера k;
  • решение можно ускорить, переиспользуя вычисления соседнего окна.

Алгоритм

Различают два типа окон.

Фиксированное окно

Размер k постоянен. Считаем сумму первого окна, затем двигаем границу, добавляя arr[i] и вычитая arr[i-k].

func maxSumSubarray(arr []int, k int) int {
    if k <= 0 || k > len(arr) {
        return 0
    }
    windowSum := 0
    for i := 0; i < k; i++ {
        windowSum += arr[i]
    }
    maxSum := windowSum
    for i := k; i < len(arr); i++ {
        windowSum += arr[i] - arr[i-k] // +новый, −старый за O(1)
        if windowSum > maxSum {
            maxSum = windowSum
        }
    }
    return maxSum
}

Переменное окно

Размер меняется под условие: расширяем окно правой границей right, а при нарушении условия сжимаем слева left. Состояние окна (счётчики, частоты) держим в map или переменной.

// Самая длинная подстрока, где не более k различных символов
func longestKDistinct(s string, k int) int {
    freq := make(map[byte]int)
    left, maxLen := 0, 0
    for right := 0; right < len(s); right++ {
        freq[s[right]]++
        for len(freq) > k { // условие нарушено — сжимаем слева
            freq[s[left]]--
            if freq[s[left]] == 0 {
                delete(freq, s[left])
            }
            left++
        }
        if cur := right - left + 1; cur > maxLen {
            maxLen = cur
        }
    }
    return maxLen
}

Порядок шагов для переменного окна: расширить (right++) → проверить условие → сжать при необходимости (left++) → обновить результат.

Two Pointers (Два указателя)

Теория

Two Pointers — техника, в которой по линейной структуре (массив, строка, список) движутся два индекса, согласованно меняя позиции до выполнения условия. Вместо перебора всех пар (O(n²)) мы используем отсортированность или монотонность данных, чтобы за один шаг отбрасывать целые области поиска. Это снижает сложность до O(n) при O(1) памяти.

Три основных варианта:

  • Встречные указатели — left с начала, right с конца, движутся навстречу.
  • Одно направление — slow и fast идут с одного края (фильтрация, дедупликация).
  • Быстрый и медленный — движение с разной скоростью (см. Fast & Slow Pointers).

Когда применять:

  • массив отсортирован (для встречных указателей это обязательно);
  • нужно найти пару/тройку/подмассив, удовлетворяющий условию;
  • задача сводится к движению с двух концов или к фильтрации на месте;
  • хочется убрать вложенный цикл и улучшить сложность.

Алгоритм

Встречные указатели

left и right стоят на краях. Сравниваем сумму с целью: если меньше — двигаем left вправо (нужно больше), если больше — двигаем right влево (нужно меньше).

func twoSumSorted(arr []int, target int) (int, int, bool) {
    left, right := 0, len(arr)-1
    for left < right {
        sum := arr[left] + arr[right]
        switch {
        case sum == target:
            return left, right, true
        case sum < target:
            left++ // нужна большая сумма
        default:
            right-- // нужна меньшая сумма
        }
    }
    return 0, 0, false
}

Одно направление

slow отмечает границу обработанной части, fast сканирует массив. Применяется для удаления дубликатов из отсортированного массива на месте: arr[0..slow] всегда содержит уникальные элементы.

func removeDuplicates(nums []int) int {
    if len(nums) == 0 {
        return 0
    }
    slow := 0
    for fast := 1; fast < len(nums); fast++ {
        if nums[slow] != nums[fast] {
            slow++
            nums[slow] = nums[fast]
        }
    }
    return slow + 1 // длина уникального префикса
}

Линейность следует из того, что left только растёт, right только убывает, а в варианте «одно направление» каждый указатель проходит массив максимум один раз.

Типичные ошибки

  1. Применение встречных указателей к неотсортированному массиву — сначала sort.Ints(arr), иначе логика отбрасывания пар неверна.
  2. Неверное условие цикла — используйте for left < right, а не !=, чтобы не проскочить точку пересечения.
  3. Неправильное направление сдвига — при sum < target двигают left, при sum > target — right; перепутать значит зациклиться или пропустить пару.
  4. Off-by-one в «одном направлении» — сначала slow++, затем nums[slow] = nums[fast], иначе затрёте нужный элемент.
  5. Забыли обновить результат в задачах на максимум (площадь, вода) перед сдвигом указателей.
  6. Не обработаны границы — пустой массив или массив из одного элемента.

Fast & Slow Pointers (Быстрые и медленные указатели)

Теория

Fast & Slow Pointers (алгоритм «заяц и черепаха», обнаружение циклов Флойда) — два указателя движутся по структуре с разной скоростью: медленный на 1 шаг, быстрый на 2. Если в списке есть цикл, быстрый рано или поздно догонит медленный внутри цикла; если цикла нет — быстрый первым достигнет конца.

Техника даёт O(n) по времени и O(1) по памяти там, где наивный подход с хеш-таблицей тратит O(n) дополнительной памяти.

Когда применять:

  • определить наличие цикла в связанном списке;
  • найти середину списка за один проход;
  • найти K-й элемент с конца;
  • работать с циклическими структурами за O(1) памяти.

Алгоритм

Обнаружение цикла

Двигаем slow на шаг, fast на два. Совпадение указателей означает цикл; выход fast в nil — цикла нет. Условие fast != nil && fast.Next != nil защищает от разыменования nil.

type ListNode struct {
    Val  int
    Next *ListNode
}

func hasCycle(head *ListNode) bool {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast {
            return true
        }
    }
    return false
}

Начало цикла

После встречи возвращаем slow в head и двигаем оба указателя по одному шагу: точка их новой встречи — начало цикла. Это работает потому, что расстояние от головы до начала цикла равно расстоянию от точки встречи до начала цикла.

func detectCycle(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast {
            break
        }
    }
    if fast == nil || fast.Next == nil {
        return nil // цикла нет
    }
    slow = head
    for slow != fast {
        slow = slow.Next
        fast = fast.Next
    }
    return slow
}

Середина списка

Когда fast дойдёт до конца, slow окажется в середине.

func middleNode(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }
    return slow
}

Типичные ошибки

  1. Условие цикла for fast != nil без проверки fast.Next — разыменование nil при fast.Next.Next. Правильно: for fast != nil && fast.Next != nil.
  2. Сдвиг старта — инициализируйте оба указателя head, а не head.Next.

  5. Поиск K-го с конца, когда K больше длины — двигая fast вперёд на K шагов, проверяйте fast == nil.

Merge Intervals (Слияние интервалов)

Теория

Merge Intervals — техника для работы с перекрывающимися интервалами: их слияния, поиска пересечений и вставки новых интервалов в отсортированный список.

Ключевая идея: если интервалы отсортированы по начальной точке, то для проверки перекрытия достаточно сравнить начало текущего интервала с концом последнего объединённого. Два интервала [a, b] и [c, d] перекрываются при a <= d && c <= b; при слиянии получаем [min(a, c), max(b, d)]. Сортировка превращает задачу из O(n²) (проверка всех пар) в O(n log n).

Когда применять:

  • работаете с интервалами, которые могут перекрываться;
  • нужно объединить перекрытия или найти их пересечения;
  • задача связана с временными диапазонами, расписаниями или сегментами;
  • нужно вставить новый интервал в отсортированный список.

Алгоритм

Сортируем по началу, затем идём в один проход, сравнивая текущий интервал только с последним в результате.

func mergeIntervals(intervals [][]int) [][]int {
    if len(intervals) == 0 {
        return [][]int{}
    }
    // Сортировка по началу — после неё достаточно смотреть только на последний интервал
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][0] < intervals[j][0]
    })

    result := [][]int{intervals[0]}
    for i := 1; i < len(intervals); i++ {
        current := intervals[i]
        last := result[len(result)-1]
        if current[0] <= last[1] { // перекрытие
            if current[1] > last[1] {
                last[1] = current[1] // расширяем конец до максимума
            }
        } else {
            result = append(result, current) // разрыв — новый интервал
        }
    }
    return result
}

Для вставки нового интервала в уже отсортированный список делаем один проход: интервалы, заканчивающиеся до нового, копируем как есть; пересекающиеся поглощаем, расширяя границы нового; остальные добавляем после.

func insertInterval(intervals [][]int, newInterval []int) [][]int {
    var result [][]int
    i, n := 0, len(intervals)

    for i < n && intervals[i][1] < newInterval[0] { // целиком слева
        result = append(result, intervals[i])
        i++
    }
    merged := []int{newInterval[0], newInterval[1]}
    for i < n && intervals[i][0] <= merged[1] { // перекрытие — поглощаем
        if intervals[i][0] < merged[0] {
            merged[0] = intervals[i][0]
        }
        if intervals[i][1] > merged[1] {
            merged[1] = intervals[i][1]
        }
        i++
    }
    result = append(result, merged)

    for i < n { // целиком справа
        result = append(result, intervals[i])
        i++
    }
    return result
}

Для слияния доминирует сортировка O(n log n), сам проход линеен. Вставка не требует сортировки — вход уже упорядочен.

Cyclic Sort (Циклическая сортировка)

Теория

Cyclic Sort — сортировка массива на месте, когда числа лежат в известном диапазоне (обычно от 1 до N). Алгоритм использует то, что число x должно стоять на позиции x - 1 (для диапазона 1..N) или на позиции x (для 0..N-1).

Каждый элемент за один цикл перестановок «отправляется» на своё место. Поскольку после размещения элемент больше не двигается, всего происходит не более N перестановок — это даёт O(n) времени и O(1) памяти.

Когда применять:

  • массив содержит числа в диапазоне 1..N (или 0..N-1);
  • нужна сортировка на месте без дополнительной памяти;
  • требуется найти отсутствующее, дублирующееся или неправильно расположенное число.

Алгоритм

Идём по массиву индексом i. Если nums[i] не на своём месте — меняем его с элементом на правильной позиции и не увеличиваем i (нужно проверить новый элемент). Если на месте — переходим дальше.

func cyclicSort(nums []int) {
    i, n := 0, len(nums)
    for i < n {
        v := nums[i]
        // Guard: значение вне [1, n] нельзя поставить на «свою» позицию — пропускаем
        if v < 1 || v > n {
            i++
            continue
        }
        correctPos := v - 1 // число x должно стоять на индексе x-1
        if nums[i] != nums[correctPos] {
            nums[i], nums[correctPos] = nums[correctPos], nums[i]
            // i не увеличиваем — на позиции i теперь новый элемент
        } else {
            i++
        }
    }
}

Сравнение nums[i] != nums[correctPos] (а не i != correctPos) защищает от бесконечного цикла на дубликатах: если на целевой позиции уже такое же значение, обмен бессмыслен — двигаемся дальше.

После сортировки легко найти первое число, стоящее не на своём месте, — это и есть отсутствующее (или лишнее).

func findMissingNumber(nums []int) int {
    cyclicSort(nums)
    for i := 0; i < len(nums); i++ {
        if nums[i] != i+1 {
            return i + 1
        }
    }
    return len(nums) + 1 // все числа 1..n на месте
}

[5, 1, 3, 4, 2]  i=0: 5→поз.4, swap с nums[4]=2
[2, 1, 3, 4, 5]  i=0: 2→поз.1, swap с nums[1]=1
[1, 2, 3, 4, 5]  i=0: 1 на месте → i++
[1, 2, 3, 4, 5]  i=1..4: все на местах → i++

Типичные ошибки

  1. Неверная формула позиции — для диапазона 1..N это x-1, для 0..N-1 это x.
  2. Бесконечный цикл на дубликатах — сравнивайте значения (nums[i] != nums[correctPos]), а не индексы.
  3. Выход за границы — добавляйте guard для значений вне [1, n], иначе nums[v-1] упадёт.
  4. Увеличение i после обмена — после swap на позиции i стоит новый элемент, его тоже нужно проверить; i++ только когда элемент уже на месте.
  5. Не обработан пустой массив — цикл i < n это покрывает, но проверьте, что постобработка (поиск пропуска) не падает на пустом входе.

Modified Binary Search (Модифицированный бинарный поиск)

Теория

Modified Binary Search расширяет классический бинарный поиск на задачи, где ищут не точное значение, а границу монотонного предиката: первое/последнее вхождение, позицию вставки, минимум в повернутом массиве, элемент в 2D-матрице.

Ключевая идея: бинарный поиск работает для любого монотонного условия. Меняя условие сравнения и правило обновления границ, мы решаем разные задачи поиска за O(log n), сохраняя инвариант «решение, если оно есть, лежит в [left, right]».

Когда применять:

  • массив отсортирован (полностью или частично — например, повернут);
  • нужно первое/последнее вхождение или позиция вставки;
  • ищем границу диапазона значений;
  • пространство поиска монотонно (значение, индекс, ответ в матрице).

Алгоритм

Делим интервал [left, right] пополам, сравниваем arr[mid] с target и отбрасываем половину, где target заведомо нет. mid считаем как left + (right-left)/2, чтобы избежать переполнения.

// Классический поиск точного значения
func binarySearch(arr []int, target int) int {
    left, right := 0, len(arr)-1
    for left <= right {
        mid := left + (right-left)/2
        switch {
        case arr[mid] == target:
            return mid
        case arr[mid] < target:
            left = mid + 1 // ищем в правой половине
        default:
            right = mid - 1 // ищем в левой половине
        }
    }
    return -1 // не найдено
}

Для первого вхождения при равенстве не останавливаемся, а продолжаем сжимать правую границу — так находим самый левый индекс с target.

func findFirstOccurrence(arr []int, target int) int {
    left, right := 0, len(arr)-1
    result := -1
    for left <= right {
        mid := left + (right-left)/2
        switch {
        case arr[mid] == target:
            result = mid    // запоминаем и продолжаем влево
            right = mid - 1
        case arr[mid] < target:
            left = mid + 1
        default:
            right = mid - 1
        }
    }
    return result
}

В повернутом массиве одна из половин [left..mid] или [mid..right] всегда отсортирована. Проверяем arr[left] <= arr[mid]: если да — отсортирована левая половина, иначе правая. Ищем target только в отсортированной половине.

Идиоматичный Go использует sort.Search — он находит наименьший индекс, для которого предикат истинен:

import "sort"

func searchIdiomatic(arr []int, target int) int {
    i := sort.Search(len(arr), func(i int) bool {
        return arr[i] >= target
    })
    if i < len(arr) && arr[i] == target {
        return i
    }
    return -1
}

Типичные ошибки

  1. Переполнение mid — считайте left + (right-left)/2, а не (left + right)/2.
  2. Неверное условие цикла — left <= right ищет в закрытом интервале; left < right (с right = mid) — для поиска границы. Смешивать нельзя.

  4. Повернутый массив: забыли определить отсортированную половину перед отбрасыванием — тогда теряете target.
  5. Не обработаны границы — пустой массив, один элемент, target вне диапазона.

Bit Manipulation (Битовые операции)

Теория

Bit Manipulation использует побитовые операции (AND, OR, XOR, сдвиги) для решения задач с минимальной памятью. Ключевое свойство — «самообнуление» XOR: a ^ a = 0 и a ^ 0 = a. Это позволяет находить единственный элемент среди пар, работать с флагами и масками битов за O(1) дополнительной памяти.

Когда применять:

  • нужно найти единственный элемент среди пар;
  • проверить или изменить отдельные биты числа;
  • работать с множеством флагов (включено/выключено);
  • задача упоминает «биты», «чётность», «степень двойки», требует O(1) памяти.

Алгоритм

Целое число хранится как последовательность битов; позиции нумеруются справа налево с нуля. Например, 5 = 0101 — биты на позициях 0 и 2 установлены, 8 = 1000 — один бит (степень двойки).

Свойства XOR

  • a ^ a = 0 — одинаковые значения обнуляются;
  • a ^ 0 = a — нейтральный элемент;
  • a ^ b ^ a = b — коммутативность и ассоциативность.

Поиск единственного числа. XOR всех элементов: пары обнуляются, остаётся непарный элемент.

// Single Number: один элемент встречается 1 раз, остальные — по 2 раза
func singleNumber(nums []int) int {
    result := 0
    for _, num := range nums {
        result ^= num // пары обнуляются, остаётся единственный
    }
    return result
}

Проверка степени двойки. У степени двойки ровно один установленный бит, а n & (n-1) обнуляет младший единичный бит.

func isPowerOfTwo(n int) bool {
    if n <= 0 {
        return false
    }
    return n&(n-1) == 0
}

Подсчёт единичных битов (Brian Kernighan). Каждая итерация удаляет младший установленный бит, поэтому число итераций равно числу единиц.

func hammingWeight(n uint32) int {
    count := 0
    for n != 0 {
        n &= n - 1 // удаляем младший установленный бит
        count++
    }
    return count
}

Reverse Linked List (Разворот связанного списка)

Теория

Reverse Linked List — разворот связанного списка на месте (in-place): мы меняем направление каждого указателя next, не создавая новых узлов. Итеративный вариант хранит три ссылки (предыдущий, текущий, следующий) и стоит O(1) памяти; рекурсивный короче, но тратит O(n) на стек вызовов.

Когда применять:

  • нужно развернуть весь список или его часть;
  • требуется обработать элементы в обратном порядке;
  • задача про палиндром, переупорядочивание или развороты группами;
  • основа для более сложных манипуляций с указателями списка.

Алгоритм

Итеративный подход

Идём по списку, на каждом узле сохраняем next, переключаем curr.Next на prev и сдвигаем оба указателя. По завершении prev — новая голова.

type ListNode struct {
    Val  int
    Next *ListNode
}

func reverseListIterative(head *ListNode) *ListNode {
    var prev *ListNode
    curr := head
    for curr != nil {
        next := curr.Next // сохраняем остаток списка
        curr.Next = prev  // разворачиваем указатель
        prev = curr       // двигаемся вперёд
        curr = next
    }
    return prev
}

Рекурсивный подход

Базовый случай — пустой список или один узел. Иначе разворачиваем хвост, затем переключаем единственный указатель: head.Next.Next = head, head.Next = nil.

func reverseListRecursive(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head
    }
    newHead := reverseListRecursive(head.Next)
    head.Next.Next = head
    head.Next = nil
    return newHead
}

ИтеративныйO(n)O(1)

Каждый узел посещается ровно один раз. Для длинных списков предпочтительнее итеративный вариант — он не рискует переполнением стека.

Tree BFS (Обход дерева в ширину)

Теория

Tree BFS (Breadth-First Search) обходит дерево уровень за уровнем: все узлы уровня k обрабатываются прежде, чем алгоритм перейдёт к уровню k+1. Узлы хранятся в очереди (FIFO): добавляем в конец, извлекаем из начала — это естественным образом задаёт порядок «сначала ближние, потом дальние».

Когда применять:

  • нужно обработать узлы по уровням (вывод по строкам, среднее уровня, вид справа);
  • ищется кратчайший путь по числу рёбер (минимальная глубина);
  • задача связана с шириной дерева или порядком обнаружения узлов.

Алгоритм

Кладём корень в очередь. На каждой итерации фиксируем размер текущего уровня levelSize и обрабатываем ровно столько узлов, добавляя их детей в конец очереди для следующего уровня.

type TreeNode struct {
    Val   int
    Left  *TreeNode
    Right *TreeNode
}

// Обход по уровням: значения узлов, сгруппированные по уровням
func levelOrder(root *TreeNode) [][]int {
    if root == nil {
        return [][]int{}
    }

    queue := []*TreeNode{root}
    result := [][]int{}

    for len(queue) > 0 {
        levelSize := len(queue)               // сколько узлов на текущем уровне
        level := make([]int, 0, levelSize)

        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]                 // dequeue из начала
            level = append(level, node.Val)

            if node.Left != nil {             // детей кладём в конец
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }

        result = append(result, level)
    }

    return result
}

Фиксация levelSize до начала внутреннего цикла критична: во время обработки уровня мы добавляем детей в ту же очередь, и без снимка размера границы уровней «съедут».

Сложность

МетрикаЗначение
ВремяO(n) — каждый узел добавляется и извлекается один раз
ПамятьO(w), где w — максимальная ширина дерева (до n/2)

Tree DFS (Обход дерева в глубину)

Теория

Tree DFS (Depth-First Search) идёт вглубь по каждой ветви до конца, прежде чем вернуться и перейти к следующей. Рекурсивная природа дерева (корень + поддеревья) естественно ложится на рекурсию; неявный стек вызовов хранит путь от корня. Порядок обработки корня относительно поддеревьев задаёт три варианта обхода:

  • Pre-order: корень → левое → правое (копирование дерева, префиксные выражения);
  • In-order: левое → корень → правое (для BST даёт отсортированную последовательность);
  • Post-order: левое → правое → корень (удаление дерева, постфиксные выражения).

Когда применять:

  • нужно обойти все узлы или найти путь от корня до листа;
  • проверяются свойства дерева (симметричность, валидность BST);
  • значение узла зависит от результатов поддеревьев (сумма, высота, путь).

Алгоритм

Все три обхода отличаются только моментом записи node.Val относительно рекурсивных вызовов.

type TreeNode struct {
    Val   int
    Left  *TreeNode
    Right *TreeNode
}

// Pre-order: корень → левое → правое
func preorderTraversal(root *TreeNode) []int {
    result := []int{}

    var dfs func(*TreeNode)
    dfs = func(node *TreeNode) {
        if node == nil { // базовый случай
            return
        }
        result = append(result, node.Val) // обрабатываем ДО рекурсии
        dfs(node.Left)
        dfs(node.Right)
    }

    dfs(root)
    return result
}

// In-order: левое → корень → правое
func inorderTraversal(root *TreeNode) []int {
    result := []int{}

    var dfs func(*TreeNode)
    dfs = func(node *TreeNode) {
        if node == nil {
            return
        }
        dfs(node.Left)
        result = append(result, node.Val) // обрабатываем МЕЖДУ рекурсиями
        dfs(node.Right)
    }

    dfs(root)
    return result
}

// Post-order: левое → правое → корень
func postorderTraversal(root *TreeNode) []int {
    result := []int{}

    var dfs func(*TreeNode)
    dfs = func(node *TreeNode) {
        if node == nil {
            return
        }
        dfs(node.Left)
        dfs(node.Right)
        result = append(result, node.Val) // обрабатываем ПОСЛЕ рекурсии
    }

    dfs(root)
    return result
}

Для очень глубоких деревьев рекурсия рискует переполнить стек — тогда используют итеративный обход с явным стеком []*TreeNode.

Two Heaps (Две кучи)

Теория

Two Heaps хранит данные в двух кучах: max-heap для меньшей половины элементов и min-heap для большей. Медиана разделяет отсортированный набор на две равные части — держа это разделение, мы получаем медиану из вершин куч за O(1), а вставку — за O(log n), вместо пересортировки всего набора.

Инвариант, который поддерживается после каждой вставки:

  • любой элемент max-heap ≤ любого элемента min-heap;
  • размеры куч отличаются не более чем на 1.

Когда применять:

  • нужно поддерживать медиану потока чисел;
  • данные делятся на «меньшую» и «большую» половины с балансировкой;
  • ищется K-й элемент или баланс между двумя множествами.

Куча (heap) — приоритетная очередь: min-heap даёт минимум за O(1), max-heap — максимум, вставка и удаление — за O(log n). В Go куча реализуется через container/heap поверх среза. См. также Глоссарий.

Алгоритм

Новый элемент кладём в maxHeap, если он не больше его вершины, иначе в minHeap. Затем выравниваем размеры: если одна куча переросла другую больше чем на 1, переносим вершину. Медиана — это вершина большей кучи либо среднее двух вершин при равных размерах.

import "container/heap"

// MaxHeap — меньшая половина (максимум на вершине)
type MaxHeap []int

func (h MaxHeap) Len() int            { return len(h) }
func (h MaxHeap) Less(i, j int) bool  { return h[i] > h[j] } // обратный порядок
func (h MaxHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *MaxHeap) Push(x interface{}) { *h = append(*h, x.(int)) }
func (h *MaxHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

// MinHeap — большая половина (минимум на вершине)
type MinHeap []int

func (h MinHeap) Len() int            { return len(h) }
func (h MinHeap) Less(i, j int) bool  { return h[i] < h[j] }
func (h MinHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *MinHeap) Push(x interface{}) { *h = append(*h, x.(int)) }
func (h *MinHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

type MedianFinder struct {
    maxHeap *MaxHeap // все элементы <= медианы
    minHeap *MinHeap // все элементы >= медианы
}

func NewMedianFinder() *MedianFinder {
    return &MedianFinder{maxHeap: &MaxHeap{}, minHeap: &MinHeap{}}
}

func (mf *MedianFinder) AddNum(num int) {
    if mf.maxHeap.Len() == 0 || num <= (*mf.maxHeap)[0] {
        heap.Push(mf.maxHeap, num)
    } else {
        heap.Push(mf.minHeap, num)
    }

    // балансировка: размеры отличаются не более чем на 1
    if mf.maxHeap.Len() > mf.minHeap.Len()+1 {
        heap.Push(mf.minHeap, heap.Pop(mf.maxHeap).(int))
    } else if mf.minHeap.Len() > mf.maxHeap.Len()+1 {
        heap.Push(mf.maxHeap, heap.Pop(mf.minHeap).(int))
    }
}

func (mf *MedianFinder) FindMedian() float64 {
    switch {
    case mf.maxHeap.Len() == mf.minHeap.Len():
        return float64((*mf.maxHeap)[0]+(*mf.minHeap)[0]) / 2.0
    case mf.maxHeap.Len() > mf.minHeap.Len():
        return float64((*mf.maxHeap)[0])
    default:
        return float64((*mf.minHeap)[0])
    }
}

Типичные ошибки

  1. Сломанная балансировка — после каждой вставки разница размеров должна оставаться ≤ 1; иначе вершина перестаёт быть медианой.

  4. Чтение медианы из пустой структуры — проверяйте, что хотя бы одна куча непуста.
  5. Сравнение не с той вершиной — выбор кучи для нового элемента делается по вершине max-heap, а не min-heap.

Top K Elements (Топ K элементов)

Теория

Top K Elements — шаблон для поиска K наибольших, наименьших или наиболее частых элементов коллекции без полной сортировки. Ключевая идея — поддерживать кучу размера K (приоритетную очередь): нам не нужны все элементы в порядке, достаточно держать инвариант «в куче — K лучших».

Куча (heap) даёт минимум/максимум за O(1), а вставку и удаление за O(log K). См. Глоссарий.

Когда применять:

  • нужно найти K наибольших/наименьших элементов;
  • нужно найти K наиболее частых элементов;
  • задача связана с приоритетами или ранжированием;
  • решение без полной сортировки выгодно при k << n.

Алгоритм

Для K наибольших держим min-heap размера K: вершина — это худший (минимальный) из K лучших. Новый элемент больше вершины → выталкиваем вершину и вставляем новый. Для K наименьших симметрично используем max-heap.

import "container/heap"

// MinHeap — для K наибольших элементов
type MinHeap []int

func (h MinHeap) Len() int            { return len(h) }
func (h MinHeap) Less(i, j int) bool  { return h[i] < h[j] }
func (h MinHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *MinHeap) Push(x interface{}) { *h = append(*h, x.(int)) }
func (h *MinHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

// K наибольших элементов
func findKLargest(nums []int, k int) []int {
    if k <= 0 || len(nums) == 0 {
        return nil
    }
    h := &MinHeap{}
    heap.Init(h)
    for _, num := range nums {
        if h.Len() < k {
            heap.Push(h, num)
        } else if num > (*h)[0] { // больше худшего из лучших — заменяем
            heap.Pop(h)
            heap.Push(h, num)
        }
    }
    result := make([]int, h.Len())
    for i := len(result) - 1; i >= 0; i-- {
        result[i] = heap.Pop(h).(int)
    }
    return result
}

Для K наиболее частых сначала считаем частоты в map, затем тем же приёмом отбираем K элементов с наибольшей частотой:

func topKFrequent(nums []int, k int) []int {
    freq := make(map[int]int, len(nums))
    for _, num := range nums {
        freq[num]++
    }
    type pair struct{ num, count int }
    pairs := make([]pair, 0, len(freq))
    for num, count := range freq {
        pairs = append(pairs, pair{num, count})
    }
    sort.Slice(pairs, func(i, j int) bool { return pairs[i].count > pairs[j].count })
    result := make([]int, k)
    for i := 0; i < k; i++ {
        result[i] = pairs[i].num
    }
    return result
}

K-way Merge (K-way слияние)

Теория

K-way Merge объединяет K отсортированных массивов (списков, потоков) в один отсортированный результат. Это обобщение слияния двух отсортированных массивов.

Ключевая идея: следующий минимальный элемент результата — это минимум среди первых непрочитанных элементов всех K массивов. Min-heap позволяет находить этот минимум за O(log k), храня по одному «текущему» элементу от каждого массива. Извлекли минимум — добавили следующий элемент из того же массива.

Когда применять:

  • нужно слить K отсортированных массивов/списков в один;
  • требуется внешняя сортировка (данные не помещаются в память, лежат в отсортированных файлах);
  • нужно обработать несколько отсортированных потоков и брать глобальный минимум.

Алгоритм

Кладём в кучу первый элемент каждого массива вместе с индексом массива и позицией. Пока куча не пуста: извлекаем минимум в результат и добавляем следующий элемент из того же массива.

import "container/heap"

// Элемент кучи: значение + откуда оно пришло
type Element struct {
    Val      int // значение
    ArrayIdx int // индекс массива
    ElemIdx  int // позиция в этом массиве
}

type MinHeap []Element

func (h MinHeap) Len() int            { return len(h) }
func (h MinHeap) Less(i, j int) bool  { return h[i].Val < h[j].Val }
func (h MinHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *MinHeap) Push(x interface{}) { *h = append(*h, x.(Element)) }
func (h *MinHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func mergeKSortedArrays(arrays [][]int) []int {
    h := &MinHeap{}
    heap.Init(h)
    // Первый элемент каждого непустого массива
    for i := range arrays {
        if len(arrays[i]) > 0 {
            heap.Push(h, Element{Val: arrays[i][0], ArrayIdx: i, ElemIdx: 0})
        }
    }

    result := make([]int, 0)
    for h.Len() > 0 {
        minElem := heap.Pop(h).(Element) // глобальный минимум среди непрочитанных
        result = append(result, minElem.Val)

        next := minElem.ElemIdx + 1
        if next < len(arrays[minElem.ArrayIdx]) {
            heap.Push(h, Element{
                Val:      arrays[minElem.ArrayIdx][next],
                ArrayIdx: minElem.ArrayIdx,
                ElemIdx:  next,
            })
        }
    }
    return result
}

K-way merge с кучейO(n log k)O(k)

Где n — общее число элементов, k — количество массивов. Каждый из n элементов проходит через push/pop кучи размера ≤ k за O(log k).

Subsets (Подмножества)

Теория

Шаблон Subsets генерирует все возможные подмножества множества. Для каждого элемента есть два выбора — включить его в подмножество или не включать. Это образует бинарное дерево решений с 2^n листьями, по одному на каждое подмножество.

Основной приём — backtracking (откат): строим решение пошагово в одном общем массиве, после обработки варианта «откатываемся» — убираем добавленный элемент. Это экономит память, не создавая 2^n промежуточных копий.

Когда применять:

  • нужно сгенерировать все подмножества или комбинации;
  • задача — перебор всех вариантов по принципу «включить/исключить»;
  • нужны подмножества с определёнными свойствами (комбинации, перестановки, сумма).

Алгоритм

На каждом шаге добавляем элемент в current, рекурсивно обрабатываем остаток, затем откатываемся. Текущее подмножество сохраняем в результат копией, так как current будет меняться дальше.

func subsets(nums []int) [][]int {
    var result [][]int
    var current []int

    var backtrack func(start int)
    backtrack = func(start int) {
        // Сохраняем копию текущего подмножества
        subset := make([]int, len(current))
        copy(subset, current)
        result = append(result, subset)

        for i := start; i < len(nums); i++ {
            current = append(current, nums[i]) // выбор: включить nums[i]
            backtrack(i + 1)
            current = current[:len(current)-1] // откат: убрать nums[i]
        }
    }

    backtrack(0)
    return result
}

Backtracking (Поиск с возвратом)

Описание шаблона

Backtracking (поиск с возвратом) — это техника систематического перебора, при которой решение строится по одному элементу за раз. Как только становится понятно, что текущий частичный вариант не может привести к допустимому решению, алгоритм откатывается (backtrack) на шаг назад и пробует другой вариант.

По сути это обход в глубину (DFS) по дереву решений: каждый узел — частичное решение, каждое ребро — выбор следующего элемента. Ключевая идея — «сделал выбор → рекурсивно продолжил → отменил выбор».

Когда применять

Используйте этот шаблон, когда нужно:

  • Сгенерировать все комбинации, перестановки или подмножества.
  • Найти все пути или конфигурации, удовлетворяющие ограничениям (судоку, N ферзей, расстановка скобок).
  • Решить задачу вида «существует ли последовательность выборов, дающая результат».

Признак-маркер: в условии есть слова «все возможные», «сгенерируйте», «найдите все комбинации/пути», а размер входа невелик (перебор экспоненциальный).

Алгоритм/Подход

Общий каркас одинаков почти для всех задач:

func backtrack(current []int, choices []int, result *[][]int) {
    // 1. Базовый случай: текущий вариант — готовое решение
    if isComplete(current) {
        // важно копировать срез, иначе все решения будут ссылаться на один буфер
        solution := make([]int, len(current))
        copy(solution, current)
        *result = append(*result, solution)
        return
    }

    // 2. Перебираем варианты следующего шага
    for _, choice := range choices {
        if !isValid(current, choice) {
            continue // отсечение недопустимых веток (pruning)
        }
        current = append(current, choice) // делаем выбор
        backtrack(current, choices, result)
        current = current[:len(current)-1] // ОТМЕНЯЕМ выбор (backtrack)
    }
}

Три обязательных компонента:

  1. Выбор (append) — добавляем элемент в частичное решение.
  2. Ограничения (isValid) — отсекаем заведомо тупиковые ветки как можно раньше. Чем раньше отсечение, тем меньше дерево перебора.
  3. Цель (isComplete) — условие, при котором частичное решение становится полным.

func permute(nums []int) [][]int {
    var result [][]int
    used := make([]bool, len(nums))
    var current []int

    var backtrack func()
    backtrack = func() {
        if len(current) == len(nums) {
            perm := make([]int, len(current))
            copy(perm, current)
            result = append(result, perm)
            return
        }
        for i, n := range nums {
            if used[i] {
                continue
            }
            used[i] = true
            current = append(current, n)
            backtrack()
            current = current[:len(current)-1]
            used[i] = false
        }
    }

    backtrack()
    return result
}

Типичные ошибки

  1. Забыли скопировать срез перед добавлением в результат. В Go срез — это дескриптор поверх общего массива; если положить в результат сам current, все записи будут указывать на один буфер и «испортятся» при следующем append. Всегда make + copy.

Graphs (Обход графов)

Описание шаблона

Граф — это набор вершин (узлов), соединённых рёбрами. В отличие от дерева, граф может содержать циклы, несколько компонент и любое число рёбер у вершины. Деревья (Tree BFS, Tree DFS) и топологическая сортировка — частные случаи работы с графами.

Большинство «графовых» задач сводятся к обходу: систематически посетить вершины, не зайдя в одну дважды. Два базовых обхода — BFS (в ширину, очередь) и DFS (в глубину, стек/рекурсия) — плюс структура Union-Find для задач о связности.

Представление графа

Чаще всего используют список смежности — для каждой вершины храним список соседей:

// n вершин, edges — список рёбер [u, v]
func buildAdjacency(n int, edges [][]int, directed bool) [][]int {
    adj := make([][]int, n)
    for _, e := range edges {
        u, v := e[0], e[1]
        adj[u] = append(adj[u], v)
        if !directed {
            adj[v] = append(adj[v], u) // для неориентированного — ребро в обе стороны
        }
    }
    return adj
}

BFS и DFS

// BFS: обход по уровням от стартовой вершины
func bfs(adj [][]int, start int) []int {
    visited := make([]bool, len(adj))
    order := []int{}
    queue := []int{start}
    visited[start] = true
    for len(queue) > 0 {
        node := queue[0]
        queue = queue[1:]
        order = append(order, node)
        for _, next := range adj[node] {
            if !visited[next] {
                visited[next] = true // помечаем ПРИ добавлении в очередь
                queue = append(queue, next)
            }
        }
    }
    return order
}

// DFS: рекурсивный обход в глубину
func dfs(adj [][]int, node int, visited []bool, order *[]int) {
    visited[node] = true
    *order = append(*order, node)
    for _, next := range adj[node] {
        if !visited[next] {
            dfs(adj, next, visited, order)
        }
    }
}

⚠️ Ключевой момент: массив visited обязателен — без него обход зациклится на графе с циклами. В BFS вершину помечают посещённой в момент добавления в очередь, а не извлечения, иначе она попадёт в очередь несколько раз.

Подсчёт компонент связности

Запускаем обход из каждой ещё не посещённой вершины — число запусков равно числу компонент:

func countComponents(n int, edges [][]int) int {
    adj := buildAdjacency(n, edges, false)
    visited := make([]bool, n)
    count := 0
    for i := 0; i < n; i++ {
        if !visited[i] {
            count++
            var order []int
            dfs(adj, i, visited, &order)
        }
    }
    return count
}

Union-Find (система непересекающихся множеств, DSU)

Union-Find отвечает на вопрос «в одной ли группе две вершины» почти за O(1). Идеален для динамической связности и обнаружения циклов в неориентированном графе.

type UnionFind struct{ parent, rank []int }

func NewUnionFind(n int) *UnionFind {
    uf := &UnionFind{parent: make([]int, n), rank: make([]int, n)}
    for i := range uf.parent {
        uf.parent[i] = i // каждая вершина — свой корень
    }
    return uf
}

// Find с сжатием пути (path compression)
func (uf *UnionFind) Find(x int) int {
    for uf.parent[x] != x {
        uf.parent[x] = uf.parent[uf.parent[x]] // подвешиваем ближе к корню
        x = uf.parent[x]
    }
    return x
}

// Union по рангу; возвращает false, если x и y уже в одном множестве
func (uf *UnionFind) Union(x, y int) bool {
    rx, ry := uf.Find(x), uf.Find(y)
    if rx == ry {
        return false
    }
    if uf.rank[rx] < uf.rank[ry] {
        rx, ry = ry, rx
    }
    uf.parent[ry] = rx
    if uf.rank[rx] == uf.rank[ry] {
        uf.rank[rx]++
    }
    return true
}

С обеими оптимизациями (сжатие пути + объединение по рангу) амортизированная сложность операции — O(α(n)), где α — обратная функция Аккермана, практически константа.

Обнаружение цикла в неориентированном графе: если оба конца ребра уже в одном множестве — ребро замыкает цикл.

func hasCycle(n int, edges [][]int) bool {
    uf := NewUnionFind(n)
    for _, e := range edges {
        if !uf.Union(e[0], e[1]) {
            return true
        }
    }
    return false
}

Обнаружение цикла в ориентированном графе

Union-Find для ориентированных графов не годится. Используют DFS с тремя состояниями (белый/серый/чёрный): если в процессе обхода встретили серую (ещё обрабатываемую) вершину — есть цикл. Это та же идея, что лежит в основе топологической сортировки: граф топологически сортируем тогда и только тогда, когда в нём нет циклов.

Типичные ошибки

  1. Забыли visited — на графе с циклом обход уходит в бесконечность.
  2. В BFS помечают при извлечении, а не при добавлении — вершина дублируется в очереди.

Графы: сетки и кратчайшие пути

Это продолжение главы «Обход графов». Здесь — два частых на собеседованиях расширения: сетки (двумерные поля как графы) и взвешенные кратчайшие пути (алгоритм Дейкстры).

Сетки как графы

Двумерная сетка (матрица) — это граф, где вершина — клетка (r, c), а рёбра ведут к соседним клеткам. Чаще всего соседей четыре (вверх/вниз/влево/вправо), иногда восемь (с диагоналями).

// Четыре направления: смещения по строке и столбцу
var dirs = [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}}

func neighbors(r, c, rows, cols int) [][2]int {
    var res [][2]int
    for _, d := range dirs {
        nr, nc := r+d[0], c+d[1]
        if nr >= 0 && nr < rows && nc >= 0 && nc < cols { // проверка границ!
            res = append(res, [2]int{nr, nc})
        }
    }
    return res
}

Number of Islands («подсчёт островов»)

Классическая задача: в сетке из 1 (суша) и 0 (вода) посчитать число «островов» — связных групп суши. Это подсчёт компонент связности на сетке: запускаем обход из каждой ещё не посещённой клетки-суши, «затапливая» весь остров.

func numIslands(grid [][]int) int {
    rows := len(grid)
    if rows == 0 {
        return 0
    }
    cols := len(grid[0])
    visited := make([][]bool, rows)
    for i := range visited {
        visited[i] = make([]bool, cols)
    }

    var dfs func(r, c int)
    dfs = func(r, c int) {
        // выходим, если за границей, вода или уже посещали
        if r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] == 0 || visited[r][c] {
            return
        }
        visited[r][c] = true
        dfs(r-1, c)
        dfs(r+1, c)
        dfs(r, c-1)
        dfs(r, c+1)
    }

    count := 0
    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            if grid[r][c] == 1 && !visited[r][c] {
                count++
                dfs(r, c) // затапливаем весь остров
            }
        }
    }
    return count
}

Сложность: O(R · C) — каждую клетку посещаем один раз.

💡 Multi-source BFS. Если фронт распространяется одновременно из нескольких точек (гниющие апельсины, пожар, вода), загрузите в очередь BFS сразу все стартовые клетки и обходите по уровням — каждый уровень это «шаг времени». Так считается минимальное время до заполнения всей сетки.

Взвешенные кратчайшие пути: алгоритм Дейкстры

В невзвешенном графе кратчайший путь по числу рёбер находит обычный BFS (все рёбра «стоят» 1). Но если у рёбер разные веса (расстояния, цены, время), BFS не подходит: путь с большим числом рёбер может оказаться дешевле.

Алгоритм Дейкстры находит кратчайшие пути от источника до всех вершин в графе с неотрицательными весами. Идея: жадно расширяем границу, каждый раз выбирая ещё не финализированную вершину с минимальным известным расстоянием — для этого нужна приоритетная очередь (мин-куча, см. Two Heaps).

import "container/heap"

// Элемент очереди: вершина и текущее расстояние до неё
type item struct{ node, dist int }
type pq []item

func (p pq) Len() int            { return len(p) }
func (p pq) Less(i, j int) bool  { return p[i].dist < p[j].dist } // мин-куча по dist
func (p pq) Swap(i, j int)       { p[i], p[j] = p[j], p[i] }
func (p *pq) Push(x any)         { *p = append(*p, x.(item)) }
func (p *pq) Pop() any {
    old := *p
    n := len(old)
    it := old[n-1]
    *p = old[:n-1]
    return it
}

// adj[u] = список соседей вида {to, weight}
func dijkstra(n int, adj [][][2]int, src int) []int {
    const INF = 1 << 62
    dist := make([]int, n)
    for i := range dist {
        dist[i] = INF
    }
    dist[src] = 0

    h := &pq{{node: src, dist: 0}}
    for h.Len() > 0 {
        cur := heap.Pop(h).(item)
        if cur.dist > dist[cur.node] {
            continue // устаревшая запись — уже нашли путь короче
        }
        for _, e := range adj[cur.node] {
            to, w := e[0], e[1]
            if nd := cur.dist + w; nd < dist[to] {
                dist[to] = nd
                heap.Push(h, item{node: to, dist: nd})
            }
        }
    }
    return dist // dist[v] == INF означает «недостижима»
}

Сложность: O((V + E) · log V) — каждое ребро может добавить запись в кучу, а операции с кучей — логарифмические.

Ключевые моменты

  • Только неотрицательные веса. При отрицательных рёбрах Дейкстра ломается — нужен Bellman–Ford (O(V · E), умеет находить отрицательные циклы).
  • «Ленивое» удаление. В Go у container/heap нет операции «уменьшить ключ», поэтому мы просто кладём новую запись, а устаревшие отбрасываем проверкой cur.dist > dist[cur.node].
  • Все рёбра веса 1? Не тратьте время на Дейкстру — обычный BFS даст ответ за O(V+E).

Bellman–Ford: кратчайшие пути с отрицательными весами

Дейкстра требует неотрицательных весов. Bellman–Ford работает при любых весах и умеет обнаруживать отрицательные циклы (по которым расстояние можно уменьшать бесконечно).

Идея — релаксация: проходим по всем рёбрам и пытаемся улучшить расстояние dist[v] = min(dist[v], dist[u] + w). Кратчайший путь содержит не более V−1 рёбер, поэтому V−1 полных проходов гарантируют сходимость. Если на V-м проходе расстояние всё ещё уменьшается — в графе есть отрицательный цикл.

// edges — ориентированные рёбра [u, v, w]; w может быть отрицательным
func bellmanFord(n int, edges [][]int, src int) (dist []int, hasNegCycle bool) {
    const INF = 1 << 62
    dist = make([]int, n)
    for i := range dist {
        dist[i] = INF
    }
    dist[src] = 0

    // V-1 проходов релаксации
    for i := 0; i < n-1; i++ {
        for _, e := range edges {
            u, v, w := e[0], e[1], e[2]
            if dist[u] != INF && dist[u]+w < dist[v] {
                dist[v] = dist[u] + w
            }
        }
    }

    // V-й проход: если что-то ещё улучшается — есть отрицательный цикл
    for _, e := range edges {
        u, v, w := e[0], e[1], e[2]
        if dist[u] != INF && dist[u]+w < dist[v] {
            return dist, true
        }
    }
    return dist, false
}

Сложность: O(V · E). Медленнее Дейкстры, но единственный простой выбор при отрицательных весах. (Для графа без отрицательных рёбер используйте Дейкстру.)

A*: направленный поиск с эвристикой

A* — это Дейкстра, которому «подсказывают» направление. Кроме фактической стоимости пути g(n) от старта, используется эвристика h(n) — оценка оставшегося расстояния до цели. Из очереди выбираем вершину с минимальным f(n) = g(n) + h(n).

Если эвристика допустима (admissible — никогда не переоценивает реальное расстояние), A* находит оптимальный путь, но исследует меньше вершин, чем Дейкстра. На сетке с движением по 4 направлениям допустима манхэттенская эвристика |Δr| + |Δc|.

import "container/heap"

// grid: 0 — свободно, 1 — препятствие. Шаг по 4 направлениям стоит 1.
// Возвращает минимальное число шагов из (0,0) в (R-1,C-1) или -1.
func aStar(grid [][]int) int {
    rows := len(grid)
    if rows == 0 {
        return -1
    }
    cols := len(grid[0])
    gr, gc := rows-1, cols-1
    if grid[0][0] == 1 || grid[gr][gc] == 1 {
        return -1
    }
    h := func(r, c int) int { return abs(gr-r) + abs(gc-c) } // манхэттен

    g := make([][]int, rows)
    for i := range g {
        g[i] = make([]int, cols)
        for j := range g[i] {
            g[i][j] = 1 << 30
        }
    }
    g[0][0] = 0

    open := &nodePQ{{r: 0, c: 0, f: h(0, 0)}}
    dirs := [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}}
    for open.Len() > 0 {
        cur := heap.Pop(open).(node)
        if cur.r == gr && cur.c == gc {
            return g[gr][gc]
        }
        for _, d := range dirs {
            nr, nc := cur.r+d[0], cur.c+d[1]
            if nr < 0 || nr >= rows || nc < 0 || nc >= cols || grid[nr][nc] == 1 {
                continue
            }
            if tentative := g[cur.r][cur.c] + 1; tentative < g[nr][nc] {
                g[nr][nc] = tentative
                heap.Push(open, node{r: nr, c: nc, f: tentative + h(nr, nc)})
            }
        }
    }
    return -1
}

При h(n) = 0 A* вырождается в Дейкстру. Чем точнее (но всё ещё допустимая) эвристика, тем меньше вершин просматривается.

Минимальное остовное дерево (MST)

Остовное дерево связного неориентированного графа — это поддерево, соединяющее все V вершин ровно V−1 ребром. Минимальное остовное дерево (MST) — то, у которого суммарный вес рёбер наименьший. Применения: прокладка сетей, кластеризация.

Алгоритм Краскала (Kruskal)

Сортируем рёбра по весу и жадно добавляем самое лёгкое, если оно не образует цикл (проверка через Union-Find).

func kruskalMST(n int, edges [][]int) int {
    sort.Slice(edges, func(i, j int) bool { return edges[i][2] < edges[j][2] })
    uf := NewUnionFind(n) // см. главу «Обход графов»
    total, used := 0, 0
    for _, e := range edges {
        if uf.Union(e[0], e[1]) { // ребро соединяет две разные компоненты
            total += e[2]
            used++
        }
    }
    if used != n-1 {
        return -1 // граф несвязный — остовного дерева нет
    }
    return total
}

Сложность: O(E · log E) — доминирует сортировка рёбер.

Алгоритм Прима (Prim)

Выращиваем дерево из одной вершины, каждый раз добавляя самое лёгкое ребро, ведущее наружу из уже построенного дерева. Для выбора такого ребра используется мин-куча.

func primMST(n int, adj [][][2]int) int { // adj[u] = {сосед, вес}
    visited := make([]bool, n)
    h := &edgePQ{{node: 0, weight: 0}}
    total := 0
    for h.Len() > 0 {
        e := heap.Pop(h).(edge)
        if visited[e.node] {
            continue
        }
        visited[e.node] = true
        total += e.weight
        for _, nb := range adj[e.node] {
            if !visited[nb[0]] {
                heap.Push(h, edge{node: nb[0], weight: nb[1]})
            }
        }
    }
    return total
}

Сложность: O(E · log V). Прим выгоднее на плотных графах, Краскал — на разреженных и когда рёбра уже отсортированы.

  3. A* с недопустимой (переоценивающей) эвристикой — путь может оказаться неоптимальным.
  4. Kruskal без проверки used == n-1 — на несвязном графе вернёте вес остовного леса, а не дерева.
  5. Prim: не пропускаете уже посещённые вершины при извлечении из кучи — лишняя работа или неверный результат.

Topological Sort (Топологическая сортировка)

Теория

Topological Sort находит линейный порядок вершин ориентированного ациклического графа (DAG), где каждое ребро — зависимость: если A → B, то A идёт перед B.

DAG — ориентированный граф без циклов. Топологическая сортировка существует тогда и только тогда, когда граф — DAG; при наличии цикла порядок построить нельзя.

Ключевое наблюдение: в DAG всегда есть вершина без входящих рёбер (in-degree = 0) — источник. Обрабатывая источники и «удаляя» их из графа, мы открываем новые источники и строим порядок. Это и есть алгоритм Кана (BFS по in-degree).

Когда применять:

  • работа с DAG, зависимостями между задачами;
  • нужно определить порядок выполнения (сборка, установка пакетов, расписание);
  • нужно проверить отсутствие циклов (можно ли выполнить все задачи).

Алгоритм

Считаем in-degree каждой вершины, кладём в очередь все вершины с in-degree = 0. Берём вершину из очереди, добавляем в результат, уменьшаем in-degree её соседей; когда in-degree соседа становится 0 — кладём его в очередь. Если в результате оказалось меньше вершин, чем всего, — в графе есть цикл.

// Алгоритм Кана. prerequisites[i] = {course, prerequisite}: course зависит от prerequisite
func topologicalSort(numCourses int, prerequisites [][]int) []int {
    graph := make([][]int, numCourses)
    inDegree := make([]int, numCourses)

    for _, prereq := range prerequisites {
        course, prerequisite := prereq[0], prereq[1]
        graph[prerequisite] = append(graph[prerequisite], course)
        inDegree[course]++
    }

    queue := []int{}
    for i := 0; i < numCourses; i++ {
        if inDegree[i] == 0 {
            queue = append(queue, i)
        }
    }

    result := []int{}
    for len(queue) > 0 {
        node := queue[0]
        queue = queue[1:]
        result = append(result, node)

        for _, neighbor := range graph[node] {
            inDegree[neighbor]--
            if inDegree[neighbor] == 0 {
                queue = append(queue, neighbor)
            }
        }
    }

    if len(result) != numCourses {
        return []int{} // обнаружен цикл — сортировка невозможна
    }
    return result
}

Альтернатива — DFS-подход: обходим граф в глубину, и когда вершина полностью обработана (все потомки посещены), кладём её в стек. Развёрнутый стек даёт топологический порядок; цикл ловится по «серой» (находящейся в обработке) вершине.

Сложность

ПодходВремяПамять

DFSO(V + E)O(V + E)

Каждая вершина обрабатывается один раз (O(V)), каждое ребро рассматривается один раз (O(E)).

Типичные ошибки

  1. Путаница in-degree/out-degree — считайте входящие рёбра, а не исходящие.
  2. Неправильное направление ребра — course зависит от prerequisite, поэтому ребро prerequisite → course.
  3. Забыта проверка цикла — если len(result) != numCourses, сортировка невозможна.
  4. In-degree обновляется не у тех вершин — уменьшайте только у прямых соседей текущей вершины.
  5. Несколько источников / компонент связности — кладите в очередь сразу все вершины с in-degree = 0, иначе пропустите часть графа.
  6. Дубликаты рёбер в prerequisites завышают in-degree; при необходимости отсеивайте через множество.

Greedy (Жадные алгоритмы)

Описание шаблона

Жадный алгоритм на каждом шаге делает локально оптимальный выбор в надежде, что последовательность таких выборов приведёт к глобальному оптимуму. Он никогда не пересматривает уже сделанный выбор — в этом его скорость и его опасность.

Жадность работает не всегда. Она корректна, только когда задача обладает свойством жадного выбора (локально оптимальный выбор входит в некоторое глобально оптимальное решение) и оптимальной подструктурой. Если это не доказано — жадный ответ может быть неверным, и нужно динамическое программирование.

⚠️ Классический контрпример: размен суммы 6 монетами [1, 3, 4]. Жадность берёт 4 + 1 + 1 = 3 монеты, а оптимум — 3 + 3 = 2. Поэтому Coin Change решается ДП, а не жадно.

Когда применять

  • Задачи на расписание/интервалы: выбрать максимум непересекающихся событий.
  • Минимизация/максимизация с очевидным критерием сортировки.
  • Задачи, где можно доказать «жадный остаётся впереди» (greedy stays ahead) или применить аргумент обмена (exchange argument).

Как доказать корректность

Два стандартных приёма:

  1. Greedy stays ahead — по индукции показываем, что после каждого шага жадное решение не хуже любого другого.
  2. Exchange argument — берём оптимальное решение и показываем, что его можно «переставить» к жадному, не ухудшив.

Без такого рассуждения жадность — лишь гипотеза.

Пример 1: выбор заявок (Activity Selection)

Дан набор интервалов; нужно выбрать максимум взаимно непересекающихся. Жадный критерий: сортировка по времени окончания и выбор каждого следующего интервала, который начинается не раньше конца предыдущего.

import "sort"

func maxActivities(intervals [][]int) int {
    if len(intervals) == 0 {
        return 0
    }
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][1] < intervals[j][1] // по концу
    })
    count := 1
    lastEnd := intervals[0][1]
    for _, iv := range intervals[1:] {
        if iv[0] >= lastEnd { // не пересекается с последним выбранным
            count++
            lastEnd = iv[1]
        }
    }
    return count
}

Почему именно конец? Выбирая интервал, заканчивающийся раньше всех, мы оставляем максимум места для остальных — это и есть «жадный остаётся впереди».

Пример 2: Jump Game

Можно ли из первого элемента массива допрыгнуть до последнего, если nums[i] — максимум шагов вперёд? Жадно ведём «самую дальнюю достижимую позицию».

func canJump(nums []int) bool {
    maxReach := 0
    for i, v := range nums {
        if i > maxReach {
            return false // сюда не допрыгнуть
        }
        if i+v > maxReach {
            maxReach = i + v
        }
    }
    return true
}

Dynamic Programming (Динамическое программирование)

Описание шаблона

Динамическое программирование (ДП) — это техника решения задач путём разбиения их на перекрывающиеся подзадачи и сохранения результатов уже решённых подзадач, чтобы не вычислять их повторно. Если backtracking перебирает все варианты, то ДП превращает экспоненциальный перебор в полиномиальное решение за счёт запоминания.

Задача поддаётся ДП, когда есть два свойства:

  1. Перекрывающиеся подзадачи (overlapping subproblems) — одни и те же подзадачи встречаются многократно. Наивная рекурсия Фибоначчи пересчитывает fib(2) десятки раз.
  2. Оптимальная подструктура (optimal substructure) — оптимальное решение задачи строится из оптимальных решений её подзадач.

Когда применять

Признаки-маркеры в условии:

  • «Сколькими способами…» (подсчёт вариантов).
  • «Найдите минимум / максимум / самый длинный…» при последовательности выборов.
  • «Можно ли достичь…» (достижимость через комбинацию шагов).
  • Каждый шаг — выбор с последствиями, и варианты перекрываются.

Если же все подзадачи уникальны (не повторяются) — это обычная рекурсия или backtracking, а не ДП.

Два подхода

Мемоизация (сверху вниз)

Обычная рекурсия + кэш уже посчитанных значений. Пишется естественно, считает только нужные подзадачи.

func fibMemo(n int) int {
    memo := make(map[int]int)
    var f func(int) int
    f = func(k int) int {
        if k < 2 {
            return k
        }
        if v, ok := memo[k]; ok {
            return v // подзадача уже решена
        }
        memo[k] = f(k-1) + f(k-2)
        return memo[k]
    }
    return f(n)
}

Табуляция (снизу вверх)

Заполняем таблицу от базовых случаев к ответу, без рекурсии. Обычно эффективнее по памяти и без риска переполнения стека.

func fibTab(n int) int {
    if n < 2 {
        return n
    }
    prev, cur := 0, 1
    for i := 2; i <= n; i++ {
        prev, cur = cur, prev+cur // храним только два последних значения
    }
    return cur
}

Здесь видна и оптимизация памяти: вместо массива на n элементов достаточно двух переменных — O(1) памяти.

Как построить ДП-решение

  1. Состояние — что описывает подзадачу? (например, dp[i] = ответ для префикса длины i).
  2. Переход — как ответ для состояния выражается через меньшие состояния? (рекуррента).
  3. База — тривиальные случаи (dp[0], dp[1]).
  4. Порядок вычисления — такой, чтобы нужные подзадачи были посчитаны раньше.

Примеры

1D ДП: Climbing Stairs / House Robber

«На сколько ступеней можно подняться, делая шаги по 1 или 2?» — это Фибоначчи: dp[i] = dp[i-1] + dp[i-2]. Тот же приём — в House Robber, где dp[i] = max(dp[i-1], dp[i-2] + nums[i]).

Coin Change (минимум монет)

Состояние dp[a] — минимум монет, чтобы набрать сумму a. Переход: пробуем каждую монету c: dp[a] = min(dp[a], dp[a-c] + 1).

func coinChange(coins []int, amount int) int {
    const INF = 1 << 30
    dp := make([]int, amount+1)
    for i := 1; i <= amount; i++ {
        dp[i] = INF
        for _, c := range coins {
            if c <= i && dp[i-c]+1 < dp[i] {
                dp[i] = dp[i-c] + 1
            }
        }
    }
    if dp[amount] >= INF {
        return -1 // сумму набрать нельзя
    }
    return dp[amount]
}

2D ДП: Longest Common Subsequence (LCS)

Состояние dp[i][j] — длина наибольшей общей подпоследовательности префиксов a[:i] и b[:j]. Если символы совпали — берём диагональ +1, иначе — лучшее из двух соседей.

func lcs(a, b string) int {
    m, n := len(a), len(b)
    dp := make([][]int, m+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
    }
    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            if a[i-1] == b[j-1] {
                dp[i][j] = dp[i-1][j-1] + 1
            } else {
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
            }
        }
    }
    return dp[m][n]
}

0/1 Рюкзак (knapsack)

Состояние dp[i][w] — максимальная ценность из первых i предметов при вместимости w. Для каждого предмета выбор «взять / не взять»: dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i]). Часто сворачивается до 1D-массива по w (идём по w в обратную сторону).

Фибоначчи / лестницаO(n)O(1)O(n)O(1)

Типичные ошибки

  1. Неправильная база — забыли dp[0] или задали неверно; вся таблица «съезжает».
  2. Неверный порядок обхода — состояние используется раньше, чем посчитано.
  3. Путаница индексов строк и таблицы — для строк длины m таблица размера m+1, символ a[i-1] соответствует dp[i].
  4. Мемоизация без кэша на самом деле — забыли записать результат перед return, экспонента осталась.
  5. 0/1-рюкзак: проход по w в прямом порядке при свёрнутом массиве — предмет ошибочно берётся несколько раз (это уже unbounded knapsack).

Строковые алгоритмы: поиск подстроки

Описание

Задача поиска подстроки — найти первое вхождение образца pattern (длины m) в текст text (длины n). Наивный подход сравнивает образец с каждой позицией текста за O(n · m): при несовпадении он «забывает» всё, что уже сравнил, и начинает заново.

Два классических алгоритма доводят это до O(n + m), по-разному переиспользуя информацию: KMP — через предвычисленную префикс-функцию, Rabin–Karp — через скользящий хеш.

Knuth–Morris–Pratt (KMP)

Идея: при несовпадении не возвращать указатель текста назад, а сдвинуть образец на максимально возможную величину, используя уже совпавший префикс. Для этого считают префикс-функцию (LPS, longest proper prefix which is also suffix): lps[i] — длина наибольшего собственного префикса pattern[0..i], совпадающего с его суффиксом.

// lps[i] — длина наибольшего префикса-суффикса для pattern[:i+1]
func buildLPS(pattern string) []int {
    lps := make([]int, len(pattern))
    length := 0
    for i := 1; i < len(pattern); {
        if pattern[i] == pattern[length] {
            length++
            lps[i] = length
            i++
        } else if length > 0 {
            length = lps[length-1] // откатываемся по уже посчитанным префиксам
        } else {
            lps[i] = 0
            i++
        }
    }
    return lps
}

func kmpSearch(text, pattern string) int {
    if len(pattern) == 0 {
        return 0
    }
    lps := buildLPS(pattern)
    i, j := 0, 0 // i — по тексту, j — по образцу
    for i < len(text) {
        if text[i] == pattern[j] {
            i++
            j++
            if j == len(pattern) {
                return i - j // нашли вхождение
            }
        } else if j > 0 {
            j = lps[j-1] // сдвигаем образец, НЕ трогая i
        } else {
            i++
        }
    }
    return -1
}

Сложность: O(n + m) по времени, O(m) на массив lps. Указатель текста i никогда не уменьшается — в этом весь выигрыш.

Rabin–Karp

Идея: сравнивать не символы, а хеши. Считаем полиномиальный хеш образца и хеш каждого окна длины m в тексте. Хеш окна обновляется за O(1) по принципу скользящего окна (rolling hash): убрали левый символ, добавили правый. Совпали хеши — проверяем строки посимвольно (защита от коллизий).

func rabinKarp(text, pattern string) int {
    n, m := len(text), len(pattern)
    if m == 0 {
        return 0
    }
    if m > n {
        return -1
    }
    const base, mod = 256, 1_000_000_007

    power := 1 // base^(m-1) % mod — вклад самого левого символа окна
    for i := 0; i < m-1; i++ {
        power = power * base % mod
    }

    var patHash, winHash int
    for i := 0; i < m; i++ {
        patHash = (patHash*base + int(pattern[i])) % mod
        winHash = (winHash*base + int(text[i])) % mod
    }

    for i := 0; i+m <= n; i++ {
        if patHash == winHash && text[i:i+m] == pattern {
            return i
        }
        if i+m < n { // сдвигаем окно вправо
            remove := int(text[i]) * power % mod
            winHash = ((winHash-remove+mod)*base + int(text[i+m])) % mod
        }
    }
    return -1
}

Сложность: O(n + m) в среднем; в худшем случае (много коллизий) — O(n · m), но при хорошем mod это редкость. Rabin–Karp особенно удобен для поиска нескольких образцов сразу и для задач со сравнением подстрок по хешу.

Типичные ошибки

  1. В KMP двигают указатель текста назад — теряется весь смысл; назад откатывается только j через lps.
  2. Неверная префикс-функция — самая частая ошибка; протестируйте buildLPS отдельно (например, "aabaab" → [0,1,0,1,2,3]).
  3. Rabin–Karp без проверки строк при совпадении хешей — коллизии дадут ложные срабатывания.
  4. Переполнение/отрицательные значения хеша — берите остаток по модулю и добавляйте mod перед %, чтобы избежать отрицательных чисел.
  5. Пустой образец — договоритесь о соглашении (здесь — возвращаем 0).

Trie (Префиксное дерево)

Описание шаблона

Trie (префиксное дерево, бор) — это древовидная структура для хранения набора строк, где каждый узел соответствует символу, а путь от корня до узла образует префикс. Строки с общим префиксом разделяют общий путь, поэтому Trie особенно эффективен для операций «по префиксу».

В отличие от хеш-таблицы, Trie даёт не только проверку «есть ли слово», но и «есть ли слова с таким префиксом» — за время, пропорциональное длине запроса, не зависящее от числа хранимых строк.

Когда применять

  • Автодополнение и подсказки по префиксу.
  • Проверка словаря: быстро узнать, есть ли слово/префикс.
  • Поиск множества образцов в тексте одновременно.
  • Задачи на сетках со словарём (Word Search II) и на XOR-максимум (бинарный Trie).

Структура и операции

Для строчных латинских букв узел хранит до 26 ссылок на детей и флаг «здесь кончается слово».

type Trie struct {
    children [26]*Trie
    isEnd    bool // в этом узле заканчивается какое-то вставленное слово
}

func NewTrie() *Trie { return &Trie{} }

// Insert добавляет слово, создавая недостающие узлы по пути.
func (t *Trie) Insert(word string) {
    node := t
    for i := 0; i < len(word); i++ {
        c := word[i] - 'a'
        if node.children[c] == nil {
            node.children[c] = &Trie{}
        }
        node = node.children[c]
    }
    node.isEnd = true
}

// find возвращает узел, соответствующий строке s, или nil.
func (t *Trie) find(s string) *Trie {
    node := t
    for i := 0; i < len(s); i++ {
        c := s[i] - 'a'
        if node.children[c] == nil {
            return nil
        }
        node = node.children[c]
    }
    return node
}

// Search: слово есть, если путь существует И в конце стоит флаг isEnd.
func (t *Trie) Search(word string) bool {
    node := t.find(word)
    return node != nil && node.isEnd
}

// StartsWith: достаточно, чтобы существовал путь префикса.
func (t *Trie) StartsWith(prefix string) bool {
    return t.find(prefix) != nil
}

⚠️ Разница между Search и StartsWith — только в проверке isEnd. Без флага вы не отличите вставленное слово "app" от просто префикса слова "apple".

Segment Tree (Дерево отрезков)

Описание шаблона

Дерево отрезков — структура для задач, где нужно одновременно запрашивать агрегат на диапазоне (сумму, минимум, максимум, НОД…) и обновлять элементы, причём обе операции — за O(log n).

Сравните с альтернативами:

  • Массив: запрос суммы на диапазоне O(n), обновление O(1).
  • Префиксные суммы: запрос O(1), но обновление O(n) (нужно пересчитать хвост).
  • Дерево отрезков: и запрос, и обновление O(log n) — баланс, выигрывающий, когда обновления и запросы чередуются.

Когда применять

  • Много запросов «сумма/мин/макс на [l, r]» вперемешку с изменениями элементов.
  • Динамические задачи на диапазонах: подсчёт инверсий, «сколько меньших справа».
  • Когда префиксных сумм не хватает из-за частых обновлений.

Идея

Лист дерева хранит элемент массива, внутренний узел — агрегат своих двух детей. Запрос на диапазоне разбивается на O(log n) узлов, целиком покрывающих этот диапазон.

arr = [1, 3, 5, 7]            сумма на [1,3] = 3+5+7 = 15

                 [0..3]=16
                /         \
         [0..1]=4         [2..3]=12
         /     \          /      \
     [0]=1   [1]=3    [2]=5    [3]=7

Реализация (итеративная, сумма)

Компактный вариант: массив tree размера 2n, листья в [n, 2n), родитель узла i — это i/2.

type SegmentTree struct {
    n    int
    tree []int
}

// NewSegmentTree строит дерево за O(n).
func NewSegmentTree(arr []int) *SegmentTree {
    n := len(arr)
    st := &SegmentTree{n: n, tree: make([]int, 2*n)}
    for i := 0; i < n; i++ {
        st.tree[n+i] = arr[i] // листья
    }
    for i := n - 1; i > 0; i-- {
        st.tree[i] = st.tree[2*i] + st.tree[2*i+1] // агрегат снизу вверх
    }
    return st
}

// Update устанавливает arr[i] = val за O(log n).
func (st *SegmentTree) Update(i, val int) {
    i += st.n
    st.tree[i] = val
    for i > 1 {
        i /= 2
        st.tree[i] = st.tree[2*i] + st.tree[2*i+1] // обновляем предков
    }
}

// Query возвращает сумму на ВКЛЮЧИТЕЛЬНОМ диапазоне [l, r] за O(log n).
func (st *SegmentTree) Query(l, r int) int {
    res := 0
    l += st.n
    r += st.n + 1 // полуинтервал [l, r)
    for l < r {
        if l&1 == 1 { // l — правый ребёнок: берём его и сдвигаемся
            res += st.tree[l]
            l++
        }
        if r&1 == 1 { // r — правый ребёнок: берём левого соседа
            r--
            res += st.tree[r]
        }
        l /= 2
        r /= 2
    }
    return res
}

Чтобы получить дерево минимумов/максимумов, замените + на min/max в трёх местах (построение, обновление, запрос) и нейтральный элемент 0 на +∞/−∞.

Lazy propagation: обновление диапазона

Точечного обновления мало для задач вида «прибавить значение ко всем элементам [l, r]». Наивно это O(n) на запрос. Отложенные обновления решают проблему: если узел целиком покрыт диапазоном обновления, мы применяем изменение к нему сразу, а к детям — позже («проталкиваем» лениво, только когда в них спускаемся). Так range-update и range-query оба становятся O(log n).

Хранятся два массива: tree (агрегаты) и lazy (отложенная прибавка для поддерева). Удобнее рекурсивная реализация.

type LazySegmentTree struct {
    n          int
    tree, lazy []int
}

func NewLazySegmentTree(arr []int) *LazySegmentTree {
    n := len(arr)
    l := &LazySegmentTree{n: n, tree: make([]int, 4*n), lazy: make([]int, 4*n)}
    if n > 0 {
        l.build(1, 0, n-1, arr)
    }
    return l
}

func (l *LazySegmentTree) build(node, lo, hi int, arr []int) {
    if lo == hi {
        l.tree[node] = arr[lo]
        return
    }
    mid := (lo + hi) / 2
    l.build(2*node, lo, mid, arr)
    l.build(2*node+1, mid+1, hi, arr)
    l.tree[node] = l.tree[2*node] + l.tree[2*node+1]
}

// apply применяет прибавку delta ко всему отрезку [lo, hi] узла.
func (l *LazySegmentTree) apply(node, lo, hi, delta int) {
    l.tree[node] += (hi - lo + 1) * delta // вклад в сумму
    l.lazy[node] += delta                 // запоминаем для детей
}

// push проталкивает отложенное значение детям.
func (l *LazySegmentTree) push(node, lo, hi int) {
    if l.lazy[node] != 0 {
        mid := (lo + hi) / 2
        l.apply(2*node, lo, mid, l.lazy[node])
        l.apply(2*node+1, mid+1, hi, l.lazy[node])
        l.lazy[node] = 0
    }
}

// RangeUpdate прибавляет delta ко всем элементам [ql, qr].
func (l *LazySegmentTree) RangeUpdate(ql, qr, delta int) { l.update(1, 0, l.n-1, ql, qr, delta) }

func (l *LazySegmentTree) update(node, lo, hi, ql, qr, delta int) {
    if qr < lo || hi < ql { // не пересекается
        return
    }
    if ql <= lo && hi <= qr { // целиком внутри — применяем и не спускаемся
        l.apply(node, lo, hi, delta)
        return
    }
    l.push(node, lo, hi)
    mid := (lo + hi) / 2
    l.update(2*node, lo, mid, ql, qr, delta)
    l.update(2*node+1, mid+1, hi, ql, qr, delta)
    l.tree[node] = l.tree[2*node] + l.tree[2*node+1]
}

// RangeQuery возвращает сумму на [ql, qr].
func (l *LazySegmentTree) RangeQuery(ql, qr int) int { return l.query(1, 0, l.n-1, ql, qr) }

func (l *LazySegmentTree) query(node, lo, hi, ql, qr int) int {
    if qr < lo || hi < ql {
        return 0
    }
    if ql <= lo && hi <= qr {
        return l.tree[node]
    }
    l.push(node, lo, hi)
    mid := (lo + hi) / 2
    return l.query(2*node, lo, mid, ql, qr) + l.query(2*node+1, mid+1, hi, ql, qr)
}

Ключевое правило: перед спуском к детям всегда push, иначе они вернут устаревшие данные. И update, и query соблюдают это.

Fenwick Tree (Дерево Фенвика, BIT)

Описание шаблона

Дерево Фенвика (Binary Indexed Tree, BIT) — компактная структура для префиксных сумм с обновлениями: и точечное обновление, и запрос префиксной суммы выполняются за O(log n), используя всего один массив размера n+1.

По возможностям оно уже, чем дерево отрезков (только обратимые операции вроде суммы, без min/max в общем случае), зато проще в коде, меньше по памяти и с меньшей константой. Если задача — «сумма на диапазоне + точечные изменения», BIT обычно лучший выбор.

Когда применять

  • Префиксные/диапазонные суммы при частых точечных обновлениях.
  • Подсчёт инверсий, «сколько меньших элементов слева/справа».
  • Везде, где хватает обратимой операции (сумма, xor) и не нужен min/max.

Идея: младший установленный бит

Вся магия — в трюке i & (-i), выделяющем младший установленный бит числа. Узел i отвечает за i & (-i) элементов, заканчивающихся на позиции i. Поэтому:

  • при обновлении идём вверх, прибавляя младший бит: i += i & (-i);
  • при запросе префикса идём вниз, вычитая его: i -= i & (-i).

Дерево использует 1-индексацию внутри; наружу удобно отдавать привычную 0-индексацию.

type Fenwick struct {
    n    int
    tree []int // 1-индексация: tree[0] не используется
}

// NewFenwick строит дерево по массиву.
func NewFenwick(arr []int) *Fenwick {
    f := &Fenwick{n: len(arr), tree: make([]int, len(arr)+1)}
    for i, v := range arr {
        f.add(i+1, v)
    }
    return f
}

// add прибавляет delta к 1-индексированной позиции i, обновляя предков.
func (f *Fenwick) add(i, delta int) {
    for ; i <= f.n; i += i & (-i) {
        f.tree[i] += delta
    }
}

// Update прибавляет delta к элементу с 0-индексом i (это ДОБАВЛЕНИЕ, не запись).
func (f *Fenwick) Update(i, delta int) {
    f.add(i+1, delta)
}

// prefix возвращает сумму 1-индексированных элементов [1..i].
func (f *Fenwick) prefix(i int) int {
    sum := 0
    for ; i > 0; i -= i & (-i) {
        sum += f.tree[i]
    }
    return sum
}

// PrefixSum возвращает сумму элементов [0..i] (0-индексация, включительно).
func (f *Fenwick) PrefixSum(i int) int {
    return f.prefix(i + 1)
}

// RangeSum возвращает сумму на включительном диапазоне [l, r].
func (f *Fenwick) RangeSum(l, r int) int {
    return f.PrefixSum(r) - f.PrefixSum(l-1) // при l=0 PrefixSum(-1)=0
}

Типичные ошибки

  1. Путаница 0- и 1-индексации — самая частая ошибка; держите 1-индексацию строго внутри, конвертируйте на границе.
  2. Update как «запись» вместо «прибавления» — BIT хранит дельты; чтобы установить значение, прибавьте (новое − старое).
  3. Попытка хранить min/max — обычный BIT не поддерживает необратимые операции на произвольных диапазонах.
  4. Цикл i -= i & (-i) при i = 0 — не зайдёт в тело (условие i > 0), это корректно возвращает 0.

Приложение: память, GC и профилирование в Go

Эта страница — единый справочник по особенностям Go, которые упоминаются во многих главах: модель памяти, escape analysis, сборщик мусора и инструменты профилирования. Главы ссылаются сюда, чтобы не повторять одну и ту же теорию.

Стек и куча

  • Стек — локальные переменные, примитивы, небольшие структуры. Аллокация и освобождение почти бесплатны (сдвиг указателя стека).
  • Куча — данные, которые «переживают» функцию или имеют динамический размер. За освобождение отвечает сборщик мусора (GC).

Куда поместить переменную, решает не программист, а компилятор — на основе escape analysis.

Escape Analysis

Escape analysis — статический анализ компилятора: «убегает» ли переменная за пределы функции. Если да — она аллоцируется в куче, если нет — остаётся на стеке.

Типичные причины «побега» в кучу:

  1. Возврат указателя на локальную переменную (return &x).
  2. Сохранение указателя в глобальную переменную или долгоживущую структуру.
  3. Упаковка значения в интерфейс (var i any = x).
  4. Слишком большой объект или срез с неизвестным на этапе компиляции размером.

Проверить решения компилятора:

go build -gcflags=-m ./...

Вывод вида moved to heap: x или x escapes to heap показывает, что переменная ушла в кучу.

Как уменьшить аллокации:

// ❌ возвращаем указатель — побег в кучу
func bad() *int { x := 42; return &x }

// ✅ возвращаем значение — остаётся на стеке
func good() int { x := 42; return x }

// ✅ заранее выделяем ёмкость среза — меньше перевыделений
buf := make([]int, 0, expectedSize)

Сборщик мусора (GC)

Go использует конкурентный mark-and-sweep с трёхцветной маркировкой (белый/серый/чёрный), работающий параллельно с программой и минимизирующий паузы Stop-The-World.

  • Триггер: по умолчанию GC запускается, когда куча вырастает примерно вдвое относительно прошлого цикла. Регулируется переменной GOGC (меньше значение — агрессивнее GC, меньше памяти, больше пауз).
  • Принудительно: runtime.GC() (нужно редко, в основном для тестов/бенчмарков).

Снижение нагрузки на GC — это в первую очередь снижение числа аллокаций:

// Переиспользование буфера вместо аллокации на каждой итерации
buf := make([]int, 0, 1024)
for ... {
    buf = buf[:0] // очистка без новой аллокации
    // ... работаем с buf
}

// sync.Pool для переиспользования временных объектов в горячих путях
var pool = sync.Pool{New: func() any { return make([]byte, 0, 1024) }}

Резюме изученных шаблонов

Группа 1: Базовые техники (массивы и строки)

Sliding Window (Скользящее окно)

  • Когда использовать: Работа с подмассивами/подстроками фиксированного или переменного размера
  • Сложность: O(n) по времени, O(1) или O(k) по памяти
  • Ключевые задачи: Поиск подстроки, максимум/минимум в окне, анаграммы

Two Pointers (Два указателя)

  • Когда использовать: Работа с отсортированными массивами, поиск пар, палиндромы
  • Сложность: O(n) по времени, O(1) по памяти
  • Ключевые задачи: Поиск двух чисел с заданной суммой, валидация палиндрома, удаление дубликатов

Fast & Slow Pointers (Быстрые и медленные указатели)

  • Когда использовать: Работа со связанными списками, обнаружение циклов, поиск середины
  • Сложность: O(n) по времени, O(1) по памяти
  • Ключевые задачи: Обнаружение цикла, поиск середины списка, палиндром в списке

Группа 2: Работа с данными

Merge Intervals (Слияние интервалов)

  • Когда использовать: Работа с перекрывающимися интервалами, планирование
  • Сложность: O(n log n) по времени (сортировка), O(n) по памяти
  • Ключевые задачи: Слияние интервалов, вставка интервала, пересечение интервалов

Cyclic Sort (Циклическая сортировка)

  • Когда использовать: Массивы с числами в диапазоне [1, n], поиск отсутствующих/дубликатов
  • Сложность: O(n) по времени, O(1) по памяти
  • Ключевые задачи: Поиск отсутствующего числа, поиск дубликатов, первое отсутствующее положительное

Modified Binary Search (Модифицированный бинарный поиск)

  • Когда использовать: Поиск в отсортированных данных, поиск границ, повернутые массивы
  • Сложность: O(log n) по времени, O(1) по памяти
  • Ключевые задачи: Поиск в повернутом массиве, поиск первой/последней позиции, поиск в 2D матрице

Группа 3: Структуры данных - списки

Reverse Linked List (Разворот связанного списка)

  • Когда использовать: Работа со связанными списками, реверс части списка
  • Сложность: O(n) по времени, O(1) по памяти (итеративно) или O(n) по памяти (рекурсивно)
  • Ключевые задачи: Разворот всего списка, разворот части списка, разворот группами

Группа 4: Структуры данных - деревья

Tree BFS (Обход дерева в ширину)

  • Когда использовать: Обход дерева по уровням, поиск кратчайшего пути
  • Сложность: O(n) по времени, O(w) по памяти (где w - максимальная ширина)
  • Ключевые задачи: Обход по уровням, среднее значение уровней, вид справа

Tree DFS (Обход дерева в глубину)

  • Когда использовать: Обход дерева в глубину, валидация, построение дерева
  • Сложность: O(n) по времени, O(h) по памяти (где h - высота дерева)
  • Ключевые задачи: Pre-order/In-order/Post-order обход, валидация BST, максимальная сумма пути

Группа 5: Продвинутые структуры данных

Two Heaps (Две кучи)

  • Когда использовать: Поддержание медианы, балансировка данных
  • Сложность: O(log n) для вставки, O(1) для получения медианы
  • Ключевые задачи: Медиана из потока данных, медиана скользящего окна

Top K Elements (Топ K элементов)

  • Когда использовать: Поиск K наибольших/наименьших элементов, частотный анализ
  • Сложность: O(n log k) по времени, O(k) по памяти
  • Ключевые задачи: K-й наибольший элемент, топ K частых элементов, K ближайших точек

K-way Merge (K-way слияние)

  • Когда использовать: Слияние K отсортированных массивов/списков
  • Сложность: O(n log k) по времени, O(k) по памяти
  • Ключевые задачи: Слияние K списков, K-й наименьший элемент в матрице, K пар с наименьшими суммами

Группа 6: Комбинаторика и графы

Subsets (Подмножества)

  • Когда использовать: Генерация всех подмножеств, комбинации, перестановки
  • Сложность: O(2^n) по времени и памяти
  • Ключевые задачи: Все подмножества, комбинации суммы, перестановки

Topological Sort (Топологическая сортировка)

  • Когда использовать: Работа с графами, зависимостями, планирование задач
  • Сложность: O(V + E) по времени, O(V) по памяти
  • Ключевые задачи: Расписание курсов, словарь инопланетян, реконструкция последовательности

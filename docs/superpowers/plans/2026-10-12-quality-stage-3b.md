# Качество учебника, этап 3b «Конец у каждой главы и таблица путаемых пар» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** У всех 23 глав ядра есть черта «Глава сдана выше» и три строки «📌 Что унести»; эти строки стали вопросами и ответами карточки `ch:` (в главах с «объясни сам» новых `ch:` нет); одна таблица путаемых пар работает в «🔗» глав, в руководстве по выбору (с веткой хеш-таблицы и уровнями) и в ответе смешанной тренировки после промаха.

**Architecture:** Два источника правды и два генератора. Строки «Что унести» пишутся в самой главе; `scripts/gen-takeaways.js` собирает их и список глав с «объясни сам» в `assets/takeaways.js`, из которого `srs.js` строит карточку `ch:`. Таблица пар — JS-реестр `assets/pairs.js`; `scripts/gen-pairs.js` вписывает из него блоки между метками в «🔗» глав и в руководство, а `mixed.js` читает его в браузере. Оба генератора имеют `--check` в CI. Линт `check-chapter-shape.js` получает второй, узкий режим — список `ENDED`, где проверяется только конец главы (правила R2–R4).

**Tech Stack:** Markdown + HTML-блоки mdBook 0.5.2, vanilla JS (`assets/srs.js`, `assets/mixed.js`, новые `assets/takeaways.js`, `assets/pairs.js`), Node 20 + jsdom (проверки и генераторы), Playwright MCP (браузер).

## Заметные решения этого плана

Для автора книги: что изменится и что трудно откатить.

1. **Конец главы — без перестройки главы.** 19 глав входят не в `REBUILT` (полная форма), а в новый список `ENDED` линта: проверяются только черта, блок «Что унести» и порядок «лестница → черта → что унести → 🔗» (R2–R4). Полная форма потребовала бы в этих главах переписать 15 «Запомни» и завести 7 новых (R1: в `big-o`, `recursion`, `invariants` блока нет, у `tree-dfs`, `backtracking`, `topological-sort`, `dynamic-programming` заголовок с припиской в скобках), а в 11 главах — переписать начало «📝» и «🧭» (R5–R6). Это и есть перестройка глав-шаблонов — пункт 14, подэтап 3c; там глава переходит из `ENDED` в `REBUILT`. Строки «что унести», написанные сейчас, 3c может уточнить — карточка подхватит правку сама (генератор).
2. **Источник строк «что унести» — сама глава.** `assets/takeaways.js` генерируется (`node scripts/gen-takeaways.js`), руками не правится, CI сверяет его с главами (`--check`). Второй копии строк в `srs.js` или `progress.js` нет.
3. **Карточка `ch:` — три вопроса и ответ.** Вопросы одни на все главы ядра: «По каким словам условия узнать приём?», «Что должно быть верно, чтобы он работал?», «Где он ломается и чем заменить?»; ответ — три строки главы и ссылка на неё, оценки — только после «Показать ответ» (как у `mix:`). Ключ карточки не меняется (`ch:<страница>.html`), расписание читателя остаётся. У глав вне ядра «что унести» нет — их карточка остаётся прежней («вспомни предусловие и инвариант»).
4. **В главах с «объясни сам» новых `ch:` не заводится.** Список берётся из разметки (`<div class="algo-explain" data-key>` — сейчас 12 глав, 10 из них в ядре), а не руками. Уже заведённые `ch:` этих глав не удаляются и показывают те же три вопроса. Следствие: глава с «объясни сам», отмеченная пройденной без заполненного виджета, карточки не даёт вовсе — её карточкой станет `expl:` после виджета.
5. **Реестр не загрузился — прежнее поведение.** Без `window.ALGO_TAKEAWAYS` движок заводит `ch:` как раньше и показывает прежний вопрос: сбой загрузки не стирает очередь и не прячет главы. Порядок подключения (`takeaways.js` раньше `srs.js`, `pairs.js` раньше `mixed.js`) сверяет `check-registries.js`.
6. **Таблица путаемых пар — `assets/pairs.js`.** 15–19 строк вида `{ must, use, not, why }`: «что обязано быть верно» → приём `use` → почему не сосед `not`. Блоки в «🔗» глав и в руководстве вписывает `scripts/gen-pairs.js` между метками `<!-- pairs:begin … -->` / `<!-- pairs:end -->`; правка руками внутри меток красит CI.
7. **Смешанная тренировка: строка пары — только в точном направлении.** После промаха под «Как это было узнать» (поле `g`, признак задачи — уже есть) встаёт строка пары, если в реестре есть ряд «верный приём = `use`, выбранный = `not`»; иначе ничего. `CONFUSABLE` остаётся источником неверных вариантов, а не объяснений; правило сверки: обе главы каждой пары, если обе — главы-ответы банка, лежат в одной группе `CONFUSABLE` (держит `mixed-check.js`). В режиме собеседования строка пары тоже показывается — шаблон там уже назван вердиктом.
8. **Руководство по выбору:** дерево из ~70 узлов остаётся текстом; листья получают метку уровня `[ядро]` / `[расширение]` / `[справочник]` (сверяется с `progress.js`); добавляется ветка хеш-таблицы и раздел «Путаемые пары» (сгенерированная таблица). Two Sum в главе о хеш-таблице появится только в 3d (пункт 15) — ветка ссылается на главу о хеш-таблице и на раздел «Нужны исходные индексы?» главы «Два указателя».
9. **В `top-k-elements` и `backtracking` блок «💻 Реши прямо здесь» своего пакета поднимается выше черты** (сейчас стоит после конкурентного раздела); виджеты конкурентных пакетов (`wordcount`, `parallelnqueens`) остаются в своих разделах за чертой. Задачи `algo-challenge` и виджеты `algo-viz` не переставляются.

```js
  // pairFor — ряд таблицы путаемых пар для промаха: верный приём задачи p (c или одна из a) — use,
  // выбранный — not. Только точное направление; ряда нет — null, и строка не показывается.
  function pairFor(p, picked) {
    var rows = window.ALGO_PAIRS || [];
    var right = answers(p);
    for (var i = 0; i < rows.length; i++) {
      if (rows[i].not === picked && right.indexOf(rows[i].use) >= 0) return rows[i];
    }
    return null;
  }
  // pairLine — строка под вердиктом: «Здесь обязано быть верно: <must> → <use>. Почему не «<not>»: <why>».
  function pairLine(p, picked, into) {
    var row = pairFor(p, picked);
    if (!row) return;
    into.appendChild(el("p", "algo-mixed__pair",
      "Здесь обязано быть верно: " + row.must + " → " + chapterTitle(row.use) +
      ". Почему не «" + chapterTitle(row.not) + "»: " + row.why + "."));
  }
```

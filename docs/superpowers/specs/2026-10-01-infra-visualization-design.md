# Визуализация инфраструктурных тем: Postgres, Redis, Kafka (волна 1)

Дата: 2026-10-01. Статус: черновик на ревью.

## Цель
Читатель (Go-разработчик, ~1 год опыта, цель — стать инженером) должен *увидеть*, как устроены Postgres, Redis и Kafka внутри, и понять это простым языком. Для каждой темы две вещи: доступная теория и пошаговая визуализация в манере AlgoMaster (шаги, режим 🎯 «предсказывать», пресеты граничных случаев, легенда).

## Вне объёма (следующие волны)
gRPC, Docker, Linux; алгоритмические главы без виджетов (`graph-connectivity`, `probability`, `combinatorics`, `invariants`, `parallel-algorithms`, `skip-the-work`, `appendix-go-memory`, `code-review`).

## Допущения
- Новые виджеты строятся на существующем движке `assets/algo-viz.js` (vanilla JS/SVG, без сборщика).
- Числа и поведение в виджетах и тексте сверяются с реальными контейнерами (Postgres — `pglab/`; Redis и Kafka — новые лаборатории). Непроверенное не утверждается.
- Язык контента русский, код Go, стиль теории — как в ядре книги (аналогии, «Типичные ошибки», связанные главы).

## Архитектура
1. **Хук в движке.** В `algo-viz.js` добавляется `window.ALGO_VIZ.register(type, cfg)` (~30 строк): тот же `cfg`, что у встроенных типов `DASH`. Пока тип не зарегистрирован, виджет показывает сообщение об ошибке, а не молчит.
2. **`assets/infra-viz.js`** — новые типы, подключается в `book.toml` после `algo-viz.js`. Движок по-прежнему даёт управление, 🎯, пресеты, легенду, SRS-карточки `viz:<тип>`.
3. **Проверки.** `check-viz.js`, `check-viz-names.js`, `predict-check.js`, `viz-render-check.js` видят зарегистрированные типы наравне со встроенными (при необходимости читают их из `infra-viz.js`).

## Состав
### Postgres
Новая глава «Как Postgres хранит данные» перед `postgres-plans.md`; виджеты и в ней, и в `postgres-plans.md`:
- `pg-page` — страница 8 КБ: заголовок, массив указателей, tuple растут навстречу; вставка, удаление, переполнение.
- `pg-index-to-heap` — B-tree → `ctid` → страница кучи; Index Scan против Index Only Scan.
- `pg-scan-kinds` — Seq / Index / Bitmap Scan на одной таблице, счёт прочитанных страниц.
- `pg-join` — Nested Loop, Hash Join, Merge Join шагами (связь с главами о хеш-таблице и слиянии).
- `pg-mvcc` — `UPDATE` создаёт версию, `xmin`/`xmax`, что видит каждая транзакция.
- `pg-vacuum` — удаление мёртвых версий, карта видимости.
- `pg-wal` — журнал раньше страницы, восстановление после сбоя.

### Redis (в `miniredis.md`)
- `redis-resp` — разбор кадра RESP байт за байтом.
- `redis-ttl` — ленивое и активное удаление протухших ключей.
- `redis-persist` — `SAVE` (снапшот) против AOF; что теряется при сбое.

### Kafka (новая глава `kafka.md`)
- `kafka-log` — лог только на дозапись, offset, чтение с позиции.
- `kafka-partition` — `hash(key) % partitions`, порядок только внутри партиции (ссылка на консистентное хеширование).
- `kafka-group` — consumer group, назначение партиций, ребаланс при падении консьюмера.
- `kafka-isr` — репликация, лидер, ISR, что значит `acks=all`.
- Лаборатория `kafka-lab/` (docker-compose, пришпиленная версия образа) по образцу `pglab/`; цели `make` в корневом `Makefile`.
- Redis-лаборатория для сверки RESP/TTL, если пригодного контейнера в репозитории нет.

## Теория в каждой главе
Простым языком, аналогия до определения; раздел «Что видно в `EXPLAIN` / `redis-cli` / `kafka-topics`»; «Типичные ошибки»; ссылки на связанные главы. Новые главы добавляются в `SUMMARY.md`, реестр `progress.js` (поле `lvl`), `check-registries.js`.

## Порядок работ
1. Хук `register` + пустой `infra-viz.js`; все существующие смоуки зелёные.
2. Postgres (глава + виджеты, сверка с `pglab/`).
3. Redis.
4. Kafka (лаборатория, глава, виджеты).
5. Реестры, CI-проверки, живая проверка в браузере (все пресеты, 🎯, телефон 320–400px, тёмные темы).

## Критерии готовности
- `mdbook build`, `node scripts/check-links.js`, `check-registries.js`, `check-viz.js`, `predict-check.js` и остальные смоуки проходят; jsdom установлен, пропуск без него не считается успехом.
- Каждый новый виджет прошаган до конца в Chrome, итоговые статусы прочитаны.
- Каждое число в тексте воспроизведено на лаборатории.

## Риски
- Файл `algo-viz.js` и его проверки могут предполагать закрытый реестр типов — выясняется на шаге 1.
- Образы Kafka тяжёлые и меняют настройки между версиями: версию пришпиливаем и проверяем запуск с нуля.
- Объём волны большой; каждая подтема (Postgres, Redis, Kafka) — отдельный план и отдельная проверка.

## 🎬 Визуализация

> 💡 **Интерактивная демонстрация (MST, Краскал).** Рёбра рассматриваются по возрастанию веса:
> зелёные добавлены в остов, пунктир/тусклые — отброшены (замкнули бы цикл, Union-Find). Справа —
> код с подсветкой строки и переменные (ребро, вес, вес MST), внизу — кликабельные шаги. Можно
> подставить свой граф. (Виджет работает в собранной книге `mdbook serve`/`mdbook build`, а не при
> просмотре `.md` на GitHub.)

<div class="algo-viz" data-viz="mst-kruskal" data-nodes="A,B,C,D,E" data-edges="A-B-2,A-D-6,B-C-3,B-D-8,B-E-5,C-E-7,D-E-9"></div>

> 💡 **Интерактивная демонстрация (Bellman–Ford).** Здесь есть **отрицательное** ребро
> `B→C (−3)`: следи, как на проходах подпись `dist` под `C` уменьшается даже после того, как до
> неё уже дошли — Bellman–Ford ничего не финализирует и потому переживает отрицательные веса.
> Жёлтым подсвечивается релаксируемое ребро, синим — достигнутые вершины. Последний (V-й) проход —
> детектор отрицательного цикла. Можно подставить свой граф. (Виджет работает в собранной книге.)

<div class="algo-viz" data-viz="bellman-ford" data-nodes="A,B,C,D" data-edges="A-B-4,A-C-5,B-C--3,C-D-4,B-D-8" data-start="0"></div>

> 💡 **Интерактивная демонстрация (A\*).** Поиск пути от `S` к `G` по сетке. В каждой посещённой
> клетке — оценка `f = g + h` (`g` — путь от старта, `h` — манхэттен до цели). Жёлтая — раскрываемая
> сейчас, фиолетовые — в открытом списке (frontier), синие — уже закрытые, зелёные в конце — путь.
> Благодаря эвристике фронт тянется **к цели**, а не растекается во все стороны, как у Дейкстры.
> Можно подставить свою сетку (`0` — свободно, `1` — стена). (Виджет работает в собранной книге.)

## ⚡ Шаблон для собеседования

```go
// MST через Краскала
func kruskalMST(n int, edges [][]int) int {
    sort.Slice(edges, func(i, j int) bool { return edges[i][2] < edges[j][2] })
    uf := NewUnionFind(n)
    total, used := 0, 0
    for _, e := range edges {
        if uf.Union(e[0], e[1]) { // соединяет разные компоненты?
            total += e[2]
            used++
        }
    }
    if used != n-1 {
        return -1 // граф несвязный — остова нет
    }
    return total
}
```

1. сортируем рёбра по весу;
2. берём ребро, если `Union` соединил две разные компоненты;
3. иначе ребро замкнуло бы цикл — пропускаем;
4. остов = `n−1` рёбер.

## 📖 Разбор

<details class="algo-details">
<summary>Bellman–Ford, A*, MST (Kruskal и Prim), сложности</summary>

#### Bellman–Ford (отрицательные веса)

Релаксация: проходим по всем рёбрам, улучшая `dist[v] = min(dist[v], dist[u] + w)`.
Кратчайший путь ≤ V−1 рёбер, поэтому V−1 проходов достаточно. Если на V-м проходе ещё
улучшается — есть отрицательный цикл.

```go
func bellmanFord(n int, edges [][]int, src int) (dist []int, hasNegCycle bool) {
    const INF = 1 << 62
    dist = make([]int, n)
    for i := range dist {
        dist[i] = INF
    }
    dist[src] = 0
    for i := 0; i < n-1; i++ {
        for _, e := range edges {
            u, v, w := e[0], e[1], e[2]
            if dist[u] != INF && dist[u]+w < dist[v] {
                dist[v] = dist[u] + w
            }
        }
    }
    for _, e := range edges { // V-й проход — детектор цикла
        u, v, w := e[0], e[1], e[2]
        if dist[u] != INF && dist[u]+w < dist[v] {
            return dist, true
        }
    }
    return dist, false
}
```

Сложность O(V·E). Для неотрицательных весов используйте Дейкстру.

#### A* (направленный поиск)

A* = Дейкстра + эвристика `h(n)` (оценка оставшегося пути). Из очереди берём минимум
`f(n) = g(n) + h(n)`. При **допустимой** (не переоценивающей) эвристике путь оптимален, но
вершин просматривается меньше. На сетке (4 направления) допустима манхэттенская
`|Δr| + |Δc|`. При `h ≡ 0` A* вырождается в Дейкстру.

#### MST: Краскал

```go
func kruskalMST(n int, edges [][]int) int {
    sort.Slice(edges, func(i, j int) bool { return edges[i][2] < edges[j][2] })
    uf := NewUnionFind(n)
    total, used := 0, 0
    for _, e := range edges {
        if uf.Union(e[0], e[1]) {
            total += e[2]
            used++
        }
    }
    if used != n-1 {
        return -1
    }
    return total
}
```

#### MST: Прим

Выращиваем дерево из одной вершины, каждый раз добавляя лёгкое ребро наружу (мин-куча).

```go
func primMST(n int, adj [][][2]int) int {
    visited := make([]bool, n)
    h := &edgePQ{{node: 0, weight: 0}}
    total := 0
    for h.Len() > 0 {
        e := heap.Pop(h).(edge)
        if visited[e.node] {
            continue
        }
        visited[e.node] = true
        total += e.weight
        for _, nb := range adj[e.node] {
            if !visited[nb[0]] {
                heap.Push(h, edge{node: nb[0], weight: nb[1]})
            }
        }
    }
    return total
}
```

| Алгоритм | Подход                         | Сложность   | Когда выбирать    |
|----------|--------------------------------|-------------|-------------------|
| Kruskal  | сортировка рёбер + Union-Find  | O(E log E)  | разреженный граф  |
| Prim     | растущее дерево + мин-куча      | O(E log V)  | плотный граф      |

</details>

## 🧠 Почему это корректно

### Bellman–Ford: почему `V−1` проходов и почему `V`-й ловит цикл

Инвариант релаксации: **после `k`-го прохода `dist[v]` верно для всех кратчайших путей,
использующих ≤ `k` рёбер.** База: `dist[src] = 0` (0 рёбер). Шаг: на проходе `k+1`
каждое ребро `u→v` пробует продлить лучший путь до `u` (≤ `k` рёбер) ещё на одно.

Кратчайший путь в графе без отрицательных циклов **простой**, значит содержит ≤ `V−1`
рёбер. Поэтому `V−1` проходов достаточно. Если на `V`-м проходе что-то всё ещё
улучшается — нашёлся путь из `V` рёбер дешевле любого из `V−1`, а это возможно только
при **отрицательном цикле** (повтор вершины, снижающий стоимость). Отсюда бесплатный
детектор.

> **Почему отрицательные рёбра ломают Дейкстру, но не BF.** Дейкстра **финализирует**
> вершину при извлечении из кучи, считая её расстояние окончательным — отрицательное
> ребро позже могло бы его уменьшить, но поздно. Bellman–Ford ничего не финализирует:
> он **перепроверяет все рёбра** каждый проход, поэтому переживает отрицательные веса.

### MST: свойство разреза (cut property)

И Kruskal, и Prim — частные случаи одной теоремы:

> **Cut property.** Для любого разреза графа минимальное по весу ребро, пересекающее
> разрез, входит в *некоторое* минимальное остовное дерево.

*Exchange argument.* Пусть MST `T` не содержит лёгкое ребро разреза `e`. Добавим `e` в
`T` — образуется цикл, который пересекает разрез ещё хотя бы раз, ребром `e'` с весом
`≥ w(e)`. Уберём `e'`: снова остов, вес `≤ w(T)` → тоже MST, и он содержит `e`. ∎

Отсюда корректность обоих: **Kruskal** берёт глобально лёгкое ребро, не образующее цикл
(оно лёгкое для разреза между его компонентами — `Union` вернул `true`); **Prim** берёт
лёгкое ребро, выходящее наружу из растущего дерева (разрез «дерево / остальное»).

### A*: почему допустимая эвристика даёт оптимум

`f(n) = g(n) + h(n)`. Если `h` **не переоценивает** оставшийся путь (допустима), то
`f(n)` — нижняя оценка полной стоимости пути через `n`. Когда из очереди извлекается
цель, её `f` равно реальной длине, и она не больше `f` любой другой вершины → более
дешёвого пути не существует. Переоценивающая `h` это свойство ломает — и ответ может
быть неоптимальным.

## ⚙️ Цена на практике

### Какой алгоритм кратчайших путей брать

- невзвешенный граф → [BFS](graphs.md) `O(V+E)`;
- неотрицательные веса → [Дейкстра](grids-and-shortest-paths.md) `O(E log V)`;
- есть отрицательные рёбра → Bellman–Ford `O(V·E)`;
- нужен детектор отрицательного цикла → Bellman–Ford (`V`-й проход);
- есть хорошая допустимая эвристика → A* (та же оптимальность, меньше раскрытых вершин).

### Kruskal или Prim — по плотности

Kruskal сортирует рёбра (`O(E log E)`) — выигрывает на **разреженном** графе. Prim растит
дерево кучей (`O(E log V)`) — лучше на **плотном**. На собеседовании Kruskal обычно
короче (сортировка + готовый Union-Find).

### «Ленивый» Prim держит устаревшие записи

Показанный Prim кладёт в кучу рёбра, не убирая протухшие, — поэтому на извлечении
обязателен `if visited[...] continue`. Куча может разрастись до `O(E)`. «Жадный» Prim с
decrease-key держит кучу размера `O(V)`, но сложнее в коде.

### Переполнение `INF`

`dist[u] + w` при `dist[u] = INF` переполнится — отсюда проверка `dist[u] != INF` перед
релаксацией. И бери `INF = 1<<62`, а не `MaxInt`, чтобы сложение не ушло в минус.

## ⚠️ Типичные ошибки

1. **Дейкстра при отрицательных весах** — берите Bellman–Ford.
2. **Bellman–Ford: забыли проверку `dist[u] != INF`** перед релаксацией — переполнение.
3. **A\* с недопустимой (переоценивающей) эвристикой** — путь может оказаться неоптимальным.
4. **Kruskal без проверки `used == n-1`** — на несвязном графе вернёте вес леса, а не дерева.
5. **Prim: не пропускаете уже посещённые вершины** при извлечении из кучи.

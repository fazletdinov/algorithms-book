## 🧱 Как устроено

AVL-дерево — это [BST](bst-structure.md), у каждого узла которого дополнительно хранится **высота**
(или баланс). Инвариант: для любого узла высоты левого и правого поддеревьев отличаются не больше
чем на 1.

```go
type Node struct {
    val         int
    left, right *Node
    h           int // высота поддерева
}

func height(n *Node) int  { if n == nil { return 0 }; return n.h }
func balance(n *Node) int { return height(n.left) - height(n.right) } // >0 левый перевес
```

Базовый кирпич балансировки — **поворот**, локальная перестройка трёх узлов, сохраняющая порядок:

```
правый поворот вокруг y:           левый поворот — зеркально

      y                 x
     / \               / \
    x   C    ──▶       A   y
   / \                   / \
  A   B                 B   C
```

Три факта, которые держат всё:

1. **Поворот сохраняет порядок.** До и после `A < x < B < y < C` — in-order обход не меняется,
   поэтому повёрнутое дерево остаётся корректным BST.
2. **Поворот меняет высоту.** Он «поднимает» одно поддерево и «опускает» другое, уменьшая высоту
   перекошенной стороны на 1 — ровно это и чинит дисбаланс.
3. **Дисбаланс локален.** Вставка добавляет 1 к высоте по одному пути; нарушиться баланс может
   только у предков на этом пути, и **первый** же поворот снизу восстанавливает высоту всего
   дерева.

### Когда одинарного поворота мало — двойной

Одинарный поворот чинит дисбаланс, только если перекос **«прямой»** (LL или RR: новый узел ушёл
на ту же сторону, что и перевесившее поддерево). Если перекос **«ломаный»** (LR или RL: новый узел
ушёл в *противоположную* сторону от среднего узла), одного поворота мало — сначала выпрямляем
цепочку, потом поворачиваем. На примере **LR** (перекос влево, но новый узел справа от левого ребёнка):

```
  начало             1) левый поворот x       2) правый поворот z
     z                      z                        y
    / \                    / \                      /  \
   x   D                  y   D                    x    z
  / \        ─────▶      / \         ─────▶       / \  / \
 A   y                  x   C                     A  B C  D
    / \                / \
   B   C              A   B
```

Шаг 1 превращает «ломаный» LR в «прямой» LL (`z ← y ← x`), шаг 2 его выпрямляет. In-order всё время
один и тот же — `A < x < B < y < C < z < D`, — поэтому BST сохраняется. **RL — зеркально:** сначала
правый поворот правого ребёнка, затем левый поворот узла.

## ➕ Вставка с балансировкой

Вставка идёт как в обычном BST (спуск до листа), затем на **обратном пути** пересчитываются высоты
и проверяется баланс; при `|баланс| > 1` выполняется поворот по одному из четырёх случаев.

```go
func insert(node *Node, val int) *Node {
    if node == nil { return &Node{val: val, h: 1} }   // вставка листа
    if val < node.val { node.left = insert(node.left, val) } else { node.right = insert(node.right, val) }
    update(node)                                       // высота = 1 + max(детей)
    b := balance(node)                                 // высота левого − правого
    if b > 1 && balance(node.left) >= 0  { return rotateRight(node) }                                  // LL
    if b > 1                             { node.left = rotateLeft(node.left); return rotateRight(node) } // LR
    if b < -1 && balance(node.right) <= 0 { return rotateLeft(node) }                                  // RR
    if b < -1                            { node.right = rotateRight(node.right); return rotateLeft(node) } // RL
    return node
}
```

> 💡 **Демонстрация вставки.** В сбалансированное дерево из `30,20,40,10` вставляем `5`: спуск
> `30 → 20 → 10`, новый лист `5`. На подъёме узел `20` получает баланс `2` — **дисбаланс случая
> LL**, делается правый поворот вокруг `20`: его место занимает `10` (дети `5` и `20`), дерево снова
> сбалансировано. Подставь своё значение — например, такое, что вызовет двойной поворот (LR/RL).

## ➖ Удаление с балансировкой

Удаление устроено похоже, но с одним важным отличием. Сначала убираем узел **как в обычном
BST**:

- узел-**лист** — просто отцепляем;
- узел с **одним ребёнком** — на его место встаёт ребёнок;
- узел с **двумя детьми** — находим **преемника** (минимум правого поддерева), копируем его
  значение в удаляемый узел, а сам преемник (у него не больше одного ребёнка) физически убираем.

А потом — балансируем, **поднимаясь вверх по всему пути** от места удаления к корню. И вот
отличие от вставки: при вставке хватало **одного** поворота, а при удалении баланс может
нарушиться на **нескольких** уровнях подряд — поэтому поворот не завершает работу, а продолжаем
проверять предков до самого корня.

```go
func (t *AVL) Delete(val int) {
    node := t.find(val)
    if node == nil { return }
    if node.left != nil && node.right != nil {
        s := min(node.right)   // преемник — минимум правого поддерева
        node.val = s.val       // копируем значение
        node = s               // физически удаляем преемника (≤1 ребёнка)
    }
    unlink(node)
    for n := node.parent; n != nil; n = n.parent {  // вверх по предкам
        update(n)
        if abs(balance(n)) > 1 {
            rebalance(n)       // поворот — и идём ВЫШЕ, не останавливаемся
        }
    }
}
```

Нажми «▶»: удаляем `80`. Узел уходит, правое поддерево «худеет», у предка возникает перевес
влево — и балансировка вверх по пути чинит это поворотом (жёлтый — текущий узел, зелёный —
корень повёрнутого поддерева):

## 🧠 Почему это корректно

### Почему поворот сохраняет BST-порядок

Поворот лишь переставляет три узла и перецепляет среднее поддерево (`B` на схеме выше), но
относительный порядок `A < x < B < y < C` остаётся. Значит in-order обход не меняется, и
инвариант BST («левее — меньше, правее — больше») сохраняется. Поворот — это «переформулировка»
той же упорядоченной последовательности другим деревом.

### Почему четыре случая и почему хватает одного поворота

Дисбаланс `|баланс| > 1` возникает в четырёх конфигурациях по тому, **куда** легла вставка
относительно перекошенного узла: слева-слева (LL), справа-справа (RR) — лечатся одним поворотом;
слева-справа (LR), справа-слева (RL) — сначала «выпрямляются» поворотом ребёнка, потом основным
поворотом (двойной). После вставки высота поддерева увеличилась на 1; поворот возвращает её к
исходной, поэтому выше по дереву баланс уже не нарушается — **один** поворот (одинарный или
двойной) чинит всё дерево.

### Почему высота — O(log n)

Из инварианта `|баланс| ≤ 1` следует, что минимальное число узлов в AVL-дереве высоты `h` растёт
как числа Фибоначчи, то есть экспоненциально по `h`. Значит `h ≤ 1.44 · log₂(n)` — высота всегда
логарифмическая, а с ней и все операции. Это и есть **гарантия**, которой нет у обычного BST.

## ⚙️ Цена на практике

### AVL против red-black дерева

- **AVL** держит баланс **строже** (`|баланс| ≤ 1`), поэтому деревья ниже и **поиск быстрее** —
  выбор, когда чтений много.
- **Red-black** допускает более перекошенные деревья, но делает **меньше поворотов** на
  вставку/удаление — выбор, когда много записей. Именно red-black лежит в основе `std::map`,
  `TreeMap` и т.п.

Оба гарантируют O(log n); разница — в константах и в балансе чтение/запись.

### AVL против обычного BST и хеш-таблицы

Перед обычным [BST](bst-structure.md) AVL выигрывает гарантией: не выродится на отсортированном
входе. Перед [хеш-таблицей](hash-table-structure.md) — даёт **порядок** (диапазоны, k-й, сосед),
которого у хеша нет, но проигрывает в среднем по скорости простого доступа по ключу.

### В Go готового нет

Стандартная библиотека Go не содержит сбалансированного дерева — на практике берут `map` (без
порядка), отсортированный срез или внешнюю реализацию (B-дерево, red-black). Понимать механику
поворотов всё равно нужно — это классика собеседований и фундамент упорядоченных структур.

## ⚠️ Типичные ошибки

1. **Забыть обновить высоту** после вставки/поворота — баланс посчитается по устаревшим данным.
2. **Перепутать случай LR/RL с LL/RR** — двойной поворот требует сперва повернуть ребёнка; одного поворота не хватит.
3. **Не перецепить поддерево к родителю** после поворота — корень поддерева сменился, ссылку предка надо обновить (или вернуть новый корень).
4. **Балансировать только корень** — проверять и чинить нужно на всём обратном пути от листа.
5. **Сломать порядок при ручной перестройке** — после поворота обязательно сохраняется in-order.

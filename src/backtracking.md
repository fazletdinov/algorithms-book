## 🧭 Откуда берётся поиск с возвратом: выведем его сами

Три пункта «Запомни» вырастают из двух задач. Первая показывает, зачем **отмена**; вторая — зачем
**отсечение**.

### Откат: все подмножества `[1, 2, 3]`

> **Задача (Subsets).** Выписать все подмножества `[1, 2, 3]` — их `2³ = 8`.

**Как решает человек.** Держу в руке текущий набор и записываю его. Потом по очереди пробую
добавить каждое следующее число: добавил — ушёл глубже с новым набором, вернулся — снова держу
прежний. Чтобы не получить `{2,1}` рядом с `{1,2}`, добавляю только числа правее последнего
взятого (`start`). В коде «держу в руке» — один срез `cur` на весь перебор:

```go
var res [][]int
var cur []int
var bt func(start int)
bt = func(start int) {
    res = append(res, append([]int{}, cur...)) // записать копию
    for i := start; i < len(nums); i++ {
        cur = append(cur, nums[i]) // выбрать
        bt(i + 1)
        cur = cur[:len(cur)-1] // откат
    }
}
```

Проследим `cur` по строкам этого кода до записи `[1,3]` — через два отката:

```text
cur       что сделала строка
[]        записали копию []
[1]       взяли 1, записали копию [1]
[1,2]     взяли 2, записали копию [1,2]
[1,2,3]   взяли 3, записали копию [1,2,3]
[1,2]     сняли 3        ← первый откат: bt(3) вернулся
[1]       сняли 2        ← второй откат: bt(2) кончил цикл
[1,3]     взяли 3, записали копию [1,3]
```

Без строки отката после `[1,2,3]` следующей веткой стал бы `[1,2,3,3]`, а не `[1,3]`.
**Буфер `cur` один на все ветки, поэтому каждая ветка обязана вернуть его таким, каким
получила: что положил перед вызовом — сними сразу после.** По той же причине в ответ идёт
копия: сам `cur` через строку изменится. Весь порядок ответов — `[] [1] [1,2] [1,2,3] [1,3] [2]
[2,3] [3]`: обход дерева решений в глубину. Виджет ниже проигрывает эти подмножества по тому же
коду — сверь его шаги с трассой: первый откат — шаг 15, второй — шаг 17.

### Отсечение: Combination Sum

> **Задача (Combination Sum).** Из чисел `[2, 3, 6, 7]` собрать все наборы с суммой `7`;
> каждое число можно брать сколько угодно раз, порядок внутри набора не важен.
> Ответ — `[2,2,3]` и `[7]`.

**Как решает человек.** На каждом шаге пробую положить любое из четырёх чисел. Сумма стала
`7` — записываю набор. Перевалила за `7` — назад. Это тот же перебор с откатом, и ответ
он находит. Но по дороге делает много лишнего:

- **Один набор — трижды.** `[2,2,3]`, `[2,3,2]` и `[3,2,2]` — один и тот же набор, а перебор
  строит его тремя путями. Дубли потом пришлось бы вычищать.
- **Заходы в заведомый тупик.** В ветке `[2,2,2]` сумма уже `6`. Перебор всё равно заходит во
  все четыре продолжения — с суммами `8`, `9`, `12`, `13`, — чтобы в каждом узнать «много».

Посчитаем вызовы. Узлов с суммой меньше `7` девять: `[]`, `[2]`, `[3]`, `[6]`, `[2,2]`,
`[2,3]`, `[3,2]`, `[3,3]`, `[2,2,2]`. У каждого четыре продолжения, плюс сам корень:
`1 + 9·4 = 37` вызовов, и 24 из них — заходы, где сумма уже больше `7`.

**Что чинит.** Обе беды снимаются **на развилке**, до спуска в ветку:

- бери числа только по неубыванию индекса (каждый следующий индекс не меньше предыдущего; параметр `start`) — тогда `[2,2,3]` строится одним
  путём, а `[3,2,…]` не возникает вовсе;
- отсортируй числа и проверяй кандидата **до** входа: если `2` больше остатка `1`, то `3`, `6`
  и `7` — тем более, `break`, ни одного лишнего вызова.

Тот же ответ находится за 10 вызовов, и фильтровать в конце нечего.

**Поиск с возвратом — это «сгенерируй всё и отфильтруй», у которого фильтр переехал из листьев
на развилки.** Этот приём — перебор с отсечением (pruning); код Combination Sum с отсечением и
дерево всех 10 вызовов — в [«📝 Разборе задачи»](#-разбор-задачи).

## 🎬 Визуализация

> 💡 **Интерактивная демонстрация на примере подмножеств.** Сверху — **дерево решений**: каждый
> узел — вызов `bt` со своим набором, путь от корня до синего узла — это и есть стек вызовов,
> зелёные узлы закончены, бледные ещё впереди. Порядок ответов — обход этого дерева в глубину:
> поэтому `{1,2,3}` появляется раньше `{1,3}`, а `{1,3}` — раньше `{2}`. Ядро backtracking:
> **выбор** (берём элемент, синий) → **рекурсия** (спуск на узел ниже) → **отмена** (откат,
> жёлтый, — подъём на узел выше). В строке «Найдено» копятся готовые подмножества. Панель «стек вызовов» показывает активные кадры `bt(start)` и их `i`: видно, в какой
> кадр вернулась рекурсия и откуда продолжится цикл. Под холстом — строка шага и переменные, ниже — ползунок шагов (или ←/→ на клавиатуре) и код с подсветкой строки. Можно
> подставить своё множество и нажать «⟲ Запустить».

## ⚡ Шаблон для собеседования

```go
func backtrack(current []int, choices []int, result *[][]int) {
    if isComplete(current) { // 1. готовое решение
        solution := make([]int, len(current))
        copy(solution, current) // копируем срез!
        *result = append(*result, solution)
        return
    }
    for _, choice := range choices {
        if !isValid(current, choice) {
            continue // 2. отсечение тупиков (pruning)
        }
        current = append(current, choice)      // выбор
        backtrack(current, choices, result)     // рекурсия
        current = current[:len(current)-1]      // отмена (backtrack)
    }
}
```

1. базовый случай: частичное решение готово → копируем в результат;
2. перебираем варианты, отсекая недопустимые;
3. делаем выбор → рекурсия → **отменяем** выбор.

В подмножествах из «🧭» ответ — каждый узел, а не только лист: поэтому там запись стоит в начале
вызова и `return` нет.

## 📖 Разбор

**Backtracking** — техника систематического перебора, при которой решение строится по
одному элементу за раз. Как только понятно, что текущий частичный вариант не приведёт к
допустимому решению, алгоритм **откатывается** на шаг назад. По сути это обход в глубину
(DFS) по **дереву решений**: узел — частичное решение, ребро — выбор следующего элемента.

В каждом узле дерева решений — те же действия из «Запомни»: **выбор**
(`append`), **рекурсия** вглубь, **отмена** (`pop`) и **отсечение**. Шаблон решает,
что делать, двумя проверками: **цель** (`isComplete` — решение собрано: копируем и
выходим) и **ограничения** (`isValid` — недопустимый выбор отсекаем, не спускаясь в ветку).

#### Дерево решений для перестановок [1, 2, 3]

<div class="algo-fig" data-fig="tree" data-tree="[]([1]([1,2]([1,2,3]!),[1,3]([1,3,2]!)),[2]([2,1]([2,1,3]!),[2,3]([2,3,1]!)),[3]([3,1]([3,1,2]!),[3,2]([3,2,1]!)))" data-caption="В узле — current; синие листья — готовые перестановки, слева направо в порядке записи"></div>

Каждый уровень — ещё один выбранный элемент, лист — готовая перестановка. Обход в глубину идёт
по этому дереву слева направо: дошёл до листа — записал ответ и **откатился** к развилке выше.
В отличие от подмножеств, здесь годится любой ещё не взятый элемент, а не только правее
последнего, — поэтому вместо `start` нужны флаги `used`.

#### Пример: все перестановки

```go
func permute(nums []int) [][]int {
    var result [][]int
    used := make([]bool, len(nums))
    var current []int

    var backtrack func()
    backtrack = func() {
        if len(current) == len(nums) {
            perm := make([]int, len(current))
            copy(perm, current)
            result = append(result, perm)
            return
        }
        for i, n := range nums {
            if used[i] {
                continue
            }
            used[i] = true
            current = append(current, n)
            backtrack()
            current = current[:len(current)-1]
            used[i] = false
        }
    }

    backtrack()
    return result
}
```

#### N ферзей — отсечение по ограничению

Расставить `n` ферзей на доске `n×n` так, чтобы никакие два не били друг друга. В каждой строке
стоит ровно один ферзь, поэтому выбор на уровне `r` — столбец для ферзя строки `r`. Ограничение
проверяется **на развилке**: столбец и обе диагонали клетки должны быть свободны. Клетки одной
диагонали дают одно и то же `r+c`, клетки другой — одно и то же `r−c` (в коде `r−c+n`, чтобы
индекс не ушёл в минус). Например, `(0,2)`, `(1,1)`, `(2,0)` лежат на одной диагонали — у всех
`r+c = 2`; `(0,0)`, `(1,1)`, `(2,2)` — на другой, у всех `r−c = 0`:

```go
func countFrom(r, n int, cols, diag1, diag2 []bool) int {
    if r == n {
        return 1 // все строки заняты — одна расстановка
    }
    count := 0
    for c := range n {
        d1, d2 := r+c, r-c+n
        if cols[c] || diag1[d1] || diag2[d2] {
            continue // бьётся — в ветку не спускаемся
        }
        cols[c], diag1[d1], diag2[d2] = true, true, true // выбор
        count += countFrom(r+1, n, cols, diag1, diag2)
        cols[c], diag1[d1], diag2[d2] = false, false, false // отмена
    }
    return count
}
```

Вызов — `countFrom(0, n, make([]bool, n), make([]bool, 2*n), make([]bool, 2*n))`. На доске 8×8
он находит 92 расстановки за 2057 вызовов, хотя ставить по ферзю в строку «как попало» —
`8⁸ = 16 777 216` вариантов. В тренажёре это `SolveNQueensCount` — напиши её сам, закрыв код выше.

Перебор экспоненциален, поэтому вход у таких задач маленький: подмножества — до `n ≈ 20`,
перестановки — до `n ≈ 10` (см. [«Размер входа подсказывает
сложность»](big-o.md#размер-входа-подсказывает-сложность)).

**Нужен один ответ, а не все.** Перебор сам не останавливается: цикл каждого уровня пробует все
варианты до конца. Если задача спрашивает «есть ли хоть одно решение», вызов возвращает `bool`,
и уровень, получив `true` от рекурсии, сразу возвращает `true` сам — оставшиеся варианты не
пробуются.

| Перестановки          | O(n · n!)    | O(n)                |
| Комбинации C(n, k)    | O(k · C(n,k))| O(k)                |
| Расстановка скобок    | O(4ⁿ / √n)   | O(n)                |

Backtracking почти всегда **экспоненциален** — решений экспоненциально много. Главный
рычаг ускорения — **раннее отсечение** (pruning).

</details>

## 🧠 Почему это корректно

Три вопроса: почему перебор **ничего не пропускает**, почему откат **обязателен**, и
почему результат нужно **копировать**.

### Почему перебор полон и без дублей

Каждый полный кандидат — это **ровно один путь** от корня до листа в дереве решений.
Цикл на каждом уровне перебирает **все** доступные на этом шаге выборы, поэтому:

- **полнота:** любой допустимый кандидат где-то заканчивается листом, а раз мы
  спускаемся по всем рёбрам — этот лист будет достигнут;
- **без повторов:** дисциплина выбора (флаги `used[]` для перестановок, индекс `start`
  для подмножеств/комбинаций) гарантирует, что один и тот же кандидат не построится
  двумя путями.

### Почему откат обязателен

`current` — **общее изменяемое состояние** всех веток. После возврата из `backtrack()`
мы должны вернуть `current` и `used[i]` в прежний вид:

```go
current = append(current, n) // выбрали
backtrack()                  // ушли вглубь
current = current[:len(current)-1] // ← откат: иначе соседняя ветка
used[i] = false                    //   стартует с испорченного префикса
```

Забыли `current = current[:len(current)-1]` или `used[i] = false` — и следующий сосед по циклу
строит кандидата поверх чужого «хвоста». Откат восстанавливает инвариант: *на входе в
каждую итерацию цикла `current` — ровно выборы на пути от корня до текущего узла*.

### Почему результат копируют, а не добавляют срез

`current` — срез, который **продолжает меняться** после записи. Если положить его в
ответ напрямую (`result = append(result, current)`), все записи окажутся **псевдонимами
одного массива** (разными срезами поверх тех же ячеек) и в конце станут одинаковыми (последнее состояние). Поэтому снимаем
снимок:

```go
perm := make([]int, len(current))
copy(perm, current)          // независимая копия
result = append(result, perm)
```

### Корректность отсечения (pruning)

Отсечь ветку можно **только** если частичный кандидат **доказуемо** не продолжается ни
в одно допустимое решение (нарушено ограничение). Если срезать ветку, в которой решение
*могло* быть, перебор перестанет быть полным и потеряет ответы. Отсечение ускоряет, но
проверка-условие должна быть **корректной**, иначе это уже не та задача.

## ⚙️ Цена на практике

### Экспонента неизбежна — но дерево можно обрезать

Backtracking почти всегда экспоненциален, потому что **самих решений экспоненциально
много** (2ⁿ подмножеств, n! перестановок) — обойти это нельзя, выходные данные столько и
весят. Стоимость = **(число узлов дерева) × (работа в узле)**. Единственный реальный
рычаг — **отсечение**: чем раньше отбраковываешь тупиковую ветку, тем меньше дерево.

### Проверяй ограничение ДО рекурсии, а не в листе

Дешёвое ускорение: проверяй валидность **перед** спуском, а не только в конце. В
N ферзей проверка диагоналей до рекурсии срезает огромные поддеревья (на доске 8×8 — 2057
вызовов вместо 16 777 216 расстановок «по ферзю в строку», [раздел выше](#n-ферзей--отсечение-по-ограничению)); «сгенерировать
всё, потом отфильтровать» — антипаттерн, который превращает выполнимую задачу в
зависание.

### Снимок стоит `O(длина решения)`

Каждый `copy` готового кандидата — это `O(n)`, и таких копий экспоненциально много:
итоговая работа включает размер вывода. Память самой рекурсии скромная — `O(глубины)`
на стек плюс `O(n)` на `current`; доминирует **выходной** массив, а не служебные данные.

## ⚠️ Типичные ошибки

1. **Забыли скопировать срез перед добавлением в результат.** В Go срез — дескриптор
   поверх общего массива; положив сам `current`, все записи будут указывать на один буфер.
   Всегда `make` + `copy`.
2. **Забыли отменить выбор.** Без `current = current[:len(current)-1]` состояние
   «протекает» в соседние ветки.
3. **Позднее отсечение.** Проверяй ограничения до рекурсивного вызова, а не в базовом
   случае — иначе дерево перебора раздувается.
4. **Дубликаты.** Для входа с повторами сначала отсортируй. В подмножествах пропускай
   `i > start && nums[i] == nums[i-1]`; в перестановках — `i > 0 && nums[i] == nums[i-1] && !used[i-1]`:
   равный левый сосед на этом уровне уже пробовался и снят. Без `!used[i-1]` вторую `1`
   не возьмёшь никогда, и на `[1,1,2]` перестановок не будет вовсе.

> 🌍 **Где это в настоящем коде**
>
> - [`tryBacktrack`](https://github.com/golang/go/blob/go1.24.0/src/regexp/backtrack.go#L138) (Go 1.24) — один из движков пакета `regexp` для коротких выражений и текстов. На развилке (`a|b`, `*`) он идёт в первую ветку, а вторую откладывает на стек, чтобы вернуться, если первая не сошлась. Битовая карта «здесь уже был» не даёт пройти одно состояние дважды — это отсечение.

## 📝 Разбор задачи

Перебор и наблюдение — в [«🧭 Откуда берётся поиск с возвратом»](#-откуда-берётся-поиск-с-возвратом-выведем-его-сами):
наивный перебор делает 37 вызовов и строит один набор тремя путями, а `start` и обрыв `break` на
развилке сводят его к 10 вызовам. Здесь — код и трасса той же задачи.

> **Задача (Combination Sum).** Дан массив различных **положительных** чисел
> `candidates` и `target`. Вернуть **все** комбинации, дающие в сумме `target`;
> один и тот же элемент можно брать **сколько угодно раз**. Две комбинации
> различны, если различается **мультимножество** чисел — набор, где важно, какие числа и
> сколько раз каждое, но не порядок: `[2,2,3]` и `[3,2,2]` — одна комбинация.
> Пример: `candidates = [2,3,6,7]`, `target = 7` → `[[2,2,3], [7]]`.

**Оптимум: перебор с отсечением — без дублей, обрезанное дерево.** Числа берутся по неубыванию
индекса (`start`), поэтому каждое мультимножество строится [ровно одним
путём](#почему-перебор-полон-и-без-дублей); повтор разрешён, поэтому в рекурсию уходит `i`, а
не `i+1`. Массив отсортирован, и кандидат больше остатка обрывает весь уровень — это
[корректное отсечение](#корректность-отсечения-pruning): правее только числа ещё больше.

```go
func combinationSum(candidates []int, target int) [][]int {
    sort.Ints(candidates) // для обрыва ветки и порядка по неубыванию
    var result [][]int
    var current []int
    var backtrack func(start, remain int)
    backtrack = func(start, remain int) {
        if remain == 0 { // набрали ровно target
            combo := make([]int, len(current))
            copy(combo, current) // снимок: current ещё будет меняться
            result = append(result, combo)
            return
        }
        for i := start; i < len(candidates); i++ {
            if candidates[i] > remain {
                break // отсортировано ⇒ дальше только больше — обрываем ветку
            }
            current = append(current, candidates[i]) // выбор
            backtrack(i, remain-candidates[i])        // i, не i+1 — повтор разрешён
            current = current[:len(current)-1]        // отмена
        }
    }
    backtrack(0, target)
    return result
}
```

Вместо «сумма» удобнее нести **остаток** `remain`: база — `remain == 0`, отсечение —
`candidates[i] > remain`.

Прогони перебор с остатком на `candidates = [2,3,6,7]`, `target = 7`: берём кандидата
(можно повторно), уменьшаем `remain`, а ветку с `candidates[i] > remain` обрываем. На шаге
отсечения в строке «Множество» зачёркнут не только этот кандидат, но и все правее: массив
отсортирован, так что они тоже больше `remain`, и `break` отбрасывает их без проверки. В дереве
решений под узлом — его `remain`; зелёная рамка — `remain == 0` (найденная комбинация), красный
«пенёк» ✂ — место, где `break` отрезал всю правую часть уровня:

<div class="algo-viz" data-viz="combination-sum" data-array="2,3,6,7" data-target="7"></div>

**Трассировка** на отсортированном `candidates = [2,3,6,7]`, `target = 7` — это дерево
вызовов `backtrack(start, remain)` в виджете выше: в узле — `current`, под ним — `remain`.
Пролистай его до конца и сверь с итогом ниже.

Результат — `[[2,2,3], [7]]`. Видно, как `break` срезает целые поддеревья
(`6 > 5`, `6 > 4`), а старт с индекса `i` не даёт построить `[3,2,…]` — дубль `[2,3]`
уже учтён в ветке слева. Тот же набор даёт и наивный перебор из «🧭» — но после удаления
перестановок-дублей; отсечённая версия не порождает их вовсе.

## 🧵 Конкурентный перебор (Go)

Дерево перебора с возвратом ветвится: каждый выбор на верхнем уровне открывает **независимое
поддерево**. Такие ветви параллелятся почти бесплатно (тот же приём для сортировки слиянием — в главе
[«K-way Merge»](k-way-merge.md#-конкурентная-сортировка-слиянием-go), вне ядра). Возьмём счёт расстановок **N ферзей**:
последовательная версия `countFrom` — в разделе [о N ферзях](#n-ферзей--отсечение-по-ограничению)
выше. Выбор столбца для ферзя в первой строке задаёт `n` непересекающихся поддеревьев: горутина
ставит ферзя в строку 0 сама и досчитывает своё поддерево той же `countFrom` со строки 1.

```go
for c := range n {
    go func(c int) {
        // СВОЯ доска: занятость столбцов и диагоналей у каждой горутины своя
        cols, d1, d2 := make([]bool, n), make([]bool, 2*n), make([]bool, 2*n)
        cols[c], d1[c], d2[n-c] = true, true, true // строка 0: r+c = c, r−c+n = n−c
        results[c] = countFrom(1, n, cols, d1, d2) // досчитываем поддерево
    }(c)
}
// wg.Wait(), затем сумма results
```

**Гонки нет по устройству:** каждая горутина заводит собственные срезы занятости и пишет в свою
ячейку `results`. Никакой общей изменяемой доски — а значит, и замков. На `n=12` конкурентная
версия в бенчмарке тренажёра обгоняет последовательную примерно **в 6–7 раз**.

> 💡 Ключ — не «расставить горутины по рекурсии», а **порезать задачу по верхним веткам** и дать
> каждой полностью своё состояние. Тогда параллелизм даровой. Если же ветви делят изменяемое
> состояние (общий best, счётчик) — придётся синхронизировать, и выигрыш растает.

**Тренажёр** — пакет `parallelnqueens`:

```bash
cd exercises
go test -tags solution ./parallelnqueens/          # эталон
go test -tags solution -race ./parallelnqueens/    # гонок нет: у каждой горутины своя доска
go test -tags solution -bench=. ./parallelnqueens/ # Conc обгоняет Seq
```

> **Ситуация.** Задача с жёсткими ограничениями: составить расписание экзаменов без конфликтов, решить

**Вывод.** «Расставить/выбрать при ограничениях; найти все решения или проверить, есть ли хоть одно» —
сигнал **backtracking с отсечениями**; чем раньше отсекаешь нарушенные ветки, тем практичнее. По сути это
управляемый перебор для [NP-трудных задач](complexity-classes.md) (для них не известно решения за полиномиальное время — n в постоянной степени: n, n², n³) при малом входе.

## 🔗 Связанные шаблоны

<!-- pairs:begin — сгенерировано node scripts/gen-pairs.js из assets/pairs.js, руками не править -->
**Не спутай с соседом** (вся таблица — в [руководстве по выбору](pattern-selection-guide.md#путаемые-пары-что-обязано-быть-верно)):

- если нужны сами варианты, все подмножества, перестановки или расстановки, а не их число — Поиск с возвратом, а не [Динамическое программирование](dynamic-programming.md): в ячейке ДП лежит одно число, оптимум или счёт вариантов, а не список самих вариантов.
- если подзадачи перекрываются, а нужен оптимум или число вариантов, а не сами варианты — [Динамическое программирование](dynamic-programming.md), а не Поиск с возвратом: перебор заново решает одни и те же подзадачи и уходит в экспоненту, а ДП решает каждую один раз.
<!-- pairs:end -->

- **[Subsets](subsets.md)** — частный случай backtracking (выбор «брать / не брать»).
- **[Tree DFS](tree-dfs.md)** — backtracking это и есть DFS по дереву выборов.
- **[Dynamic Programming](dynamic-programming.md)** — когда подзадачи перекрываются,
  перебор с возвратом заменяется мемоизацией/ДП.

## 🎬 Визуализация

> 💡 **Интерактивная демонстрация (Single Number).** XOR накапливается по массиву: пары взаимно
> уничтожаются (`a^a=0`), остаётся уникальное число. Справа — код с подсветкой строки и переменные
> (`result` и его двоичный вид), внизу — шаги. Можно подставить свой массив и нажать «⟲ Запустить».
> (Виджет работает в собранной книге `mdbook serve`/`mdbook build`, а не при просмотре `.md` на GitHub.)

## ⚡ Шаблон для собеседования

```go
// Single Number: один элемент 1 раз, остальные по 2 раза
result := 0
for _, num := range nums {
    result ^= num // пары обнуляются, остаётся единственный
}
return result
```

Полезные трюки в одну строку:

- проверить i-й бит: `(n >> i) & 1`
- установить / сбросить / переключить: `n | (1<<i)` · `n &^ (1<<i)` · `n ^ (1<<i)`
- младший единичный бит: `n & (-n)`; сбросить его: `n & (n-1)`
- степень двойки: `n > 0 && n&(n-1) == 0`

## 📖 Разбор

<details class="algo-details">
<summary>Операторы, свойства, степень двойки, подсчёт битов и сложность</summary>

**Bit Manipulation** использует побитовые операции (AND, OR, XOR, сдвиги) для
решения задач с минимальной памятью. Ключевое свойство — «самообнуление» XOR:
`a ^ a = 0` и `a ^ 0 = a`. Целое хранится как последовательность битов; позиции
нумеруются справа налево с нуля (`5 = 0101`, `8 = 1000` — степень двойки).

#### Базовые операторы

| Оператор | Обозначение | Описание |
|----------|-------------|----------|
| AND | `&` | 1 только если оба бита 1 |
| OR | `\|` | 1 если хотя бы один бит 1 |
| XOR | `^` | 1 если биты разные |
| NOT | `^x` (унарный в Go) | Побитовое дополнение |
| Сдвиг влево | `<<` | Умножение на 2^n |
| Сдвиг вправо | `>>` | Целочисленное деление на 2^n |

#### Поиск единственного числа

```go
func singleNumber(nums []int) int {
    result := 0
    for _, num := range nums {
        result ^= num // пары обнуляются, остаётся единственный
    }
    return result
}
```

#### Проверка степени двойки

У степени двойки ровно один установленный бит, а `n & (n-1)` обнуляет младший
единичный бит.

```go
func isPowerOfTwo(n int) bool {
    if n <= 0 {
        return false
    }
    return n&(n-1) == 0
}
```

#### Подсчёт единичных битов (Brian Kernighan)

Каждая итерация удаляет младший установленный бит — итераций столько, сколько единиц.

```go
func hammingWeight(n uint32) int {
    count := 0
    for n != 0 {
        n &= n - 1 // удаляем младший установленный бит
        count++
    }
    return count
}
```

#### Манипуляции с отдельными битами

| Операция | Код (Go) | Описание |
|----------|----------|----------|
| Проверить i-й бит | `(n >> i) & 1` | 1 если бит установлен |
| Установить i-й бит | `n \| (1 << i)` | Включить бит |
| Сбросить i-й бит | `n &^ (1 << i)` | Выключить бит (AND NOT) |
| Переключить i-й бит | `n ^ (1 << i)` | XOR с маской |
| Изолировать младший 1 | `n & (-n)` | Получить младший установленный бит |
| Сбросить младший 1 | `n & (n-1)` | Удалить младший бит |

#### Сложность

| Операция | Время | Память |
|----------|-------|--------|
| Single Number (XOR) | O(n) | O(1) |
| Power of Two | O(1) | O(1) |
| Hamming Weight | O(k), k — число единичных битов | O(1) |
| Проверка/установка бита | O(1) | O(1) |

</details>

## 🧠 Почему это корректно

### Почему XOR-приём с единственным числом работает

XOR **коммутативен и ассоциативен**, поэтому порядок неважен: пары `a ^ a = 0`
взаимоуничтожаются где бы ни стояли, а `a ^ 0 = a` оставляет одиночку. Доказательство —
ровно эти два свойства, без перебора.

### Почему `n & (n−1)` снимает младший единичный бит

Вычитание `1` переворачивает младший установленный бит в `0`, а все нули под ним — в `1`.
`AND` с `n` оставляет всё **выше** младшего бита и обнуляет его. Отсюда: степень двойки =
ровно один бит ⟺ `n & (n−1) == 0`; а Кернигановский подсчёт делает столько итераций,
сколько единиц. Двойственная операция — `n & (−n)` *изолирует* младший бит (см.
[дерево Фенвика](fenwick-tree-structure.md)).

### Перебор подмасок: почему `(sub−1) & mask` обходит ровно все

Классический приём — перебрать **все подмножества** заданной маски:

```go
for sub := mask; sub > 0; sub = (sub - 1) & mask {
    // sub — очередная непустая подмаска mask
}
```

Почему это перечисляет каждую подмаску ровно раз и по убыванию: `sub − 1` «занимает» из
младшего установленного бита, заполняя единицами всё под ним, а `& mask` тут же гасит
биты, которых в `mask` нет. Так из любой подмаски получается **следующая меньшая**
подмаска того же `mask` — без повторов и пропусков. Суммарно по всем `mask` это `3ⁿ`
итераций (каждый бит независимо: в `mask` и в `sub`, в `mask` но не в `sub`, или вне
`mask`) — отсюда и берётся `O(3ⁿ)` у ДП по подмножествам.

## ⚙️ Цена на практике

### Знак и ширина — главная ловушка

В Go `>>` для **знакового** `int` — арифметический сдвиг (тянет знаковый бит)! Для
битовых трюков бери **беззнаковый** тип (`uint`/`uint32`), иначе на отрицательных
получишь сюрприз. Следи и за переполнением `1 << i` при больших `i`.

### Когда биты уместны

Маленькая вселенная (≤ 64 флага) → **битовая маска** как множество: членство, объединение,
пересечение за `O(1)`; компрессия состояния в ДП; перечисление подмножеств
(см. [Subsets](subsets.md)). Но не жертвуй читаемостью ради микрооптимизации вне горячего
пути — `n & (n-1)` экономит такты, но запутывает там, где это не нужно.

### Не пиши руками то, что есть в `math/bits`

Подсчёт единиц, поиск старшего/младшего бита, разворот — это **аппаратные инструкции**
(POPCNT, LZCNT, TZCNT). Go отдаёт их через пакет `math/bits`: `bits.OnesCount(x)`,
`bits.LeadingZeros(x)`, `bits.TrailingZeros(x)`, `bits.Reverse(x)` — компилятор
разворачивает их в одну машинную команду. Ручной цикл Кернигана за `O(числа единиц)`
проигрывает константному `OnesCount`. Правило: трюк понимать надо (его и спрашивают на
собеседовании), но в продакшен-коде звать стандартную библиотеку — короче, быстрее и без
ошибок со знаком/шириной.

## ⚠️ Типичные ошибки

1. **Путаница `^` и возведения в степень**: в Go `^` — это XOR, а не степень.
2. **Приоритет операций**: `n & n-1` требует скобок — пишите `n & (n-1)`.
3. **Сдвиг отрицательных**: сдвиг вправо знакового `int` арифметический (сохраняет
   знак); для битовых масок используйте `uint`/`uint32`.
4. **Отрицательные числа**: побитовые операции над `int` работают в дополнительном
   коде — для беззнаковой логики берите `uint`.
5. **Пустой массив в Single Number**: непарного элемента нет, XOR вернёт 0 — обработайте
   по соглашению.

## 📝 Разбор задачи

Single Number выше находит **одну** одиночку. Усложним: одиночек **ровно две**.
Рассуждаем как на собеседовании — сначала рабочий перебор, потом понимание, *почему*
он расходует память, и только потом XOR-трюк за O(1).

> **Задача.** В массиве `nums` **ровно два** числа встречаются по одному разу, все
> остальные — строго парами. Вернуть оба одиночных числа (в любом порядке).
> Пример: `nums = [1,2,1,3,2,5]` → ответ `[3,5]` (пары `1,1` и `2,2` сокращаются).

**Шаг 1. Наивно: хеш-счётчики — O(n) времени, O(n) памяти.**

```go
func twoSingleNaive(nums []int) []int {
    cnt := make(map[int]int)
    for _, x := range nums {
        cnt[x]++
    }
    res := make([]int, 0, 2)
    for k, v := range cnt {
        if v == 1 {
            res = append(res, k) // встретился ровно раз — одиночка
        }
    }
    return res
}
```

Это **работает и проходит тесты**, но держит в куче весь набор различных значений —
`O(n)` памяти. А задача почти наверняка просит именно `O(1)` (см. подсказку «просят
O(1) памяти там, где напрашивается хеш-множество»). Хеш здесь — лишняя сущность.

**Шаг 2. Ключевое наблюдение.** Сделаем XOR **всех** элементов. По свойствам XOR пары
взаимоуничтожаются (`a ^ a = 0`), и остаётся `xorAll = a ^ b` — XOR двух искомых чисел
(см. [почему XOR-приём работает](#почему-xor-приём-с-единственным-числом-работает)).
Само по себе `a ^ b` не разделяет `a` и `b`, но даёт зацепку: раз `a ≠ b`, у `a ^ b`
есть **хотя бы один единичный бит** — позиция, в которой `a` и `b` различаются.

Возьмём **младший** такой бит: `diff = xorAll & (-xorAll)` (изоляция младшей единицы,
см. таблицу трюков). По этому биту разобьём массив на две группы: где бит установлен и
где нет. Ключ: `a` и `b` попадут в **разные** группы (они различаются именно в этом
бите), а любая пара `x, x` — в **одну и ту же** (одинаковые числа имеют одинаковый
бит). Значит XOR внутри каждой группы снова гасит все пары и оставляет ровно одну
одиночку — `a` в одной, `b` в другой.

**Шаг 3. Оптимум: двойной XOR с разбиением по биту — O(n) времени, O(1) памяти.**

```go
func twoSingle(nums []int) []int {
    xorAll := 0
    for _, x := range nums {
        xorAll ^= x // остаётся a ^ b: пары сократились
    }
    diff := xorAll & (-xorAll) // младший бит, где a и b различаются
    a, b := 0, 0
    for _, x := range nums {
        if x&diff != 0 {
            a ^= x // группа: бит установлен
        } else {
            b ^= x // группа: бит сброшен
        }
    }
    return []int{a, b}
}
```

Прогоните двойной XOR на `nums = [1,2,1,3,2,5]`: первый проход даёт `xorAll = a^b`, затем
`diff` делит числа на две группы, и в каждой пары сокращаются, оставляя по одиночке:

<div class="algo-viz" data-viz="two-single" data-array="1,2,1,3,2,5"></div>

**Шаг 4. Трассировка** на `nums = [1,2,1,3,2,5]`. Первый проход даёт
`xorAll = 3 ^ 5 = 0b110 = 6`, отсюда `diff = 6 & (-6) = 0b010 = 2` (бит № 1). Второй
проход делит числа по биту № 1 и копит XOR в группах `a` (бит=1) и `b` (бит=0):

| `x` | биты | бит №1 | группа | `a` после | `b` после |
|-----|------|--------|--------|-----------|-----------|
| 1   | `001` | 0 | b | `000` | `001` (=1) |
| 2   | `010` | 1 | a | `010` (=2) | `001` |
| 1   | `001` | 0 | b | `010` | `000` (1^1=0) |
| 3   | `011` | 1 | a | `001` (2^3=1) | `000` |
| 2   | `010` | 1 | a | `011` (1^2=3) | `000` |
| 5   | `101` | 0 | b | `011` | `101` (0^5=5) |

Итог: `a = 3`, `b = 5` → `[3,5]`. Пары `1,1` (обе в группе `b`) и `2,2` (обе в группе
`a`) внутри своих групп сократились в ноль, оставив по одной одиночке. Два прохода по
`n` элементов и пара переменных — `O(n)` времени, `O(1)` памяти.

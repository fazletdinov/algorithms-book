## 1. Зачем инженеру считать, не перебирая

Главы [Subsets](subsets.md) и [Backtracking](backtracking.md) учат **генерировать** варианты:
все 2ⁿ подмножеств, все n! перестановок, сочетания через «взять / пропустить». Их сложности —
`O(2ⁿ·n)` и `O(n·n!)` — это не свойство конкретного кода, а размер самого выходного
пространства. Комбинаторика отвечает на вопрос «а сколько их вообще?» **до** того, как ты
запустил перебор:

- **Оценка перебора.** Прежде чем писать backtracking, посчитай листья дерева: `n = 20`
  флагов → `2²⁰ ≈ 10⁶` комбинаций, погоняем; `n = 40` → `10¹²`, за вечер не успеет.
  Одна строка арифметики экономит часы отладки безнадёжного решения.
- **Оценка числа состояний ДП.** Память и время [динамики](dynamic-programming.md) — это
  число состояний × работа на состояние. «Индекс × собранная сумма» — `n·S` состояний;
  «битмаска посещённых вершин» — `2ⁿ` состояний. Не посчитав, не узнаешь, влезет ли в память.
- **Capacity-планирование.** Сколько строк даст декартово произведение таблиц? Сколько пар
  серверов в full-mesh из n узлов (`C(n,2)`)? Сколько вариантов конфигурации придётся покрыть
  интеграционными тестами? Это те же формулы.

## 2. Правило суммы и правило произведения

Вся комбинаторика стоит на двух правилах, которые ты уже используешь интуитивно:

- **Правило произведения.** Если выбор делается в несколько **независимых** шагов —
  m способов на первом, k на втором — всего `m · k` вариантов. Деплой: 3 типа инстансов ×
  4 региона × 2 ОС = 24 конфигурации. Это в точности мощность декартова произведения:
  `len(A) * len(B)` строк даст `SELECT ... FROM a, b` без условия соединения.
- **Правило суммы.** Если варианты разбиваются на **непересекающиеся** группы, их количества
  складываются: маршруты «через кэш» и «мимо кэша» считаем отдельно и суммируем. Ключевое
  слово — непересекающиеся: если группы перекрываются, простая сумма посчитает общее дважды,
  и понадобится включение-исключение (секция 5).

Произведение отвечает за экспоненты: «по 2 варианта на каждый из n элементов» — это `2ⁿ`,
«по n, потом n−1, потом n−2…» — это `n!`. Все страшные сложности перебора — следствия одного
правила.

## 3. Перестановки, размещения, сочетания

Три базовых вопроса «сколькими способами» различаются только тем, важен ли порядок и все ли
элементы берём:

| Что считаем | Формула | Пример (n = 5, k = 2) |
|---|---|---|
| **Перестановки** P(n) — расставить все n по порядку | `n!` | P(5) = 120 |
| **Размещения** A(n, k) — выбрать k из n, **порядок важен** | `n·(n−1)·…·(n−k+1)` | A(5, 2) = 20 |
| **Сочетания** C(n, k) — выбрать k из n, **порядок не важен** | `A(n, k) / k!` | C(5, 2) = 10 |

Связь между ними — правило произведения: размещение — это «выбрать сочетание, потом
упорядочить его k! способами», поэтому `A(n,k) = C(n,k) · k!`. Проверочный вопрос при выборе
формулы один: **отличаются ли варианты только порядком?** Если {Аня, Боря} и {Боря, Аня} —
один вариант (команда), это сочетание. Если разные (капитан и заместитель) — размещение.

### Треугольник Паскаля и «брать / не брать»

Числа `C(n, k)` — **биномиальные коэффициенты** — образуют треугольник Паскаля: каждое —
сумма двух над ним:

```text
n=0:            1
n=1:          1   1
n=2:        1   2   1
n=3:      1   3   3   1
n=4:    1   4   6   4   1
n=5:  1   5  10  10   5   1
```

Правило суммирования — рекуррента:

```text
C(n, k) = C(n−1, k−1) + C(n−1, k)
```

Это дословно выбор из главы [Subsets](subsets.md): смотрим на последний элемент — либо
**берём** его (осталось выбрать k−1 из n−1), либо **не берём** (выбрать k из n−1). Дерево
перебора «взять / пропустить» и рекуррента Паскаля — одна и та же развилка; разница в том,
что перебор спускается в обе ветки и строит варианты, а счёт складывает два числа. Таблица
по этой рекурренте — готовое ДП за `O(n·k)`: так считают `C(n, k)` по модулю, когда прямая
формула с делением не работает.

## 4. Как считать C(n, k) в коде и не переполниться

Учебниковая формула `C(n,k) = n! / (k!·(n−k)!)` в коде — ловушка: уже `21!` не влезает в
`int64`, хотя сам ответ `C(21, 2) = 210` крошечный. Считать надо итеративно, **деля на каждом
шаге**:

```go
// Binomial возвращает C(n, k) за O(min(k, n−k)) умножений, без факториалов.
func Binomial(n, k int) int {
    if k < 0 || k > n {
        return 0
    }
    if k > n-k {
        k = n - k // симметрия: C(n, k) == C(n, n−k), берём меньшее k
    }
    res := 1
    for i := 1; i <= k; i++ {
        res = res * (n - k + i) / i // деление всегда нацело — см. «Почему это корректно»
    }
    return res
}
```

Почему деление на каждом шаге не теряет точность — разобрано ниже, а границы такие:

- **Значение**: центральные коэффициенты `C(n, n/2)` влезают в `int64` до `C(66, 33) ≈ 7,2·10¹⁸`
  включительно; `C(67, 33)` уже нет.
- **Вычисление**: узкое место — промежуточное произведение `res * (n−k+i)` **до** деления.
  В `int64` метод безопасен для всех `k` при `n ≤ 61`; в `uint64` — при `n ≤ 62` (отсюда
  фольклорное «`C(62, 31)` — последний»: само значение `≈ 4,7·10¹⁷` влезает с запасом, но
  промежуточное произведение при его подсчёте — только в беззнаковый тип). Инженерная мораль:
  проверяй переполнение не по ответу, а по самому большому промежуточному значению.
- **Дальше** — либо таблица Паскаля по модулю `1e9+7` (сложение переполниться не даст), либо
  формула с [модульным обратным](number-theory.md) через быстрое возведение в степень, либо
  `math/big`.

## 5. Включение-исключение

Правило суммы ломается на пересекающихся множествах — включение-исключение его чинит,
попеременно прибавляя и вычитая пересечения:

```text
|A ∪ B|     = |A| + |B| − |A ∩ B|
|A ∪ B ∪ C| = |A| + |B| + |C| − |A∩B| − |A∩C| − |B∩C| + |A∩B∩C|
```

Общий вид для m множеств: по всем непустым подмножествам индексов, знак `+` при нечётном
размере подмножества, `−` при чётном.

### Пример: делимость хотя бы на одно из {2, 3, 5}

Сколько чисел от 1 до n делятся хотя бы на одно из {2, 3, 5}? Кратных d среди 1..n ровно
`⌊n/d⌋`; пересечение «делится на 2 и на 3» — это кратные `lcm(2,3) = 6`. Для n = 30:

```text
⌊30/2⌋ + ⌊30/3⌋ + ⌊30/5⌋ − ⌊30/6⌋ − ⌊30/10⌋ − ⌊30/15⌋ + ⌊30/30⌋
  = 15  +  10   +   6    −   5    −    3     −    2     +    1     = 22
```

«По всем непустым подмножествам» — это готовая [битовая маска](bit-manipulation.md):
маска от 1 до 2ᵐ−1, установленные биты говорят, какие делители вошли в пересечение:

```go
// Сколько чисел в [1, n] делятся хотя бы на один из divisors.
func CountDivisibleByAny(n int, divisors []int) int {
    m, total := len(divisors), 0
    for mask := 1; mask < 1<<m; mask++ { // все непустые подмножества делителей
        l, bits := 1, 0
        for i := 0; i < m; i++ {
            if mask&(1<<i) != 0 {
                bits++
                l = lcm(l, divisors[i]) // пересечение кратных = кратные НОК
            }
        }
        if bits%2 == 1 {
            total += n / l // нечётное подмножество — прибавляем
        } else {
            total -= n / l // чётное — вычитаем
        }
    }
    return total
}
```

В боевой версии (пакет тренажёра) добавляются три щита: нули в `divisors` игнорируются,
дубликаты схлопываются, а ветка обрывается, как только НОК превысил n — вклад `n/l` всё
равно нулевой, зато НОК не успевает переполниться.

### Деранжементы — «все письма не в свои конверты»

Классика включения-исключения: сколькими способами можно разложить n писем по n конвертам,
чтобы **ни одно** не попало в свой? Из всех n! перестановок вычитаем те, где хотя бы одно
письмо на месте (множество Aᵢ — «i-е письмо в своём конверте»). В коде удобна рекуррента
`D(n) = (n−1)·(D(n−1) + D(n−2))` c базой `D(0) = 1, D(1) = 0`: она целочисленная и без
факториалов. Факт для интуиции: при случайной раздаче писем примерно в 37 % случаев никто не
получит своё — и эта доля почти не зависит от n.

## ⚡ Что помнить на собеседовании

- **Порядок важен?** Да → размещение `A(n,k)`; нет → сочетание `C(n,k) = A(n,k)/k!`; все
  элементы и порядок → `n!`.
- **C(n, k)** — итеративно: `res = res * (n−k+i) / i`, `k = min(k, n−k)`; никаких факториалов.
- **Рекуррента Паскаля** `C(n,k) = C(n−1,k−1) + C(n−1,k)` — «брать / не брать»; таблица по
  ней — способ считать по модулю.
- **«Хотя бы одно из»** → включение-исключение: знак по чётности размера подмножества,
  перебор подмножеств — битмаской.
- **Прикидка перед перебором**: `2²⁰ ≈ 10⁶`, `10! ≈ 3,6·10⁶`, `20! ≈ 2,4·10¹⁸`. Если
  пространство больше ~10⁸ — перебор не взлетит, ищи формулу или ДП.

## 🧠 Почему это корректно

### Рекуррента Паскаля: разбор по последнему элементу

Все k-элементные подмножества {1..n} делятся на два непересекающихся класса: содержащие
элемент n и не содержащие. Первых столько, сколько способов добрать k−1 из оставшихся n−1 —
`C(n−1, k−1)`; вторых — `C(n−1, k)`. Классы не пересекаются и вместе покрывают всё, значит,
по правилу суммы `C(n,k) = C(n−1,k−1) + C(n−1,k)`. Это тот же аргумент, которым мы
обосновывали полноту перебора «взять / пропустить» в [Subsets](subsets.md), — только теперь
он складывает количества, а не строит списки.

### Почему `res * (n−k+i) / i` делится нацело

После каждого шага цикла в `res` лежит какое-то `C` — а `C` это количество способов, то есть
целое число. Поэтому деление на `i` на каждом шаге проходит нацело, без остатка
(например, для `C(5, 2)`: `1·4/1 = 4`, затем `4·5/2 = 10`).

## ⚙️ Цена на практике

### Комбинаторный взрыв в числах

Прикидка при 10⁸ операций в секунду (порядок машинной скорости для простого тела цикла):

| n | 2ⁿ | n! | C(n, n/2) |
|---|---|---|---|
| 10 | 1024 — мгновенно | 3,6·10⁶ — 0,04 с | 252 — мгновенно |
| 20 | ≈10⁶ — 0,01 с | 2,4·10¹⁸ — ~770 лет | 1,8·10⁵ — мгновенно |
| 30 | ≈1,1·10⁹ — ~11 с | 2,7·10³² — ∞ | 1,6·10⁸ — ~1,6 с |
| 40 | ≈1,1·10¹² — ~3 ч | 8,2·10⁴⁷ — ∞ | 1,4·10¹¹ — ~23 мин |

Отсюда рабочие пороги: перебор `2ⁿ` допустим при **n ≤ 20–25**, перебор `n!` — при
**n ≤ 10–11**, `C(n, n/2)` живёт заметно дольше, но к n = 40 тоже умирает. Факториал
обгоняет любую экспоненту: с ростом n на единицу `2ⁿ` удваивается, а `n!` умножается на n.
Эта таблица — самый дешёвый профилировщик: одна строка арифметики до кода вместо часа
ожидания после.

### Число пар — скрытая квадратичность

`C(n, 2) = n(n−1)/2` — количество пар — встречается чаще всех остальных формул: пары
серверов в full-mesh, пары значений, способные дать коллизию хеша, пары строк при
дедупликации «каждый с каждым». Рост квадратичный: 1000 узлов — полмиллиона пар, 10⁶ значений
— полтриллиона потенциальных коллизий. Именно счёт пар объясняет парадокс дней рождения —
почему коллизии наступают «неожиданно рано», уже при n порядка корня из размера
пространства значений; подробно разберём в главе [Вероятность](probability.md).

### Когда счёт не спасает

Формулы отвечают «сколько», но если по условию нужно **вывести** все варианты — платить
размер вывода придётся в любом случае, и это нижняя граница генерации из
[Backtracking](backtracking.md). Комбинаторика здесь всё равно полезна: посчитай размер
вывода заранее и реши, не сломает ли он память и канал.

## ⚠️ Типичные ошибки

1. **`C(n,k)` через факториалы** — `n!` переполняется уже при n = 21, хотя ответ маленький.
   Только итеративно с делением на каждом шаге или таблицей Паскаля.
2. **Спутаны размещения и сочетания** — не спросил «важен ли порядок?». Капитан и вратарь —
   размещение (110), пара игроков — сочетание (55). Разница ровно в k!.
3. **Знак в включении-исключении** — «плюс при нечётном размере подмножества, минус при
   чётном»; перепутанная чётность или пропущенное подмножество дают тихо неверный ответ.
   Проверяй на крошечном примере руками (n = 30, {2, 3} → 20).
4. **Переполнение НОК в включении-исключении** — `lcm` подмножества делителей растёт как
   произведение; если `lcm > n`, вклад нулевой — обрывай ветку до умножения.
5. **Перемножение вероятностей зависимых событий** — правило произведения требует
   независимости и для количеств, и для вероятностей. «Каждый из n сервисов падает с
   вероятностью p, значит все сразу — pⁿ» верно только для независимых отказов; общая стойка
   питания эту арифметику отменяет. Подробнее — в главе [Вероятность](probability.md).

## 📝 Разбор задачи: Unique Paths

> **Задача** ([LeetCode 62](https://leetcode.com/problems/unique-paths/)).
> Робот в углу сетки m×n ходит только вправо и вниз. Сколько путей до противоположного угла?
> Пример: m = 3, n = 7 → 28.

**Шаг 1. Перебор.** DFS по двум веткам «вправо / вниз» — корректно, но путей
экспоненциально много: для 20×20 перебор не закончится.

**Шаг 2. ДП.** `dp[i][j] = dp[i−1][j] + dp[i][j−1]` — в клетку приходят сверху или слева.
`O(m·n)` — уже хорошо. Присмотрись к рекурренте: это в точности треугольник Паскаля,
записанный по сетке.

**Шаг 3. Счёт.** Любой путь — это последовательность из `m−1` шагов вниз и `n−1` шагов
вправо, всего `m+n−2` шагов. Путь однозначно задаётся выбором, **какие** из шагов — вниз:

```go
func uniquePaths(m, n int) int {
    return Binomial(m+n-2, m-1) // C(8, 2) = 28 для 3×7
}
```

`O(min(m, n))` времени, `O(1)` памяти. Типичная лестница этой главы: перебор → ДП → формула;
каждая ступень убирает целый класс работы, потому что вопрос был «сколько», а не «какие».

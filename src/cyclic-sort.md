# Cyclic Sort (Циклическая сортировка)

## Теория

**Cyclic Sort** — сортировка массива на месте, когда числа лежат в известном
диапазоне (обычно от 1 до N). Алгоритм использует то, что число `x` должно стоять на
позиции `x - 1` (для диапазона 1..N) или на позиции `x` (для 0..N-1).

Каждый элемент за один цикл перестановок «отправляется» на своё место. Поскольку
после размещения элемент больше не двигается, всего происходит не более N перестановок —
это даёт **O(n)** времени и **O(1)** памяти.

**Когда применять:**

- массив содержит числа в диапазоне 1..N (или 0..N-1);
- нужна сортировка на месте без дополнительной памяти;
- требуется найти отсутствующее, дублирующееся или неправильно расположенное число.

## Алгоритм

Идём по массиву индексом `i`. Если `nums[i]` не на своём месте — меняем его с
элементом на правильной позиции и **не** увеличиваем `i` (нужно проверить новый
элемент). Если на месте — переходим дальше.

```go
func cyclicSort(nums []int) {
    i, n := 0, len(nums)
    for i < n {
        v := nums[i]
        // Guard: значение вне [1, n] нельзя поставить на «свою» позицию — пропускаем
        if v < 1 || v > n {
            i++
            continue
        }
        correctPos := v - 1 // число x должно стоять на индексе x-1
        if nums[i] != nums[correctPos] {
            nums[i], nums[correctPos] = nums[correctPos], nums[i]
            // i не увеличиваем — на позиции i теперь новый элемент
        } else {
            i++
        }
    }
}
```

Сравнение `nums[i] != nums[correctPos]` (а не `i != correctPos`) защищает от
бесконечного цикла на дубликатах: если на целевой позиции уже такое же значение,
обмен бессмыслен — двигаемся дальше.

После сортировки легко найти первое число, стоящее не на своём месте, — это и есть
отсутствующее (или лишнее).

```go
func findMissingNumber(nums []int) int {
    cyclicSort(nums)
    for i := 0; i < len(nums); i++ {
        if nums[i] != i+1 {
            return i + 1
        }
    }
    return len(nums) + 1 // все числа 1..n на месте
}
```

### Сложность

| Случай       | Время | Память |
|--------------|-------|--------|
| Любой        | O(n)  | O(1)   |

Cyclic Sort всегда линеен: каждый элемент перемещается максимум один раз на своё
место, перестановка стоит O(1).

## Визуализация

Сортировка `[3, 1, 5, 4, 2]`, диапазон [1, 5]. Правило: число `x` → индекс `x - 1`.

```
[3, 1, 5, 4, 2]  i=0: 3→поз.2, swap с nums[2]=5
[5, 1, 3, 4, 2]  i=0: 5→поз.4, swap с nums[4]=2
[2, 1, 3, 4, 5]  i=0: 2→поз.1, swap с nums[1]=1
[1, 2, 3, 4, 5]  i=0: 1 на месте → i++
[1, 2, 3, 4, 5]  i=1..4: все на местах → i++
```

Пока `nums[0]` не встал на место, индекс `i` не двигается — отсюда «циклические»
перестановки. Результат: `[1, 2, 3, 4, 5]`.

## Типичные ошибки

1. **Неверная формула позиции** — для диапазона 1..N это `x-1`, для 0..N-1 это `x`.
2. **Бесконечный цикл на дубликатах** — сравнивайте *значения*
   (`nums[i] != nums[correctPos]`), а не индексы.
3. **Выход за границы** — добавляйте guard для значений вне `[1, n]`, иначе
   `nums[v-1]` упадёт.
4. **Увеличение `i` после обмена** — после swap на позиции `i` стоит новый элемент,
   его тоже нужно проверить; `i++` только когда элемент уже на месте.
5. **Не обработан пустой массив** — цикл `i < n` это покрывает, но проверьте, что
   постобработка (поиск пропуска) не падает на пустом входе.

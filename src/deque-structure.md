> 🧭 **Зачем отдельная глава.** Дек (double-ended queue) — это последовательность, у которой
> **оба конца** работают за O(1): можно класть и снимать и спереди, и сзади. Стек (один конец) и
> очередь (с разных концов) — его частные случаи. Главное прикладное применение — **монотонный
> дек**: он решает «максимум в скользящем окне» за O(n) (см. [скользящее окно](sliding-window.md)).

## 🧱 Как устроено

Дек — это последовательность с двумя «рабочими» концами: **перёд** (front) и **зад** (back).
Логически это ряд элементов; физически — кольцевой буфер или двусвязный список, чтобы оба конца
были дёшевы.

```go
type Deque struct {
    data []int // концептуально; для O(1) с обоих концов — кольцевой буфер
}

func (d *Deque) PushBack(x int)  { d.data = append(d.data, x) }
func (d *Deque) PushFront(x int) { d.data = append([]int{x}, d.data...) }
func (d *Deque) PopBack() int    { n := len(d.data) - 1; x := d.data[n]; d.data = d.data[:n]; return x }
func (d *Deque) PopFront() int   { x := d.data[0]; d.data = d.data[1:]; return x }
```

```
PushFront ↓                      ↓ PushBack
PopFront  ↑                      ↑ PopBack
        ◀ перёд [ 0 | 1 | 2 | 3 ] зад ▶
```

Три факта, которые держат всё:

1. **Оба конца равноправны.** В отличие от стека (один конец) и очереди (вход с одного, выход с
   другого), дек кладёт и снимает с любого конца — это его суперсила.
2. **O(1) требует правильного физического представления.** На срезе `PushBack` дёшев, а
   `PushFront` сдвигает всё — O(n). Настоящий дек — это **кольцевой буфер** (два индекса
   head/tail по модулю) или **двусвязный список**, где оба конца — O(1).
3. **Монотонный дек — главное применение.** Если держать в деке только «полезные» элементы в
   отсортированном порядке, его передний конец мгновенно даёт максимум/минимум текущего окна.

## 🔁 Операции с обоих концов

Четыре операции, все O(1) при правильном представлении: добавить/снять спереди и сзади.

> 💡 **Демонстрация операций.** Последовательность: `PushBack 1, 2, 3` → `PushFront 0` →
> `PopBack` → `PopFront`. Видно, как элементы появляются и уходят с разных концов. Зелёный —
> только что добавленный, янтарный (зачёркнут) — снимаемый. Подставь свою последовательность
> (`b`N = PushBack, `f`N = PushFront, `B` = PopBack, `F` = PopFront).

## 🧠 Почему это корректно

### Почему оба конца за O(1) — но только с кольцевым буфером

Кольцевой буфер хранит элементы в массиве и два индекса — `head` и `tail` — которые двигаются по
модулю размера. `PushFront` сдвигает `head` назад (по кругу), `PushBack` двигает `tail` вперёд;
никакого сдвига элементов нет, поэтому все четыре операции — O(1). Двусвязный список достигает
того же через указатели на оба конца. **Срез же** даёт O(1) только сзади: `PushFront`/`PopFront`
двигают начало и вынуждены копировать — O(n) (код выше нагляден, но не оптимален).

### Стек и очередь — частные случаи

Используя только один конец (`PushBack` + `PopBack`), дек становится **стеком** (LIFO). Используя
`PushBack` + `PopFront` — **очередью** (FIFO). Поэтому дек — обобщение обоих, и любой алгоритм на
стеке или очереди можно выразить через дек.

### Почему монотонный дек даёт максимум окна за O(n)

В задаче «максимум скользящего окна» дек хранит **индексы** элементов по убыванию значений. При
добавлении нового элемента справа выбрасываем с заднего конца всех, кто меньше его (они уже
никогда не будут максимумом), а слева снимаем индексы, вышедшие за окно. Тогда **передний конец —
всегда максимум окна**. Каждый индекс входит и выходит из дека один раз → суммарно O(n).

## ⚙️ Цена на практике

### Кольцевой буфер против двусвязного списка

- **Кольцевой буфер:** массив + два индекса, плотная память, дружелюбно к кэшу; минус — при
  переполнении нужно перевыделение (как у динамического массива).
- **Двусвязный список:** O(1) вставка/удаление без перевыделений, но указатели (память, промахи
  кэша). На практике кольцевой буфер обычно быстрее.

### В Go нет готового дека — но есть `container/list`

Стандартная библиотека Go даёт `container/list` (двусвязный список) — на нём дек строится прямо.
Для производительности часто пишут свой кольцевой буфер. Срез использовать можно, но помни: дешёвы
только операции с конца; для частых `PushFront` это O(n) на операцию.

### Дек как стек И очередь

Раз дек обобщает оба, одна реализация закрывает три структуры. Но если нужен **только** стек или
**только** очередь — бери их (или просто срез): меньше кода и накладных расходов, чем у полного
дека.

## ⚠️ Типичные ошибки

1. **`PushFront`/`PopFront` через срез** — это O(n) (сдвиг), а не O(1); для двустороннего дека нужен кольцевой буфер.
2. **Pop из пустого дека** — проверяй длину, иначе паника на `data[0]` / `data[n-1]`.
3. **Монотонный дек: хранить значения, а не индексы** — без индексов не понять, вышел ли элемент за окно.
4. **Перепутать концы** — для очереди вход и выход на разных концах; ошибка превращает её в стек.
5. **Забыть снять устаревшие** с переднего конца в монотонном деке — максимум будет вне окна.

## 🏋️ Тренажёр

Реализуй сам дек на кольцевом буфере — в нём вся соль: обёртка индексов через границу и рост
буфера без потери порядка.

```bash
cd exercises
go test ./deque/                 # ваша реализация (красные)
go test -tags solution ./deque/  # эталон (зелёные)
```

Пакет `deque`: `NewDeque`, `PushFront`/`PushBack`/`PopFront`/`PopBack`/`Front`/`Back`/`Len`,
амортизированно O(1) с обоих концов. Подумай, почему «голова −1» берётся по модулю ёмкости и зачем
при росте перекладывать элементы в начало нового буфера.

> 📌 В тренажёре `Pop*`/`Front`/`Back` возвращают `(значение, ok bool)`, а не паникуют на пустом
> деке, как упрощённый `PopBack() int` выше. Конструктор — `NewDeque()`.

Монотонный дек — отдельная техника поверх этой структуры; он в задаче о максимуме скользящего окна:

```bash
go test ./slidingwindow/   # MaxSlidingWindow — монотонный дек
```

## 🧭 Откуда берётся ДП: выведем его сами

Четыре слова из «Запомни» — «состояние, переход, база, порядок» — не заклинание, которое надо
зазубрить. Это то, что **остаётся от обычной рекурсии, если запретить ей переспрашивать**.
Проследим на живой задаче — и дальше вся глава будет читаться сама.

> **Задача (House Robber).** Вдоль улицы — дома с деньгами `nums`. Нельзя брать два соседних.
> Какой максимум можно унести?

Начнём, как рассуждает человек, а не учебник: **какой у меня выбор?** Смотрю на дома `0..i`
и решаю про последний из них, дом `i`. Вариантов ровно два:

- **пропустить** его → остаётся та же задача для домов `0..i-1`;
- **взять** `nums[i]` → сосед `i-1` под запретом, остаётся та же задача для домов `0..i-2`.

```go
// f(i) — максимум добычи с домов 0..i
func f(i int) int {
    if i < 0 {
        return 0                        // домов нет
    }
    return max(f(i-1), nums[i]+f(i-2))  // пропустить или взять
}
```

Это честная рекурсия ([база + шаг](recursion.md)), и она уже **содержит всё ДП** — кроме одной
беды: она экспоненциальна. Посчитаем вызовы на пяти домах, `f(4)`. `f(2)` зовут и `f(4)`, и
`f(3)`; `f(1)` — три раза, `f(0)` — пять, а до пустых `f(-1)` и `f(-2)` доходим 13 раз. Всего
**25 вызовов**, а разных вопросов про дома — пять: «максимум с домов `0..i`» для `i` от 0 до 4.
На тридцати домах вызовов уже **4 356 617** — ради тридцати вопросов. Дерево ветвится, как у
наивного Фибоначчи из главы о рекурсии.

Запретим переспрашивать: заведём таблицу `memo`, где у каждого вопроса записан ответ, а `-1`
значит «ещё не спрашивали». Функция та же, добавились две строки — проверка и запись:

```go
var memo []int // len(nums) ячеек, все -1 перед первым вызовом

func f(i int) int {
    if i < 0 {
        return 0
    }
    if memo[i] != -1 {
        return memo[i] // уже отвечали — не спрашиваем снова
    }
    memo[i] = max(f(i-1), nums[i]+f(i-2))
    return memo[i]
}
```

Теперь каждый вопрос считается один раз, а повтор берёт готовое из таблицы: на пяти домах
**11 вызовов**, на тридцати — **61**. Это уже ДП — **сверху вниз** (мемоизация): порядок
ответов выбирает сама рекурсия. **Снизу вверх** (табуляция) — то же без рекурсии: ты сам идёшь
от меньших вопросов к большим циклом, стека вызовов нет, и видно, какие ячейки уже можно
выбросить.

Дальше таблицу ответов назовём `dp`: `dp[i]` — то же, что `memo[i]` и `f(i)`. Четыре слова из
«Запомни» — это части уже написанного кода:

| Слово | Что это в нашей рекурсии |
|---|---|
| **Состояние** `dp[i]` | сам ВОПРОС: «максимум добычи с домов `0..i`» |
| **Переход** | её строка выбора: `dp[i] = max(dp[i-1], nums[i] + dp[i-2])` |
| **База** | её условие выхода: до начала массива добыча 0 |
| **Порядок** | отвечать от меньших вопросов к большим — слева направо, чтобы `dp[i-1]` был готов раньше `dp[i]` |

Отсюда и сложность любой задачи на ДП. **Число состояний** — сколько разных вопросов, то есть
ячеек в таблице: здесь их `n`, по одной на дом. **Цена перехода** — работа на одну ячейку: здесь
максимум из двух готовых чисел, `O(1)`. Время — ячейки × работа на ячейку: `n · O(1) = O(n)`.
В размене монет ячейка на каждую сумму от `0` до `amount` (суммы, которую надо набрать), а на каждую перебираются все `k`
монет — `O(amount · k)`; в двумерных задачах таблица `n × m` — `O(n · m)`.

**ДП — это рекурсия, у которой отобрали право переспрашивать.** Рецепт всегда один: напиши
наивную рекурсию через «какой у меня выбор?» → убедись, что её вопросы повторяются → заведи
таблицу по вопросу. Цикл снизу вверх для этой задачи, свёрнутый до двух переменных, и его
трасса — в [«📝 Разборе задачи»](#-разбор-задачи) ниже; а виджет сразу за этим разделом
переносит тот же приём на новую задачу — размен монет (Coin Change: наименьшее число монет на
сумму `amount`).

## 🎬 Визуализация

> 💡 **Интерактивная демонстрация (пошаговый дебаг Coin Change).** Для каждой суммы `a` перебирается
> каждая монета `c`. Зелёная рамка и плашка `a` — сумма, которую считаем; голубая рамка — остаток
> `dp[a−c]`. Дуга над ними — сам переход «положить монету `c` последней»: сплошная, если вариант
> лучше прежних, пунктирная — если нет. Под массивом — монеты (текущая жёлтая) и все варианты для
> суммы `a` списком: сразу видно, из чего выбирается минимум. Под холстом — строка шага и переменные (`a`, `c`, `dp[a−c]`, `best`, `dp[a]`), ниже — код с подсветкой строки. Можно подставить свои монеты и `amount`.

## ⚡ Шаблон для собеседования

Тот же вывод для Coin Change, в одну строку рассуждения: вопрос (состояние) — «минимум монет на
сумму `a`»; выбор — **какая монета последняя**: если последней была монета `c`, то до неё была
собрана сумма `a−c`, и вопрос стал меньше. Отсюда переход `dp[a] = min(dp[a−c] + 1)` по всем `c`:

```go
// Coin Change: dp[a] = минимум монет на сумму a
const INF = 1 << 30 // «набрать нельзя»; почему не MaxInt — в «⚙️ Цене на практике»
dp := make([]int, amount+1)
for a := 1; a <= amount; a++ {
    dp[a] = INF
    for _, c := range coins {
        if c <= a && dp[a-c]+1 < dp[a] {
            dp[a] = dp[a-c] + 1 // переход через меньшую сумму
        }
    }
}
// dp[amount] — ответ; если он >= INF, набрать нельзя (по условию LeetCode верни -1)
```

1. состояние `dp[a]` — ответ для суммы `a`;
2. база `dp[0] = 0`;
3. переход: пробуем каждую монету `c`, `dp[a] = min(dp[a], dp[a-c]+1)`;
4. идём от меньших сумм к большим.

## 📖 Разбор: примеры (1D / 2D / рюкзак) и сложность

ДП разбивает задачу на **перекрывающиеся подзадачи** и сохраняет их результаты. Нужны
два свойства: перекрывающиеся подзадачи и оптимальная подструктура (лучший ответ собирается из
лучших ответов меньших подзадач — как в [жадной главе](greedy.md#-разбор)). Два способа запретить
переспрашивать — мемоизация и табуляция — уже показаны на домах в «🧭», одномерный Coin Change
целиком — в [«⚡ Шаблоне»](#-шаблон-для-собеседования). Ниже тот же вопрос «какой выбор у
последнего?» — на двух строках и на рюкзаке.

#### 2D ДП: Longest Common Subsequence

Двумерность не меняет рецепта — только вопрос теперь про **две** строки: найти **LCS**
(longest common subsequence) — самую длинную общую подпоследовательность. Состояние `dp[i][j]` —
«LCS первых `i` символов `a` и первых `j` символов `b`». Выбор подсказывают **последние символы**:

- **совпали** (`a[i−1] == b[j−1]`) — брать этот символ в ответ никогда не хуже. Возьми любую
  самую длинную общую подпоследовательность и посмотри, с какими позициями строк сопоставлены её
  буквы. Не задействованы ни `a[i−1]`, ни `b[j−1]` — их пару можно дописать, выйдет длиннее самой
  длинной, так не бывает. Задействован один, скажем `a[i−1]`, — он последний в ответе и
  сопоставлен с буквой `b` левее `b[j−1]`; переставь пару на `b[j−1]`: буква та же, длина та же.
  Задействованы оба — они уже сопоставлены друг с другом, иначе пары пересеклись бы. Поэтому
  приклеиваем символ к LCS обеих строк **без** последних символов. Отсюда диагональ: `dp[i−1][j−1] + 1`;
- **не совпали** — вместе им в общем ответе не бывать, значит один из двух лишний. Пробуем выкинуть
  последний символ `a` (это `dp[i−1][j]`) или последний символ `b` (это `dp[i][j−1]`) — и берём максимум.

Вот и вся рекуррента; таблица ниже просто отвечает на эти вопросы в правильном порядке.

> 💡 **Интерактивная демонстрация (LCS, 2D-таблица).** Таблица `dp[i][j]` заполняется по
> строкам слева направо. Синяя ячейка — текущая `dp[i][j]`; фиолетовая — **источник** перехода:
> при совпадении символов берётся **диагональ** `dp[i-1][j-1]+1`, иначе **максимум** из верхней и
> левой (бледная — отвергнутый кандидат). Заголовки таблицы — сами буквы: строка `i` подписана
> `a[i-1]`, столбец `j` — `b[j-1]`. Буквы текущей строки и столбца подчёркнуты синим, на шаге сравнения
> загораются зелёным (совпали) или красным. Последний шаг — обратный ход: жёлтые рамки ведут от
> ответа к краю таблицы, буквы ответа в заголовках обведены жёлтым, а карточка под таблицей называет
> саму подпоследовательность. Под холстом — строка шага и переменные, ниже — код с подсветкой строки.
> Можно подставить свои строки.

<div class="algo-viz" data-viz="dp-lcs" data-a="AGCAT" data-b="GAC"></div>

```go
func lcs(a, b string) int {
    m, n := len(a), len(b)
    dp := make([][]int, m+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
    }
    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            if a[i-1] == b[j-1] {
                dp[i][j] = dp[i-1][j-1] + 1
            } else {
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
            }
        }
    }
    return dp[m][n]
}
```

#### 2D ДП: Edit Distance — те же две строки, другой вопрос

**Edit Distance** (LeetCode 72, «расстояние Левенштейна») — наименьшее число правок, которое
превращает строку `a` в строку `b`. Правка — одна из трёх: **вставить** символ, **удалить** символ,
**заменить** символ другим. Так считают «похожесть» строк: подсказка «возможно, вы имели в виду…»,
сравнение ДНК.

Состояние — как у LCS, по префиксам обеих строк: `dp[i][j]` — сколько правок нужно, чтобы первые
`i` символов `a` стали первыми `j` символами `b`. И снова смотрим на **последние символы**
`a[i−1]` и `b[j−1]`:

- **совпали** — их трогать незачем, правок столько же, сколько без них: `dp[i−1][j−1]`;
- **не совпали** — последней правкой было что-то одно из трёх, и каждое оставляет задачу поменьше:
  - **заменить** `a[i−1]` на `b[j−1]` — теперь последние совпали, остаётся превратить первые `i−1`
    символов `a` в первые `j−1` символов `b`: `1 + dp[i−1][j−1]` (диагональ);
  - **удалить** `a[i−1]` — остаются первые `i−1` символов `a`, а цель прежняя, все `j` символов `b`:
    `1 + dp[i−1][j]` (клетка сверху);
  - **вставить** в конец `b[j−1]` — последний символ цели закрыт, осталось превратить все `i`
    символов `a` в первые `j−1` символов `b`: `1 + dp[i][j−1]` (клетка слева);

  берём наименьшее из трёх.

**База** — пустая строка. Превратить `i` символов в пустую строку — удалить все: `dp[i][0] = i`.
Из пустой строки получить `j` символов — вставить все: `dp[0][j] = j`. Поэтому, в отличие от LCS,
нулевые строка и столбец таблицы — не нули, а `0, 1, 2, 3…`.

Таблица для `a = "horse"`, `b = "ros"` (строки — префиксы `a`, столбцы — префиксы `b`; числа
посчитаны эталоном `dp.EditDistance`):

|          | `""` | `r` | `o` | `s` |
|----------|-----:|----:|----:|----:|
| **`""`** | 0    | 1   | 2   | 3   |
| **`h`**  | 1    | 1   | 2   | 3   |
| **`o`**  | 2    | 2   | 1   | 2   |
| **`r`**  | 3    | 2   | 2   | 2   |
| **`s`**  | 4    | 3   | 3   | 2   |
| **`e`**  | 5    | 4   | 4   | 3   |

Две клетки руками. `dp[1][1]` (`h` против `r`): символы разные, кандидаты — замена `1 + dp[0][0] = 1`,
удаление `1 + dp[0][1] = 2`, вставка `1 + dp[1][0] = 2`; наименьший — 1. `dp[2][2]` (`ho` против
`ro`): последние `o` совпали — берём диагональ `dp[1][1] = 1`. Ответ — правый нижний угол, 3:
`horse → rorse` (заменить `h` на `r`), `rorse → rose` (удалить `r`), `rose → ros` (удалить `e`).

**Связь с LCS.** Та же таблица по префиксам и та же диагональ при совпадении, только LCS
**максимизирует** совпавшие символы, а Edit Distance **минимизирует** правки; если бы замены не было
(только вставки и удаления), ответ был бы ровно `m + n − 2·LCS` — для `horse`/`ros` это
`5 + 3 − 2·2 = 4`.

Код писать тебе — это функция `EditDistance` тренажёра (виджет «Реши прямо здесь» внизу главы):
по форме он повторяет `lcs` выше, отличаются база и строка перехода.

#### 0/1 Рюкзак

Состояние `dp[i][w]` — максимальная ценность из первых `i` предметов при вместимости `w`.
Переход — снова вопрос «какой выбор у последнего?», здесь — у предмета `i`:

- **не берём** его → вся ценность набирается первыми `i−1` предметами при той же вместимости:
  `dp[i−1][w]`;
- **берём** (если влезает: `weight[i] ≤ w`) → его ценность плюс лучший ответ для первых `i−1`
  предметов при вместимости, **уменьшенной на его вес**: `dp[i−1][w−weight[i]] + value[i]`.

Оба кандидата — уже посчитанные меньшие состояния; берём максимум:
`dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])`.
Таблицу можно свернуть в одну строку — но с условием на порядок, о нём абзац под виджетом.

> 💡 **Интерактивная демонстрация (0/1 рюкзак).** Строки — предметы (`вес·ценность`), столбцы —
> вместимость `0..W` (в виджете она `c`, а не `w`). Синяя ячейка — текущая `dp[i][c]`; фиолетовые — два источника выбора: «не
> брать» (`dp[i-1][c]`, прямо сверху) и «взять» (`dp[i-1][c-вес]+ценность`); бледная — отвергнутый
> вариант. Если предмет не влезает — берётся только верх. Можно подставить свои предметы и `W`.

<div class="algo-viz" data-viz="knapsack" data-items="1-1,3-4,4-5,5-7" data-capacity="7"></div>

**Свёрнутый рюкзак.** Каждая строка таблицы читает только предыдущую, поэтому вместо таблицы
хватит одной строки `dp[w]`, которую каждый предмет переписывает на месте. Когда считаем
`dp[w]`, ячейка `dp[w − вес]` должна ещё хранить значение **прошлой** строки — «без этого
предмета». Идём по `w` справа налево — так и есть: до ячеек левее мы ещё не дошли. Идём слева
направо — `dp[w − вес]` уже обновлена, предмет в ней уже лежит, и мы кладём его второй раз.
Проверь на числах: один предмет (вес 1, ценность 1), рюкзак 3. Слева направо строка выходит
`[0, 1, 2, 3]` — предмет взят трижды. Справа налево — `[0, 1, 1, 1]`: один раз, как и положено.

```go
dp := make([]int, W+1) // dp[w] — лучшая ценность при вместимости w
for i := range weight {
    for w := W; w >= weight[i]; w-- { // справа налево: левее — ещё прошлая строка
        dp[w] = max(dp[w], dp[w-weight[i]]+value[i])
    }
}
```

Порядок циклов решает и в **Coin Change II** (LeetCode 518) — числе способов набрать сумму, где
`dp[s] += dp[s−c]`. База тут другая, чем в Coin Change: `dp[0] = 1` — сумму 0 набирает ровно
один способ, пустой набор; с `dp[0] = 0` к нулю нечего прибавлять, и все `dp` останутся нулями.
У минимума монет база `0` — это число монет, а у подсчёта база `1` — это число способов. Монеты
`{1, 2, 5}`, сумма 5: цикл по монетам **снаружи** даёт 4 набора, а цикл по сумме снаружи — 9,
потому что `1+2+2`, `2+1+2` и `2+2+1` сосчитаны как разные.

Внутренний цикл по сумме здесь идёт **слева направо**: монету можно брать сколько угодно раз, и
«второй раз» из свёрнутого рюкзака — ровно то, что нужно. А монеты снаружи дают порядок: пока
идёт монета 2, в `dp[s−2]` лежат наборы только из единиц и двоек, и новая двойка всегда встаёт
последней — каждый набор считается один раз, монетами по неубыванию. Пройди суммы справа налево —
и каждая монета возьмётся не больше раза: на тех же `{1, 2, 5}` и 5 выйдет 1 набор (`5`) вместо 4.

Рюкзак отвечает и на вопрос «можно ли». Разбить массив на две части с равными суммами (416) —
значит найти подмножество с суммой ровно половины: остальные числа и есть вторая часть, а при
нечётной сумме ответ сразу «нет». Это рюкзак вместимостью в полсуммы, где вес предмета — само число, а вместо ценности —
да/нет: «набирается ли вес `w`». База — `dp[0] = true` по той же причине, что `1` у подсчёта:
пустой набор набирает 0. На `[1, 5, 11, 5]` сумма 22, половина 11 набирается — `11` или `1 + 5 + 5`.

#### Тот же вопрос в задачах практики

У задач практики, которых не было выше, — своё состояние и свой «последний выбор». Два
одномерных — открыто:

- **Min Cost Climbing Stairs** (746: за ступень `i` платят `cost[i]`, стартовать можно с 0 или 1,
  цель — встать выше последней): `dp[i]` — минимальная цена, чтобы встать на ступень `i`;
  на неё пришли с `i−1` или с `i−2` и заплатили за ту ступень; `dp[0] = dp[1] = 0`. `ClimbStairs` — то же со
  сложением (сколькими способами подняться на `n` ступеней шагами по 1 и 2):
  `dp[n] = dp[n−1] + dp[n−2]`, `dp[0] = 1`.
- **Maximum Subarray** (53, Кадане): `cur` — лучшая сумма куска, кончающегося здесь; выбор —
  продлить прошлый кусок или начать новый с текущего числа. Ответ — лучший `cur` за проход;
  тот же ответ через префиксы — в [«Префиксных суммах»](prefix-sums.md#кадане--вернись-после-главы-о-дп).

У остальных задач тренажёра и добивки — тоже свой вопрос и свой последний выбор; сначала
сформулируй их сам. Подсказки ниже — в две ступени: открывай вторую, только если первая не помогла.

<details class="algo-details">
<summary>Если застрял, ступень 2: состояние и переход</summary>

- **`LongestIncreasingSubsequence`**: `dp[i]` — длина самой длинной возрастающей подпоследовательности,
  кончающейся на `nums[i]`; предпоследним стоит любой `j < i` с `nums[j] < nums[i]`. Это `O(n²)`; `O(n log n)`
  — бинарный поиск, сверх главы.
- **`UniquePaths`** (сколько путей из левого верхнего угла сетки в правый нижний ходами вправо
  и вниз): в клетку пришли сверху или слева, `dp[i][j] = dp[i−1][j] + dp[i][j−1]`.
- **`WordBreak`** (можно ли разрезать строку на слова словаря): `dp[i]` — разбивается ли префикс длины `i`; последнее слово — `s[j:i]` из
  словаря при `dp[j]`, `dp[0] = true`.
- **`DeleteAndEarn`**: взял одно `x` — бери все `x`, их соседи уже сгорели. Сложи очки по значениям
  (`v` × число повторов `v`) и иди по значениям `1, 2, 3, …`: `dp[v]` — лучший счёт, если решать только
  про значения до `v`. Последний выбор — брать `v` или нет, а взять `v` можно, только если `v−1` не взято.
- **Decode Ways** (91; цифры читают как буквы `A = 1` … `Z = 26`): `dp[i]` — способов прочесть первые `i` цифр; последняя буква — одна
  цифра (не `0`) или две (от 10 до 26).
- **Longest Palindromic Substring** (5): `dp[i][j]` — палиндром ли кусок `s[i..j]`: крайние
  символы равны и середина — палиндром; заполнять по возрастанию длины куска.

</details>

#### Карта классов ДП: какое состояние брать

Самое трудное в новой задаче — назвать `dp[...]`. Задачи на ДП повторяют несколько **форм
состояния**, и форму обычно выдаёт само условие. Первые пять ты уже видел; последние три в книге
не разобраны — это **сверх главы**, ориентир на будущее, а не планка.

| Класс | Сигнал в условии | Состояние | Задача |
|---|---|---|---|
| Линейное | ответ для первых `i` элементов собирается из ответов для более коротких префиксов | `dp[i]` | House Robber (198) |
| Две последовательности | две строки или два массива: общее, выравнивание, «превратить одно в другое» | `dp[i][j]` — префиксы обеих | Edit Distance (72) |
| Сетка | ходы по клеткам вправо и вниз, путь в угол | `dp[r][c]` — клетка | Unique Paths (62) |
| Рюкзак | предметы с весом и лимит: вместимость, сумма, бюджет | `dp[i][w]` — предмет × вместимость, или одна строка `dp[w]` | Partition Equal Subset Sum (416) |
| На деревьях | ответ узла складывается из ответов детей | возврат `dfs(узел)` — см. диаметр в [«Обходе в глубину»](tree-dfs.md#-откуда-берётся-подсчёт-снизу-вверх-выведем-его-сами) | House Robber III (337) |
| Интервальное — сверх главы | отрезок `s[l..r]` сжимается с краёв или делится внутри на два | `dp[l][r]`, заполнять по возрастанию длины отрезка | Burst Balloons (312) |
| По маскам — сверх главы | надо выбрать порядок или распределить **всех**, а `n ≤ 20` | `dp[mask]` — какие элементы уже взяты | Minimum XOR Sum of Two Arrays (1879) |
| По состояниям — сверх главы | на каждом шаге ты в одном из нескольких режимов: держу акцию, не держу, отдыхаю | `dp[i][режим]` | Best Time to Buy and Sell Stock with Cooldown (309) |

Три незнакомых слова из нижних строк. **Интервальное**: ответ для куска `s[l..r]` выражается через
куски внутри него; у палиндрома из добивки (`dp[i][j]` — палиндром ли `s[i..j]`) ровно такая форма.
**Маска** — целое число, у которого `k`-й бит равен 1, если `k`-й элемент уже взят: `0b0101` — взяты
нулевой и второй. Всех подмножеств `2ⁿ`, и при `n = 20` это около миллиона состояний — отсюда
потолок `n ≤ 20` в условии как сигнал. **По состояниям** — к индексу добавляется режим, в котором ты
стоишь; переход — правило «из какого режима в какой можно перейти за шаг» (из «держу» продать —
и на день в «отдыхаю»).

## 🧠 Почему это корректно

ДП легко написать неверно: неполное состояние или неправильный порядок заполнения
дают тихо неправильный ответ. Корректность держится на двух предусловиях и одном
правиле порядка.

### Два предусловия — и что ломается без каждого

- **Оптимальная подструктура:** оптимум задачи строится из оптимумов подзадач. Без
  неё ДП даёт **неверный** ответ. Классический контрпример — «самый длинный *простой*
  путь в графе»: оптимальный путь не складывается из оптимальных подпутей. Пример —
  треугольник `A`, `B`, `C`. Самый длинный простой путь из `A` в `B` — `A→C→B`. Его кусок `A→C` —
  одно ребро, хотя самый длинный путь `A→C` — `A→B→C`; а приклеить к нему `C→B` нельзя: `B` уже
  пройдена. ДП тут неприменимо.
- **Перекрывающиеся подзадачи:** одни и те же подзадачи встречаются многократно. Без
  перекрытия ДП ничего не ускоряет — это просто «разделяй и властвуй».

### Состояние должно быть полным резюме

Рекуррента может быть корректной, **только если** состояние содержит всё, что влияет
на будущее. Самый частый баг — забытое измерение состояния. Попробуй рюкзак с одним
индексом: `dp[i]` — «лучшая ценность из первых `i` предметов». Переход не пишется: брать ли
предмет `i`, зависит от того, **сколько места осталось**, а состояние об этом молчит. Два
рюкзака с разным остатком места выглядят одинаково — значит, остаток обязан войти в
состояние: `dp[i][w]`. Если два разных будущих неразличимы по состоянию — состояние неполно,
и ответ поедет.

### Переход: наивная рекурсия → мемоизация → табуляция

Все три — **одна и та же рекуррента**, отсюда и корректность. На домах из «🧭»: **мемоизация** —
*та же* функция `f` плюс таблица `memo`. Корректна она потому, что вычисление идентично наивному:
кэш лишь убирает повторный счёт — 25 вызовов на пяти домах превращаются в 11, `O(n)`.
**Табуляция** (`rob` в «📝 Разборе задачи») переворачивает порядок: считаем подзадачи снизу
вверх и храним только нужное.

| Подход | Направление | Хранилище | Память | Когда удобнее |
|---|---|---|---|---|
| Наивная рекурсия | сверху вниз | — | O(глубины) | никогда (экспонента) — лишь как отправная точка мышления |
| Мемоизация | сверху вниз | кэш (`map`/массив) | O(состояний) | разреженные/сложные состояния; легко получить прямо из рекурсии |
| Табуляция | снизу вверх | таблица | O(состояний), часто **O(1)** со скользящим массивом (хранят лишь последние ячейки) | плотные состояния, нужен контроль порядка и памяти |

Путь почти всегда один: написал наивную рекурренту → навесил кэш (мемоизация) → при желании
развернул в цикл снизу вверх (табуляция) и ужал память.

> **Правило порядка для табуляции.** Подзадачи образуют ориентированный граф
> зависимостей (DAG). Заполнять надо в его **топологическом порядке** — каждое
> `dp[i]` после всех `dp[j]`, от которых оно зависит. В Coin Change это `i` по
> возрастанию (`dp[i]` зависит от `dp[i-c]`), в [свёрнутом рюкзаке](#01-рюкзак) `w` идёт
> **в обратную** сторону: там одна строка хранит две строки таблицы сразу, и порядок решает,
> какую из них прочитаешь. Перепутать порядок — взять предмет дважды или прочитать ещё не
> посчитанную ячейку.

## ⚙️ Цена на практике

### Сложность читается прямо из задачи

**Время ≈ (число состояний) × (стоимость перехода).** Это не формула для запоминания, а
способ оценить незнакомую задачу вслух на собеседовании: опиши состояние → посчитай,
сколько их → посчитай цену одного перехода → перемножь. Для LCS: `O(m·n)` состояний ×
`O(1)` переход = `O(m·n)`.

### Память: скользящий массив

Если `dp[i]` зависит только от пары последних ячеек (дома, лестница), а строка таблицы — только
от прошлой строки (рюкзак, LCS), весь массив не нужен — хватит одной-двух строк. `O(n)` →
`O(1)`, а 2D `O(m·n)` → `O(min(m, n))`. Это любимый дополнительный вопрос интервьюера: «а
можешь по памяти?».

### Мемоизация против табуляции — не только стиль

- **Мемоизация** (рекурсия + кэш): считает только **достижимые** состояния — выигрыш,
  когда их меньше, чем всех возможных. Минусы: накладные расходы на вызовы и **глубина
  стека** (риск переполнения на большой `n`).
- **Табуляция** (цикл + массив): быстрее (нет вызовов и хеширования), без риска стека,
  но считает **все** состояния и требует продумать порядок заполнения.

### Сторож «бесконечность» — `1<<30`, не `MaxInt`

Для «недостижимо» нужен INF, к которому **прибавляют** (`dp[i-c] + 1`). Если взять
`math.MaxInt`, то `+1` переполнится и станет отрицательным — сравнение сломается.
Бери `const INF = 1 << 30`: заведомо больше любого реального ответа, но с запасом до
переполнения.

> 🔧 **Где это в Go.** Обратный пример — тоже урок. Движки регулярных выражений многих языков
> перебирают варианты с возвратом, и на «злом» шаблоне такой перебор уходит в экспоненту: одна
> строка во входных данных может подвесить сервис (это называют ReDoS). Пакет
> [`regexp`](https://pkg.go.dev/regexp) в Go так **сознательно не делает**: он идёт по строке один
> раз и держит в уме все варианты сразу (подход библиотеки RE2) — гарантированно `O(len(input))`.
> Это то же «не пересчитывай заново», что у ДП, только возведённое в правило дизайна. А
> классическое ДП в инструментах разработчика — дифф: `git diff` ищет кратчайший способ превратить один файл в
> другой (алгоритм Майерса), и это родня LCS из этой главы.

## 🧾 Восстановление ответа: не «сколько», а «какие»

Все примеры выше возвращают **значение** оптимума: минимум монет, длину LCS, сумму
грабежа. На практике почти всегда нужен сам **ответ-свидетель**: какие именно монеты,
какая подпоследовательность (это буквально `diff` — LCS двух файлов), какой набор
задач взял планировщик. Хорошая новость: таблица уже всё знает.

Приём один и тот же: **пройди таблицу обратным ходом** и в каждом состоянии спроси
«какой переход дал это значение?» — тот выбор и был сделан. Для Coin Change из «⚡ Шаблона»:

```go
// после заполнения dp: dp[i] — минимум монет на сумму i
func restoreCoins(coins, dp []int, amount int) []int {
    // INF — как в шаблоне «⚡». Сумма недостижима: без этой проверки цикл ниже не закончится.
    if dp[amount] >= INF {
        return nil
    }
    res := []int{}
    for i := amount; i > 0; {
        for _, c := range coins {
            if c <= i && dp[i-c]+1 == dp[i] { // этот переход дал оптимум
                res = append(res, c)
                i -= c
                break
            }
        }
    }
    return res // например, amount=11, coins=[1,2,5] → [1, 5, 5]
}
```

Обратный ход бесплатен по памяти (таблица уже есть) и стоит `O(длина ответа × число переходов)`
времени. Альтернатива — хранить **указатель выбора** рядом с каждым состоянием
(`choice[i] = c`): код восстановления упрощается до цепочки переходов, цена — ещё
один массив на все состояния. Для LCS обратный ход читается прямо из рекурренты:
символы совпали — символ в ответ и шаг по диагонали, иначе — шаг в сторону большего
из `dp[i-1][j]` / `dp[i][j-1]` (при равенстве годится любой; виджет идёт вверх). Его показывает
последний шаг виджета LCS выше: от `dp[5][3]` к ответу «AC» для `AGCAT` и `GAC`.

Одно «но»: восстановлению нужна **полная таблица**. Оптимизация памяти скользящим
массивом из раздела выше её уничтожает — это честный размен: значение за `O(n)`
памяти *или* ответ за `O(n·m)`. (Есть и хитрый обход для LCS — алгоритм Хиршберга; на
собеседовании хватает полной таблицы.)

## ⚠️ Типичные ошибки

1. **Неправильная база** — забыли `dp[0]` или задали неверно; вся таблица «съезжает».
2. **Неверный порядок обхода** — состояние используется раньше, чем посчитано.
3. **Путаница индексов строк и таблицы** — для строк длины `m` таблица размера `m+1`, символ `a[i-1]` соответствует `dp[i]`.
4. **Мемоизация без кэша на самом деле** — забыли записать результат перед `return`.
5. **0/1-рюкзак: проход по `w` в прямом порядке** при свёрнутом массиве — предмет берётся несколько раз.

## 📝 Разбор задачи

Перебор и идея — в [«🧭 Откуда берётся ДП»](#-откуда-берётся-дп-выведем-его-сами): наивная
рекурсия `f` и таблица `memo`, которая сводит 25 вызовов к 11. Здесь — та же задача циклом
снизу вверх, свёртка памяти до двух переменных и трасса.

> **Задача (House Robber).** Дан массив `nums` — деньги в домах подряд. Грабитель не
> может обчистить **два соседних** дома (сработает сигнализация). Найти максимальную
> сумму. Пример: `nums = [2,7,9,3,1]` → ответ `12` (дома `2 + 9 + 1`).

**Оптимум: ДП со свёрткой до двух переменных — O(n) время, O(1) память.** Таблица `dp[i]` —
ровно `f(i)` из «🧭», только заполняем её слева направо: `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`.

```go
func rob(nums []int) int {
    prev2, prev1 := 0, 0 // dp[i-2] и dp[i-1]
    for _, x := range nums {
        cur := max(prev1, prev2+x) // пропустить дом или взять его
        prev2, prev1 = prev1, cur  // сдвигаем окно из двух значений
    }
    return prev1
}
```

`dp[i]` зависит только от двух предыдущих ячеек, поэтому весь массив держать не нужно —
это ровно тот [скользящий массив](#память-скользящий-массив) из «⚙️ Цены на практике».

Прогони свёртку на `nums = [2,7,9,3,1]`: для каждого дома `cur = max(пропустить prev1,
взять prev2+x)`, и всё ДП живёт в двух переменных `prev2`, `prev1`. Строка `dp[i]` под
домами — полная таблица для наглядности: обведены две ячейки, которые код ещё держит, а
левее всё погашено, потому что уже забыто. На финале зелёным — дома, из которых собран ответ:

**Трассировка** на `nums = [2,7,9,3,1]` (логически `dp[i] = max(dp[i-1], dp[i-2]+nums[i])`):

| `i` | `nums[i]` | `dp[i-1]` (пропустить) | `dp[i-2]+nums[i]` (взять) | `dp[i]` |
|-----|-----------|-----------------------|---------------------------|---------|
| 0   | 2         | 0                     | 0 + 2 = 2                 | **2**   |
| 1   | 7         | 2                     | 0 + 7 = 7                 | **7**   |
| 2   | 9         | 7                     | 2 + 9 = 11                | **11**  |
| 3   | 3         | 11                    | 7 + 3 = 10                | **11**  |
| 4   | 1         | 11                    | 11 + 1 = 12               | **12**  |

Ответ — `12` (дома `2 + 9 + 1`), и совпадает с рекурсией из «🧭». Каждое `dp[i]` берёт
**больший** из двух столбцов; в свёрнутой версии вся таблица сжата до пары `prev2, prev1`.

> 🧵 **Конкурентность?** Почти нет — у ДП **цепочки зависимостей**: `dp[i]` опирается на уже
> посчитанные `dp[i-1]`, `dp[i-2]`, … Пока не готовы предшественники, клетку не вычислить, поэтому
> наивно параллелить нельзя. Теоретически независимы клетки одной **антидиагонали** (клеток с одинаковым `i + j`; например, в
> `EditDistance`/`LCS`), но работы на клетку — копейки, и горутины тут проиграют. ДП почти всегда
> последовательно.

## 🏗️ Инженерный кейс

> **Ситуация.** Тебе дают задачу оптимизации: «минимум монет на сумму», «максимум прибыли», «сколько
> способов». Соблазн — схватить жадность (она проще и быстрее). Но жадность **молча** даёт неверный ответ
> на многих задачах. Как понять, что здесь нужно ДП, а не жадный выбор?

Это решение — распознать природу задачи **до** того, как написан код. Разберём на классической ловушке:

**Вывод.** Цепочка выборов + повторяющиеся подзадачи → **ДП**. Жадность — только когда локальный оптимум
**доказуемо** глобален (и это надо проверять контрпримером, а не надеждой). Не уверен — начни с перебора,
заметь повторяющиеся подзадачи, навесь мемоизацию: перебор превратится в ДП.

## 🔗 Связанные шаблоны

**Не спутай с соседом** (вся таблица — в [руководстве по выбору](pattern-selection-guide.md#путаемые-пары-что-обязано-быть-верно)):

- если есть доказательство, что локально лучший выбор входит в какой-то оптимум — [Жадные алгоритмы](greedy.md), а не Динамическое программирование: даже где ДП применимо, жадность проще и быстрее, ведь делает один выбор на шаг без таблицы состояний.
- если жадный выбор опровергнут контрпримером или его верность не удаётся доказать — Динамическое программирование, а не [Жадные алгоритмы](greedy.md): жадный выбор не пересматривается, и на монетах 1, 3, 4 при сумме 6 он берёт 4 + 1 + 1 вместо 3 + 3.
- если нужны сами варианты, все подмножества, перестановки или расстановки, а не их число — [Поиск с возвратом](backtracking.md), а не Динамическое программирование: в ячейке ДП лежит одно число, оптимум или счёт вариантов, а не список самих вариантов.
- если подзадачи перекрываются, а нужен оптимум или число вариантов, а не сами варианты — Динамическое программирование, а не [Поиск с возвратом](backtracking.md): перебор заново решает одни и те же подзадачи и уходит в экспоненту, а ДП решает каждую один раз.
<!-- pairs:end -->

- **[Префиксные суммы](prefix-sums.md)** — Кадане без ДП: лучший подмассив, кончающийся в j, —
  это префикс минус наименьший из прошлых префиксов.
- **[Backtracking](backtracking.md)** — когда подзадачи перекрываются, перебор превращается в ДП мемоизацией.
- **[Greedy](greedy.md)** — когда жадность доказуема, она проще ДП.
- **[Modified Binary Search](modified-binary-search.md)** — ускоряет некоторые ДП: самую длинную возрастающую подпоследовательность — до O(n log n).

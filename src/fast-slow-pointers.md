## 🧭 Откуда берутся заяц и черепаха: выведем их сами

Два указателя с разной скоростью — не фокус, который надо просто запомнить. Они получаются,
если спросить, что на самом деле хранит обычное решение и без чего можно обойтись. Проследим
на задаче о входе в цикл.

> **Задача.** В односвязном списке, возможно, есть цикл: хвост ссылается на один из прежних
> узлов. Верни узел, с которого цикл начинается, или `nil`. Пример: `3 → 2 → 0 → -4`, хвост
> `-4` ведёт обратно в `2`; ответ — узел `2`.

**Как решает человек.** Иду по списку и записываю каждый узел в блокнот — множество
посещённых. Первый узел, который уже записан, и есть вход в цикл. Дошёл до `nil` — цикла нет.

**Где лишнее.** На примере блокнот растёт так: `{3}`, `{3, 2}`, `{3, 2, 0}`, `{3, 2, 0, -4}`.
Следующий `Next` ведёт в `2` — он уже записан, ответ найден. Ради одного ответа мы держали
указатель на каждый узел: n узлов — n записей в `map`, O(n) памяти и нагрузка на GC. А ведь
блокнот отвечает всего на один вопрос: «я здесь уже был?»

**Что чинит.** Вспомни двух бегунов. На прямой дороге быстрый уходит от медленного навсегда.
На круговой дорожке он рано или поздно заходит медленному в спину. Значит, сама встреча и
есть ответ «мы на кольце». Пусти по списку двоих: `slow` — по одному узлу за шаг, `fast` —
по два. Цикла нет — `fast` первым упрётся в `nil`. Цикл есть — оба рано или поздно окажутся
на кольце, и там `fast` сокращает разрыв на один узел за шаг: встреча неизбежна. На примере
пары `slow/fast` идут так: `3/3`, `2/0`, `0/2`, `-4/-4` — встреча на третьей итерации, блокнот
не нужен. Вход в цикл даёт второй проход: `slow` — снова в голову, оба по одному шагу,
`3/-4` → `2/2`. Почему они сходятся именно на входе — [вывод формулы](#вывод-формулы-начала-цикла) ниже.

**Заяц на круговой дорожке обязательно догонит черепаху — поэтому помнить пройденный путь
не нужно, хватит второго бегуна.** Этот приём — быстрый и медленный указатели, они же
алгоритм Флойда (Floyd's cycle detection). Первый виджет ниже гоняет первую фазу —
обнаружение — на другом списке, `1 → … → 8` с хвостом в узел `4`: встреча на пятой итерации в
узле `6`. Код и трасса обеих фаз на `3 → 2 → 0 → -4` — в [«📝 Разбор задачи»](#-разбор-задачи).

## ⚡ Шаблон для собеседования

Канонический каркас «заяц и черепаха» — обнаружение цикла:

```go
slow, fast := head, head
for fast != nil && fast.Next != nil {
    slow = slow.Next      // на 1 шаг
    fast = fast.Next.Next // на 2 шага
    if slow == fast {     // встретились — цикл есть
        break
    }
}
// fast == nil || fast.Next == nil → цикла нет
```

1. оба стартуют из `head`;
2. `slow` на 1 шаг, `fast` на 2;
3. условие `fast != nil && fast.Next != nil` бережёт от разыменования `nil`;
4. встреча → цикл; выход из цикла по `nil` → цикла нет.

## 📖 Разбор

**Fast & Slow Pointers** (алгоритм «заяц и черепаха», обнаружение циклов Флойда) —
два указателя движутся по структуре с разной скоростью: медленный на 1 шаг, быстрый
на 2. Если в списке есть цикл, быстрый рано или поздно догонит медленный внутри цикла;
если цикла нет — быстрый первым достигнет конца.

Техника даёт O(n) по времени и **O(1) по памяти** там, где наивный подход с хеш-таблицей
тратит O(n) дополнительной памяти.

### Обнаружение цикла

Двигаем `slow` на шаг, `fast` на два. Совпадение указателей означает цикл; выход
`fast` в `nil` — цикла нет. (`ListNode` и работа с указателями `Next` — из главы
[«Связный список: устройство и операции»](linked-list-structure.md); если списки ещё
не в пальцах — начни с неё.)

```go
type ListNode struct {
    Val  int
    Next *ListNode
}

func hasCycle(head *ListNode) bool {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast {
            return true
        }
    }
    return false
}
```

Длину кольца `L` даёт тот же проход: после встречи оставь `fast` на месте и веди `slow` по
кольцу, считая шаги, пока он снова не встанет на `fast`.

### Начало цикла

Вход в цикл — второй проход после встречи: `slow` возвращается в голову, `fast` остаётся в
точке встречи, и оба идут по одному шагу — сойдутся ровно на входе. Почему именно там —
[вывод формулы](#вывод-формулы-начала-цикла) в «🧠»; код и трасса обеих фаз — в
[«📝 Разбор задачи»](#-разбор-задачи).

### Середина списка

Когда `fast` дойдёт до конца, `slow` окажется в середине: он прошёл вдвое меньше.

```go
func middleNode(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }
    return slow
}
```

### Линейка длины k: k-й узел с конца

Ещё одно применение — не разная скорость, а **постоянный разрыв**. Уведи `fast` на `k` узлов
вперёд, потом двигай оба по одному. Разрыв между ними всё время `k` — как линейка, которую
тащат по списку. Когда `fast` выйдет за конец, `slow` стоит на k-м узле с конца. Упёрся
`fast` в `nil`, не сделав `k` шагов, — в списке меньше `k` узлов.

```go
func kthFromEnd(head *ListNode, k int) *ListNode {
    fast := head
    for i := 0; i < k; i++ {
        if fast == nil {
            return nil // k больше длины
        }
        fast = fast.Next
    }
    slow := head
    for fast != nil {
        slow = slow.Next
        fast = fast.Next
    }
    return slow
}
```

На `1 → 2 → 3 → 4 → 5`: `k = 2` — узел `4`; `k = 5` — сама голова `1`; `k = 6` — `nil`,
k больше длины.

    <div class="algo-explain__q">Почему, пустив один указатель из головы, а второй — из точки встречи, они сойдутся ровно в начале цикла?</div>
    <div class="algo-explain__ref">Пусть <code>a</code> — от головы до начала цикла, <code>b</code> — от начала цикла до точки встречи, <code>L</code> — длина цикла. К встрече <code>slow</code> прошёл <code>a+b</code>, <code>fast</code> — вдвое больше и при этом обогнал <code>slow</code> на целое число кругов: <code>2(a+b) = (a+b) + kL</code>. Отсюда <code>a+b = kL</code>. За <code>a</code> шагов первый указатель дойдёт по хвосту до начала цикла, а второй, стартовав в <code>b</code> шагах за входом, окажется в <code>b+a = kL</code> шагах от входа — то есть снова на нём.</div>
  </div>
</div>

Три вопроса: почему указатели **обязательно встретятся**, почему быстрый не
«перепрыгивает» медленный, и почему формула начала цикла работает.

### Почему встреча гарантирована и без перепрыгивания

Когда оба на кольце, следим за одной величиной — **сколько узлов `fast` осталось
пробежать, чтобы догнать `slow`**. За шаг `fast` проходит два узла, `slow` убегает на
один: расстояние сокращается ровно на 1. Число, которое каждый шаг уменьшается на
единицу, не может перепрыгнуть ноль — а ноль и есть встреча. В начале оно не больше длины
кольца `L`, значит, встреча случится не позже чем через `L` шагов.

Если цикла нет — `fast` первым упрётся в `nil` (он же быстрее), цикл `for` завершится.

### Вывод формулы начала цикла

Обозначим: `a` — путь от головы до входа в цикл, `b` — сколько `slow` прошёл по кольцу от
входа до точки встречи (`0 ≤ b ≤ L`), `L` — длина кольца:

```text
head ──a──→ [вход] ──b──→ [встреча]
              ↑               │
              └──── L − b ────┘
```

К встрече `slow` прошёл `a + b`, `fast` — вдвое больше. Встретились они в одном узле кольца,
поэтому лишний путь `fast` — это целые круги, скажем `k` кругов: `2(a + b) = (a + b) + kL`. Отсюда **`a + b = kL`**: длина пути `slow`
кратна длине кольца.

Теперь встань в точку встречи — она в `b` шагах за входом — и сделай ещё `a` шагов. От входа
ты окажешься в `b + a = kL` шагах, то есть снова на входе: целые круги возвращают туда же.
А указатель из головы за те же `a` шагов дойдёт до входа по хвосту. Оба там одновременно, а
раньше встретиться не могут: пока первый на хвосте, второй — на кольце. Доказано.

На примере `3 → 2 → 0 → -4`: `a = 1`, `b = 2`, `L = 3`, и `1 + 2 = 3` — один круг. Во вкладке
«Длинный хвост» в «📝»: `3 + 4 = 7`. Крайний случай: если цикл с самой головы (`a = 0`), указатели
встретятся там же, обойдя круг: `b = L`. Подпись под рисунком виджета «a ≡ L − b по модулю L» (≡ — «равны с точностью до целых кругов `L`») —
то же равенство: от встречи до входа осталось `L − b`, и `a` — это столько же плюс целые круги.

Попутно: `slow` до встречи проходит по кольцу **не больше одного круга** (`fast` осталось
пробежать до `slow` не больше `L` узлов, и это число убывает на 1 за шаг), поэтому всё это `O(n)`.

## ⚙️ Цена на практике

### `O(1)` памяти — в этом весь смысл

Цикл легко найти и хеш-множеством посещённых узлов, но это `O(n)` памяти. Заяц и
черепаха дают тот же `O(n)` по времени при `O(1)` памяти — на собеседовании «а можешь
без доп. памяти?» это **ожидаемый** ответ, а не хеш-множество.

### Порядок проверки `fast != nil && fast.Next != nil`

Сначала `fast`, потом `fast.Next` — благодаря короткому замыканию `&&` не будет
разыменования `nil`. Переставишь местами — паника на списке чётной длины.

### Техника шире литерального списка

«Следующий узел» — это любая функция `i → f(i)` (функциональный граф). Поэтому Floyd
ловит цикл и там, где списка нет: **Find the Duplicate Number** (индекс → значение как
указатель), **Happy Number** (число → сумма квадратов цифр). Увидел «неявную ссылку
next» — вспомни про зайца и черепаху.

Условие одно: у каждого элемента ровно один следующий, и он из того же набора. У Happy
Number цикл есть всегда, и счастливо то число, чей цикл — `1 → 1`. В массиве значение должно
быть номером ячейки: в Find the Duplicate это числа `1..n` в массиве из `n + 1` ячеек. Переходы
`i → nums[i]` из ячейки 0 бегут по конечному набору ячеек и рано или поздно зациклятся — цикл есть
всегда. Вход в кольцо — ячейка, куда ведут хотя бы две стрелки (с хвоста и с кольца): её номер записан
в массиве хотя бы дважды, это и есть дубликат. Массив
с произвольными значениями цепочки не даёт — там цикл искать не в чем, нужны обычные приёмы.

### Какая «середина» при чётной длине

При `slow, fast := head, head` и цикле `fast != nil && fast.Next != nil` для чётной
длины `slow` останавливается на **втором** среднем узле (соглашение LeetCode). Нужен
первый — стартуй `fast` с `head.Next`.

## ⚠️ Типичные ошибки

1. **Условие цикла `for fast != nil`** без проверки `fast.Next` — разыменование `nil`
   при `fast.Next.Next`. Правильно: `for fast != nil && fast.Next != nil`.
2. **Сдвиг старта** — инициализируй оба указателя `head`, а не `head.Next`.
3. **Забыли сбросить `slow` в `head`** при поиске начала цикла — иначе указатель
   остаётся внутри цикла и ответ неверный.
4. **Лишние особые случаи** — пустой список, один узел и петлю на себя закрывает само
   условие цикла `fast != nil && fast.Next != nil` при старте из `head`; отдельные проверки
   не нужны. Убедись в этом на трёх тестах.
5. **Поиск K-го с конца, когда K больше длины** — двигая `fast` вперёд на K шагов,
   проверяй `fast == nil`.

## 📝 Разбор задачи

Перебор и наблюдение — в [«🧭 Откуда берутся заяц и черепаха»](#-откуда-берутся-заяц-и-черепаха-выведем-их-сами):
блокнот посещённых узлов отвечает на один вопрос «я здесь уже был?», и его заменяет второй
бегун. Здесь — код и трасса той же задачи.

> **Задача.** Дан односвязный список. Если в нём есть цикл, верни **узел, с которого
> цикл начинается** (вход в кольцо), иначе — `nil`.
> Пример: `3 → 2 → 0 → -4`, где хвост `-4` указывает обратно на узел `2` → ответ:
> узел `2`.

Хеш-множество посещённых тоже решает её — первый узел, увиденный второй раз, и есть вход, —
но платит `O(n)` памяти, и на собеседовании за ним сразу спросят «а за `O(1)`?». Флойд
находит вход вторым проходом; почему указатели сходятся именно там — [вывод формулы](#вывод-формулы-начала-цикла).

**Алгоритм Флойда — O(n) времени, O(1) памяти.**

```go
func detectCycle(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next      // на 1 шаг
        fast = fast.Next.Next // на 2 шага
        if slow == fast {     // встреча — цикл есть
            break
        }
    }
    if fast == nil || fast.Next == nil {
        return nil            // вышли в nil — цикла нет
    }
    slow = head               // второй проход: один из головы,
    for slow != fast {        // другой из точки встречи, оба по 1 шагу
        slow = slow.Next
        fast = fast.Next
    }
    return slow               // сошлись на входе в цикл
}
```

Прогони обе фазы на `3→2→0→-4` с циклом в узел `2`. Сначала быстрый (+2) и медленный (+1)
указатели встречаются внутри цикла, потом `slow` уходит в голову, и по одному шагу оба
сходятся на входе. В фазе 2 вход в цикл обведён янтарным кольцом, точка встречи фазы 1 —
голубым пунктиром, а под рисунком — длины `a`, `b` и `L` из [вывода](#вывод-формулы-начала-цикла). На входе из
условия хвост короткий (`a = 1`), и фаза 2 заканчивается за один ход — во вкладке
«Длинный хвост» (`a = 3`, `b = 4`, `L = 7`) оба указателя делают по три шага:

*Фаза 1 — ищем встречу:*

| шаг | `slow` (×1) | `fast` (×2) | встреча? |
|-----|-------------|-------------|----------|
| старт | `3`       | `3`         | —        |
| 1   | `2`         | `0`         | нет      |
| 2   | `0`         | `2`         | нет      |
| 3   | `-4`        | `-4`        | **да**   |

*Фаза 2 — `slow` сброшен в `head`, оба по 1 шагу:*

| шаг | `slow` (из головы) | `fast` (из встречи) | равны? |
|-----|--------------------|---------------------|--------|
| старт | `3`              | `-4`                | нет    |
| 1   | `2`                | `2`                 | **да** |

Ответ — узел `2`, вход в цикл. Оба прохода линейны и не используют доп. памяти: тот
самый `O(n)` времени при `O(1)` памяти, ради которого и нужен Флойд вместо хеш-множества.

**Вывод.** Если память не узкое место, как при проверке конфига, цикл проще ловить множеством
посещённых: оно заодно называет звенья петли. Быстрый и медленный указатели нужны там, где лишней
памяти действительно нет, — и в задачах, где значение задаёт следующий индекс.

<div class="algo-mental">

    <ul>
      <li><b>Сигнал.</b> Связный список или переход «значение → следующее», а спрашивают про цикл, его начало, середину или K-й с конца — при O(1) памяти.</li>
      <li><b>Должно быть верно.</b> У каждого узла не больше одного следующего — ссылка или функция; тогда внутри кольца быстрый сокращает разрыв на 1 за шаг и не перепрыгнет медленного.</li>
      <li><b>Ломается</b>, когда у узла несколько следующих, как в графе: там цикл ищет <a href="graphs.md">обход с пометкой</a>; когда память не жалко, проще хеш-множество посещённых.</li>

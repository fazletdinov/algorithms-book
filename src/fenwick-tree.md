## 📖 Разбор

<details class="algo-details">
<summary>Полная реализация, BIT против дерева отрезков, сложность</summary>

**Дерево Фенвика** (BIT) — компактная структура для префиксных сумм с обновлениями: и
точечное обновление, и запрос префиксной суммы за O(log n), используя один массив
`n+1`. Уже, чем дерево отрезков (только обратимые операции), зато проще и легче.

```go
type Fenwick struct {
    n    int
    tree []int // 1-индексация: tree[0] не используется
}

func NewFenwick(arr []int) *Fenwick {
    f := &Fenwick{n: len(arr), tree: make([]int, len(arr)+1)}
    for i, v := range arr {
        f.add(i+1, v)
    }
    return f
}

func (f *Fenwick) add(i, delta int) {
    for ; i <= f.n; i += i & (-i) {
        f.tree[i] += delta
    }
}

func (f *Fenwick) Update(i, delta int) { f.add(i+1, delta) } // ДОБАВЛЕНИЕ, не запись

func (f *Fenwick) prefix(i int) int {
    sum := 0
    for ; i > 0; i -= i & (-i) {
        sum += f.tree[i]
    }
    return sum
}

func (f *Fenwick) PrefixSum(i int) int { return f.prefix(i + 1) }       // [0..i]
func (f *Fenwick) RangeSum(l, r int) int { return f.PrefixSum(r) - f.PrefixSum(l-1) }
```

#### BIT против дерева отрезков

| Критерий            | Fenwick (BIT)         | Segment Tree              |
|---------------------|-----------------------|---------------------------|
| Код                 | очень компактный      | объёмнее                  |
| Память              | `n+1`                 | `2n`–`4n`                 |
| Операции            | сумма, xor (обратимые)| любые (min/max/gcd, lazy) |
| Диапазонные обновления | сложнее (два BIT)  | через lazy propagation    |

#### Сложность

| Операция            | Время      | Память |
|---------------------|------------|--------|
| Построение          | O(n log n) | O(n)   |
| Update (точечное)   | O(log n)   | —      |
| PrefixSum / RangeSum| O(log n)   | —      |

</details>

## 🔧 Диапазонное обновление (два BIT)

Обычный Фенвик умеет **точечное обновление + сумма на диапазоне**. А если наоборот — надо
прибавить `x` **ко всему отрезку** `[l, r]` (и таких обновлений много), а потом спрашивать
значения? Наивно — трогать все элементы отрезка, `O(n)` на обновление. Фенвик умеет и это за
`O(log n)`, и в основе — красивый трюк.

### Шаг 1. Диапазонное обновление + точечный запрос (один BIT)

Идея: хранить не сами значения, а **разности** соседних элементов `d[i] = a[i] − a[i−1]`
(и `d[0] = a[0]`). Тогда любое значение — это префиксная сумма разностей: `a[i] = d[0] + d[1] + … + d[i]`.

Что даёт такой взгляд: прибавить `x` **ко всему** `[l, r]` — значит изменить разности лишь **в
двух точках** (внутри отрезка соседние элементы растут одинаково, разности не меняются):

- на границе входа `d[l] += x` (здесь появился скачок вверх);
- на границе выхода `d[r+1] −= x` (здесь скачок обратно).

То есть диапазонное обновление — это **два точечных** обновления по BIT над массивом разностей,
а значение `a[i]` — это `prefixSum(i)`. Оба за `O(log n)`.

```go
// bit — дерево Фенвика этой главы над массивом РАЗНОСТЕЙ, позиции с 0.
// Заводи его на n+1 позицию — NewFenwick(make([]int, n+1)): при r = n−1
// второе обновление пишет в позицию n, и в дереве на n позиций она за краем.
func rangeAdd(bit *Fenwick, l, r, x int) {
    bit.Update(l, x)    // d[l]   += x  — скачок вверх на входе
    bit.Update(r+1, -x) // d[r+1] -= x  — и обратно на выходе
}
func pointQuery(bit *Fenwick, i int) int {
    return bit.PrefixSum(i) // a[i] = сумма разностей d[0..i]
}
```

**Прогони руками.** Массив из 6 нулей, делаем `rangeAdd(1, 3, +5)` (прибавить 5 к позициям 1..3):

| позиция i | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| разности `d` после двух Add | 0 | **+5** | 0 | 0 | **−5** | 0 |
| значение `a[i] = prefixSum(i)` | 0 | 5 | 5 | 5 | 0 | 0 |

Два касания массива разностей — а «поднялся» весь отрезок `[1,3]`. Каждый `Update` внутри — это тот
самый подъём по BIT из [главы-устройства](fenwick-tree-structure.md), просто теперь их два.

### Шаг 2. Диапазонное обновление + запрос суммы на диапазоне (два BIT)

А если нужно ещё и суммировать по отрезку? Тогда одного BIT мало — нужна **пара**. Причина: сумму
`a[0..i]` через разности можно выразить как комбинацию двух префиксных сумм — обычных дельт
(**BIT B1**) и дельт с **поправкой на индекс** (**BIT B2**). Обновление и запрос трогают оба:

```go
// b1 и b2 — деревья Фенвика на n+1 позицию, позиции с 0 (как в шаге 1)
func rangeAdd(l, r, x int) {
    b1.Update(l, x)
    b1.Update(r+1, -x)
    b2.Update(l, x*l)
    b2.Update(r+1, -x*(r+1))
}
func prefix(i int) int { // сумма a[0..i]; при i = −1 даёт 0
    return b1.PrefixSum(i)*(i+1) - b2.PrefixSum(i)
}
func rangeSum(l, r int) int { return prefix(r) - prefix(l-1) }
```

Итог — **диапазонное обновление и диапазонная сумма за O(log n)** на двух деревьях Фенвика. Формулу
наизусть не держат: важно понимать, что это тот же приём разностей, просто с поправкой на индекс,
разнесённой во второй BIT. Если операция не сводится к такой алгебре (например, диапазонный
`min`) — Фенвик уже не подходит, берут [дерево отрезков с lazy propagation](segment-tree.md).

## 📝 Разбор задачи

Пройдём путь от наивного решения к оптимальному — так, как стоит рассуждать на
собеседовании: сначала рабочий перебор, затем понимание, *почему* он медленный, и
только потом BIT.

> **Задача.** Дан массив целых `nums`. Посчитать число **инверсий** — пар индексов
> `i < j`, для которых `nums[i] > nums[j]`. (Тот же приём решает «count of smaller
> numbers after self».)
> Пример: `nums = [5,2,6,1]` → ответ `4` (пары `(5,2)`, `(5,1)`, `(2,1)`, `(6,1)`).

**Шаг 1. Наивно: перебрать все пары — O(n²).**

```go
func countInversionsNaive(nums []int) int {
    cnt := 0
    for i := 0; i < len(nums); i++ {
        for j := i + 1; j < len(nums); j++ {
            if nums[i] > nums[j] { // элемент слева больше элемента справа
                cnt++
            }
        }
    }
    return cnt
}
```

Это **работает и проходит тесты**, но делает O(n²) сравнений. Для каждого `i` мы заново
просматриваем весь хвост справа, хотя по сути нас интересует одно и то же: «сколько уже
виденных элементов меньше текущего». Этот повторяющийся подсчёт «меньших» и убирает BIT.

Прогони перебор по шагам на `nums = [5,2,6,1]`: для каждого левого `i` указатель `j`
проходит весь хвост, и каждая инверсия (`nums[i] > nums[j]`) подсвечивается:

<div class="algo-viz" data-viz="count-inversions-naive" data-array="5,2,6,1"></div>

**Шаг 2. Ключевое наблюдение.** Пройдём массив **справа налево** и будем поддерживать
частотную таблицу уже встреченных значений. Тогда вклад элемента `nums[i]` в число
инверсий — это **количество уже встреченных (то есть стоящих справа) значений, строго
меньших `nums[i]`**, а это в точности **префиксная сумма частот** на отрезке рангов
`[1, rank−1]`. Частоты меняются точечно (`+1` за элемент), а запрашиваем префикс — ровно
то, для чего создано [дерево Фенвика](fenwick-tree-structure.md#зона-ответственности-узла-и-почему-i---i--это-младший-бит):
оба за O(log n) благодаря прыжкам по `i & (-i)`.

Значения бывают большими/отрицательными, поэтому делаем **сжатие координат**: уникальные
отсортированные значения нумеруем рангами `1..m`, и BIT работает по рангам, а не по самим
числам. Размер дерева — `m+1`, а не максимум значения.

> ⚠️ Дубликаты: спрашиваем `prefix(rank−1)` (строго меньшие), поэтому равные значения
> справа **не** считаются инверсией — это и нужно для определения `nums[i] > nums[j]`.

**Шаг 3. Оптимум: сжатие координат + BIT по частотам — O(n log n).**

```go
func countInversionsBIT(nums []int) int {
    // сжатие координат: значение -> ранг 1..m
    sorted := append([]int(nil), nums...)
    sort.Ints(sorted)
    rank := make(map[int]int)
    m := 0
    for _, v := range sorted {
        if _, ok := rank[v]; !ok {
            m++
            rank[v] = m
        }
    }
    tree := make([]int, m+1) // BIT по частотам рангов, 1-индексация
    add := func(i int) {
        for ; i <= m; i += i & (-i) {
            tree[i]++
        }
    }
    prefix := func(i int) int {
        s := 0
        for ; i > 0; i -= i & (-i) {
            s += tree[i]
        }
        return s
    }
    inv := 0
    for i := len(nums) - 1; i >= 0; i-- { // справа налево
        ri := rank[nums[i]]
        inv += prefix(ri - 1) // сколько справа строго меньше nums[i]
        add(ri)               // регистрируем nums[i] как встреченный
    }
    return inv
}
```

Сортировка для сжатия — O(n log n), затем `n` пар операций `add`/`prefix` по O(log m) —
итого **O(n log n)**, память **O(n)**.

Прогони оптимум на тех же `nums = [5,2,6,1]`. Идём справа налево; внизу — BIT частот
рангов `tree[1..4]`. На каждом элементе сначала спуск `prefix(rank−1)` собирает вклад
(сколько меньших уже справа), затем подъём `add(rank)` регистрирует текущий ранг —
сравни накопленный `inv` с колонкой трассировки ниже:

**Шаг 4. Трассировка** на `nums = [5,2,6,1]`. Ранги: `1→1, 2→2, 5→3, 6→4`. Идём справа
налево; `tree[1..4]` — частотный BIT (узел `i` отвечает за зону, заканчивающуюся в `i` по
`i & (-i)`):

| `i` | `nums[i]` | `rank` | `prefix(rank−1)` | вклад | `add` обновляет узлы | `tree[1..4]` | `inv` |
|-----|-----------|--------|------------------|-------|----------------------|--------------|-------|
| 3   | 1         | 1      | `prefix(0)` = 0  | 0     | 1→2→4                | `[1,1,0,1]`  | 0     |
| 2   | 6         | 4      | `prefix(3)` = 1  | 1     | 4                    | `[1,1,0,2]`  | 1     |
| 1   | 2         | 2      | `prefix(1)` = 1  | 1     | 2→4                  | `[1,2,0,3]`  | 2     |
| 0   | 5         | 3      | `prefix(2)` = 2  | 2     | 3→4                  | `[1,2,1,4]`  | **4** |

Ответ — `4`, что совпадает с наивным перебором. Обрати внимание на строку `i=2`:
`prefix(3)` спускается `3 → 3−(3&-3)=2 → 2−2=0`, складывая `tree[3]+tree[2] = 0+1 = 1` —
один меньший элемент (`1`) уже стоял справа от `6`.

## ⚙️ Цена на практике

И Фенвик, и [дерево отрезков](segment-tree.md) дают `O(log n)` — но платят по-разному.

- **Память**: Фенвик — ровно один `[]int64` размера `n+1`. Дерево отрезков — `4n` узлов (а с lazy —
  ещё массив меток). На 10⁸ элементов это разница «0.8 ГБ против 3.2+ ГБ».
- **Константа**: цикл Фенвика — несколько сложений и битовая операция `i & (-i)` на итерацию, обходит
  **один массив** (дружит с кэшем и префетчером). Дерево отрезков прыгает по «дереву в массиве» с
  ветвлениями — константа заметно больше.
- **Узость API — цена компактности**: Фенвик умеет только **обратимые** агрегаты (сумма, XOR, счёт).
  Минимум/максимум на отрезке, «присвоить на диапазоне», сложные lazy-операции — это к дереву
  отрезков. Правило: **если хватает суммы — бери Фенвик; нужна выразительность — плати деревом отрезков**.
- **А иногда не нужен ни тот, ни другой**: если обновлений нет — [префиксные суммы](prefix-sums.md)
  за `O(1)` на запрос; если запросов единицы — пересчёт в лоб дешевле, чем городить структуру.

## 🔗 Связанные шаблоны

<!-- pairs:begin — сгенерировано node scripts/gen-pairs.js из assets/pairs.js, руками не править -->
**Не спутай с соседом** (вся таблица — в [руководстве по выбору](pattern-selection-guide.md#путаемые-пары-что-обязано-быть-верно)):

- если массив между запросами суммы не меняется, а запросов много — [Префиксные суммы](prefix-sums.md), а не Дерево Фенвика: Фенвик платит O(log n) за запрос ради обновлений, которых нет, а префикс отвечает за O(1).
- если массив меняется между запросами суммы, точечные правки идут вперемешку с запросами — Дерево Фенвика, а не [Префиксные суммы](prefix-sums.md): одна правка меняет весь хвост префиксов за O(n), а Фенвик и обновляет, и отвечает за O(log n).
<!-- pairs:end -->

- **[Segment Tree](segment-tree.md)** — более универсальная, но более тяжёлая альтернатива.
- **[Bit Manipulation](bit-manipulation.md)** — трюк `i & (-i)` для младшего бита.
- **[Modified Binary Search](modified-binary-search.md)** — поиск k-го элемента спуском по дереву.

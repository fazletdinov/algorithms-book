> 🧭 **О чём глава.** Дерево Фенвика (BIT, Binary Indexed Tree) — **один массив**, где каждая ячейка
> хранит сумму своего куска исходного массива, а навигация — арифметика над младшим битом индекса.
> Префиксная сумма — сумма первых элементов: для `[3, 2, −1]` префикс до индекса 1 равен `5`.
> Сначала строим структуру, потом решаем на ней задачу о числе инверсий.

## 🧱 Как устроена структура

BIT — это **один массив** `tree[1..n]` (нулевой индекс не используется). Узел `i` хранит сумму
**`lowbit(i)` элементов, заканчивающихся в позиции `i`**, где `lowbit(i) = i & (−i)` — младший
единичный бит: `12 = 1100₂ → 100₂ = 4`, значит `tree[12]` — сумма позиций 9..12. Никакого явного
дерева нет — связи задаются битовой арифметикой.

```go
type Fenwick struct {
    n    int
    tree []int // 1-индексация: tree[0] не используется
}
```

<div class="algo-fig" data-fig="array" data-array="1,2,1,4,1,2,1,8" data-rows="lowbit(i)" data-index="1" data-index-label="i" data-ranges="tree[1]@1-1; tree[2]@1-2; tree[3]@3-3; tree[4]@1-4; tree[5]@5-5; tree[6]@5-6; tree[7]@7-7; tree[8]@1-8" data-caption="Под рядом — зона каждого узла tree[i]: lowbit(i) позиций, кончая i. Наведи на позицию — загорятся узлы, чья зона её накрывает: их и обновит Add"></div>

`tree[8]` — сумма всех восьми, `tree[6]` — пары `[5,6]`, `tree[7]` — одного `[7]`. `Add` прыгает
вверх по узлам, чьи зоны накрывают позицию; `PrefixSum` — вниз по зонам, замощающим `[1, i]`.
Прыжков не больше `log n` — отсюда O(log n) у обеих операций.

## ➕ Обновление: `Add` (подъём `i += i & −i`)

Прибавить `delta` к элементу — значит обновить **все узлы, чья зона накрывает эту позицию**.

```go
func (f *Fenwick) Add(i, delta int) {
    i++                   // в 1-индексацию
    for i <= f.n {
        f.tree[i] += delta // зона ответственности узла i
        i += i & (-i)      // следующий ответственный узел
    }
}
```

> 💡 Прибавляем `5` к индексу `2` в массиве из 8 элементов: узел `i = 3` (зона `[2,2]`), затем
> `3 → 4` (зона `[0,3]`) `→ 8` (зона `[0,7]`). Подставь свой индекс и delta.

## 🔎 Запрос: `PrefixSum` (спуск `i −= i & −i`)

Сумма префикса `[0, i]` собирается из **непересекающихся зон**: берём зону узла `i`, прыгаем в
`i − lowbit` — к концу следующего непокрытого куска — и так до нуля.

```go
func (f *Fenwick) PrefixSum(i int) int {
    i++                   // в 1-индексацию
    sum := 0
    for i > 0 {
        sum += f.tree[i]  // зона ответственности узла i
        i -= i & (-i)     // к следующей зоне левее
    }
    return sum
}

func (f *Fenwick) RangeSum(l, r int) int { return f.PrefixSum(r) - f.PrefixSum(l-1) }
```

> 💡 Префиксная сумма до индекса `5`: прыжки вниз складывают зоны узлов, пока `i > 0`.
> `RangeSum(l, r)` — две такие суммы.

### Построение за `O(n)` и конструктор

`n` вызовов `Add` строят дерево за `O(n log n)`. Быстрее — за `O(n)`: положить в узел его элемент и
сразу протолкнуть накопленное в ближайший накрывающий узел `i + lowbit(i)`:

```go
func NewFenwick(arr []int) *Fenwick {
    n := len(arr)
    f := &Fenwick{n: n, tree: make([]int, n+1)}
    for i := 1; i <= n; i++ {
        f.tree[i] += arr[i-1] // дети уже протолкнули в узел свои суммы
        if j := i + (i & -i); j <= n {
            f.tree[j] += f.tree[i]
        }
    }
    return f
}
```

## ⚖️ BIT против дерева отрезков

| Критерий            | Фенвик (BIT)           | [Дерево отрезков](segment-tree.md) |
|---------------------|------------------------|---------------------------|
| Код                 | десяток строк          | объёмнее                  |
| Память              | `n+1`                  | `2n`–`4n`                 |
| Операции            | сумма, xor (обратимые) | любые (min/max/НОД, lazy) |
| Диапазонные обновления | два BIT (ниже)      | ленивые метки (lazy propagation) |
| Построение          | `O(n)`                 | `O(n)`                    |
| Точечное обновление / запрос | `O(log n)`    | `O(log n)`                |

Правило: **хватает суммы — бери Фенвик; нужна выразительность — плати деревом отрезков**.

## 🔧 Диапазонное обновление (два BIT)

Обычный Фенвик умеет **точечное обновление + сумму на диапазоне**. А если надо прибавить `x`
**ко всему отрезку** `[l, r]`? Наивно — трогать все элементы, `O(n)` на обновление.

Идея: хранить не значения, а **разности** соседей `d[i] = a[i] − a[i−1]` (и `d[0] = a[0]`).
Тогда `a[i] = d[0] + … + d[i]` — префиксная сумма разностей. Прибавить `x` ко всему `[l, r]` —
изменить разности лишь **в двух точках** (внутри отрезка соседи растут одинаково):
`d[l] += x` на входе и `d[r+1] −= x` на выходе.

```go
// bit — дерево Фенвика над массивом РАЗНОСТЕЙ, позиции с 0.
// Заводи его на n+1 позицию — NewFenwick(make([]int, n+1)): при r = n−1
// второе обновление пишет в позицию n, и в дереве на n позиций она за краем.
func rangeAdd(bit *Fenwick, l, r, x int) {
    bit.Add(l, x)    // d[l]   += x  — скачок вверх на входе
    bit.Add(r+1, -x) // d[r+1] -= x  — и обратно на выходе
}
func pointQuery(bit *Fenwick, i int) int {
    return bit.PrefixSum(i) // a[i] = сумма разностей d[0..i]
}
```

**Прогони руками.** Массив из 6 нулей, `rangeAdd(1, 3, +5)`:

| позиция i | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| разности `d` после двух Add | 0 | **+5** | 0 | 0 | **−5** | 0 |
| значение `a[i] = PrefixSum(i)` | 0 | 5 | 5 | 5 | 0 | 0 |

Два касания — а «поднялся» весь отрезок `[1,3]`, и оба за `O(log n)`.

<details class="algo-details">
<summary>⚙️ Второй проход: диапазонное обновление + сумма на диапазоне — читать, когда освоишься</summary>

Если нужно ещё и суммировать по отрезку, одного BIT мало. Сумму `a[0..i]` через разности можно
выразить комбинацией двух префиксных сумм — обычных дельт (**B1**) и дельт с **поправкой на индекс**
(**B2**):

```go
// b1 и b2 — деревья Фенвика на n+1 позицию, позиции с 0
func rangeAdd(l, r, x int) {
    b1.Add(l, x)
    b1.Add(r+1, -x)
    b2.Add(l, x*l)
    b2.Add(r+1, -x*(r+1))
}
func prefix(i int) int { // сумма a[0..i]; при i = −1 даёт 0
    return b1.PrefixSum(i)*(i+1) - b2.PrefixSum(i)
}
func rangeSum(l, r int) int { return prefix(r) - prefix(l-1) }
```

Формулу наизусть не держат: это тот же приём разностей, а поправка на индекс вынесена во второй BIT.
Если операция не сводится к такой алгебре (диапазонный `min`) — нужно
[дерево отрезков с lazy propagation](segment-tree.md).

</details>

## 📝 Разбор задачи

> **Задача.** Дан массив целых `nums`. Посчитать число **инверсий** — пар индексов
> `i < j`, для которых `nums[i] > nums[j]`. (Тот же приём решает «count of smaller
> numbers after self».)
> Пример: `nums = [5,2,6,1]` → ответ `4` (пары `(5,2)`, `(5,1)`, `(2,1)`, `(6,1)`).

**Шаг 1. Наивно: перебрать все пары — O(n²).**

```go
func countInversionsNaive(nums []int) int {
    cnt := 0
    for i := 0; i < len(nums); i++ {
        for j := i + 1; j < len(nums); j++ {
            if nums[i] > nums[j] { // элемент слева больше элемента справа
                cnt++
            }
        }
    }
    return cnt
}
```

Работает, но для каждого `i` заново просматривает весь хвост, хотя вопрос всегда один:
«сколько элементов справа меньше текущего».

<div class="algo-viz" data-viz="count-inversions-naive" data-array="5,2,6,1"></div>

**Шаг 2. Наблюдение.** Идём **справа налево** и ведём таблицу частот уже встреченных значений.
Вклад `nums[i]` — число встреченных (стоящих справа) значений, строго меньших его, то есть
**префиксная сумма частот** до `nums[i] − 1`. Частоты меняются точечно (`+1`), запрашиваем префикс —
ровно работа для BIT.

Значения бывают большими и отрицательными, поэтому делаем **сжатие координат**: уникальные
значения по возрастанию нумеруем рангами `1..m` (`[100, −7, 100]` → ранги `2, 1, 2`), и BIT
работает по рангам. Размер дерева — `m+1`, а не максимум значения.

> ⚠️ Дубликаты: спрашиваем `prefix(rank−1)` (строго меньшие), поэтому равные значения справа
> **не** считаются инверсией — как и требует `nums[i] > nums[j]`.

**Шаг 3. Оптимум: сжатие координат + BIT по частотам — O(n log n).**

```go
func countInversionsBIT(nums []int) int {
    // сжатие координат: значение -> ранг 1..m
    sorted := append([]int(nil), nums...)
    sort.Ints(sorted)
    rank := make(map[int]int)
    m := 0
    for _, v := range sorted {
        if _, ok := rank[v]; !ok {
            m++
            rank[v] = m
        }
    }
    tree := make([]int, m+1) // BIT по частотам рангов, 1-индексация
    add := func(i int) {
        for ; i <= m; i += i & (-i) {
            tree[i]++
        }
    }
    prefix := func(i int) int {
        s := 0
        for ; i > 0; i -= i & (-i) {
            s += tree[i]
        }
        return s
    }
    inv := 0
    for i := len(nums) - 1; i >= 0; i-- { // справа налево
        ri := rank[nums[i]]
        inv += prefix(ri - 1) // сколько справа строго меньше nums[i]
        add(ri)               // регистрируем nums[i] как встреченный
    }
    return inv
}
```

Сортировка — O(n log n), затем `n` пар `add`/`prefix` по O(log m) — итого **O(n log n)**, память **O(n)**.

На каждом элементе сначала спуск `prefix(rank−1)` собирает вклад, затем подъём `add(rank)`
регистрирует ранг — сравни `inv` с трассировкой ниже:

<div class="algo-viz" data-viz="count-inversions-bit" data-array="5,2,6,1"></div>

**Шаг 4. Трассировка** на `nums = [5,2,6,1]`. Ранги: `1→1, 2→2, 5→3, 6→4`:

| `i` | `nums[i]` | `rank` | `prefix(rank−1)` | вклад | `add` обновляет узлы | `tree[1..4]` | `inv` |
|-----|-----------|--------|------------------|-------|----------------------|--------------|-------|
| 3   | 1         | 1      | `prefix(0)` = 0  | 0     | 1→2→4                | `[1,1,0,1]`  | 0     |
| 2   | 6         | 4      | `prefix(3)` = 1  | 1     | 4                    | `[1,1,0,2]`  | 1     |
| 1   | 2         | 2      | `prefix(1)` = 1  | 1     | 2→4                  | `[1,2,0,3]`  | 2     |
| 0   | 5         | 3      | `prefix(2)` = 2  | 2     | 3→4                  | `[1,2,1,4]`  | **4** |

Ответ `4` совпадает с перебором. В строке `i=2` `prefix(3)` спускается `3 → 2 → 0`,
складывая `tree[3]+tree[2] = 0+1 = 1` — один меньший элемент (`1`) уже стоял справа от `6`.

**Вывод.** «Суммы **плюс обновления**» — сигнал Фенвика; данные только читают — префиксный массив.

## 🧠 Почему это корректно

- **`PrefixSum(i)`** на каждом шаге берёт зону `(i−lowbit, i]` и прыгает в `i − lowbit` — к концу
  следующего непокрытого куска. Зоны не пересекаются и **в точности замощают `[1, i]`**. Каждый прыжок
  гасит один единичный бит, поэтому шагов ≤ `log n`.
- **`Add(i)`** проходит ровно по узлам, чьи зоны накрывают позицию `i`, — поэтому правка учтётся в
  каждом `PrefixSum(j)` с `j ≥ i`. Проверь по рисунку на `i = 5`: `5 → 6 → 8`, а узел `7`
  (зона `[7]`) пропущен — позицию 5 он не накрывает.
- **Только обратимые операции.** `RangeSum(l, r) = PrefixSum(r) − PrefixSum(l−1)` держится на
  вычитании. Из `min[0..r]` и `min[0..l−1]` нельзя получить `min[l..r]` — поэтому диапазонный
  минимум — это [дерево отрезков](segment-tree.md).

<details class="algo-details">
<summary>⚙️ Второй проход: почему подъём <code>i += lowbit</code> не промахивается — читать, когда освоишься</summary>

`i & -i` выделяет младший бит потому, что `-i = ~i + 1`: прибавление единицы к инвертированному `i`
возвращает младший единичный бит на место (нули под ним остаются нулями), а всё выше остаётся
перевёрнутым — `&` обнуляет всё, кроме этого бита.

Зоны устроены как **двоичная линейка**: зона длины `2^k` кончается на числе, кратном `2^k`. Кто,
кроме узла `i`, накрывает позицию `i`? Индексы **между** `i` и `i + lowbit(i)` лежат между двумя
соседними кратными `2^k`, их младший бит меньше `2^k`, и их короткие зоны целиком правее `i` — мимо.
А `i + lowbit(i)` — следующее кратное: его младший бит как минимум вдвое больше, и его зона
дотягивается влево за `i`. Каждый прыжок перескакивает всех «мелких» соседей и попадает в ближайший
накрывающий узел.

</details>

## ⚙️ Цена на практике

- **Память**: ровно один массив `n+1`. Дерево отрезков — `4n` узлов (с lazy — ещё массив меток).
  На 10⁸ элементов `int64` это «0.8 ГБ против 3.2+ ГБ».
- **Константа**: итерация — пара сложений и `i & (-i)` по **одному массиву** (дружит с кэшем).
  Дерево отрезков прыгает по узлам с ветвлениями — константа заметно больше.
- **1-индексация обязательна**: `0 & -0 = 0`, шаг `i += 0` стоит на месте, и цикл виснет молча.
  Поэтому в `Add`/`PrefixSum` стоит сдвиг `+1` — самый частый баг в реализации BIT.
- **Иногда не нужен ни Фенвик, ни дерево отрезков**: обновлений нет —
  [префиксные суммы](prefix-sums.md) за `O(1)`; запросов единицы — пересчёт в лоб дешевле.

## ⚠️ Типичные ошибки

1. **Путаница 0- и 1-индексации** — держи 1-индексацию строго внутри, конвертируй на границе.
2. **`Add` как «запись» вместо «прибавления»** — BIT хранит дельты; чтобы *установить* значение, прибавь `(новое − старое)`.
3. **Попытка хранить min/max** — обычный BIT не поддерживает необратимые операции.
4. **Зависание при `i += i & (-i)`, если забыли `+1`** — `lowbit(0) = 0`, шаг на месте. (Цикл `i -= i & (-i)` при `i = 0` безопасен: условие `i > 0` не пустит в тело.)
5. **Дерево разностей на `n` позиций вместо `n+1`** — `Add(r+1, −x)` при `r = n−1` уходит за край.

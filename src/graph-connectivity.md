## 🏭 Где это живёт в проде

Go запрещает циклы импортов: `go build` падает с `import cycle not allowed`. Вопрос
«какие именно пакеты завязаны в цикл» — это в точности поиск SCC в графе импортов:
каждая компонента сильной связности размера больше единицы — отдельный клубок, который
надо распутывать. То же самое делает Terraform, когда ресурсы ссылаются друг на друга
по кругу. Второй классический сюжет — **дедлоки**: в wait-for-графе (горутина → ресурс,
которого она ждёт → горутина, которая его держит) дедлок — это цикл, а «кто именно кого
заблокировал» — SCC размера больше единицы; так работают детекторы взаимоблокировок в
базах данных.

Третий — **аудит отказоустойчивости**. В графе сети (узлы — машины/свитчи/сервисы,
рёбра — линки) *мост* — ребро, без которого граф распадается: единственный кабель между
двумя датацентрами. *Точка сочленения* — узел с тем же свойством: свитч, после падения
которого половина стойки недоступна. Оба списка считаются одним DFS за O(V+E).

И наконец, **конденсация**: сожми каждую SCC в одну вершину — получится DAG, и снова
работает весь арсенал <a href="topological-sort.md">топологической сортировки</a>. Любой
ориентированный граф — это DAG из SCC: циклы сжали, группы отсортировали, пересобираем
группами — так строят порядок пересборки при циклических зависимостях.

## ⚡ Шаблон для собеседования

```go
// SCC по Косарайю: два DFS + транспонированный граф
// (radj — списки смежности с развёрнутыми рёбрами; полный код — в тренажёре scc)
func scc(n int, adj, radj [][]int) [][]int {
    visited := make([]bool, n)
    order := make([]int, 0, n) // порядок ЗАВЕРШЕНИЯ вершин
    var dfs1 func(v int)
    dfs1 = func(v int) {
        visited[v] = true
        for _, w := range adj[v] {
            if !visited[w] {
                dfs1(w)
            }
        }
        order = append(order, v) // после всех потомков
    }
    for v := 0; v < n; v++ {
        if !visited[v] {
            dfs1(v)
        }
    }
    assigned := make([]bool, n)
    var comp []int
    var dfs2 func(v int) // тот же DFS, но по radj (рёбра развёрнуты)
    dfs2 = func(v int) {
        assigned[v] = true
        comp = append(comp, v)
        for _, w := range radj[v] {
            if !assigned[w] {
                dfs2(w)
            }
        }
    }
    var comps [][]int
    for i := n - 1; i >= 0; i-- { // обратный порядок завершения
        if v := order[i]; !assigned[v] {
            comp = nil
            dfs2(v)
            comps = append(comps, comp) // один запуск = одна SCC
        }
    }
    return comps
}
```

1. DFS №1 по исходному графу — запоминаем порядок **завершения** вершин;
2. транспонируем граф (разворачиваем все рёбра);
3. DFS №2 по транспонированному графу, стартуя с последней завершившейся вершины;
4. каждый запуск DFS №2 собирает ровно одну компоненту сильной связности.

## 📖 Разбор

<details class="algo-details">
<summary>SCC и конденсация, Косарайю, Тарьян, мосты и точки сочленения</summary>

#### Определения

Вершины `u` и `v` **сильно связаны**, если существует путь и `u → v`, и `v → u`.
Это отношение эквивалентности, и его классы — **компоненты сильной связности** (SCC).
В неориентированном графе достаточно обычной связности (<a href="graphs.md">DFS/Union-Find</a>);
«сильная» имеет смысл только там, где у рёбер есть направление.

Сожми каждую SCC в одну вершину — получишь **конденсацию**. Она всегда **DAG**: будь
между двумя сжатыми вершинами цикл, их компоненты были бы взаимно достижимы и слились
бы в одну SCC. Отсюда главный мостик к <a href="topological-sort.md">топосортировке</a>:
**любой ориентированный граф — это DAG из SCC**.

#### Косарайю: два DFS

Код — в шаблоне выше. Интуиция: DFS №1 нумерует вершины по завершении, и **позже всех
завершается вершина из SCC-«истока» конденсации** (из неё достижимо всё «вниз по
течению»). В транспонированном графе направления развёрнуты — исток становится
**стоком**: из него никуда не убежишь, и DFS №2 собирает ровно его компоненту.
Помечаем её и повторяем со следующей по порядку — индукция по DAG конденсации.
Побочный бонус: компоненты выходят в **топологическом порядке конденсации**.

#### Тарьян: один DFS и low-link

Косарайю ходит по графу дважды и требует транспонированную копию. Тарьян успевает за
один DFS. Введём:

- `tin[v]` — номер входа в вершину (время начала обработки в DFS);
- `low[v]` — **минимальный `tin`, достижимый из поддерева `v` через не более чем одно
  обратное ребро**.

Вершины текущего пути и их «недооформленные» компоненты живут на стеке. Если после
обработки всех соседей `low[v] == tin[v]` — из поддерева `v` нет выхода к более ранним
вершинам, значит `v` — «корень» своей SCC, и всё, что лежит на стеке выше `v`
включительно, образует одну компоненту:

```go
func tarjanSCC(n int, adj [][]int) [][]int {
    tin := make([]int, n)
    low := make([]int, n)
    for i := range tin {
        tin[i] = -1
    }
    onStack := make([]bool, n)
    var stack []int
    timer := 0
    var comps [][]int
    var dfs func(v int)
    dfs = func(v int) {
        tin[v], low[v] = timer, timer
        timer++
        stack = append(stack, v)
        onStack[v] = true
        for _, w := range adj[v] {
            if tin[w] == -1 { // древесное ребро
                dfs(w)
                low[v] = min(low[v], low[w])
            } else if onStack[w] { // обратное ребро внутри текущей SCC
                low[v] = min(low[v], tin[w])
            }
        }
        if low[v] == tin[v] { // v — корень своей SCC
            var comp []int
            for {
                u := stack[len(stack)-1]
                stack = stack[:len(stack)-1]
                onStack[u] = false
                comp = append(comp, u)
                if u == v {
                    break
                }
            }
            comps = append(comps, comp)
        }
    }
    for v := 0; v < n; v++ {
        if tin[v] == -1 {
            dfs(v)
        }
    }
    return comps
}
```

Проверка `onStack[w]` важна: сосед из уже **закрытой** компоненты не должен влиять на
`low` — та SCC оформлена, путь назад через неё невозможен.

#### Мосты и точки сочленения

Теперь граф **неориентированный**. **Мост** — ребро, удаление которого увеличивает
число компонент. **Точка сочленения** — вершина с тем же свойством. Наивно можно
удалять каждое ребро и пересчитывать компоненты — O(E·(V+E)); low-link делает всё за
один DFS.

В DFS-дереве неориентированного графа обратное ребро всегда ведёт к **предку**. Ребро
`(u, v)` (где `v` — ребёнок) — мост, если из поддерева `v` **нет** обратного ребра к
`u` или выше: `low[v] > tin[u]`.

```go
type arc struct{ to, id int } // сосед + индекс исходного ребра

// tin/low/timer и запуск из каждой непосещённой вершины — как у Тарьяна выше;
// в DFS передаём индекс ребра, по которому пришли (-1 для корня)
dfs = func(v, fromEdge int) {
    tin[v], low[v] = timer, timer
    timer++
    for _, a := range adj[v] {
        if a.id == fromEdge {
            continue // к родителю по ТОМУ ЖЕ ребру не возвращаемся
        }
        if tin[a.to] == -1 { // древесное ребро
            dfs(a.to, a.id)
            low[v] = min(low[v], low[a.to])
            if low[a.to] > tin[v] {
                res = append(res, []int{v, a.to}) // мост
            }
        } else {
            low[v] = min(low[v], tin[a.to]) // обратное: tin, не low!
        }
    }
}
```

Обрати внимание на две детали, где чаще всего ошибаются. Первая: родителя пропускаем
**по индексу ребра**, а не по номеру вершины — иначе при кратных рёбрах второе
параллельное ребро (легальный обходной путь!) будет проигнорировано, и ребро ошибочно
объявится мостом. Вторая: для обратного ребра берём `tin[a.to]`, а не `low[a.to]` —
подробно в «Типичных ошибках».

**Точки сочленения** — тот же DFS, критерий чуть слабее: не-корень `u` — точка
сочленения, если хотя бы у одного ребёнка `low[child] >= tin[u]`. Разница с мостом —
нестрогое неравенство: поддереву достаточно дотянуться до **самого** `u`, ведь `u` мы
удаляем. И особый случай: для **корня** DFS-дерева критерий всегда истинен (`tin`
корня минимален), поэтому корень проверяется отдельно — он точка сочленения, только
если у него **≥ 2 детей в DFS-дереве**.

| Задача            | Граф     | Алгоритм            | Сложность | Критерий                          |
|-------------------|----------|---------------------|-----------|-----------------------------------|

## 🧠 Почему это корректно

### Косарайю: почему DFS №2 не «протекает» между компонентами

Ключевой факт: если в конденсации есть ребро `A → B` (из SCC `A` в SCC `B`), то
**максимальное время завершения в `A` больше, чем в `B`**. Либо DFS зашёл в `A`
раньше — тогда он успеет провалиться в `B` и завершить её вершины до выхода из `A`;
либо в `B` раньше — но из `B` в `A` пути нет (конденсация — DAG), и `B` целиком
завершится до старта `A`. В обоих случаях `A` «переживает» `B`. Значит, обратный
порядок завершения — это **топологический порядок конденсации**: первой идёт
SCC-исток.

В транспонированном графе исток стал стоком: рёбра из него теперь ведут *в него*.
DFS №2, стартовав в нём, физически не может покинуть компоненту — соберёт ровно её.
Помечаем собранное; следующая непомеченная вершина в порядке — исток оставшейся части
DAG, и рассуждение повторяется. Каждый запуск = ровно одна SCC. ∎

### Инвариант low-link

**Инвариант:** после обработки поддерева `v` значение `low[v]` — минимальный `tin`,
достижимый из поддерева `v` по древесным рёбрам вниз плюс **не более одного** обратного
ребра. База: `low[v] = tin[v]` (пустой путь). Шаг: древесное ребро наследует `low`
ребёнка (его пути — наши пути), обратное ребро `v—w` даёт кандидата `tin[w]`.

### Почему `low[v] > tin[u]` — это ровно «мост»

Пусть `(u, v)` — древесное ребро. В неориентированном графе **любое** недревесное
ребро соединяет предка с потомком (поперечных рёбер нет: увидев «чужую» посещённую
вершину, DFS бы в неё не вернулся, а прошёл раньше). Значит, все пути из поддерева `v`
наружу — это либо само ребро `(u, v)`, либо обратные рёбра к предкам.

Если `low[v] > tin[u]` — ни одно обратное ребро из поддерева `v` не дотягивается до
`u` или выше. Удали `(u, v)` — поддерево `v` останется без единой связи с остальным
графом: мост. Если же `low[v] <= tin[u]` — есть обратное ребро в `u` или выше, оно
образует цикл через `(u, v)`, и удаление ребра переживается обходным путём. Для точки
сочленения неравенство нестрогое: дотянуться до самого `u` недостаточно, потому что
удаляется сам `u` вместе со всеми его рёбрами.

## ⚙️ Цена на практике

### Рекурсивный DFS на графе в 10⁶ вершин — когда это реально проблема

Все алгоритмы главы — DFS, и на пути-графе глубина рекурсии равна `V`. В C++ или Java
это крах уже на ~10⁵ вершинах. В Go стек горутины **растёт динамически**: начинает с
пары килобайт и удваивается до лимита в 1 ГБ (`debug.SetMaxStack`). Кадр нашего DFS —
порядка сотни байт, так что 10⁶ вершин обойдутся в ~100 МБ стека: **работает**, но
памятью платишь честно, а на 10⁷–10⁸ вершинах упрёшься в лимит с `fatal error:
goroutine stack exceeds ...-byte limit` — это не паника, `recover` не спасёт. Для
по-настоящему больших графов DFS
переписывают на **явный стек**; муторное место — хранить в кадре позицию в списке
соседей. Косарайю итеративно переписывается проще Тарьяна: у него меньше состояния на
кадр.

### Косарайю или Тарьян

Асимптотика одинаковая — O(V+E). Косарайю: **два** прохода и транспонированная копия
графа (память ×2), но каждый проход — «школьный» DFS, его трудно написать с ошибкой, а
компоненты бесплатно выходят в топологическом порядке конденсации. Тарьян: **один**
проход без копии — экономия константы, но стек, `onStack` и инвариант `low` дают больше
мест для бага. На собеседовании начинай с Косарайю; Тарьян — когда граф впритык к
памяти или когда low-link всё равно нужен (мосты рядом).

### Наивная проверка против low-link

«Удали ребро и проверь связность» — `O(V+E)` на ребро, итого **O(E·(V+E))**: на графе
10⁵/10⁵ это ~10¹⁰ операций, десятки секунд. Low-link считает все мосты и все точки
сочленения за **один DFS** — O(V+E), меньше миллисекунды на том же графе. Наивный
вариант оставь тестам: в тренажёре он кросс-проверяет быстрый именно потому, что
до неприличия прост.

## ⚠️ Типичные ошибки

1. **Сильную связность перепутали со слабой.** Union-Find или DFS «без направлений» на
   орграфе дают *слабую* связность. Сильная — только взаимная достижимость: Косарайю/Тарьян.
2. **Мосты/точки сочленения на ориентированном графе.** Определения и алгоритм low-link
   работают для **неориентированного** графа; для орграфа вопросы «критичности» ставятся
   иначе (конденсация, рёберная связность).
3. **Забыт особый случай корня.** Критерий `low[child] >= tin[root]` для корня истинен
   всегда — без отдельной проверки «≥ 2 детей DFS-дерева» корень объявится точкой
   сочленения даже в графе из одного ребра.
4. **Возврат к родителю запрещают по вершине, а не по ребру.** При кратных рёбрах
   параллельное ребро — законный обходной путь; пропуская «вершину-родителя», ты его
   теряешь и объявляешь мостом ребро, которое мостом не является. Пропускай **индекс
   ребра**, по которому пришёл.
5. **Для обратного ребра берут `low[w]` вместо `tin[w]`.** Классическая тонкость:
   `low[w]` включает чужие обратные рёбра из поддерева `w`, а пути через них могут
   идти именно по ребру-кандидату — и мост окажется незамеченным. Обратное ребро даёт
   кандидата ровно `tin[w]`; наследовать `low` можно только у детей по древесным рёбрам.

## 📝 Разбор задачи

> **Задача (Critical Connections in a Network, LeetCode 1192).** Дана сеть из `n`
> серверов (`0..n-1`) и список двусторонних соединений `connections`. Соединение
> **критическое**, если после его удаления какие-то серверы перестанут достигать друг
> друга. Вернуть все критические соединения.
> Пример: `n = 4`, `connections = [[0,1],[1,2],[2,0],[1,3]]` → `[[1,3]]`.

Прочитаем условие глазами этой главы: «ребро, удаление которого рвёт связность» —
дословно определение **моста**.

**Шаг 1. Наивно: удалить и проверить — O(E·(V+E)).**

```go
for skip := range connections { // спрячь ребро skip и пересчитай компоненты
    if components(n, connections, skip) > components(n, connections, -1) {
        res = append(res, connections[skip])
    }
}
```

Корректно и очевидно, но на верхней границе задачи (`n = 10⁵`, `connections = 10⁵`)
это ~10¹⁰ операций — не влезает ни в какой лимит.

**Шаг 2. Ключевое наблюдение.** Ребро некритично ⇔ оно лежит **на цикле**: цикл — это
и есть обходной путь. Проверять каждое ребро отдельно не нужно — все обходные пути
видны за **один DFS**: это обратные рёбра. Осталось для каждого поддерева знать, куда
самое «высокое» обратное ребро дотягивается, — ровно это и считает `low`.

**Шаг 3. Оптимум: low-link — O(V+E).** Код `bridges` из разбора выше подходит без
изменений: строим списки смежности с индексами рёбер, один DFS, ребро `(v, to)` —
критическое при `low[to] > tin[v]`.

**Шаг 4. Трассировка** на `n = 5`, рёбра `0-1, 1-2, 2-0, 1-3, 3-4` (DFS из 0, соседи
по возрастанию):

| Событие                | tin           | low после возврата | Вывод                          |
|------------------------|---------------|--------------------|--------------------------------|
| вход в 0               | tin[0]=0      | low[0]=0           | —                              |
| вход в 1 (ребро 0-1)   | tin[1]=1      | low[1]=0           | из 2 пришло обратное ребро в 0 |
| вход в 2 (ребро 1-2)   | tin[2]=2      | low[2]=0           | обратное ребро 2-0: low=tin[0] |
| возврат 2→1            | —             | low[2]=0 ≤ tin[1]=1| 1-2 — **не мост**              |
| вход в 3 (ребро 1-3)   | tin[3]=3      | low[3]=3           | обратных рёбер нет             |
| вход в 4 (ребро 3-4)   | tin[4]=4      | low[4]=4           | лист                           |
| возврат 4→3            | —             | low[4]=4 > tin[3]=3| 3-4 — **мост**                 |
| возврат 3→1            | —             | low[3]=3 > tin[1]=1| 1-3 — **мост**                 |
| возврат 1→0            | —             | low[1]=0 ≤ tin[0]=0| 0-1 — **не мост**              |

Ответ: `[[1,3],[3,4]]` (в примере LeetCode без вершины 4 остался бы один мост `[1,3]`).
Один проход вместо `E` перезапусков — и заодно бесплатно видны точки сочленения `1` и `3`.

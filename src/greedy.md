## 🎬 Визуализация

> 💡 **Интерактивная демонстрация (Jump Game).** Жёлтым — текущий индекс, синим — диапазон
> достижимых позиций, тусклым — пока недостижимые. Жадность ведёт самую дальнюю достижимую точку
> (`maxReach`). Справа — код с подсветкой строки и переменные, внизу — шаги. Можно подставить свой
> массив и нажать «⟲ Запустить». (Виджет работает в собранной книге `mdbook serve`/`mdbook build`,
> а не при просмотре `.md` на GitHub.)

## ⚡ Шаблон для собеседования

```go
// Jump Game: ведём самую дальнюю достижимую позицию
func canJump(nums []int) bool {
    maxReach := 0
    for i, v := range nums {
        if i > maxReach {
            return false // сюда не допрыгнуть
        }
        if i+v > maxReach {
            maxReach = i + v // жадно расширяем горизонт
        }
    }
    return true
}
```

1. ведём `maxReach` — самую дальнюю достижимую позицию;
2. если текущий индекс уже за горизонтом — провал;
3. иначе расширяем горизонт `i + nums[i]`;
4. дошли до конца — можно.

## 📖 Разбор

<details class="algo-details">
<summary>Доказательство корректности, Activity Selection, Jump Game и сложность</summary>

**Жадный алгоритм** на каждом шаге делает **локально оптимальный** выбор в надежде, что
последовательность таких выборов приведёт к **глобальному оптимуму**, и никогда не
пересматривает уже сделанный выбор.

Жадность корректна, только когда задача обладает **свойством жадного выбора** (локально
оптимальный выбор входит в некоторое глобально оптимальное решение) и **оптимальной
подструктурой**. Иначе нужно [динамическое программирование](dynamic-programming.md).

#### Как доказать корректность

1. **Greedy stays ahead** — по индукции: после каждого шага жадное решение не хуже любого
   другого.
2. **Exchange argument** — берём оптимальное решение и «переставляем» его к жадному, не
   ухудшив.

#### Пример 1: выбор заявок (Activity Selection)

Выбрать максимум взаимно непересекающихся интервалов. Критерий: **сортировка по времени
окончания**, берём каждый следующий, что начинается не раньше конца предыдущего.

```go
func maxActivities(intervals [][]int) int {
    if len(intervals) == 0 {
        return 0
    }
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][1] < intervals[j][1] // по концу
    })
    count := 1
    lastEnd := intervals[0][1]
    for _, iv := range intervals[1:] {
        if iv[0] >= lastEnd { // не пересекается с последним выбранным
            count++
            lastEnd = iv[1]
        }
    }
    return count
}
```

Выбирая интервал, заканчивающийся раньше всех, мы оставляем максимум места для остальных —
это и есть «жадный остаётся впереди».

#### Пример 2: Jump Game

```go
func canJump(nums []int) bool {
    maxReach := 0
    for i, v := range nums {
        if i > maxReach {
            return false
        }
        if i+v > maxReach {
            maxReach = i + v
        }
    }
    return true
}
```

#### Сложность

| Задача            | Время        | Память |
|-------------------|--------------|--------|
| Выбор заявок      | O(n log n)   | O(1)   |
| Jump Game         | O(n)         | O(1)   |

Чаще всего стоимость определяется **сортировкой** O(n log n); сам проход линейный.

## 🧠 Почему это корректно

Жадный код всегда крошечный — вся сложность в **доказательстве**, что локальный выбор
ведёт к глобальному оптимуму. Без него жадность бывает уверенно неправильной.

### Когда жадность вообще применима

Нужны два свойства. **Свойство жадного выбора:** существует оптимальное решение,
содержащее локально оптимальный (жадный) выбор. **Оптимальная подструктура:** после
жадного выбора остаётся подзадача того же вида, и её оптимум достраивает ответ.

**Где ломается:** размен монетами произвольных номиналов (`{1, 3, 4}`, сумма `6`):
жадность берёт `4 + 1 + 1 = 3` монеты, оптимум — `3 + 3 = 2`. Свойство жадного выбора
не держится → нужно [ДП](dynamic-programming.md). 0/1-рюкзак по отношению ценность/вес —
та же ловушка. Поэтому жадную гипотезу всегда надо **доказывать**, а не «чувствовать».

### Exchange argument для выбора заявок — полностью

Докажем, что сортировка по **концу** и жадный захват оптимальны.

> **Лемма.** Заявка `g` с самым ранним временем окончания входит в *некоторое*
> оптимальное решение.

*Доказательство.* Возьмём любое оптимальное решение `O`, упорядоченное по концу, и пусть
его первая заявка — `a`. По выбору `g` её конец **не позже** конца `a` (`g` кончается
раньше всех вообще). Заменим в `O` заявку `a` на `g`. Замена допустима: `g` кончается не
позже `a`, поэтому не пересекается со второй заявкой `O` и далее. Размер решения не
изменился → `O' = O \ {a} ∪ {g}` тоже оптимально и содержит `g`. ∎

После взятия `g` остаётся подзадача «заявки, начинающиеся не раньше конца `g`» — того же
вида. По индукции жадность оптимальна на ней, а значит и на всей задаче. Это строгая
форма интуиции «жадный остаётся впереди».

> **Ключ:** корректность держится именно на **ключе сортировки**. По концу — работает; по
> началу или по длительности — даёт неоптимум. Сорт-ключ *и есть* алгоритм.

## ⚙️ Цена на практике

### Настоящая стоимость — сортировка

Сам жадный проход линеен, но почти всегда ему предшествует `sort` → реальная сложность
**`O(n log n)`**. Не заявляй «O(n)», если отсортировал вход. `Jump Game` — исключение:
там жадность работает по уже данному массиву за чистое `O(n)`.

### Доказывай вслух — иначе рискуешь быть уверенно неправым

На собеседовании жадное решение **без обоснования** опасно: код проходит примеры, но
критерий может быть неверным. Проговори exchange argument или «greedy stays ahead» —
это отличает инженера от угадывающего.

### Как быстро проверить жадную гипотезу

Прежде чем коммитить жадность — сравни её с brute-force на маленьких случайных входах
(как в рандом-тестах тренажёра — пакет `exercises/greedy`). Если
хоть раз разошлись — критерий неверен, и ты только что сэкономил себе провал на сложном
тесте. Это дешёвая инженерная привычка.

## ⚠️ Типичные ошибки

1. **Неверный критерий жадности** — для выбора заявок сортировка по началу или по
   длительности даёт неоптимум; правильно — по концу.
2. **Применение жадности без доказательства** — для многих задач (Coin Change,
   0/1 рюкзак) жадность неверна, нужно ДП.
3. **Игнорирование граничных случаев** — пустой вход, один элемент, совпадающие границы
   интервалов.

## 📝 Разбор задачи

Пройдём путь от наивного решения к жадному — так, как стоит рассуждать на
собеседовании: сначала рабочий перебор достижимости, затем понимание, *почему* жадность
здесь доказуемо оптимальна, и только потом проход за один цикл.

> **Задача (Jump Game).** Дан массив неотрицательных целых `nums`. Стоя на индексе `i`,
> можно прыгнуть вперёд на любое число шагов от `1` до `nums[i]`. Достижим ли последний
> индекс, стартуя с нулевого?
> Пример: `nums = [2,3,1,1,4]` → `true` (например, `0→1→4`); `nums = [3,2,1,0,4]` →
> `false` (на индексе `3` стоит `0`, дальше не прыгнуть).

**Шаг 1. Наивно: динамика достижимости — O(n²).**

```go
func canJumpDP(nums []int) bool {
    n := len(nums)
    reachable := make([]bool, n)
    reachable[0] = true
    for i := 0; i < n; i++ {
        if !reachable[i] {
            continue // сюда не допрыгнуть — пропускаем
        }
        for step := 1; step <= nums[i] && i+step < n; step++ {
            reachable[i+step] = true // помечаем всё в досягаемости
        }
    }
    return reachable[n-1]
}
```

Это **работает и проходит тесты**, но в худшем случае делает O(n²) операций: из каждой
достижимой клетки заново помечаем весь её диапазон, и эти диапазоны жирно перекрываются.
Память тоже O(n) под массив `reachable`. Вся повторная пометка одних и тех же позиций —
ровно то, что убирает жадность.

Прогоните наивную динамику на `nums = [2,3,1,1,4]`: из каждой достижимой клетки метим
весь диапазон прыжка — обратите внимание, как одни позиции помечаются по многу раз:

<div class="algo-viz" data-viz="jump-game-dp" data-array="2,3,1,1,4"></div>

**Шаг 2. Ключевое наблюдение.** Вместо «какие клетки достижимы» достаточно одного числа:
самого дальнего достижимого индекса `reach`. Сработает [свойство жадного
выбора](#когда-жадность-вообще-применима): идя слева направо, на каждом достижимом `i`
жадно расширяем `reach = max(reach, i + nums[i])`. Это корректно по индукции (*greedy
stays ahead*): после обработки индекса `i` значение `reach` равно **максимальной**
позиции, достижимой из любого `j ≤ i`. Раз мы знаем самый дальний достижимый индекс, нам
**не важно, каким именно прыжком** туда попасть — промежуточные клетки `≤ reach` все
достижимы тривиально, и хранить их по отдельности не нужно. Как только `i` обгоняет
`reach`, перед нами провал: до `i` не дотянуться ниоткуда левее, а правее мы ещё не были.

**Шаг 3. Оптимум: один проход с `reach` — O(n), O(1) памяти.**

```go
func canJump(nums []int) bool {
    maxReach := 0
    for i, v := range nums {
        if i > maxReach {
            return false // сюда не допрыгнуть
        }
        if i+v > maxReach {
            maxReach = i + v // жадно расширяем горизонт
        }
    }
    return true
}
```

Прогоните жадный проход на `nums = [2,3,1,1,4]`: `maxReach` тянется вправо, и пока
индекс не обгонит его — последний достижим:

<div class="algo-viz" data-viz="jump-game" data-array="2,3,1,1,4"></div>

**Шаг 4. Трассировка** на `nums = [2,3,1,1,4]`:

| `i` | `nums[i]` | `i > maxReach`? | `i + nums[i]` | `maxReach` после |
|-----|-----------|-----------------|---------------|------------------|
| 0   | 2         | `0 > 0` — нет   | 2             | 2                |
| 1   | 3         | `1 > 2` — нет   | 4             | 4                |
| 2   | 1         | `2 > 4` — нет   | 3             | 4                |
| 3   | 1         | `3 > 4` — нет   | 4             | 4                |
| 4   | 4         | `4 > 4` — нет   | 8             | 8                |

Цикл дошёл до конца без `return false` → ответ **`true`**. На `[3,2,1,0,4]` к индексу `4`
горизонт застрял на `maxReach = 3` (после `0` на индексе `3`), условие `4 > 3` срабатывает
→ **`false`**, что совпадает с наивной динамикой.

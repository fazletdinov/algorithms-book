# Greedy (Жадные алгоритмы)

## Описание шаблона

**Жадный алгоритм** на каждом шаге делает **локально оптимальный** выбор в надежде, что
последовательность таких выборов приведёт к **глобальному оптимуму**. Он никогда не
пересматривает уже сделанный выбор — в этом его скорость и его опасность.

Жадность работает **не всегда**. Она корректна, только когда задача обладает **свойством
жадного выбора** (локально оптимальный выбор входит в некоторое глобально оптимальное
решение) и **оптимальной подструктурой**. Если это не доказано — жадный ответ может быть
неверным, и нужно [динамическое программирование](dynamic-programming.md).

> ⚠️ Классический контрпример: размен суммы 6 монетами `[1, 3, 4]`. Жадность берёт
> `4 + 1 + 1 = 3` монеты, а оптимум — `3 + 3 = 2`. Поэтому Coin Change решается ДП, а не
> жадно.

## Когда применять

- Задачи на **расписание/интервалы**: выбрать максимум непересекающихся событий.
- **Минимизация/максимизация** с очевидным критерием сортировки.
- Задачи, где можно доказать «жадный остаётся впереди» (*greedy stays ahead*) или
  применить **аргумент обмена** (*exchange argument*).

## Как доказать корректность

Два стандартных приёма:

1. **Greedy stays ahead** — по индукции показываем, что после каждого шага жадное решение
   не хуже любого другого.
2. **Exchange argument** — берём оптимальное решение и показываем, что его можно
   «переставить» к жадному, не ухудшив.

Без такого рассуждения жадность — лишь гипотеза.

## Пример 1: выбор заявок (Activity Selection)

Дан набор интервалов; нужно выбрать **максимум** взаимно непересекающихся. Жадный
критерий: **сортировка по времени окончания** и выбор каждого следующего интервала,
который начинается не раньше конца предыдущего.

```go
import "sort"

func maxActivities(intervals [][]int) int {
    if len(intervals) == 0 {
        return 0
    }
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][1] < intervals[j][1] // по концу
    })
    count := 1
    lastEnd := intervals[0][1]
    for _, iv := range intervals[1:] {
        if iv[0] >= lastEnd { // не пересекается с последним выбранным
            count++
            lastEnd = iv[1]
        }
    }
    return count
}
```

**Почему именно конец?** Выбирая интервал, заканчивающийся раньше всех, мы оставляем
максимум места для остальных — это и есть «жадный остаётся впереди».

## Пример 2: Jump Game

Можно ли из первого элемента массива допрыгнуть до последнего, если `nums[i]` — максимум
шагов вперёд? Жадно ведём «самую дальнюю достижимую позицию».

```go
func canJump(nums []int) bool {
    maxReach := 0
    for i, v := range nums {
        if i > maxReach {
            return false // сюда не допрыгнуть
        }
        if i+v > maxReach {
            maxReach = i + v
        }
    }
    return true
}
```

## Временная и пространственная сложность

| Задача            | Время        | Память |
|-------------------|--------------|--------|
| Выбор заявок      | O(n log n)   | O(1)   |
| Jump Game         | O(n)         | O(1)   |

Чаще всего стоимость жадного алгоритма определяется **сортировкой** O(n log n); сам
проход — линейный.

## Типичные ошибки

1. **Неверный критерий жадности** — для выбора заявок сортировка по началу или по
   длительности даёт неоптимум; правильно — по концу.
2. **Применение жадности без доказательства** — для многих задач (Coin Change,
   0/1 рюкзак) жадность неверна, нужно ДП.
3. **Игнорирование граничных случаев** — пустой вход, один элемент, совпадающие границы
   интервалов.

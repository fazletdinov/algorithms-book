## 🧭 Откуда берётся жадность: выведем её сами

«Локальный выбор без пересмотра» из «Запомни» звучит как риск: а вдруг пересмотр был нужен?
Посмотрим, откуда такой выбор берётся и почему здесь он законен. Проследим на задаче.

> **Задача (Jump Game).** В клетке `i` записано `nums[i]` — на сколько клеток вперёд можно
> прыгнуть оттуда (от 1 до `nums[i]`). Можно ли из клетки `0` добраться до последней?
> Пример: `[2,3,1,1,4]` → да.

В лоб: завести флаги «сюда можно попасть» и из каждой достижимой клетки пометить все, куда из
неё допрыгнешь. На `[2,3,1,1,4]`: из `0` метим `1, 2`; из `1` — `2, 3, 4`; из `2` — `3`; из
`3` — `4`. Семь пометок на четыре клетки `1..4`: клетки `2`, `3` и `4` помечены дважды. На
длинном массиве диапазоны перекрываются сильнее — отсюда `O(n²)` в худшем случае.

Теперь посмотри на сами флаги. После клетки `0` помечено `0..2`, после клетки `1` — `0..4`.
Дыр нет и быть не может: прыжок из `1` долетел до `4` — значит, тот же прыжок, только короче,
долетает и до `2`, и до `3`. Весь массив флагов описывает одно число — правый край, `maxReach`.

Отсюда жадный выбор: в каждой клетке двигаем край на `i + nums[i]`, если это дальше. Клетки `2`
и `3` дотягиваются до `3` и `4` — ничего нового, край уже `4`. Выбрав самый дальний край и забыв
остальное, мы ничего не теряем: всё, что ближе края, и так достижимо.

Здесь это доказуемо, а не просто кажется: такой же уверенный выбор бывает и неверным — как на
встречах в [«Выборе заявок»](#выбор-заявок-activity-selection) ниже и на
[размене монет](#когда-жадность-вообще-применима).

**Жадность — это перебор, которому доказали, что прошлое можно забыть.** Здесь от всего
прошлого остаётся одно число — `maxReach`. Этот приём — жадный алгоритм. Виджет ниже гоняет тот
же проход на другом входе, `[3,2,1,0,4]`, где допрыгнуть нельзя; код и трасса на
`[2,3,1,1,4]` — в [«📝 Разбор задачи»](#-разбор-задачи).

## 🎬 Визуализация

> 💡 **Интерактивная демонстрация (Jump Game).** Жёлтая рамка — текущий индекс, голубым
> оттенком — диапазон достижимых позиций, тусклым — пока недостижимые. Жадность ведёт самую дальнюю достижимую точку
> (`maxReach`). Под холстом — строка шага и переменные, ниже — ползунок шагов (или ←/→ на клавиатуре) и код с подсветкой строки. Можно подставить свой
> массив и нажать «⟲ Запустить».

Здесь вход, на котором допрыгнуть **нельзя**: на индексе 3 стоит `0`, `maxReach` упирается в
3, и на `i = 4` индекс его обгоняет — это и есть ветка `return false`. Успешный проход на
`[2,3,1,1,4]` — ниже, рядом с трассировкой.

## ⚡ Шаблон для собеседования

```go
// Jump Game: ведём самую дальнюю достижимую позицию
func canJump(nums []int) bool {
    maxReach := 0
    for i, v := range nums {
        if i > maxReach {
            return false // сюда не допрыгнуть
        }
        if i+v > maxReach {
            maxReach = i + v // жадно расширяем горизонт
        }
    }
    return true
}
```

1. ведём `maxReach` — самую дальнюю достижимую позицию;
2. если текущий индекс уже за горизонтом — провал;
3. иначе расширяем горизонт `i + nums[i]`;
4. дошли до конца — можно.

## 📖 Разбор

**Жадный алгоритм** на каждом шаге делает **локально оптимальный** выбор в надежде, что
последовательность таких выборов приведёт к **глобальному оптимуму**, и никогда не
пересматривает уже сделанный выбор.

Жадность корректна, только когда задача обладает **свойством жадного выбора** (локально
оптимальный выбор входит в некоторое глобально оптимальное решение) и **оптимальной
подструктурой**. Иначе нужно [динамическое программирование](dynamic-programming.md).

### Выбор заявок (Activity Selection)

Дан список встреч `[начало, конец]` и один зал. Провести **как можно больше** встреч, чтобы
никакие две не пересекались; встреча, которая начинается ровно в момент конца другой, с ней не
пересекается. Критерий: **сортировка по времени окончания**, берём каждую следующую, что
начинается не раньше конца последней взятой.

```go
func maxActivities(intervals [][]int) int {
    if len(intervals) == 0 {
        return 0
    }
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][1] < intervals[j][1] // по концу
    })
    count := 1
    lastEnd := intervals[0][1]
    for _, iv := range intervals[1:] {
        if iv[0] >= lastEnd { // не пересекается с последним выбранным
            count++
            lastEnd = iv[1]
        }
    }
    return count
}
```

Встреча, которая кончается раньше всех, оставляет залу больше всего времени на остальные.

Прогон на встречах `[0,6]`, `[1,4]`, `[3,5]`, `[5,7]`, `[8,9]`. По концу они встают так: `[1,4]`,
`[3,5]`, `[0,6]`, `[5,7]`, `[8,9]`. Берём `[1,4]`, зал свободен с 4; `[3,5]` и `[0,6]` начинаются
раньше 4 — пропуск; `[5,7]` — берём, зал свободен с 7; `[8,9]` — берём. Три встречи — и перебор
всех подмножеств тоже даёт три.

**Почему именно по концу.** Три правила звучат одинаково разумно: бери встречу, которая
**раньше начинается**; бери **самую короткую**; бери ту, что **раньше кончается**. Не верь ни
одному — сломай:

- «Раньше начинается»: `[1,10]`, `[2,3]`, `[4,5]`. Правило хватает `[1,10]` и занимает зал на
  весь день: одна встреча. А можно две — `[2,3]` и `[4,5]`.
- «Самая короткая»: `[1,5]`, `[4,7]`, `[6,10]`. Короче всех `[4,7]`, и она задевает обе
  остальные: одна встреча вместо двух.
- «Раньше кончается»: на обоих входах даёт две. Сломать не получается — и вот теперь есть
  смысл доказывать. Доказательство — в [«🧠»](#доказательство-заменой-для-выбора-заявок--полностью).

Контрпример ищут на трёх-четырёх элементах: например, одна «жадная» встреча перекрывает две хорошие.
Не нашёл руками — сравни правило с перебором на маленьких случайных входах (так проверены и
эти три: «по концу» с перебором не разошлось ни разу).

### Как доказать корректность

1. **«Жадный остаётся впереди»** — по индукции: после каждого шага жадное решение не хуже
   любого другого. Так устроен довод в «🧭»: после каждой клетки `maxReach` не меньше края, до
   которого дотянулся бы любой другой способ прыгать.
2. **Доказательство заменой** — берём любое лучшее решение и переделываем
   его под жадный выбор, не ухудшив. Полностью — для выбора заявок в «🧠».

### Жадные правила задач практики

Каждое правило — гипотеза, пока нет довода, поэтому у каждого стоит «почему» тем же способом,
что в главе: заменой или «жадный остаётся впереди». Правила в том виде, как они записаны здесь
(кроме дробного рюкзака), сверены с перебором на тысячах маленьких случайных входов — ни одного
расхождения.

- **`FractionalKnapsack`** — бери предметы по убыванию цены за единицу веса, последний —
  частью. Замена тут законна именно потому, что предмет можно резать. Ценности `60, 100, 120`,
  веса `10, 20, 30`, вместимость `50`: целиком первые два и `20/30` третьего — `240`. В
  0/1-рюкзаке (без частей) то же правило берёт `60 + 100 = 160`, а лучше `100 + 120 = 220`.

- **Partition Labels (763)** — запомни последнее вхождение каждой буквы; идя слева, отодвигай
  конец куска до самого дальнего последнего вхождения его букв; дошёл до конца — режь. Тот же
  «край», что `maxReach`. *Почему:* резать после клетки `i` можно, только если ни одна буква
  слева не встречается правее — ровно тогда край равен `i`; правило режет в каждом таком месте,
  поэтому кусков больше не бывает.
- **Gas Station (134)** — если по всему кругу газа хватает, ответ есть; веди бак от старта, и
  когда он ушёл в минус на станции `i`, ни одна станция от старта до `i` не годится — начни с
  `i + 1` с пустым баком. *Почему:* на каждую станцию между стартом и `i` бак приходил с запасом
  не меньше нуля; начав там с пустым баком, к `i` приедешь с баком не больше — и тоже уйдёшь в
  минус. А раз сумма по кругу не меньше нуля, запас хвоста от последнего старта покрывает
  дефицит начала круга.
- **Task Scheduler (621)** — пусть самая частая задача встречается `maxF` раз, а `n` —
  кулдаун (сколько тактов должно пройти между двумя одинаковыми задачами). Самая частая задача
  задаёт каркас: `maxF − 1` блоков длины `n + 1` плюс последний ряд из задач максимальной
  частоты; если задач больше, чем мест, ответ — их число. *Почему:* две копии самой частой
  задачи стоят не ближе `n + 1` тактов, поэтому меньше каркаса не уложить; остальные задачи
  раскладываются по столбцам каркаса, а если их больше, чем мест, каркас растягивается без
  простоев.
- **`MinJumps` (Jump Game II)** — на текущем прыжке достижимы клетки до `end`, по дороге копишь
  самый дальний край; дошёл до `end` — прыжок, и `end` = этот край. Последнюю клетку не
  обрабатывай: ты уже на месте, лишний прыжок не нужен (`[2,3,1,1,4]` → 2, `[0]` → 0). *Почему:*
  это слои обхода в ширину без очереди — клетки до `end` достижимы за текущее число прыжков, а
  от `end` до нового края — ровно за одно больше; жадный край не меньше края любого другого
  плана прыжков, поэтому ни один план не доберётся быстрее.
- **`MaxProfit`** (сделок сколько угодно) — сложи все положительные приросты цены между
  соседними днями. *Почему:* прибыль сделки «купил в день `a`, продал в день `b`» — сумма
  приростов между соседними днями от `a` до `b`; сделки не перекрываются (держать две акции
  разом нельзя), так что каждый прирост входит в прибыль не больше одного раза — значит, она не
  больше суммы положительных. А каждый положительный прирост берётся сделкой на один день.
- **Assign Cookies (455)** — отсортируй детей и печенье; самое маленькое подходящее печенье —
  самому нетребовательному из оставшихся. *Почему (заменой):* возьми лучшее решение. Если
  нетребовательный ребёнок там голоден, отдай ему печенье любого накормленного — счёт тот же.
  Если он ест печенье крупнее самого маленького подходящего, обменяй их: маленькое либо было
  свободно, либо досталось ребёнку не менее требовательному, и тому подойдёт крупное.

## 🧠 Почему это корректно

Жадный код всегда крошечный — вся сложность в **доказательстве**, что локальный выбор
ведёт к глобальному оптимуму. Без него жадность бывает уверенно неправильной.

### Когда жадность вообще применима

Нужны два свойства. **Свойство жадного выбора:** существует оптимальное решение,
содержащее локально оптимальный (жадный) выбор. **Оптимальная подструктура:** после
жадного выбора остаётся подзадача того же вида, и её оптимум достраивает ответ.

**Где ломается:** размен монетами произвольных номиналов (`{1, 3, 4}`, сумма `6`):
жадность берёт 4, потом 1 и 1 — три монеты, а оптимум — 3 + 3, две. Свойство жадного выбора
не держится → нужно [ДП](dynamic-programming.md). 0/1-рюкзак по отношению ценность/вес —
та же ловушка. Поэтому жадную гипотезу всегда надо **доказывать**, а не «чувствовать».

### Доказательство заменой для выбора заявок — полностью

Задача, код `maxActivities` и контрпримеры к другим правилам — в
[«Выборе заявок»](#выбор-заявок-activity-selection). Докажем, что сортировка по **концу** и
жадный захват оптимальны. Идея в одну фразу:
**любое лучшее расписание можно переделать так, чтобы оно начиналось с жадного выбора, и
хуже оно не станет.**

Возьми любое лучшее расписание и его первую заявку `a`. Жадная заявка `g` кончается раньше
всех вообще — значит, не позже `a`. Замени `a` на `g`: `g` освобождает зал не позже, чем `a`,
поэтому со второй заявкой расписания и дальше не пересечётся. Заявок столько же — расписание
всё ещё лучшее, и теперь оно начинается с `g`. Такое рассуждение называют **доказательством
заменой** (exchange argument).

После `g` остаётся та же задача поменьше: заявки, которые начинаются не раньше конца `g`.
Повторяя замену шаг за шагом (это и есть индукция), получаем, что жадный ответ не хуже
любого лучшего. «Жадный остаётся впереди» — другой приём из
[«Как доказать корректность»](#как-доказать-корректность): эту же задачу можно доказать и им,
но здесь обошлись заменой.

> **Ключ:** корректность держится именно на **ключе сортировки**. По концу — работает; по
> началу или по длительности — даёт неоптимум (контрпримеры — в «Выборе заявок»). Ключ
> сортировки *и есть* алгоритм.

## ⚙️ Цена на практике

### Настоящая стоимость — сортировка

Сам жадный проход линеен, но почти всегда ему предшествует `sort` → реальная сложность
**`O(n log n)`**. Не заявляй «O(n)», если отсортировал вход. `Jump Game` — исключение:
там жадность работает по уже данному массиву за чистое `O(n)`.

### Доказывай вслух — иначе рискуешь быть уверенно неправым

На собеседовании жадное решение **без обоснования** опасно: код проходит примеры, но
критерий может быть неверным. Проговори доказательство заменой или «жадный остаётся впереди» —
это отличает инженера от угадывающего.

### Как быстро проверить жадную гипотезу

Прежде чем коммитить жадность — сравни её с brute-force на маленьких случайных входах
(как в рандом-тестах тренажёра — пакет `exercises/greedy`). Если
хоть раз разошлись — критерий неверен, и ты только что сэкономил себе провал на сложном
тесте. Это дешёвая инженерная привычка.

> 🔧 **Где это в Go.** Канонический жадный алгоритм живёт в стандартной библиотеке:
> [`compress/flate`](https://pkg.go.dev/compress/flate) (это gzip/zip) строит **код Хаффмана** —
> жадно сливает два наименее частых символа, пока не останется одно дерево
> ([`huffman_code.go`](https://github.com/golang/go/blob/master/src/compress/flate/huffman_code.go)).
> Это жадность с доказуемым оптимумом — как интервальное планирование из этой главы: каждый раз,
> когда твой сервис отдаёт сжатый ответ, внутри отработал жадный алгоритм.

## ⚠️ Типичные ошибки

1. **Неверный критерий жадности** — для выбора заявок сортировка по началу или по
   длительности даёт неоптимум; правильно — по концу.
2. **Применение жадности без доказательства** — для многих задач (Coin Change,
   0/1 рюкзак) жадность неверна, нужно ДП.
3. **Игнорирование граничных случаев** — пустой вход, один элемент, совпадающие границы
   интервалов.

## 📝 Разбор задачи

Перебор и наблюдение — в [«🧭 Откуда берётся жадность»](#-откуда-берётся-жадность-выведем-её-сами):
флаги достижимости без дыр сжимаются в одно число `maxReach`. Здесь — код и трасса той же задачи.

> **Задача (Jump Game).** Дан массив неотрицательных целых `nums`. Стоя на индексе `i`,
> можно прыгнуть вперёд на любое число шагов от `1` до `nums[i]`. Достижим ли последний
> индекс, стартуя с нулевого?
> Пример: `nums = [2,3,1,1,4]` → `true` (например, `0→1→4`); `nums = [3,2,1,0,4]` →
> `false` (на индексе `3` стоит `0`, дальше не прыгнуть).

**В лоб: флаги достижимости.** Пометки из «🧭» на полном входе — из каждой достижимой клетки
метим весь диапазон прыжка, и одни клетки помечаются по нескольку раз:

<div class="algo-viz" data-viz="jump-game-dp" data-array="2,3,1,1,4"></div>

**Оптимум: один проход с `maxReach` — O(n), O(1) памяти.** Код — функция `canJump` из
[шаблона «⚡»](#-шаблон-для-собеседования). Прогони её на `nums = [2,3,1,1,4]`: `maxReach`
тянется вправо, и пока индекс не обгонит его — последний достижим:

<div class="algo-viz" data-viz="jump-game" data-array="2,3,1,1,4"></div>

**Трассировка** на `nums = [2,3,1,1,4]`:

| `i` | `nums[i]` | `i > maxReach`? | `i + nums[i]` | `maxReach` после |
|-----|-----------|-----------------|---------------|------------------|
| 0   | 2         | `0 > 0` — нет   | 2             | 2                |
| 1   | 3         | `1 > 2` — нет   | 4             | 4                |
| 2   | 1         | `2 > 4` — нет   | 3             | 4                |
| 3   | 1         | `3 > 4` — нет   | 4             | 4                |
| 4   | 4         | `4 > 4` — нет   | 8             | 8                |

Цикл дошёл до конца без `return false` → ответ **`true`**. На `[3,2,1,0,4]` к индексу `4`
горизонт застрял на `maxReach = 3` (после `0` на индексе `3`), условие `4 > 3` срабатывает
→ **`false`**, что совпадает с флагами достижимости.

<div class="algo-challenge" data-type="choice" data-options="Ранний конец оставляет максимум времени остальным — доказывается заменой|Так проще писать код|Это работает случайно, без доказательства" data-answer="0" data-explain="Доказательство заменой: в любом оптимальном расписании первую встречу можно заменить на встречу с самым ранним концом, не ухудшив результат. Значит, жадный выбор ведёт к оптимуму. В этом отличие доказуемой жадности от эвристики.">
<div class="algo-challenge__q">Почему критерий «самый ранний конец» доказуемо оптимален?</div>

<div class="algo-challenge" data-type="choice" data-options="Здесь жадный выбор доказуемо глобально оптимален — ДП не нужно|Ничем, это одно и то же|Жадность тут медленнее ДП" data-answer="0" data-explain="Ключевое отличие: для этой задачи есть ДОКАЗАТЕЛЬСТВО, что локальный жадный выбор ведёт к глобальному оптимуму. Для coin change {1,3,4} такого доказательства нет (и есть контрпример) — там нужно ДП. Всегда спрашивай: доказуем ли жадный выбор?">
<div class="algo-challenge__q">Чем этот случай отличается от размена монет, где нужно ДП?</div>
</div>

**Вывод.** Интервальное планирование «максимум непересекающихся» — жадность по **самому раннему концу**, и
здесь она **доказуемо** оптимальна (доказательство заменой). Мораль паттерна: прежде чем брать жадность —
попробуй сломать её контрпримером, не сломалась — докажи заменой, а не надейся.

    <div class="algo-mental__title">Что унести</div>
    <ul>
      <li><b>Сигнал.</b> «Максимум непересекающихся», «можно ли допрыгнуть до конца массива», очевидный критерий сортировки — по концу интервала, по стоимости.</li>
      <li><b>Должно быть верно.</b> Есть доказательство — заменой или «жадный остаётся впереди», — что какой-то оптимум содержит локально лучший выбор, а остаток — задача того же вида.</li>
      <li><b>Ломается</b>, когда свойство жадного выбора не держится: монеты {1, 3, 4} на сумму 6 — жадный берёт 4 + 1 + 1, а оптимум 3 + 3; тогда <a href="dynamic-programming.md">ДП</a>.</li>
    </ul>

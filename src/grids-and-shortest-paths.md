## 🎬 Визуализация

> 💡 **Интерактивная демонстрация (BFS по сетке).** Волна BFS идёт от `S` к `G`, огибая
> препятствия (тёмные клетки). Жёлтая — текущая, синие — посещённые. Справа — код с подсветкой
> строки и переменные (клетка, расстояние), внизу — кликабельные шаги. Можно подставить свою сетку
> и нажать «⟲ Запустить». (Виджет работает в собранной книге `mdbook serve`/`mdbook build`, а не
> при просмотре `.md` на GitHub.)

## ⚡ Шаблон для собеседования

```go
var dirs = [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}}

// BFS по сетке: кратчайшее число шагов
queue := [][2]int{{sr, sc}}
dist[sr][sc] = 0
for len(queue) > 0 {
    cell := queue[0]; queue = queue[1:]
    r, c := cell[0], cell[1]
    for _, d := range dirs {
        nr, nc := r+d[0], c+d[1]
        if inBounds(nr, nc) && grid[nr][nc] == 0 && dist[nr][nc] < 0 {
            dist[nr][nc] = dist[r][c] + 1
            queue = append(queue, [2]int{nr, nc})
        }
    }
}
```

1. 4 направления через массив смещений;
2. **проверка границ** перед доступом;
3. посещаем клетку только если она свободна и ещё не размечена;
4. для весов — замени очередь на мин-кучу (Дейкстра).

## 📖 Разбор

<details class="algo-details">
<summary>Сетки, Number of Islands, Дейкстра и сравнение алгоритмов</summary>

Двумерная сетка — это граф, где **вершина** — клетка `(r, c)`, а **рёбра** ведут к
соседним клеткам (обычно 4, иногда 8 с диагоналями).

```go
var dirs = [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}}
```

#### Number of Islands

Подсчёт компонент связности на сетке: запускаем обход из каждой непосещённой клетки-суши,
«затапливая» весь остров.

```go
func numIslands(grid [][]int) int {
    rows := len(grid)
    if rows == 0 {
        return 0
    }
    cols := len(grid[0])
    visited := make([][]bool, rows)
    for i := range visited {
        visited[i] = make([]bool, cols)
    }
    var dfs func(r, c int)
    dfs = func(r, c int) {
        if r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] == 0 || visited[r][c] {
            return
        }
        visited[r][c] = true
        dfs(r-1, c); dfs(r+1, c); dfs(r, c-1); dfs(r, c+1)
    }
    count := 0
    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            if grid[r][c] == 1 && !visited[r][c] {
                count++
                dfs(r, c)
            }
        }
    }
    return count
}
```

> 💡 **Multi-source BFS.** Если фронт распространяется из нескольких точек (гниющие
> апельсины, пожар), загрузите в очередь **сразу все** старты и обходите по уровням —
> каждый уровень это шаг времени.

#### Алгоритм Дейкстры

Для **неотрицательных** весов: жадно расширяем границу, выбирая ещё не финализированную
вершину с минимальным известным расстоянием (мин-куча, см. [Two Heaps](two-heaps.md)).

> 💡 **Интерактивная демонстрация (Дейкстра).** Из приоритетной очереди извлекается ближайшая
> вершина (жёлтая) — её расстояние **финально** (синие); затем по её рёбрам идёт **релаксация**:
> подпись `dist` под соседом уменьшается, если найден более короткий путь. Видно и «ленивое
> удаление» устаревших записей. Справа — код с подсветкой строки и переменные (`u`, `dist[u]`,
> очередь, ребро). Можно подставить свой граф. (Виджет работает в собранной книге.)

<div class="algo-viz" data-viz="dijkstra" data-nodes="A,B,C,D,E" data-edges="A-C-1,A-B-4,C-B-2,B-D-1,C-D-5,D-E-3,B-E-7" data-start="0"></div>

```go
func dijkstra(n int, adj [][][2]int, src int) []int {
    const INF = 1 << 62
    dist := make([]int, n)
    for i := range dist {
        dist[i] = INF
    }
    dist[src] = 0
    h := &pq{{node: src, dist: 0}}
    for h.Len() > 0 {
        cur := heap.Pop(h).(item)
        if cur.dist > dist[cur.node] {
            continue // устаревшая запись
        }
        for _, e := range adj[cur.node] {
            to, w := e[0], e[1]
            if nd := cur.dist + w; nd < dist[to] {
                dist[to] = nd
                heap.Push(h, item{node: to, dist: nd})
            }
        }
    }
    return dist
}
```

- **Только неотрицательные веса** (иначе Bellman–Ford).
- **«Ленивое» удаление**: в Go нет «уменьшить ключ», кладём новую запись, устаревшие
  отбрасываем проверкой `cur.dist > dist[cur.node]`.
- **Все рёбра веса 1?** Хватит обычного BFS за O(V+E).

#### Сравнение алгоритмов кратчайшего пути

| Алгоритм       | Веса рёбер      | Сложность        | Когда применять                    |
|----------------|-----------------|------------------|------------------------------------|
| BFS            | все равны (1)   | O(V + E)         | невзвешенный граф, сетки           |
| Дейкстра       | неотрицательные | O((V+E) log V)   | взвешенный граф без отрицат. рёбер |
| Bellman–Ford   | любые           | O(V · E)         | есть отрицательные рёбра/циклы     |

</details>

## 🧠 Почему это корректно

### Сетка — неявный граф

Список смежности не нужен: соседи вычисляются из `(r, c) ± dirs`. Подсчёт островов —
это [компоненты связности](graphs.md), затопление помечает всю компоненту. **Multi-source
BFS** корректен, потому что, загрузив все старты на уровень 0, мы получаем для каждой
клетки расстояние до **ближайшего** источника (свойство уровней BFS сохраняется и при
нескольких стартах).

### Почему жадность Дейкстры верна (неотрицательные веса)

Когда вершина извлекается из кучи с минимальным `dist`, это расстояние **окончательно**:
любой другой путь к ней шёл бы через ещё не финализированную вершину с расстоянием `≥`
текущего, а неотрицательные рёбра его только увеличат. Отрицательное ребро это
рассуждение ломает — тогда [Bellman–Ford](advanced-graph-algorithms.md).

## ⚙️ Цена на практике

### `visited` на месте против отдельного массива

Пометка прямо в сетке (затопить клетку в `0`/маркер) экономит `O(R·C)` памяти под
`visited`, но **мутирует вход**. Нельзя менять — заводи отдельный `visited`.

### Брать ли вообще Дейкстру

- все рёбра веса 1 → обычный **BFS** `O(V+E)` (без кучи — дешевле);
- неотрицательные веса → Дейкстра `O((V+E) log V)`;
- отрицательные → Bellman–Ford.

И «ленивое удаление»: в Go нет decrease-key, поэтому кладём новую запись и отбрасываем
устаревшие проверкой `cur.dist > dist[cur.node]` — иначе обработаем вершину повторно.

## ⚠️ Типичные ошибки

1. **Нет проверки границ сетки** перед доступом к `grid[nr][nc]` — паника index-out-of-range.
2. **Дейкстра с отрицательными весами** — даёт неверный результат; используйте Bellman–Ford.
3. **Не отбрасываются устаревшие записи** в куче — корректно, но медленнее; проверка `cur.dist > dist[cur.node]` важна.
4. **BFS вместо Дейкстры на взвешенном графе** — кратчайший по числу рёбер ≠ по сумме весов.
5. **Сетка с диагоналями** — если соседей восемь, не забудьте 4 диагональных смещения.

## 📝 Разбор задачи

Пройдём путь от наивного решения к оптимальному — так, как стоит рассуждать на
собеседовании: сначала рабочая симуляция, затем понимание, *почему* она медленная, и
только потом BFS из нескольких источников.

> **Задача (Rotting Oranges).** Дана сетка `grid`, где `0` — пусто, `1` — свежий
> апельсин, `2` — гнилой. Каждую минуту гнилой апельсин заражает соседей по 4
> направлениям. Сколько минут пройдёт, пока **все** свежие сгниют? Если хотя бы один
> недостижим — вернуть `-1`.
> Пример: `[[2,1,1],[1,1,0],[0,1,1]]` → ответ `4`.

**Шаг 1. Наивно: симулировать поминутно, сканируя всю сетку — O((R·C)²).**

```go
func orangesRottingNaive(grid [][]int) int {
    rows, cols := len(grid), len(grid[0])
    minutes := 0
    for {
        // снимок: свежезаражённые в эту же минуту дальше пока не заражают
        snap := make([][]int, rows)
        for i := range grid {
            snap[i] = append([]int(nil), grid[i]...)
        }
        changed := false
        for r := 0; r < rows; r++ {
            for c := 0; c < cols; c++ {
                if snap[r][c] != 2 {
                    continue
                }
                for _, d := range dirs {
                    nr, nc := r+d[0], c+d[1]
                    if nr >= 0 && nr < rows && nc >= 0 && nc < cols && snap[nr][nc] == 1 {
                        grid[nr][nc] = 2
                        changed = true
                    }
                }
            }
        }
        if !changed {
            break
        }
        minutes++
    }
    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            if grid[r][c] == 1 {
                return -1 // остался недостижимый свежий
            }
        }
    }
    return minutes
}
```

Это **работает и проходит тесты**, но за каждую минуту заново проходит **всю** сетку,
а минут может быть до `R·C` — итого O((R·C)²). Почти весь труд — это повторное
сканирование уже отработавших клеток.

Прогоните наивную симуляцию: каждую минуту мы пересканируем ВСЮ сетку в поисках гнилых
(счётчик «сканов сетки» растёт) — результат тот же, но работы кратно больше:

<div class="algo-viz" data-viz="oranges-rotting-naive" data-grid="2,1,1;1,1,0;0,1,1"></div>

**Шаг 2. Ключевое наблюдение.** «Минута» — это в точности **уровень BFS**. Если
загрузить в очередь **сразу все** гнилые апельсины (multi-source), то на `i`-й волне
заразятся ровно те свежие, до которых ближайший гнилой добирается за `i` минут — это
[свойство уровней BFS при нескольких стартах](#сетка--неявный-граф). Каждую клетку
посещаем один раз, заражаем один раз — пересканировать ничего не нужно.

> 💡 Это тот же приём, что в callout «Multi-source BFS» выше: один виртуальный
> «суперисточник» соединён со всеми стартами рёбрами веса 0, поэтому уровень волны =
> минута гниения.

**Шаг 3. Оптимум: multi-source BFS, уровни = минуты — O(R·C).**

```go
func orangesRotting(grid [][]int) int {
    rows, cols := len(grid), len(grid[0])
    queue := make([][2]int, 0)
    fresh := 0
    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            switch grid[r][c] {
            case 2:
                queue = append(queue, [2]int{r, c}) // все старты на уровень 0
            case 1:
                fresh++
            }
        }
    }
    if fresh == 0 {
        return 0 // нечему гнить — ноль минут
    }
    minutes := 0
    for len(queue) > 0 && fresh > 0 {
        var next [][2]int
        for _, cell := range queue { // обрабатываем весь текущий уровень
            r, c := cell[0], cell[1]
            for _, d := range dirs {
                nr, nc := r+d[0], c+d[1]
                if nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] == 1 {
                    grid[nr][nc] = 2 // помечаем прямо в сетке
                    fresh--
                    next = append(next, [2]int{nr, nc})
                }
            }
        }
        queue = next
        minutes++
    }
    if fresh > 0 {
        return -1 // остались изолированные свежие
    }
    return minutes
}
```

Обработка по слоям (`queue` → `next`) даёт счётчик минут «бесплатно»: одно
приращение `minutes` на волну. Счётчик `fresh` избавляет от финального скана — как
только он обнулился, можно останавливаться, а если остался `> 0` — это и есть `-1`.

Прогоните волны гниения на `grid = [[2,1,1],[1,1,0],[0,1,1]]`: гнилые апельсины (🦠) —
источники на минуте 0, и каждую минуту заражаются свежие 4-соседи (🍊):

<div class="algo-viz" data-viz="oranges-rotting" data-grid="2,1,1;1,1,0;0,1,1"></div>

**Шаг 4. Трассировка** на `grid = [[2,1,1],[1,1,0],[0,1,1]]` (волны BFS по минутам):

| минута | очередь (заразились на этой волне) | `fresh` после волны | сетка (`.`=пусто, `2`=гнилой, `1`=свежий) |
|--------|------------------------------------|---------------------|-------------------------------------------|
| 0      | `(0,0)` — стартовый гнилой          | 6                   | `211 / 110 / .11`                         |
| 1      | `(0,1) (1,0)`                       | 4                   | `221 / 210 / .11`                         |
| 2      | `(0,2) (1,1)`                       | 2                   | `222 / 220 / .11`                         |
| 3      | `(2,1)`                             | 1                   | `222 / 220 / .21`                         |
| 4      | `(2,2)`                             | 0                   | `222 / 220 / .22`                         |

Ответ — `4`. Обрати внимание: клетка `(2,1)` достижима только сверху из `(1,1)`
(клетка `(2,0)` пуста), поэтому она гниёт лишь на 3-й минуте, а не раньше — волна
честно обходит препятствия. Каждая клетка попала в очередь ровно один раз — тот самый
[O(R·C)](#сравнение-алгоритмов-кратчайшего-пути).

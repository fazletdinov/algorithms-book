> 🧭 **Зачем отдельная глава.** Куча — это **массив, который ведёт себя как полное двоичное
> дерево**: ребёнок индекса `i` лежит в `2i+1` и `2i+2`, родитель — в `(i-1)/2`. Вся механика —
> два просеивания (вверх при вставке, вниз при извлечении), и пока ты не увидел, как элемент
> «всплывает» и «тонет» по дереву, паттерны на кучах ([Two Heaps](two-heaps.md),
> [Top K](top-k-elements.md), [K-way Merge](k-way-merge.md)) выглядят магией. Здесь строим саму
> кучу; применения — в главах-паттернах.

> 🎬 **Интерактив устроен по принципу «функция → её визуализация».** Каждая операция ниже идёт со
> своим виджетом сразу после кода: вставка и извлечение. Под деревом показан backing-массив — видно
> соответствие «индекс ↔ позиция в дереве». Виджеты работают в собранной книге.

## 🧱 Как устроена куча

Куча хранится в **обычном массиве**, но читается как полное двоичное дерево. Никаких указателей:
связь «родитель–ребёнок» задаётся арифметикой индексов.

```go
type Heap struct {
    data []int // min-куча: data[(i-1)/2] <= data[i]
}

func parent(i int) int { return (i - 1) / 2 }
func left(i int) int   { return 2*i + 1 }
func right(i int) int  { return 2*i + 2 }
```

```
индексы:   0   1   2   3   4   5
массив:  [ 1 | 3 | 2 | 7 | 4 | 5 ]

как дерево:        1(0)
                 /      \
              3(1)       2(2)
             /   \      /
          7(3)  4(4)  5(5)
```

Три факта, которые держат всё:

1. **Инвариант кучи — частичный, а не полный порядок.** Родитель ≤ детей, но `3` и `2` (соседи)
   между собой не упорядочены. Поэтому куча **не** заменяет отсортированный массив — она даёт
   только быстрый доступ к экстремуму, а не полный порядок.
2. **Дерево всегда полное.** Узлы заполняют уровни слева направо без дыр — поэтому массив плотный,
   а высота ровно `⌊log₂ n⌋`. Отсюда O(log n) у обеих операций.
3. **Минимум — в корне.** Из инварианта по индукции: корень ≤ всех. `Peek` — это `data[0]`, O(1).

## ➕ Вставка: `Push` (просеивание вверх)

Кладём новый элемент **листом в конец массива** (чтобы дерево осталось полным), а затем
**просеиваем вверх**: пока он меньше родителя — меняем их местами. Так нарушение инварианта
«всплывает» к корню, остальное дерево не трогаем.

```go
func (h *Heap) Push(val int) {
    h.data = append(h.data, val)   // новый лист в конец массива
    i := len(h.data) - 1
    for i > 0 {                    // просеивание вверх
        parent := (i - 1) / 2
        if h.data[parent] <= h.data[i] {
            break                  // порядок восстановлен
        }
        h.data[i], h.data[parent] = h.data[parent], h.data[i]
        i = parent
    }
}
```

> 💡 **Демонстрация вставки.** В кучу `[1,3,2,7,4,5]` добавляем `0`. Новый лист встаёт в конец
> (индекс 6), затем всплывает: `0 < 2` (родитель) — swap, `0 < 1` (новый родитель) — swap, и `0`
> становится корнем. Подставь своё значение и кучу.

## 🔺 Извлечение: `Pop` (просеивание вниз)

Минимум — это корень. Чтобы его извлечь и сохранить полноту дерева: забираем корень,
**последний лист переносим в корень**, отрезаем хвост и **просеиваем вниз** — меняем узел с
**меньшим из детей**, пока он не окажется не больше обоих.

```go
func (h *Heap) Pop() int {
    min := h.data[0]               // корень — минимум
    last := len(h.data) - 1
    h.data[0] = h.data[last]       // последний лист → в корень
    h.data = h.data[:last]         // отрезаем хвост
    i, n := 0, len(h.data)
    for {                          // просеивание вниз
        l, r, small := 2*i+1, 2*i+2, i
        if l < n && h.data[l] < h.data[small] { small = l }
        if r < n && h.data[r] < h.data[small] { small = r }
        if small == i { break }    // порядок восстановлен
        h.data[i], h.data[small] = h.data[small], h.data[i]
        i = small
    }
    return min
}
```

> 💡 **Демонстрация извлечения.** Из `[1,3,2,7,4,5]` извлекаем минимум `1`. Последний лист `5`
> переезжает в корень, затем тонет: сравниваем с детьми, меняем с меньшим (`2`), пока куча не
> восстановится. Возвращается `1`.

## 🧠 Почему это корректно

### Почему минимум всегда в корне

Инвариант «родитель ≤ детей» по индукции даёт: корень ≤ своих детей ≤ их детей ≤ … ≤ всех узлов.
Значит наименьший элемент — в корне, и `Peek` берёт его за O(1). (Для max-кучи симметрично:
родитель ≥ детей, максимум в корне.)

### Почему просеивание восстанавливает инвариант

И `Push`, и `Pop` создают **ровно одно** локальное нарушение: новый лист может быть меньше
родителя (Push), а перенесённый в корень лист — больше детей (Pop). Просеивание двигает это
нарушение по **одному ребру за шаг** к листу или к корню, меняя местами с нужным соседом; в
остальном дереве инвариант не трогается. Когда менять больше не нужно — нарушение исчезло
везде. Длина пути ≤ высоты, поэтому O(log n).

### Почему именно с меньшим ребёнком вниз

При просеивании вниз меняться надо с **меньшим** из двух детей. Иначе наверх поднимется не
наименьший — и больший ребёнок окажется родителем меньшего, снова нарушив инвариант. Меньший
ребёнок ≤ и узла, и второго ребёнка, поэтому после обмена он корректно становится родителем.

## ⚙️ Цена на практике

### Куча против отсортированной структуры

Если нужен **только** экстремум, куча бьёт отсортированный массив/дерево: `Push`/`Pop` за
O(log n) против O(n) на поддержание полного порядка, который тебе не нужен. Но куча **не**
отвечает на «найди произвольный ключ» или «дай k-й по порядку» — там нужен BST или сортировка.

### Массив вместо указателей — и это важно

Куча на массиве плотная и дружелюбна к кэшу (никаких разбросанных узлов, как в дереве на
указателях), а связи — это арифметика индексов. Поэтому на практике куча часто быстрее «честного»
дерева той же асимптотики. Построить кучу из готового среза можно за **O(n)** (heapify: просеивать
вниз от последнего родителя к корню), а не O(n log n) поэлементными вставками.

### В Go куча — это `container/heap`

Стандартная библиотека даёт `container/heap`: ты реализуешь интерфейс (`Len`, `Less`, `Swap`,
`Push`, `Pop`) на своём срезе, а пакет делает просеивания. `Less` задаёт min- или max-кучу (а
также приоритет по своему полю). Понимать ручную реализацию всё равно нужно — `container/heap`
именно её и оркеструет.

## ⚠️ Типичные ошибки

1. **Путают кучу с сортировкой** — куча даёт только экстремум, соседи по уровню не упорядочены.
2. **Просеивание вниз с бо́льшим ребёнком** — снова ломает инвариант; меняться надо с меньшим (для min-кучи).
3. **Pop без переноса последнего листа** — нарушает полноту дерева; нельзя просто «удалить корень».
4. **0/1-индексация детей** — для 0-индексации дети это `2i+1`/`2i+2`, родитель `(i−1)/2`; перепутал — выход за границы.
5. **Сравнение не туда (min vs max)** — знак в сравнении задаёт тип кучи; перепутал — получишь не тот экстремум.

## 🏋️ Тренажёр

Соберите min-кучу на срезе руками (без `container/heap`) — `siftUp`/`siftDown` и есть весь алгоритм:

```bash
cd exercises
go test ./binheap/                 # ваша реализация (красные)
go test -tags solution ./binheap/  # эталон (зелёные)
```

Пакет `binheap`: `NewHeap`, `Push`/`Pop`/`Peek`/`Len`. Push добавляет в конец и всплывает; Pop
ставит в корень последний элемент и погружает его. Проверь, что извлечение даёт элементы по
возрастанию (это, по сути, heapsort).

> 📌 В тренажёре `Pop`/`Peek` возвращают `(значение, ok bool)`, а не паникуют на пустой куче, как
> упрощённый `Pop() int` выше — так идиоматичнее в Go. Конструктор — `NewHeap()`.

Кучи как готовый инструмент активно используются и в прикладных пакетах:

```bash
go test ./topk/       # k наибольших через кучу
go test ./twoheaps/   # медиана потока двумя кучами
```

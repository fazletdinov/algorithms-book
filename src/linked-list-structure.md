## 🧱 Как устроен узел

Узел односвязного списка — это **значение** и **ссылка на следующий узел**. Самого «массива»
нет: узлы разбросаны по памяти и держатся вместе только ссылками `Next`. Список — это указатель
на первый узел (`head`); последний узел указывает на `nil`.

```go
type ListNode struct {
    Val  int
    Next *ListNode // следующий узел; nil — конец списка
}
```

<div class="algo-fig" data-fig="list" data-list="1,2,3" data-ptrs="head@0" data-caption="Список 1 → 2 → 3: head — указатель на первый узел, Next последнего — nil. Наведи на узел — загорится путь до него от головы"></div>

Три факта, которые определяют всё поведение:

1. **Доступа по индексу нет.** Чтобы добраться до k-го узла, идём от головы по `Next` ровно
   k раз — отсюда O(n) на поиск и «доступ по позиции».
2. **Зато правка локальна.** Если узел перед местом правки уже в руках, вставка и удаление —
   это перецепление пары ссылок, O(1), без сдвига остального (в массиве сдвиг — O(n)).
3. **Ссылка — единственная связь.** Перезаписав `Next`, ты теряешь доступ к остатку. Поэтому
   главное правило всех операций: **сначала сохрани то, что собираешься перезаписать.**

Оговорка второго факта важна: O(1) — только если узел перед местом правки уже в руках. Если до
него ещё надо дойти от головы, к правке добавляется O(n) на путь.

## ➕ Вставка: `insertAt`

Вставка — это дойти до узла перед нужной позицией и **перецепить две ссылки**: новый узел
указывает на остаток, предыдущий — на новый. Фиктивная голова (`dummy`) перед списком убирает
спецслучай вставки в самое начало.

```go
func insertAt(head *ListNode, val, pos int) *ListNode {
    dummy := &ListNode{Next: head}
    prev := dummy
    for i := 0; i < pos && prev.Next != nil; i++ {
        prev = prev.Next         // идём к узлу перед позицией
    }
    node := &ListNode{Val: val}  // создаём узел
    node.Next = prev.Next        // 1. новый узел → остаток
    prev.Next = node             // 2. предыдущий → новый
    return dummy.Next
}
```

Порядок двух присваиваний критичен: сначала `node.Next = prev.Next` (привязали хвост к новому
узлу), потом `prev.Next = node`. Сделай наоборот — и `prev.Next` уже перезаписан: следующая
строка `node.Next = prev.Next` прочитает в нём сам `node`. Новый узел `9` укажет сам на себя,
узел `3` потерян, а обход после `9` пойдёт по кругу.

> 💡 **Демонстрация вставки.** В список `3→7→1→8→5` вставляем `9` в позицию `3`. Сначала `prev`
> шагает от `dummy` через три узла к `1` — это и есть цена вставки в середину, O(n). Дальше новый
> узел висит отдельно (`9 → nil`), потом смотрит на остаток (`9 → 8`) — список при этом ещё не
> изменился, — и только последним шагом стрелка из `prev` переключается на него. Изменённая
> стрелка подсвечена. В «Граничных случаях» — позиция `0`: проход исчезает, вставка в начало O(1).

## 🔎 Поиск: `search`

Найти узел по значению можно только линейным проходом: идём от головы по ссылкам и сравниваем
`Val` с целью. Перепрыгнуть вперёд нельзя — следующий узел известен только из `Next`, поэтому
каждый запрос — O(n), и для частого поиска список плох.

```go
func search(head *ListNode, target int) *ListNode {
    for node := head; node != nil; node = node.Next {
        if node.Val == target {
            return node          // нашли
        }
    }
    return nil                   // дошли до nil — значения нет
}
```

> 💡 **Демонстрация поиска.** Ищем `23` в списке `4→8→15→16→23→42`: указатель идёт по узлам,
> сравнивая значение с целью, и останавливается на совпадении — пятое сравнение. Прыгнуть сразу
> в середину, как в массиве, нельзя: до пятого узла доходят только через четыре предыдущих.
> Попробуй искомое `9` — пройдём весь список до `nil` и вернём «не найдено».

## 🗑️ Удаление: `deleteVal`

Чтобы удалить узел в односвязном списке, нужен **предыдущий** узел: именно его `Next` мы
перецепляем «через» удаляемый. Фиктивная голова снова снимает спецслучай удаления самой головы.

```go
func deleteVal(head *ListNode, target int) *ListNode {
    dummy := &ListNode{Next: head}
    prev := dummy
    for prev.Next != nil {
        if prev.Next.Val == target {
            prev.Next = prev.Next.Next  // вырезаем узел из цепочки
            break
        }
        prev = prev.Next
    }
    return dummy.Next
}
```

Удаление — это одна перезапись: `prev.Next = prev.Next.Next`. Узел просто выпадает из цепочки
(на него больше никто не ссылается — в Go его уберёт сборщик мусора). Никакого сдвига, как в
массиве, не происходит.

> 💡 **Демонстрация удаления.** Удаляем `16` из `4→8→15→16→23→42`: идём до узла перед целью,
> перецепляем ссылку через него — стрелка из `15` перепрыгивает `16`, и цепочка становится
> `4→8→15→23→42`. Сам `16` остаётся строкой «вне списка»: его `Next` всё ещё смотрит на `23`, но на
> него не смотрит никто. Попробуй значение, которого нет, — список не изменится.

## ↔️ Двусвязный список: ссылка назад

Всё выше — про **односвязный** список: у узла одна ссылка, и назад пути нет. Добавь вторую —
`Prev` — и получится **двусвязный** список:

```go
type DNode struct {
    Val        int
    Prev, Next *DNode
}
```

Что покупает вторая ссылка:

- **Удаление за O(1), имея только сам узел.** Односвязному нужен `prev` (за ним `deleteVal`
  и ходит по всей цепочке) — двусвязный узел носит его с собой:
  `node.Prev.Next = node.Next; node.Next.Prev = node.Prev` — и узел выпал.
- **Обход в обе стороны**: от хвоста к голове без всякого разворота.

Цена — лишний указатель в каждом узле и вдвое больше перецеплений при правке. Вставка теперь
переписывает **четыре** ссылки вместо двух, удаление — две вместо одной. Забудешь одну — список
останется «полуразорванным»: обход вперёд и обход назад покажут разные списки. Спецслучаи краёв
(у головы нет `Prev`, у хвоста нет `Next`) решают тем же приёмом, что и `dummy` выше, — фиктивным
узлом-стражем с обоих концов (или кольцом через один страж, как в `container/list`).

Именно двусвязный список лежит в основе [дека](deque-structure.md) (очереди, работающей с обоих концов), `container/list` из
стандартной библиотеки и LRU-кэша (врезка ниже): кэшу нужно за O(1) выдёргивать
узел из **середины** и переносить в голову — а это ровно то, что даёт `Prev`.

> 🔧 **Где это в Go.** Двусвязный список — основа **LRU-пула соединений** в `net/http.Transport`:
> `idleLRU` (тип `connLRU` поверх [`container/list`](https://pkg.go.dev/container/list) + map) хранит
> праздные keep-alive соединения и выбрасывает самое давнее при переполнении `MaxIdleConns`. Полный
> разбор **почему список + map** —
> [«Структуры данных в экосистеме Go»](go-stdlib-structures.md#-разбор-почему-пул-соединений--это-список--map-lru).

## ↩️ Разворот списка

Разворот — высшая точка правила «сначала сохрани то, что перезапишешь»: идём по списку и у
каждого узла разворачиваем `Next` назад, на предыдущий узел. Указателей три: `prev` — уже
развёрнутая часть, `curr` — узел, который разворачиваем сейчас, `next` — сохранённый остаток.

```go
func reverseList(head *ListNode) *ListNode {
    var prev *ListNode
    curr := head
    for curr != nil {
        next := curr.Next // сначала сохрани остаток
        curr.Next = prev  // разверни ссылку назад
        prev = curr       // развёрнутая часть выросла на узел
        curr = next       // переходим к остатку
    }
    return prev // последний узел стал головой
}
```

Прогон на `1 → 2 → 3`, состояние после каждой итерации:

| Итерация | `next` | `prev` — развёрнуто | `curr` — осталось |
|---|---|---|---|
| старт | — | `nil` | `1 → 2 → 3 → nil` |
| 1 | `2` | `1 → nil` | `2 → 3 → nil` |
| 2 | `3` | `2 → 1 → nil` | `3 → nil` |
| 3 | `nil` | `3 → 2 → 1 → nil` | `nil` |

Цикл кончается, когда `curr` стал `nil`, и `prev` держит новую голову `3`. Время O(n), память
O(1): каждую ссылку переписали ровно один раз, на месте. Не сохрани `next` — и уже на первой
итерации `curr.Next = prev` отрежет остаток `2 → 3`: дойти до него больше не по чему (ошибка №1
ниже).

Варианты — разворот участка, группами по `k`, проверка палиндрома, рекурсивная версия — в главе
расширения [«Reverse Linked List»](reverse-linked-list.md), с визуализацией и задачами. Для ядра
хватает этих строк.

## 🧠 Почему это корректно

### Фиктивная голова убирает спецслучай

`dummy := &ListNode{Next: head}` даёт «предыдущего» и первому узлу, поэтому `prev.Next = …`
одинаково работает и для головы. В конце `dummy.Next` — актуальная голова, даже если она сменилась.

### Разворот держит инвариант

Разворот держится на **инварианте** — утверждении, верном перед каждой итерацией цикла: `prev` —
уже развёрнутая часть, `curr` — нетронутый остаток, и вместе в них все узлы. Итерация переносит
один узел из головы `curr` в голову `prev` — сохранив `next` заранее, по правилу из
[трёх фактов](#-как-устроен-узел), — и утверждение остаётся верным. Цикл кончается на
`curr == nil` — значит, в `prev` весь список задом наперёд.

## ⚙️ Цена на практике

### Погоня за указателями и кэш

Узлы списка разбросаны по памяти, поэтому обход «прыгает» по памяти — промахи кэша: процессор не находит
следующий узел в быстром кэше и ждёт основную память. Массив той же
длины обходится заметно быстрее за счёт локальности, даже при той же оценке O(n). На
практике это часто перевешивает «красивую» O(1)-вставку: список оправдан, когда вставок/удалений
действительно много.

## ⚠️ Типичные ошибки

1. **Потеря остатка** — перезаписали `Next` до того, как сохранили то, что он указывал.
2. **Разыменование `nil`** — обращение к `node.Next.Val`, не проверив, что `node.Next != nil`.
3. **Забыли фиктивную голову** — и городят отдельную ветку для вставки/удаления головы. В такой ветке легко ошибиться на единицу (off-by-one: цикл встаёт на узел раньше или позже нужного) и разыменовать `nil`.
4. **Удаление без предыдущего узла** — в односвязном списке нельзя удалить узел, имея только его самого (нужен `prev`).
5. **Разворот/обход списка с циклом** — зациклит; при сомнении сначала проверь отсутствие цикла ([Fast & Slow Pointers](fast-slow-pointers.md)).

## 🏋️ Тренажёр

Базовые операции узлов (`InsertAt`, `Search`, `DeleteVal`) — в пакете `listcrud` (те же, что
показаны виджетами выше), с одним отличием: `Search` там возвращает не узел, а его **индекс**
(или `-1`) — в табличном тесте ожидаемое число записать проще, чем указатель на узел. Проход тот же, добавь счётчик.

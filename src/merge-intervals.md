## 🧭 Откуда берётся сортировка по началу: выведем её сами

Первый пункт «Запомни» — «сначала отсортируй по началу» — выглядит подготовкой, а не алгоритмом.
На деле весь приём в нём: сортировка убирает вопросы, которые перебор задаёт по кругу.
Проследим на задаче.

> **Задача.** Дан список интервалов `[start, end]`. Слить все перекрывающиеся (касание
> границ — тоже перекрытие) и вернуть непересекающиеся. Пример: `[[1,3],[2,6],[8,10],[15,18]]`
> → `[[1,6],[8,10],[15,18]]`.

**Как решает человек.** Перебираю все пары; перекрывающуюся склеиваю в один интервал. Если за
проход что-то склеилось, прохожу ещё раз: новый интервал мог дотянуться до кого-то ещё.
Проход без единой склейки — готово.

**Где лишняя работа.** На примере первый проход делает 4 сравнения: `[1,3]` и `[2,6]`
склеиваются в `[1,6]`, потом `[1,6]` сверяется с `[8,10]` и `[15,18]`, а `[8,10]` — с
`[15,18]`. Склейка была — нужен второй проход, и он задаёт те же три вопроса заново:
`[1,6]`–`[8,10]`, `[1,6]`–`[15,18]`, `[8,10]`–`[15,18]`. Ответ «нет» на каждый известен с
первого прохода. Итого 7 сравнений на 4 интервала, из них 3 — повторы. И вопрос про `[1,6]` и
`[15,18]` вообще лишний: между ними лежит `[8,10]`.

**Что чинит.** Отсортируй по началу. Тогда с текущим интервалом может перекрыться только
последний собранный: все более ранние кончаются ещё до начала текущего. Вопрос «с кем я
перекрываюсь?» сужается с «со всеми» до «с последним» — одно сравнение на интервал и ни
одного повторного прохода. На примере — 3 сравнения вместо 7: `2 ≤ 3` — склеить, `8 ≤ 6` и
`15 ≤ 10` — нет. Вся цена переезжает в сортировку O(n log n).

Почему ранние блоки можно не проверять: блок `[1,6]` закрылся, потому что пришёл `[8,10]`, а
`8 > 6`. Всё, что придёт после `[8,10]`, начинается не раньше `8` — значит, тоже правее `6`. До
закрытого блока уже никто не дотянется, и сверять с ним больше нечего.

**Разложи брони по времени начала — и каждую достаточно сверить с последним блоком занятости:
всё, что раньше, уже закончилось.** Этот приём — слияние интервалов (merge intervals):
сортировка по началу и один проход. Виджет ниже гоняет тот же проход на другом входе — семь
интервалов вперемешку, среди них вложенный `[4,5]`: шесть сравнений, три блока. Код и трасса на
`[[1,3],[2,6],[8,10],[15,18]]` — в [«📝 Разбор задачи»](#-разбор-задачи).

## 🎬 Визуализация

> 💡 **Интерактивная демонстрация.** Сверху — исходные интервалы на числовой прямой (жёлтым
> подсвечен текущий), снизу — результат слияния, который растёт по мере прохода. Вход
> нарочно перемешан: первый шаг показывает его как пришёл, второй — после сортировки, и
> перекрывающиеся `[1,3]` и `[2,6]` становятся соседями. Следи за `[4,5]`: он целиком внутри
> `[1,6]`, и конец результата остаётся `6` — ради этого случая в коде `max`, а не просто
> «взять конец нового». Под холстом — строка шага и переменные, ниже — ползунок шагов (или ←/→ на клавиатуре) и код с подсветкой строки. Можно подставить свои интервалы
> и нажать «⟲ Запустить».

## ⚡ Шаблон для собеседования

```go
sort.Slice(intervals, func(i, j int) bool {
    return intervals[i][0] < intervals[j][0] // по началу
})
result := [][]int{intervals[0]}
for i := 1; i < len(intervals); i++ {
    cur, last := intervals[i], result[len(result)-1]
    if cur[0] <= last[1] {                 // перекрытие
        last[1] = max(last[1], cur[1])     // расширяем конец
    } else {                               // разрыв
        result = append(result, cur)       // новый интервал
    }
}
return result
```

1. сортируем по началу;
2. кладём первый интервал в результат;
3. для каждого следующего сравниваем `cur.start` с `last.end`;
4. перекрытие → расширяем `last.end`; разрыв → добавляем новый.

## 📖 Разбор

**Merge Intervals** — семья задач о перекрывающихся интервалах: слить их, вставить новый в
отсортированный список, найти пересечения двух списков. Слияние — шаблон
[«⚡»](#-шаблон-для-собеседования) выше; здесь — два других приёма семьи.

### Вставка интервала

Список уже отсортирован по началу и без перекрытий — сортировать не нужно. Новый интервал
делит его на три зоны, и один проход обходит их по очереди: интервалы **целиком левее** нового
(конец меньше его начала) копируем как есть; интервалы, которые с ним **перекрываются**,
поглощаем, растягивая его границы; всё, что **правее**, дописываем как есть.

На числах: вставляем `[4,8]` в `[[1,2],[3,5],[6,7],[8,10],[12,16]]`. Слева — `[1,2]`: его
конец `2 < 4`. Дальше поглощаем: `[3,5]` (начало `3 ≤ 8`) тянет начало нового к `3` —
получаем `[3,8]`; `[6,7]` лежит внутри и ничего не меняет; `[8,10]` касается (`8 ≤ 8`) и
тянет конец к `10` — `[3,10]`. `[12,16]` начинается правее `10` — он справа. Ответ:
`[[1,2],[3,10],[12,16]]`. Обрати внимание: обе границы нового могут сдвинуться, поэтому при
поглощении сравнивай и начало, и конец, а не только конец.

<details class="algo-details">
<summary>Если застрял: код вставки — сверься после своей попытки (это готовое решение LeetCode 57 и <code>intervals.InsertInterval</code>)</summary>

```go
func insertInterval(intervals [][]int, newInterval []int) [][]int {
    var result [][]int
    i, n := 0, len(intervals)

    for i < n && intervals[i][1] < newInterval[0] { // целиком слева
        result = append(result, intervals[i])
        i++
    }
    merged := []int{newInterval[0], newInterval[1]}
    for i < n && intervals[i][0] <= merged[1] { // перекрытие — поглощаем
        if intervals[i][0] < merged[0] {
            merged[0] = intervals[i][0]
        }
        if intervals[i][1] > merged[1] {
            merged[1] = intervals[i][1]
        }
        i++
    }
    result = append(result, merged)

    for i < n { // целиком справа
        result = append(result, intervals[i])
        i++
    }
    return result
}
```

</details>

### Пересечение двух интервалов

У закрытых `[a,b]` и `[c,d]` общая часть — от большего из начал до меньшего из концов:
`[max(a,c), min(b,d)]`. Она есть, только если левая граница не больше правой. `[2,6]` и
`[4,9]` → `[4,6]`; у `[1,3]` и `[5,8]` левая граница `5` больше правой `3` — общей части нет.

Раскрой «большее из начал ≤ меньшего из концов» на сравнения: каждое начало не позже каждого
конца. `a ≤ b` и `c ≤ d` верны у любого интервала, остаётся `a <= d && c <= b` — так проверяют,
перекрываются ли два интервала, не строя общую часть.

Для двух отсортированных списков интервалов (LeetCode 986) идут [двумя указателями](two-pointers.md):
запиши общую часть текущей пары, если она есть, и сдвинь указатель того интервала, что кончился
раньше, — дальше он ни с кем не пересечётся. `[[0,2],[5,10]]` и `[[1,5]]`: `[1,2]`, сдвигаем
первый; `[5,5]`, сдвигаем второй — список кончился, ответ `[[1,2],[5,5]]`.

### Почему сортировки по началу достаточно

Это довод из «🧭», только без чисел. Блок результата закрывается в одном случае: пришёл
интервал, который начинается правее его конца. Все следующие начинаются не раньше этого
интервала — значит, тоже правее конца закрытого блока, и дотянуться до него не может уже
никто. Поэтому сравнение лишь с последним блоком ничего не пропускает. Инвариант: `result`
всегда хранит непересекающиеся интервалы по возрастанию; очередной либо продлевает последний,
либо начинает новый.

Заодно упрощается проверка перекрытия. В общем случае `[a,b]` и `[c,d]` перекрываются при
`a <= d && c <= b`; после сортировки по началу `a <= c <= d`, первая половина верна сама, и
остаётся `cur[0] <= last[1]`.

### Почему по началу, а не по концу

Сортировка **по концу** решает *другую* задачу — выбрать как можно больше непересекающихся
отрезков (*Non-overlapping Intervals*, LeetCode 435; *Minimum Number of Arrows to Burst
Balloons*, LeetCode 452): при наложении двух соседей оставляют тот, что кончается раньше, а с
бо́льшим концом выкидывают: ранний конец оставляет больше места справа, поздний сильнее мешает следующим. Это [«Выбор заявок» в главе о жадности](greedy.md#выбор-заявок-activity-selection).
Для слияния она ломается: по концу `[1,10]`, `[5,6]`, `[2,3]` встанут как `[2,3]`, `[5,6]`,
`[1,10]`, и шаблон вернёт `[[2,3],[5,10]]` вместо `[[1,10]]`. Интервал `[1,10]` сверился только с
последним блоком, `[5,6]`, а до `[2,3]`, лежащего у него внутри, не дотянулся.

### Касание границ — это решение из условия, а не деталь

Сливаются ли `[1,2]` и `[2,3]`? Ответ зависит от того, **закрыты** интервалы (оба конца входят) или
полуоткрыты — правый конец не входит, как у [полуинтервала `[lo, hi)`](invariants.md#рабочий-пример-бинарный-поиск-без-страха-off-by-one) в бинарном поиске. Поэтому выбор `cur[0] <= last[1]` против
`<` — не мелочь реализации, а часть условия задачи: для закрытых `[start, end]`
(касание = перекрытие) берут `<=`, для полуоткрытых `[start, end)` — `<`. Зафиксируй
семантику в начале и держи её во всех сравнениях, иначе ответ «поедет» именно на стыках.

## ⚙️ Цена на практике

### Сортировка — это и есть стоимость

Слияние — `O(n log n)`, где доминирует **сортировка**; сам проход линеен. Не заявляй
`O(n)`. А вот **вставка** интервала — честные `O(n)`: вход уже отсортирован, сортировать
не нужно. Увидел «список уже упорядочен» — не сортируй заново.

### `sort.Slice` мутирует вход

`sort.Slice(intervals, …)` переставляет элементы **на месте** — порядок исходного среза
меняется. Срез ещё нужен в исходном порядке — копируй его перед сортировкой:
`cp := append([][]int(nil), intervals...)`.

Но одной этой копии мало. Каждый интервал — тоже срез, и `last` в шаблоне смотрит в тот же
массив, что интервал вызывающего: `last[1] = …` правит чужие данные. На `[[8,10],[1,3],[2,6]]`
вызывающий молча получит `[[8,10],[1,6],[2,6]]`. Нужна неприкосновенность входа — клади в
результат копии: `result := [][]int{{intervals[0][0], intervals[0][1]}}` и
`append(result, []int{cur[0], cur[1]})`.

Обратная ловушка: будь интервал массивом `[2]int` или структурой, `last` был бы копией, и
`last[1] = …` не менял бы ничего. Копии стоят `O(n)` памяти — та же дилемма «на месте против
копии», что у `slices.Sort` против `slices.Sorted`: первая переставляет твой срез, вторая
собирает отсортированный новый.

### Сканирующая прямая: сколько одновременно

Слияние — простейший случай **сканирующей прямой** (sweep line). Когда спрашивают не «слить»,
а «сколько максимум одновременно» (*Meeting Rooms II* — минимум переговорок), сливать не надо.
Преврати каждый интервал в два события — начало `+1`, конец `−1`, — отсортируй события по
времени и веди счётчик: его максимум и есть ответ. При равном времени конец идёт раньше
начала: встреча, которая кончилась в 10, освобождает комнату для той, что в 10 начинается
(касание — не наложение, см. [«Касание границ»](#касание-границ--это-решение-из-условия-а-не-деталь)).
Если касание считается перекрытием (закрытые отрезки), при равном времени ставь начало раньше
конца: встречи `[9,10]` и `[10,11]` тогда займут две комнаты.

На `[0,30],[5,10],[15,20]`: события `0:+1, 5:+1, 10:−1, 15:+1, 20:−1, 30:−1`, счётчик после
каждого — `1, 2, 1, 2, 1, 0`, максимум `2` — хватит двух переговорок. Тот же обход можно
сделать без общего списка событий — двумя указателями по отдельно отсортированным началам
`0,5,15` и концам `10,20,30`: начало раньше ближайшего конца — `+1` и следующее начало, иначе
`−1` и следующий конец.

### Динамические интервалы — не пересортировывать

Если интервалы приходят по одному и между вставками нужны запросы, пересортировка каждый
раз — `O(n log n)` на операцию. **Дерево интервалов** — дерево поиска по началам, где узел помнит наибольший конец среди себя и всех узлов под собой (в книге не разбирается; само [BST](bst-structure.md) — глава впереди), — даёт
`O(log n)` на вставку и поиск пересечения, если дерево сбалансировано. Для статического входа это лишнее, но при
потоке правок асимптотика на операцию падает принципиально.

## ⚠️ Типичные ошибки

1. **Забыли отсортировать** перед проходом — без сортировки сравнение только с
   последним интервалом некорректно.
2. **Неверное объединение концов** — бери `max(last[1], cur[1])`, иначе
   присваивание `last[1] = cur[1]` может *уменьшить* интервал.
3. **Неправильная проверка перекрытия** — условие именно `cur[0] <= last[1]`
   (с учётом равенства, если касание считается перекрытием).
4. **Пустой вход** — обращение к `intervals[0]` упадёт; обработай `len == 0`.
5. **Некорректный интервал** (`start > end`) — при необходимости проверяй вход.

**Трассировка** на `[[1,3],[2,6],[8,10],[15,18]]` (уже отсортирован по началу):

| `i` | `cur` | `last` | `cur.start ≤ last.end`? | действие | `result` |
|-----|-------|--------|-------------------------|----------|----------|
| —   | —     | —      | —                       | первый в результат | `[[1,3]]` |
| 1   | `[2,6]`  | `[1,3]`  | `2 ≤ 3` ✓ | слить: `end=max(3,6)=6` | `[[1,6]]` |
| 2   | `[8,10]` | `[1,6]`  | `8 ≤ 6` ✗ | разрыв → новый | `[[1,6],[8,10]]` |

каждый интервал смотрим ровно один раз — вся стоимость ушла в

      <li><b>Ломается</b>, если отсортировать по концу: слияние пропустит перекрытия. «Выбери побольше непересекающихся» — другая задача, <a href="greedy.md">жадность</a> с сортировкой по концу; «сколько одновременно» — события +1 и −1 сканирующей прямой.</li>
    </ul>
  </div>
</div>

# Руководство по выбору алгоритмического шаблона

Это руководство поможет вам быстро определить, какой алгоритмический шаблон использовать для решения конкретной задачи.

> Открывай его после первых пяти-шести глав [ядра](README.md#-путь-обучения): пока шаблоны
> не пройдены, их названия в дереве решений ничего не говорят. Первый раз хватит дерева
> решений и чеклиста в конце, остальное — справочник на потом.

## Decision Tree (Дерево решений)

```
Начало
  │
  ├─ Работа с массивами/строками?
  │   │
  │   ├─ Нужен непрерывный подмассив/подстрока: окно размера k
  │   │  или самый длинный/короткий отрезок под условие?
  │   │   └─ → Sliding Window
  │   │
  │   ├─ Сумма отрезка много раз? «Сколько подмассивов с суммой k»,
  │   │  особенно с отрицательными числами? Прибавка к диапазонам?
  │   │   └─ → Prefix Sums
  │   │
  │   ├─ Каждому элементу — ближайший больший/меньший? Скобки, вложенность?
  │   │   └─ → Monotonic Stack
  │   │
  │   ├─ Массив отсортирован? Нужно найти пару/тройку?
  │   │   └─ → Two Pointers
  │   │
  │   ├─ Массив с числами в диапазоне [1, n]?
  │   │   └─ → Cyclic Sort
  │   │
  │   └─ Массив отсортирован? Нужен поиск?
  │       └─ → Modified Binary Search
  │
  ├─ Единственный элемент среди пар? Работа с битами/флагами?
  │   └─ → Bit Manipulation
  │
  ├─ Работа со связанными списками?
  │   │
  │   ├─ Нужно обнаружить цикл или найти середину?
  │   │   └─ → Fast & Slow Pointers
  │   │
  │   └─ Нужно развернуть список?
  │       └─ → Reverse Linked List
  │
  ├─ Работа с деревьями?
  │   │
  │   ├─ Нужен обход по уровням?
  │   │   └─ → Tree BFS
  │   │
  │   └─ Нужен обход в глубину?
  │       └─ → Tree DFS
  │
  ├─ Работа с интервалами?
  │   └─ → Merge Intervals
  │
  ├─ Нужно найти K наибольших/наименьших элементов?
  │   └─ → Top K Elements
  │
  ├─ Нужно поддерживать медиану?
  │   └─ → Two Heaps
  │
  ├─ Нужно слить K отсортированных массивов/списков?
  │   └─ → K-way Merge
  │
  ├─ Нужно сгенерировать все подмножества/комбинации (без явных ограничений на выбор)?
  │   └─ → Subsets
  │
  ├─ Нужно перебрать ВСЕ конфигурации под ограничениями (расставить, разложить, собрать) и вход небольшой?
  │   └─ → Backtracking
  │
  ├─ Работа с графом?
  │   │
  │   ├─ Достижимость, компоненты, цикл, кратчайший путь по числу рёбер?
  │   │   └─ → Graphs (BFS/DFS)
  │   │
  │   ├─ Зависимости между элементами (порядок выполнения)?
  │   │   └─ → Topological Sort
  │   │
  │   ├─ Динамически объединять группы / проверять «одна ли группа»?
  │   │   └─ → Union-Find (DSU)
  │   │
  │   ├─ Двумерная сетка (острова, заливка, путь по клеткам)?
  │   │   └─ → Grids & Shortest Paths
  │   │
  │   ├─ Кратчайший путь по весам? Веса отрицательные? Есть эвристика?
  │   │   └─ → Grids & Shortest Paths (Дейкстра) / Advanced Graphs (Bellman–Ford, A*)
  │   │
  │   ├─ Соединить все вершины минимальным суммарным весом?
  │   │   └─ → Advanced Graphs (MST: Kruskal/Prim)
  │   │
  │   ├─ Циклы зависимостей в ориентированном графе? Единая точка отказа в неориентированном?
  │   │   └─ → Graph Connectivity (SCC, мосты, точки сочленения)
  │   │
  │   └─ «Сколько максимум протолкнуть» через сеть? Задача о назначении?
  │       └─ → Max Flow / Min Cut
  │
  ├─ Локально оптимальный выбор доказуемо даёт глобальный оптимум (сортировка + жадный проход)?
  │   └─ → Greedy
  │
  ├─ Подзадачи перекрываются, есть оптимальная подструктура («способов», «минимум/максимум», «можно ли»)?
  │   └─ → Dynamic Programming
  │
  ├─ Любой алгоритм — экспоненциальный перебор, задача похожа на рюкзак/коммивояжёра/раскраску?
  │   └─ → Классы сложности (P/NP): проверить, точно ли нужен точный алгоритм
  │
  ├─ Работа со строками?
  │   │
  │   ├─ Найти вхождение образца в текст?
  │   │   └─ → Строковые алгоритмы (KMP, Rabin–Karp)
  │   │
  │   └─ Много строк, поиск по префиксу/словарь?
  │       └─ → Trie
  │
  ├─ Много запросов на диапазоне массива (сумма/min/max)?
  │   │
  │   ├─ Массив статичный, нужен именно O(1) на запрос?
  │   │   └─ → Sparse Table
  │   │
  │   ├─ Массив изменяемый, нужны точечные/диапазонные обновления?
  │   │   └─ → Дерево отрезков (Segment Tree)
  │   │
  │   └─ Нужна только сумма/префикс-сумма, попроще?
  │       └─ → Дерево Фенвика (BIT)
  │
  ├─ Данные не помещаются в память (диск/SSD, индексы БД)?
  │   └─ → B-дерево
  │
  ├─ Точный ответ дорог по памяти, согласны на малую ошибку (миллиарды элементов)?
  │   └─ → Вероятностные структуры (Bloom, HyperLogLog, count-min)
  │
  ├─ Нужно ПОСЧИТАТЬ количество вариантов, не перебирая их?
  │   └─ → Комбинаторика счёта
  │
  ├─ Вопрос «в среднем» — коллизии хешей, честный shuffle, ожидаемое число попыток?
  │   └─ → Дискретная вероятность
  │
  ├─ НОД/НОК, простые числа, огромная степень числа, ответ по модулю?
  │   └─ → Теория чисел
  │
  ├─ Модульная арифметика в защите данных (RSA, обратный по модулю)?
  │   └─ → Криптография
  │
  └─ Нужен порядок / k-й элемент / стабильная сортировка?
      └─ → Сортировки и порядковые статистики
```

## Детальное описание по типам задач

### Работа с массивами и строками

#### Sliding Window
**Используйте, когда:**
- Нужно найти подмассив/подстроку определенного размера
- Нужно найти подмассив/подстроку, удовлетворяющую условию
- Задача связана с "окном" фиксированного или переменного размера

**Примеры задач:**
- Найти максимальную сумму подмассива размера k
- Найти минимальную подстроку, содержащую все символы
- Найти все анаграммы в строке

#### Two Pointers
**Используйте, когда:**
- Массив отсортирован
- Нужно найти пару/тройку элементов с определенным свойством
- Нужно удалить дубликаты из отсортированного массива
- Нужно проверить палиндром

**Примеры задач:**
- Найти два числа с заданной суммой
- Удалить дубликаты из отсортированного массива
- Проверить, является ли строка палиндромом

#### Prefix Sums
**Используйте, когда:**
- Много запросов «сумма на отрезке [l, r]» к массиву, который не меняется
- Нужно посчитать подмассивы с суммой k, кратной k, с балансом — и числа бывают отрицательными (окно тут ломается)
- Много прибавлений к диапазонам, а итог нужен один раз (разностный массив)
- Сумма прямоугольника в матрице

**Примеры задач:**
- Subarray Sum Equals K — префикс + хеш-таблица прошлых префиксов
- Contiguous Array — 0 → −1 и первое вхождение каждой суммы
- Product of Array Except Self — префикс и суффикс

→ подробности и код: [Префиксные суммы и разностные массивы](prefix-sums.md)

#### Monotonic Stack
**Используйте, когда:**
- Каждому элементу нужен ближайший больший или меньший — слева или справа
- «Через сколько дней потеплеет», «сколько дней подряд не выше»
- Вложенные структуры: скобки, теги, `k[...]`
- Наибольший прямоугольник в гистограмме, вклад элемента как минимума

**Примеры задач:**
- Daily Temperatures, Next Greater Element II
- Valid Parentheses, Decode String
- Largest Rectangle in Histogram

→ подробности и код: [Стек и монотонный стек](monotonic-stack.md)

#### Cyclic Sort
**Используйте, когда:**
- Массив содержит числа в диапазоне [1, n] или [0, n-1]
- Нужно найти отсутствующие числа
- Нужно найти дубликаты
- Можно использовать индексы как хеш-таблицу

**Примеры задач:**
- Найти отсутствующее число
- Найти все дубликаты
- Найти первое отсутствующее положительное число

#### Modified Binary Search
**Используйте, когда:**
- Массив отсортирован (или частично отсортирован)
- Нужно найти элемент или границу
- Нужно найти в повернутом отсортированном массиве
- Нужно найти в 2D отсортированной матрице

**Примеры задач:**
- Найти элемент в отсортированном массиве
- Найти первую/последнюю позицию элемента
- Найти минимум в повернутом массиве

#### Bit Manipulation
**Используйте, когда:**
- Нужно найти единственный элемент среди пар (каждый элемент встречается дважды)
- Работа с отдельными битами числа (проверка, установка, сброс)
- Задача связана с флагами, степенями двойки, чётностью
- Требуется O(1) дополнительной памяти

**Примеры задач:**
- Single Number — найти единственный элемент
- Missing Number — XOR-решение
- Power of Two — проверка степени двойки
- Number of 1 Bits — подсчёт единичных битов
- Hamming Distance — расстояние Хэмминга

#### Сортировки и порядковые статистики
**Используйте, когда:**
- порядок упрощает задачу: дубликаты, k-й по величине, пары с условием
- нужен стабильный порядок по нескольким ключам (merge sort)
- числа лежат в узком диапазоне — подсчётом за O(n + k)
- нужен только один элемент по рангу — QuickSelect за O(n), без полной сортировки

**Примеры задач:**
- k-й наибольший/наименьший элемент (QuickSelect)
- сортировка почти отсортированного или ограниченного по диапазону массива (Counting Sort)
- медиана массива без полной сортировки

→ подробности и код: [Алгоритмы сортировки и порядковые статистики](sorting.md)

### Работа со связанными списками

#### Fast & Slow Pointers
**Используйте, когда:**
- Нужно обнаружить цикл в списке
- Нужно найти середину списка
- Нужно найти K-й элемент с конца
- Нужно проверить палиндром в списке

**Примеры задач:**
- Обнаружить цикл в связанном списке
- Найти середину связанного списка
- Проверить, является ли список палиндромом

#### Reverse Linked List
**Используйте, когда:**
- Нужно развернуть весь список
- Нужно развернуть часть списка
- Нужно развернуть список группами

**Примеры задач:**
- Развернуть связанный список
- Развернуть список между позициями m и n
- Развернуть узлы группами по k

### Работа с деревьями

#### Tree BFS
**Используйте, когда:**
- Нужен обход дерева по уровням
- Нужно найти кратчайший путь
- Нужно обработать все узлы на одном уровне перед переходом к следующему

**Примеры задач:**
- Обход дерева по уровням
- Найти среднее значение каждого уровня
- Найти вид дерева справа

#### Tree DFS
**Используйте, когда:**
- Нужен обход в глубину (pre-order, in-order, post-order)
- Нужно валидировать дерево
- Нужно построить дерево из обхода
- Нужно найти путь с определенным свойством

**Примеры задач:**
- Валидация бинарного дерева поиска
- Найти максимальную сумму пути
- Построить дерево из pre-order и in-order обхода

### Работа с интервалами

#### Merge Intervals
**Используйте, когда:**
- Работаете с интервалами
- Нужно объединить перекрывающиеся интервалы
- Нужно вставить новый интервал
- Нужно найти пересечение интервалов

**Примеры задач:**
- Объединить перекрывающиеся интервалы
- Вставить интервал
- Найти пересечение интервалов

### Продвинутые структуры данных

#### Top K Elements
**Используйте, когда:**
- Нужно найти K наибольших элементов
- Нужно найти K наименьших элементов
- Нужно найти K наиболее частых элементов
- Нужно найти K ближайших точек

**Примеры задач:**
- Найти K-й наибольший элемент
- Найти топ K частых элементов
- Найти K ближайших точек к началу координат

#### Two Heaps
**Используйте, когда:**
- Нужно поддерживать медиану потока данных
- Нужно балансировать две части данных
- Нужно быстро получать минимум и максимум

**Примеры задач:**
- Медиана из потока данных
- Медиана скользящего окна
- Балансировка двух множеств

#### K-way Merge
**Используйте, когда:**
- Нужно слить K отсортированных массивов
- Нужно слить K отсортированных списков
- Нужно найти K-й наименьший элемент в K отсортированных структурах

**Примеры задач:**
- Слить K отсортированных списков
- Найти K-й наименьший элемент в отсортированной матрице
- Найти K пар с наименьшими суммами

### Комбинаторика и графы

#### Subsets
**Используйте, когда:**
- Нужно сгенерировать все подмножества
- Нужно сгенерировать все комбинации
- Нужно сгенерировать все перестановки
- Задача связана с backtracking

**Примеры задач:**
- Найти все подмножества
- Найти все комбинации суммы
- Найти все перестановки

#### Backtracking
**Используйте, когда:**
- нужно сгенерировать **все** конфигурации под ограничениями (расстановка, разбиение, сборка), а не просто перечислить варианты
- нужны **все пути**/решения, удовлетворяющие условию (N ферзей, судоку, скобочные последовательности)
- вопрос «существует ли последовательность выборов, дающая результат»
- вход небольшой — перебор экспоненциальный, это осознанная плата за полноту

**Примеры задач:**
- расставить N ферзей так, чтобы не били друг друга (`SolveNQueensCount`)
- сгенерировать все правильные скобочные последовательности (`GenerateParentheses`)
- найти все комбинации чисел, дающие заданную сумму (`CombinationSum`)
- буквенные комбинации телефонного номера (`LetterCombinations`)

→ подробности и код: [Backtracking (Поиск с возвратом)](backtracking.md); чем Backtracking отличается
от Subsets — там, где Subsets просто строит все варианты, Backtracking ещё и **отсекает** ветки,
не удовлетворяющие ограничению, до того как достроит их до конца.

#### Topological Sort
**Используйте, когда:**
- Работаете с ориентированным графом
- Есть зависимости между элементами
- Нужно упорядочить элементы с учетом зависимостей
- Нужно определить, можно ли выполнить все задачи

**Примеры задач:**
- Расписание курсов
- Словарь инопланетян
- Реконструкция последовательности

### Графы: обход, кратчайшие пути, связность, потоки

#### Graphs (общий обход)
**Используйте, когда:**
- нужен путь / достижимость между вершинами
- нужно число компонент связности, «островов», групп
- нужно обнаружить цикл
- нужен кратчайший путь по числу рёбер (BFS)

**Примеры задач:**
- посчитать число компонент связности (`CountComponents`)
- проверить двудольность графа (`IsBipartite`)
- кратчайший путь по числу рёбер (`ShortestPathUnweighted`)

→ подробности и код: [Graphs (Обход графов)](graphs.md)

#### Union-Find (DSU)
**Используйте, когда:**
- нужно динамически объединять группы и проверять «в одной ли группе»
- альтернатива DFS/BFS для компонент связности, когда рёбра добавляются по одному (Kruskal, обнаружение цикла в потоке рёбер)

**Примеры задач:**
- проверить, в одной ли группе два элемента, после серии объединений (`Union`/`Find`/`Connected`)
- обнаружить цикл при добавлении рёбер по одному
- построить MST по Краскалу (см. `mst`)

→ подробности и код: [Union-Find (DSU): устройство и операции](union-find-structure.md)

#### Grids & Shortest Paths
**Используйте, когда:**
- задача — двумерное поле: острова, заливка, путь по сетке
- нужен кратчайший путь по числу шагов (BFS) или по весам (Дейкстра) при неотрицательных весах
- нужна волна из нескольких источников (multi-source BFS)

**Примеры задач:**
- число островов, площадь наибольшего острова (`NumIslands`, `MaxAreaOfIsland`)
- сгнившие апельсины — многоисточниковый BFS (`RottingOranges`)
- кратчайший путь в сети с весами (`ShortestPath`, Дейкстра)

→ подробности и код: [Графы: сетки и кратчайшие пути](grids-and-shortest-paths.md)

#### Advanced Graphs
**Используйте, когда:**
- веса рёбер могут быть **отрицательными**, нужен Bellman–Ford (и проверка отрицательного цикла)
- есть хорошая эвристика расстояния до цели — A* обгоняет Дейкстру
- нужно соединить все вершины минимальным суммарным весом — MST (Kruskal/Prim)

**Примеры задач:**
- кратчайший путь при отрицательных весах, задержка сети (`bellmanford.ShortestPath`, `NetworkDelayTime`)
- путь на сетке с манхэттенской эвристикой (`astar.ShortestPath`)
- минимальный вес связывающего дерева (`mst.MSTWeight`, Kruskal/Prim)

→ подробности и код: [Графы: продвинутые алгоритмы](advanced-graph-algorithms.md)

#### Graph Connectivity (SCC, мосты, точки сочленения)
**Используйте, когда:**
- нужно найти циклы зависимостей в **ориентированном** графе — пакеты, сервисы, дедлоки (SCC)
- нужно сжать циклы в DAG (конденсация) перед топологической сортировкой
- нужно найти единые точки отказа в **неориентированном** графе — ребро или узел, без которого сеть распадается (мосты, точки сочленения)

**Примеры задач:**
- найти компоненты сильной связности графа зависимостей (`scc.SCC`, Косарайю)
- найти рёбра-мосты и узлы-точки сочленения в сети (`Bridges`, `ArticulationPoints`)

→ подробности и код: [Графы: сильная связность, мосты и точки сочленения](graph-connectivity.md)

#### Max Flow / Min Cut
**Используйте, когда:**
- нужно узнать, сколько максимум можно «протолкнуть» через сеть с пропускными способностями
- нужно найти узкое место сети (минимальный разрез)
- нужно назначение: раздать задачи воркерам, слоты — рекламе (двудольное паросочетание)

**Примеры задач:**
- максимальный поток в сети (`maxflow.MaxFlow`, Эдмондс—Карп)
- максимальное паросочетание в двудольном графе (`MaxBipartiteMatching`, алгоритм Куна)

→ подробности и код: [Потоки в сетях: максимальный поток, минимальный разрез, паросочетания](max-flow.md)

### Оптимизация: Greedy, Dynamic Programming, когда задача трудна

#### Greedy
**Используйте, когда:**
- задача про расписание/интервалы: максимум непересекающихся событий
- минимизация/максимизация с очевидным критерием сортировки
- доказуемо работает «greedy stays ahead» или exchange argument
- выбор не нужно пересматривать в будущем (в отличие от DP)

**Примеры задач:**
- максимум непересекающихся интервалов (`MaxNonOverlapping`)
- минимум прыжков, чтобы добраться до конца массива (`MinJumps`, `CanJump`)
- дробный рюкзак (`FractionalKnapsack`)

→ подробности и код: [Greedy (Жадные алгоритмы)](greedy.md)

#### Dynamic Programming
**Используйте, когда:**
- вопрос «сколькими способами…» (подсчёт вариантов)
- вопрос «минимум / максимум / самый длинный…» при цепочке выборов
- вопрос «можно ли достичь…» (достижимость комбинацией шагов)
- подзадачи перекрываются и есть оптимальная подструктура — в отличие от Greedy, выбор иногда нужно пересмотреть

**Примеры задач:**
- размен монет минимальным числом монет (`CoinChange`)
- наибольшая общая подпоследовательность, расстояние редактирования (`LongestCommonSubsequence`, `EditDistance`)
- рюкзак 0/1, ограбление домов, число уникальных путей (`Knapsack01`, `HouseRobber`, `UniquePaths`)

→ подробности и код: [Dynamic Programming (Динамическое программирование)](dynamic-programming.md)

#### Классы сложности: когда алгоритма быстрее экспоненты не существует
**Используйте эту главу, когда подозреваете NP-трудность:**
- нужно перебрать подмножества/перестановки/разбиения и выбрать лучшее
- задача — «оптимально распределить/упаковать/назначить» без явной структуры для Greedy/DP
- любой алгоритм, что приходит в голову, — экспоненциальный перебор
- задача пахнет рюкзаком, коммивояжёром, раскраской, расписанием

Это не «шаблон решения», а чек-лист «не трачу ли я время на несуществующий полиномиальный
алгоритм» — и что делать вместо этого (approximation, эвристики, экспоненциальный, но
отсекаемый backtracking).

→ подробности и код (пакет `npcomplete`: сертификат, перебор, два приближения):
[Классы сложности: P, NP и что делать, когда задача трудна](complexity-classes.md)

### Строки и продвинутые структуры данных

#### String Matching
**Используйте, когда:**
- нужно найти вхождение образца в текст (strStr)
- нужен гарантированно линейный поиск — KMP
- несколько образцов или сравнение по хешу — Rabin–Karp
- задача про префикс-функцию (палиндромы, периоды строки)

**Примеры задач:**
- найти все вхождения образца в тексте (`KMPSearch`, `CountOccurrences`)
- сравнение подстрок по скользящему хешу (`RabinKarp`)
- наибольший общий префикс-суффикс, Z-функция (`LongestPrefixSuffix`, `ZSearch`)

→ подробности и код: [Строковые алгоритмы: поиск подстроки](string-algorithms.md)

#### Trie (Префиксное дерево)
**Используйте, когда:**
- нужен поиск/автодополнение по префиксу среди множества строк
- нужен словарь с быстрой проверкой «есть ли такое слово / такой префикс»
- задача сводится к побитовому trie (максимальный XOR пары чисел)

**Примеры задач:**
- реализовать словарь с `Insert`/`Search`/`StartsWith` (`trie.Trie`)
- найти все слова с заданным префиксом (`WordsWithPrefix`)

→ подробности и код: [Trie: устройство и построение](trie-structure.md), [Trie: разбор задач](trie.md)

#### Диапазонные запросы: Sparse Table / Дерево отрезков / Дерево Фенвика
**Используйте, когда** нужно много запросов вида «агрегат на отрезке `[l, r]`» — а какую структуру
выбрать, зависит от того, меняется ли массив:
- массив **статичный** (без обновлений), операция идемпотентна (min/max/gcd), нужен именно O(1) на запрос → **Sparse Table**
- массив **изменяемый**, нужны точечные/диапазонные обновления, операция любая (сумма, min, lazy-propagation) → **Дерево отрезков**
- нужна только сумма/префикс-сумма с обновлениями — попроще и компактнее дерева отрезков → **Дерево Фенвика (BIT)**

**Примеры задач:**
- RMQ-минимум на статичном массиве за O(1) (`sparsetable.Sparse.Query`)
- изменяемая сумма/минимум на диапазоне, диапазонное обновление (`segtree.SegmentTree`, `LazySegmentTree`)
- число инверсий, число элементов меньше текущего справа (`fenwick.CountInversions`, `CountSmallerToRight`)

→ подробности и код: [Sparse Table](sparse-table-structure.md), [Дерево отрезков: устройство](segment-tree-structure.md) + [разбор задач](segment-tree.md), [Дерево Фенвика: устройство](fenwick-tree-structure.md) + [разбор задач](fenwick-tree.md)

#### B-дерево
**Используйте, когда:**
- данные не помещаются в память — лежат на диске/SSD (индексы БД, файловые системы)
- важно минимизировать число обращений к блокам, а не число сравнений

**Примеры задач:**
- реализовать индекс с `Search`/`Insert`/`Delete` при широких узлах-блоках (`btree.BTree`)

→ подробности и код: [B-дерево: устройство и операции](btree-structure.md)

#### Вероятностные структуры (Bloom, HyperLogLog, count-min)
**Используйте, когда:**
- точный ответ стоит слишком много памяти (миллиарды элементов), а согласиться на малую управляемую ошибку — нормально
- нужно быстро отсечь «точно нет» перед дорогим чтением с диска (Bloom-фильтр перед SSTable)
- нужна оценка мощности множества (HyperLogLog) или частоты элемента в потоке (count-min)

**Примеры задач:**
- проверить «скорее всего есть / точно нет» без хранения всех элементов (`probabilistic.Bloom.MightContain`)

→ подробности и код: [Вероятностные структуры: Bloom, HyperLogLog, count-min](probabilistic-structures.md)

### Дискретная математика

#### Комбинаторика счёта
**Используйте, когда:**
- нужно количество вариантов, а не сами варианты
- нужно оценить размер пространства перебора до запуска backtracking
- в условии «хотя бы одно из условий» — работает включение-исключение
- нужно capacity-планирование: сколько состояний/пар/комбинаций конфигурации

**Примеры задач:**
- число сочетаний `C(n, k)`, число перестановок (`Binomial`, `Permutations`)
- числа, делящиеся хотя бы на одно из заданных, через включение-исключение (`CountDivisibleByAny`)

→ подробности и код: [Комбинаторика счёта: посчитать, не перебирая](combinatorics.md)

#### Дискретная вероятность
**Используйте, когда:**
- хотите вывести, а не заучить, почему хеш-таблица «в среднем O(1)», quicksort «в среднем O(n log n)»
- проектируете идентификаторы/хеши и нужно понять, когда ждать коллизий
- нужен честный shuffle или выборка из потока данных неизвестной длины (reservoir sampling)

**Примеры задач:**
- честная перетасовка массива (`sampling.Shuffle`, Fisher–Yates)
- выборка k случайных элементов из потока (`ReservoirSample`)
- порог, когда коллизия становится вероятной (`BirthdayThreshold`)

→ подробности и код: [Дискретная вероятность для инженера](probability.md)

#### Теория чисел
**Используйте, когда:**
- нужен НОД/НОК, сокращение дроби, период
- нужна проверка на простоту или все простые числа до n
- нужна огромная степень `aⁿ` или `aⁿ mod m`
- ответ задачи нужен «по модулю» (комбинаторика, хеши)

**Примеры задач:**
- НОД/НОК, решето Эратосфена, быстрое возведение в степень по модулю (`GCD`, `SieveOfEratosthenes`, `PowMod`)

→ подробности и код: [Теория чисел: НОД, простые, быстрая степень](number-theory.md)

#### Криптография
**Используйте, когда** нужна модульная арифметика в защите данных: обратный элемент по модулю,
надёжная проверка простоты больших чисел (Миллер—Рабин), понимание, почему RSA — это одно
возведение в степень по модулю на шифрование и на расшифровку.

**Примеры задач:**
- расширенный алгоритм Евклида и обратный по модулю (`ExtendedGCD`, `ModInverse`)
- вероятностная проверка простоты (`IsProbablePrime`)
- шифрование/расшифровка RSA на маленьких числах (`RSAEncrypt`, `RSADecrypt`)

→ подробности и код: [Криптография: модульная арифметика в деле](cryptography.md)

## Комбинирование шаблонов

Многие задачи требуют комбинирования нескольких шаблонов. Полные пошаговые разборы таких
связок (LRU, Word Ladder, Alien Dictionary, Meeting Rooms, Twitter, Skyline) — в главе
[«Комбинации паттернов»](pattern-combinations.md); ниже — короткая навигация:

### Sliding Window + Heap
- Поиск максимума/минимума в скользящем окне
- Пример: [Sliding Window Maximum](https://leetcode.com/problems/sliding-window-maximum/)

### DFS + Backtracking
- Генерация подмножеств и перестановок
- Пример: [N-Queens](https://leetcode.com/problems/n-queens/)

### BFS + Graph
- Топологическая сортировка
- Пример: [Course Schedule](https://leetcode.com/problems/course-schedule/)

### Сортировка + Two Pointers
- Поиск тройки с заданной суммой: сортируем, фиксируем первый элемент, пару к нему ищем двумя указателями
- Пример: [3Sum](https://leetcode.com/problems/3sum/)

## Чеклист для выбора шаблона

1. **Проанализируйте входные данные:**
   - Какой тип данных? (массив, список, дерево, граф)
   - Отсортированы ли данные?
   - Какой размер данных?

2. **Определите цель задачи:**
   - Поиск элемента?
   - Поиск подмассива/подстроки?
   - Генерация всех возможных вариантов?
   - Обход структуры данных?

3. **Учтите ограничения:**
   - Требования к временной сложности
   - Требования к пространственной сложности
   - Можно ли изменять исходные данные?

4. **Проверьте типичные паттерны:**
   - Похожа ли задача на изученные примеры?
   - Какие структуры данных используются?
   - Есть ли зависимости между элементами?

## Полезные советы

1. **Начните с простого:** Если задача кажется сложной, попробуйте упростить ее и найти базовый шаблон.

2. **Используйте визуализацию:** Нарисуйте примеры входных и выходных данных, это поможет понять паттерн.

3. **Анализируйте примеры:** Изучите примеры задач для каждого шаблона, чтобы понять типичные применения.

4. **Практикуйтесь:** Решайте задачи на LeetCode, чтобы развить интуицию для выбора правильного шаблона.

5. **Не бойтесь экспериментировать:** Если один шаблон не работает, попробуйте другой или комбинацию шаблонов.

## Заключение

Выбор правильного алгоритмического шаблона - это навык, который развивается с практикой. Используйте это руководство как отправную точку, но помните, что многие задачи могут решаться несколькими способами. Главное - понять суть задачи и выбрать наиболее подходящий подход.

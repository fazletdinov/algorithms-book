## 🎬 Визуализация

> 💡 **Интерактивная демонстрация.** Ядро backtracking: **берём** элемент (синий) → рекурсия →
> **откатываемся** (жёлтый). В строке «Найдено» копятся подмножества. Справа — код с подсветкой
> строки и переменные, внизу — кнопки шагов (или ←/→ на клавиатуре). (Виджет работает в собранной книге
> `mdbook serve`/`mdbook build`, а не при просмотре `.md` на GitHub.)

## ⚡ Шаблон для собеседования

```go
func subsets(nums []int) [][]int {
    var result [][]int
    var current []int
    var backtrack func(start int)
    backtrack = func(start int) {
        subset := make([]int, len(current))
        copy(subset, current)          // копия!
        result = append(result, subset)
        for i := start; i < len(nums); i++ {
            current = append(current, nums[i]) // выбор
            backtrack(i + 1)
            current = current[:len(current)-1] // откат
        }
    }
    backtrack(0)
    return result
}
```

1. записываем текущее подмножество (копией);
2. перебираем элементы от `start`;
3. выбор → рекурсия с `i+1` → откат.

## 📖 Разбор

<details class="algo-details">
<summary>Теория, дубликаты, итеративный подход и сложность</summary>

Шаблон **Subsets** генерирует все подмножества множества. Для каждого элемента — два
выбора: **включить** или **не включить**. Это бинарное дерево решений с 2ⁿ листьями.
Основной приём — **backtracking**: строим решение в одном общем массиве и «откатываемся»
после обработки варианта, экономя память.

#### С дубликатами

Сортируем и пропускаем повторы на одном уровне:

```go
func subsetsWithDup(nums []int) [][]int {
    sort.Ints(nums)
    var result [][]int
    var current []int
    var backtrack func(start int)
    backtrack = func(start int) {
        subset := make([]int, len(current))
        copy(subset, current)
        result = append(result, subset)
        for i := start; i < len(nums); i++ {
            if i > start && nums[i] == nums[i-1] {
                continue // пропускаем дубликат на этом уровне
            }
            current = append(current, nums[i])
            backtrack(i + 1)
            current = current[:len(current)-1]
        }
    }
    backtrack(0)
    return result
}
```

Альтернатива — **итеративный** подход: начать с `[[]]` и для каждого элемента добавить
его ко всем существующим подмножествам.

#### Сложность

| Подход                    | Время       | Память                  |
|---------------------------|-------------|-------------------------|
| Рекурсивный (backtracking)| O(2ⁿ · n)   | O(2ⁿ · n), стек O(n)    |
| Итеративный               | O(2ⁿ · n)   | O(2ⁿ · n)               |

Всего 2ⁿ подмножеств, каждое копируется за O(n).

</details>

## 🧠 Почему это корректно

### Полнота и отсутствие дублей

Дерево «включить / не включить» имеет ровно `2ⁿ` листьев, и каждое подмножество
достигается **единственным** путём → перебор полон и без повторов (детальнее — в
[backtracking](backtracking.md)). Эквивалентный взгляд: каждое число `mask ∈ [0, 2ⁿ)`
кодирует подмножество (бит `i` = «взять `nums[i]`») — это **биекция**, поэтому `2ⁿ` масок
заведомо перечисляют все подмножества.

### Почему дедуп — это sort + skip

Одинаковые значения на **одном уровне** рекурсии порождают одинаковые подмножества.
Сортировка ставит их рядом, а `if i > start && nums[i] == nums[i-1]: continue` оставляет
лишь первую ветку на каждом уровне. Пропускаются ровно дубликаты-двойники, а все
**различные** подмножества сохраняются.

## ⚙️ Цена на практике

### Размер вывода неизбежен

`2ⁿ` подмножеств × `O(n)` на копию = `O(2ⁿ · n)` — это вес самого ответа, меньше не
выйдет. Рекурсия и итеративная битовая маска — **одинаковой** сложности; маска
аллокационно легче и дружелюбна к кэшу, но ограничена `n ≤ 63` (помещается в `int`).
Backtracking же обобщается на ограничения и отсечение — бери его, когда нужно не «всё
подряд», а с условием.

### Один буфер вместо аллокации на узел

Рекурсия держит **единственный** срез `current`: добавляет элемент перед спуском,
снимает после — а копию через `make+copy` делает только в момент записи в ответ.
Поэтому аллокаций ровно `O(2ⁿ)` (неизбежные копии результата), а не по аллокации на
каждый внутренний узел дерева. Отсюда и ловушка №2: записать `current` **без копии** —
значит сохранить ссылку на тот самый буфер, который рекурсия тут же мутирует, и все
сохранённые подмножества «съедут». `make+copy` на листе — не перестраховка, а условие
корректности при переиспользовании буфера.

### Gray-код: следующее подмножество — на один элемент

Прямой перебор масок `0..2ⁿ` каждый раз собирает подмножество с нуля — `O(n)` на маску.
Если идти в порядке **кода Грея**, соседние маски различаются ровно одним битом, то есть
каждое подмножество — это предыдущее с **добавленным или убранным одним элементом**
(`O(1)` на переход). Это важно, когда работа над подмножеством инкрементальна —
поддерживаешь сумму, произведение, XOR: тогда обновляешь, а не пересчитываешь. Если же
подмножество просто печатается, выигрыша нет — `O(n)` на вывод всё равно доминирует.

## ⚠️ Типичные ошибки

1. **Забыт откат** — после рекурсивного вызова обязательно `current = current[:len(current)-1]`.
2. **Сохранение без копии** — `append(result, current)` сохраняет ссылку на изменяемый слайс; копируйте через `copy`.
3. **Дубликаты не обработаны** — для массива с повторами сортируйте и пропускайте `nums[i] == nums[i-1]` при `i > start`.
4. **Пустой массив** — корректно вернуть `[][]int{{}}` (единственное пустое подмножество).
5. **Очень большое n** — 2ⁿ растёт экспоненциально; следите за памятью.

## 📝 Разбор задачи

Пройдём путь от наивного решения к оптимальному — так, как стоит рассуждать на
собеседовании: сначала рабочий перебор, затем понимание, *почему* он расточителен, и
только потом построение без дедупликации.

> **Задача.** Дан массив целых `nums`, в котором **могут быть дубликаты**. Вернуть все
> **уникальные** подмножества (степень множества без повторяющихся подмножеств; порядок
> подмножеств не важен). Пример: `nums = [1,2,2]` →
> `[[], [1], [2], [1,2], [2,2], [1,2,2]]` (6 штук, а не 2³ = 8).

**Шаг 1. Наивно: все 2ⁿ подмножеств + дедуп через множество — O(2ⁿ·n).**

```go
func subsetsWithDupNaive(nums []int) [][]int {
    sort.Ints(nums)               // ключ должен не зависеть от порядка
    n := len(nums)
    seen := make(map[string]bool)
    var result [][]int
    for mask := 0; mask < (1 << n); mask++ {
        var subset []int
        for i := 0; i < n; i++ {
            if mask&(1<<i) != 0 {
                subset = append(subset, nums[i])
            }
        }
        parts := make([]string, len(subset))
        for i, v := range subset {
            parts[i] = strconv.Itoa(v)
        }
        key := strings.Join(parts, ",")
        if !seen[key] {           // отбрасываем уже виденное подмножество
            seen[key] = true
            result = append(result, subset)
        }
    }
    return result
}
```

Это **работает**, но генерирует все 2ⁿ масок и для каждой строит строковый ключ, чтобы
постфактум выкинуть совпадения. При `[2,2,2,…]` почти все ветки — мусор, который мы
честно собираем и тут же отбрасываем: лишняя память на `seen`, лишние аллокации строк,
лишняя работа. Хочется **не порождать** дубликаты вовсе.

**Шаг 2. Ключевое наблюдение.** Одинаковые значения на **одном уровне** рекурсии
порождают одинаковые подмножества — это ровно тот же довод, что в разделе
[«Почему дедуп — это sort + skip»](#почему-дедуп--это-sort--skip). Если отсортировать
вход, дубли встанут рядом, и достаточно на каждом уровне брать лишь **первую** копию
значения: вторую `2` мы добавляем только к подмножествам, которые **уже содержат**
первую `2`. Так каждое уникальное подмножество строится единственным путём — и дедуп
после построения не нужен.

**Шаг 3. Оптимум: sort + skip при построении — O(2ⁿ·n), без `seen`.**

```go
func subsetsWithDup(nums []int) [][]int {
    sort.Ints(nums)
    var result [][]int
    var current []int
    var backtrack func(start int)
    backtrack = func(start int) {
        subset := make([]int, len(current))
        copy(subset, current)              // копия — буфер переиспользуется
        result = append(result, subset)
        for i := start; i < len(nums); i++ {
            if i > start && nums[i] == nums[i-1] {
                continue                   // не первая копия на уровне — пропуск
            }
            current = append(current, nums[i]) // выбор
            backtrack(i + 1)
            current = current[:len(current)-1] // откат
        }
    }
    backtrack(0)
    return result
}
```

Та же `O(2ⁿ·n)` в худшем случае (когда дублей нет, выводов всё равно 2ⁿ), но при наличии
повторов число веток падает до количества **уникальных** подмножеств — и больше нет ни
`map[string]`, ни конкатенации ключей.

Прогоните построение на отсортированном `nums = [1,2,2]`: на каждом уровне второй
одинаковый элемент пропускается (`continue`), поэтому дубли подмножеств не возникают:

<div class="algo-viz" data-viz="subsets-with-dup" data-set="1,2,2"></div>

**Шаг 4. Трассировка** на `nums = [1,2,2]` (уже отсортирован). Каждый вход в `backtrack`
сразу пишет `current` в ответ; `i > start && nums[i] == nums[i-1]` срабатывает на второй
`2` верхнего уровня:

| вызов            | `start` | записали | цикл по `i`                                   |
|------------------|---------|----------|-----------------------------------------------|
| `backtrack(0)`   | 0       | `[]`     | `i=0` взять 1; `i=1` взять 2; `i=2`: 2==2 при `i>start` → **пропуск** |
| `backtrack(1)` ↳1| 1       | `[1]`    | `i=1` взять 2; `i=2`: 2==2 при `i>start` → **пропуск** |
| `backtrack(2)` ↳1,2| 2     | `[1,2]`  | `i=2` взять 2                                 |
| `backtrack(3)` ↳1,2,2| 3   | `[1,2,2]`| цикл пуст                                     |
| `backtrack(2)` ↳2| 2       | `[2]`    | `i=2` взять 2                                 |
| `backtrack(3)` ↳2,2| 3     | `[2,2]`  | цикл пуст                                     |

Итог — `[], [1], [1,2], [1,2,2], [2], [2,2]`: ровно 6 уникальных подмножеств. Дубликат
`[2]`, который дала бы вторая `2` на верхнем уровне, **не порождён вовсе** — благодаря
`continue`, а не отброшен постфактум.

**Вывод.** «Все комбинации / подмножества / сочетания» — сигнал **перебора подмножеств** (backtracking
«брать/не брать» или битовые маски). Помни цену: их `2ⁿ` — растёт экспоненциально, так что это применимо
лишь при небольшом `n` (см. [классы сложности](complexity-classes.md)).

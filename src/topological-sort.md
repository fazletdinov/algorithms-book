## 🧭 Откуда берётся алгоритм Кана: выведем его сами

У курсов есть предусловия — «чтобы пройти `a`, сначала пройди `b`». Нужен любой порядок,
в котором можно пройти все курсы.

Человек рассуждает так: **какой курс я могу взять прямо сейчас?** Тот, у которого все
предусловия пройдены. В лоб: каждый раунд пробегаем курсы по номерам и берём первый готовый.

Пять курсов цепочкой, с неудачной нумерацией: каждый требует следующий по номеру. `0?` — это
вопрос «курс `0` уже можно взять?»:

```text
цепочка:  4 ──► 3 ──► 2 ──► 1 ──► 0     (стрелка: «сначала» ──► «потом»)
раунд 1:  0? нет  1? нет  2? нет  3? нет  4? да → берём 4
раунд 2:  0? нет  1? нет  2? нет  3? да → берём 3
раунд 3:  0? нет  1? нет  2? да → берём 2
раунд 4:  0? нет  1? да → берём 1
раунд 5:  0? да → берём 0
```

15 проверок ради 5 курсов, и 10 из них — пустое «нет». Курс `0` спросили пять раз, хотя его
ответ меняется лишь однажды — когда взяли `1`. На такой цепочке из `n` курсов проверок
`n(n+1)/2`: квадрат.

Лекарство: готовность курса может измениться только в один момент — когда пройдено одно из
его предусловий. Значит, не опрашиваем всех по кругу, а заводим каждому курсу счётчик
непройденных предусловий — его **входящую степень** (in-degree). Взяли курс — уменьшаем
счётчик только у тех, кто от него зависит; дошёл до нуля — курс в очередь готовых. На цепочке
это 4 уменьшения счётчика — по одному на предусловие, — и ни одного пустого «нет».

**Входящая степень — это `sync.WaitGroup` у каждого курса: пройденное предусловие делает ему
`Done()`, и курс встаёт в очередь, когда счётчик дошёл до нуля, — никого не опрашивают по кругу.**

Это и есть **алгоритм Кана**. Виджет ниже прогоняет его на другом графе — шесть вершин `A…F`
с двумя источниками — вершинами, в которые не входит ни одна стрелка; код и трасса задачи о курсах — в [«📝 Разбор задачи»](#-разбор-задачи).

## 🎬 Визуализация

> 💡 **Интерактивная демонстрация.** Рядом с вершиной — входящая степень (`in:`). Кан убирает
> вершину со степенью 0 (жёлтая → синяя) и уменьшает степени соседей: текущее ребро жёлтое,
> а снятое становится пунктиром — это и есть «удалить источник вместе с его рёбрами».
> Вершина, у которой сняли последнее входящее ребро, зеленеет: она готова и ждёт в очереди. Под холстом — строка шага и переменные (порядок), ниже — ползунок шагов (или ←/→ на клавиатуре) и код с подсветкой строки.

В примере два источника (`A` и `B`), и **через шаг** в очереди две готовые вершины: перед
снятиями в ней по очереди 2, 1, 2, 1, 2, 1 вершины. Порядок, в котором их снимать, — дело
выбора, поэтому топологических порядков у графа несколько; будь в очереди на каждом шаге ровно
одна вершина, порядок был бы единственным.

> 🔧 **Где это в Go.** Так компилятор выбирает **порядок инициализации переменных** пакета: строит

## ⚡ Шаблон для собеседования

```go
// Алгоритм Кана (BFS по in-degree)
queue := []int{}
for v := 0; v < n; v++ {
    if inDegree[v] == 0 {
        queue = append(queue, v) // все источники сразу
    }
}
var order []int
for len(queue) > 0 {
    u := queue[0]; queue = queue[1:]
    order = append(order, u)
    for _, w := range adj[u] {
        inDegree[w]--
        if inDegree[w] == 0 {
            queue = append(queue, w)
        }
    }
}
if len(order) != n { /* цикл — порядок невозможен */ }
```

1. считаем in-degree всех вершин;
2. все вершины с in-degree 0 → в очередь;
3. убираем вершину, уменьшаем степени соседей, новые нули → в очередь;
4. `len(order) < n` ⇒ цикл.

## 📖 Разбор

**Топологическая сортировка** (topological sort) находит линейный порядок вершин
ориентированного графа без циклов (**DAG**, directed acyclic graph): если ребро A → B, то A
идёт перед B. Такой порядок существует тогда и только тогда, когда циклов в графе нет.

Ключевое наблюдение: в DAG всегда есть вершина с **входящей степенью 0** (источник). Снимая
источники вместе с их рёбрами, открываем новые — это **алгоритм Кана**, его код — шаблон
[«⚡»](#-шаблон-для-собеседования) выше.

### Слои: что можно делать одновременно

Кан можно вести **раундами**: перед раундом запомни размер очереди (`levelSize := len(queue)`) и
сними ровно столько вершин, а ставшие нулевыми уйдут в следующий раунд — так же
[Tree BFS](tree-bfs.md) отделяет уровни дерева. Вершины одного раунда друг от друга не
зависят: каждая уже готова, пока другие ещё не сняты, — их можно выполнять параллельно. Число
раундов — наименьшее число последовательных этапов: вершина раунда `k` дождалась вершины
раунда `k − 1`, та — вершины раунда `k − 2`, и так до источника, то есть ей предшествует
цепочка из `k − 1` вершин. На графе виджета раунды — `{A, B}`, `{C, D}`, `{E, F}`: три этапа
на шесть задач.

### Кан без стрелок: листья дерева

Тот же приём работает в неориентированном дереве, только счётчик — обычная степень (число
соседей), а вместо источников — **листья** (степень 1). Сними все текущие листья разом,
уменьши степени их соседей; кто стал листом — в следующий слой. Слой за слоем дерево
сжимается с краёв к середине. Топологического порядка здесь нет — у неориентированного графа
его не бывает; общий с Каном только приём: снимать готовое и пересчитывать соседей.

### Рёбер нет в условии: порядок букв

Иногда граф приходится вывести самому. Тренажёр `AlienOrder`: слова отсортированы по
неизвестному алфавиту, нужен порядок букв. Вершины — все буквы, что встретились в словах, даже если ни одно ребро
их не касается. Пара соседних слов даёт не больше одного ребра —
первая различающаяся буква первого слова стоит раньше буквы второго; буквы дальше этой
позиции ничего не говорят. На `wrt, wrf, er, ett, rftt` пары дают рёбра `t→f`, `w→e`, `r→t`,
`e→r`, и Кан выкладывает `wertf`. Если различий нет, а первое слово длиннее (`abc` перед
`ab`), — противоречие, ответа нет; цикл в рёбрах — тоже.

<details class="algo-details">
<summary>Вариант через DFS, пример и сложность</summary>

**Альтернатива — DFS:** когда вершина полностью обработана, кладём её в стек; развёрнутый
стек даёт топопорядок. Цикл ловится по «серой» (обрабатываемой) вершине.

Для графа A→B, A→C, B→C, B→D, C→D порядок: **[A, B, C, D]**. Граф с циклом
`A→B→C→A` даёт in-degree всех = 1, очередь пуста с начала → `len(order) < V` → цикл.

#### Сложность

| Подход              | Время    | Память   |
|---------------------|----------|----------|
| Алгоритм Кана (BFS) | O(V + E) | O(V + E) |
| DFS                 | O(V + E) | O(V + E) |

</details>

## 🧠 Почему это корректно

    <div class="algo-explain__q">Почему в DAG всегда найдётся вершина с нулевой входящей степенью — и почему это свойство сохраняется по ходу алгоритма?</div>
    <div class="algo-explain__ref">От противного (допустим обратное и придём к невозможному): если у каждой вершины есть входящее ребро, пойдём назад по входящим — на конечном числе вершин мы обязаны вернуться в уже посещённую, то есть получить цикл, что противоречит ацикличности. После удаления источника подграф остаётся DAG, поэтому источник найдётся снова — Кану всегда есть с чего продолжать.</div>
  </div>
  <div class="algo-explain__item">
    <div class="algo-explain__q">Сформулируй инвариант алгоритма Кана и объясни, почему <code>len(result) &lt; V</code> равносильно наличию цикла.</div>
    <div class="algo-explain__ref">Инвариант: когда вершину кладут в результат (её in-degree стал 0), все рёбра в неё уже исходят из ранее размещённых вершин — значит каждый предшественник стоит раньше, и порядок уважает все рёбра. Не дошли до нуля вершины цикла — они ждут друг друга по кругу — и все, кто от них зависит. Обратно: на DAG снятие источников опустошает граф полностью. Поэтому непустой остаток равносилен циклу, и это бесплатный детектор цикла.</div>
  </div>
</div>

Алгоритм Кана опирается на три факта: в DAG всегда есть источник, удаление источников
сохраняет валидность порядка, а застревают вершины цикла и всё, что от него зависит.

### Почему в DAG всегда есть вершина с in-degree = 0

От противного: пусть у каждой вершины есть входящее ребро. Тогда пойдём «назад» по
входящим рёбрам — на конечном числе вершин мы обязаны вернуться в уже посещённую →
**цикл**, что противоречит ацикличности. Значит источник существует, и Кану всегда есть
с чего начать. После удаления источника подграф остаётся DAG → источник найдётся снова.

### Инвариант Кана

> Когда вершину `v` кладут в результат (её `in-degree` стал `0`), **все** рёбра в `v`
> уже исходят из ранее размещённых вершин.

Значит каждый предшественник `v` уже стоит раньше — порядок уважает все рёбра. По
индукции весь вывод — корректный топопорядок.

### Почему `len(result) < V` равносильно циклу

Вершины, так и не достигшие `in-degree = 0`, — это вершины **цикла** и все, кто от цикла
зависит хотя бы через посредника: вершины цикла ждут друг друга по кругу, остальные ждут их.
И наоборот: если
граф — DAG, то многократное «снятие источников» опустошает его полностью (по первому
факту источник есть на каждом шаге). Поэтому остаток `> 0` равносилен наличию цикла —
это и есть бесплатный детектор цикла.

### Сложность

Каждая вершина попадает в очередь и выходит из неё один раз, каждое ребро уменьшает
`in-degree` соседа один раз → **`O(V + E)`**.

## ⚙️ Цена на практике

### Кан (BFS) против DFS

Кан даёт **детектор цикла даром** (через `len(order)`) и естественные «слои»
зависимостей (уровни BFS = глубина зависимости). DFS-вариант требует трёхцветной
пометки (белый/серый/чёрный) для отлова цикла и выдаёт обратный постпорядок (вершины в порядке завершения
их вызовов, развёрнутые задом наперёд). Нужны ещё
и обнаружение цикла или слои — бери Кана.

### Лексикографически наименьший порядок — куча вместо очереди

Топопорядок **не единственный**: следующим может пойти любой текущий источник. Если
задача просит лексикографически *наименьший* порядок (порядки сравнивают как слова в словаре, по
первой различающейся вершине; частое продолжение на собеседовании), замени очередь на **min-heap** —
получишь `O((V + E) log V)`. И помни: раз порядков несколько, задача обязана задать
правило разрешения ничьих, иначе «правильных» ответов много (поэтому в тренажёре
топосорт проверяется на *валидность*, а не на точную перестановку).

### Очередь срезом

Как и в [обходах графа](graphs.md): `queue = queue[1:]` не освобождает начало
нижележащего массива — на огромном графе веди индекс головы по фиксированному срезу.

## ⚠️ Типичные ошибки

1. **Путаница in-degree / out-degree** (входящая и исходящая степень) — считай входящие рёбра, а не исходящие.
2. **Неправильное направление ребра** — `course` зависит от `prerequisite`, поэтому ребро `prerequisite → course`.
3. **Забыта проверка цикла** — если `len(order) != numCourses`, сортировка невозможна.
4. **In-degree обновляется не у тех вершин** — уменьшай только у прямых соседей текущей.
5. **Несколько источников / компонент** — клади в очередь сразу все вершины с in-degree 0.
6. **Дубликаты рёбер** безопасны, только пока учтены одинаково и в in-degree, и в списке смежности (тогда лишние +1 и −1 взаимно гасятся). Дедуплицировали одно и забыли другое — вершина никогда не «освободится». Надёжнее отсеять повторы заранее через множество.

## 📝 Разбор задачи

Перебор и наблюдение — в [«🧭 Откуда берётся алгоритм Кана»](#-откуда-берётся-алгоритм-кана-выведем-его-сами):
опрос по кругу снова и снова спрашивает курс, чья готовность меняется только тогда, когда
пройдено его предусловие, — отсюда счётчик входящих рёбер. Здесь — код и трасса задачи о курсах.

> **Задача (Course Schedule II).** Есть `numCourses` курсов `0..numCourses-1` и список
> предусловий: пара `[a, b]` значит «чтобы пройти `a`, сначала нужно `b`». Верни **любой
> корректный порядок** прохождения всех курсов. Если из-за цикла зависимостей это
> невозможно — верни пустой массив.
> Пример: `numCourses = 4`, `prerequisites = [[1,0],[2,0],[3,1],[3,2]]` → `[0,1,2,3]`
> (0 не зависит ни от кого; 3 — от 1 и 2; оба после 0).

Из пар строим граф: пара `[a, b]` — ребро `b → a`, и растёт входящая степень `a`.

```go
graph := make([][]int, numCourses)
inDegree := make([]int, numCourses)
for _, p := range prerequisites {
    course, prereq := p[0], p[1]
    graph[prereq] = append(graph[prereq], course) // ребро prereq → course
    inDegree[course]++
}
```

Дальше — [шаблон «⚡»](#-шаблон-для-собеседования) без изменений (`adj` — это `graph`, `n` —
`numCourses`), а на месте комментария о цикле — `return []int{}`: курсы остались, порядок
невозможен. Иначе возвращаем `order`. Каждая вершина входит в очередь и выходит из неё один
раз, каждое ребро снимается один раз — **`O(V+E)`**.

Прогони алгоритм Кана на графе курсов: берём вершины с нулевой входящей степенью,
снимаем их рёбра, и так пока не выложим весь порядок:

<div class="algo-viz" data-viz="topo-kahn" data-nodes="0,1,2,3" data-edges="0-1,0-2,1-3,2-3"></div>

**Трассировка** на `numCourses = 4`, `prerequisites = [[1,0],[2,0],[3,1],[3,2]]`
(рёбра `0→1`, `0→2`, `1→3`, `2→3`; стартовые in-degree — `0:0, 1:1, 2:1, 3:2`):

| шаг | взяли `u` | очередь до | обновили in-degree | стало 0 → в очередь | очередь после | `order`       |
|-----|-----------|------------|--------------------|----------------------|---------------|---------------|
| 0   | —         | `[0]`      | старт               | —                    | `[0]`         | `[]`          |
| 1   | 0         | `[0]`      | `1:1→0`, `2:1→0`    | 1, 2                 | `[1,2]`       | `[0]`         |
| 2   | 1         | `[1,2]`    | `3:2→1`             | —                    | `[2]`         | `[0,1]`       |
| 3   | 2         | `[2]`      | `3:1→0`             | 3                    | `[3]`         | `[0,1,2]`     |
| 4   | 3         | `[3]`      | нет соседей         | —                    | `[]`          | `[0,1,2,3]`   |

`len(order) = 4 = numCourses` → возвращаем `[0,1,2,3]`. Каждое предусловие стоит раньше
своего курса (`0` раньше `1` и `2`; `1` и `2` раньше `3`) — порядок валиден. Граф с
циклом, например `[[0,1],[1,2],[2,0]]`, оставит очередь пустой с самого начала
(`in-degree` всех = 1), `len(order) = 0 ≠ 3` → вернётся `[]`.

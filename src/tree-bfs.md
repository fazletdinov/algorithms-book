## 🧭 Откуда берётся обход по уровням: выведем его сами

Снимок `levelSize := len(queue)` из шаблона ниже — не ритуал. Это ровно то, чего не хватает
обычной очереди, чтобы работать «по уровням». Проследим на дереве виджета ниже.

> **Задача (обход по уровням).** Дан корень бинарного дерева. Выдай значения узлов по уровням —
> сверху вниз, внутри уровня слева направо, каждый уровень отдельным списком. Здесь ответ —
> `[[1], [2, 3], [4, 5, 6]]`.

<div class="algo-fig" data-fig="tree" data-tree="1(2(4,5),3(_,6))" data-caption="Дерево 1,2,3,4,5,null,6 (запись по уровням; null — нет узла, поэтому 6 — правый ребёнок 3); уровни [1], [2, 3], [4, 5, 6]"></div>

**Первая попытка — обычная очередь на срезе, как во «Вспомни» выше:** снимаем узел с
головы, детей кладём в хвост. Узлы выходят в порядке `1, 2, 3, 4, 5, 6` — по уровням, слева
направо, но одной лентой. Где кончается уровень?

**Вторая попытка — уровень кончается, когда после снятия очередь пуста.** На `1` это верно:
сняли корень — очередь пуста, `[1]` и есть уровень. Но когда снимаем `3`, в очереди уже лежат
`4, 5` — дети `2`, встали в хвост раньше (в виджете ниже это шаг 13). Признак срабатывает только на `1` и `6` и выдаёт
`[[1], [2, 3, 4, 5, 6]]`: очередь склеила два уровня в одну ленту.

**Что чинит.** В начале уровня в очереди лежит ровно он, и никого больше: его дети ещё не
добавлены. Запомни в этот момент `levelSize := len(queue)` и сними ровно столько узлов.
Снимки `levelSize` равны 1, 2 и 3 — и уровни выходят ровно такими: `[1]`, `[2, 3]`, `[4, 5, 6]`.

**Граница между уровнями в очереди уже есть — `levelSize := len(queue)` лишь ставит на ней
засечку, пока в хвост не встали дети.** Этот приём — обход по уровням (level order). Виджет
ниже прогоняет его на этом же дереве. Задача, где из каждого уровня нужен один узел, — вид
справа — в [«📝 Разбор задачи»](#-разбор-задачи).

## 🎬 Визуализация

> 💡 **Интерактивная демонстрация.** Обход идёт по шаблону ниже: на строке
> `levelSize := len(queue)` очередь содержит ровно текущий уровень (обведён синим). Дети,
> которых кладём в хвост, встают за жёлтую черту в очереди: это уже следующий уровень
> (пунктир на дереве). Сняли `levelSize` узлов — уровень закрыт и уходит в `result`.
> Под холстом — строка шага и переменные, ниже — ползунок шагов (или ←/→ на клавиатуре) и код с подсветкой строки. Можно подставить своё дерево (по уровням, как в LeetCode)
> и нажать «⟲ Запустить».

## ⚡ Шаблон для собеседования

```go
queue := []*TreeNode{root}
for len(queue) > 0 {
    levelSize := len(queue)       // снимок размера уровня!
    for i := 0; i < levelSize; i++ {
        node := queue[0]
        queue = queue[1:]         // снимаем с головы
        // ... обрабатываем node.Val ...
        if node.Left != nil { queue = append(queue, node.Left) }
        if node.Right != nil { queue = append(queue, node.Right) }
    }
}
```

1. кладём корень в очередь;
2. фиксируем `levelSize` — сколько узлов на текущем уровне;
3. обрабатываем ровно столько, добавляя детей в конец;
4. повторяем, пока очередь не пуста.

## 📖 Разбор

**Tree BFS** (Breadth-First Search) обходит дерево уровень за уровнем: все узлы
уровня `k` обрабатываются прежде, чем алгоритм перейдёт к уровню `k+1`. Узлы хранятся
в **очереди** (FIFO): добавляем в конец, извлекаем из начала — это естественным образом
задаёт порядок «сначала ближние, потом дальние».

<details class="algo-details">
<summary>Полный код обхода по уровням и сложность</summary>

```go
type TreeNode struct {
    Val   int
    Left  *TreeNode
    Right *TreeNode
}

// Обход по уровням: значения узлов, сгруппированные по уровням
func levelOrder(root *TreeNode) [][]int {
    if root == nil {
        return [][]int{}
    }

    queue := []*TreeNode{root}
    result := [][]int{}

    for len(queue) > 0 {
        levelSize := len(queue)               // сколько узлов на текущем уровне
        level := make([]int, 0, levelSize)

        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]                 // снимаем с головы
            level = append(level, node.Val)

            if node.Left != nil {             // детей кладём в конец
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }

        result = append(result, level)
    }

    return result
}
```

Фиксация `levelSize` до начала внутреннего цикла критична: во время обработки уровня мы
добавляем детей в ту же очередь, и без снимка размера границы уровней «съедут».

#### Сложность

| Метрика | Значение                                        |
|---------|--------------------------------------------------|
| Время   | O(n) — каждый узел добавляется и извлекается один раз |
| Память  | O(w), где w — максимальная ширина дерева (до (n+1)/2) |

</details>

Задачи на уровни меняют только одно — что делать с уровнем, пока он в руках: собрать в список,
сложить, найти максимум, взять последний узел. Отдельно — **ранний выход**: уровни выходят по
возрастанию глубины, поэтому первый встреченный лист лежит на минимальной глубине, и дальше
обход можно не продолжать.

<details class="algo-details">
<summary>Если застрял: среднее, змейка и минимальная глубина в тренажёре</summary>

- **Среднее уровня** — сумма значений, делённая на `levelSize`; приведи к `float64` до деления.
- **Змейка** (`ZigzagLevelOrder`) — обычный уровень, но каждый второй, начиная со второго сверху
  (корень — уровень 0, разворачиваются 1, 3, …), разверни перед тем, как положить в ответ.
  Порядок очереди не трогай.
- **Минимальная глубина** — счётчик уровней; на первом узле без обоих детей верни номер его
  уровня, считая корень первым.

</details>

## 🧠 Почему это корректно

### Почему уровни не «съезжают»

В момент снимка `levelSize := len(queue)` очередь содержит **ровно узлы текущего
уровня**. Извлекая именно столько, мы опустошаем уровень, а добавленные за это время
дети образуют **следующий** уровень — и попадут в свой снимок на следующей итерации.
Без фиксации размера дети текущего уровня смешались бы с ним, и границы поехали.

### Очередь монотонна по глубине

В очереди в любой момент лежат узлы не больше чем двух соседних уровней, и все узлы уровня `d`
стоят раньше узлов `d+1`, — поэтому граница между уровнями в очереди есть физически, и
`levelSize` режет ровно по ней. (В [графах](graphs.md) к этому добавится пометка посещённых
вершин: у дерева циклов нет, в каждый узел ведёт одна ссылка, и пометка не нужна.)

## ⚙️ Цена на практике

### Память `O(w)` против `O(h)` у DFS

BFS держит в очереди целый уровень — до `~n/2` узлов в последнем уровне полного дерева (все
уровни, кроме последнего, заполнены; последний — слева направо без дыр), это `O(w)`.
[DFS](tree-dfs.md) тратит `O(h)` (высота). Поэтому: широкое мелкое
дерево дешевле обходить DFS, а узкие задачи «по уровням / ближайший узел» — это BFS.

### BFS даёт кратчайший путь по рёбрам

Монотонность очереди по глубине — это не только про деревья: на **невзвешенном** графе (у рёбер нет длин, каждое стоит 1) тот
же FIFO-обход достигает каждой вершины путём из минимального числа рёбер. Поэтому
*Minimum Depth*, *Right Side View* и «ближайший узел с условием» — естественно BFS, а на
графах BFS = кратчайший путь за `O(V+E)` (V — вершин, E — рёбер) без всякой кучи (см.
[сетки и кратчайшие пути](grids-and-shortest-paths.md)). [DFS](tree-dfs.md) находит
*какой-то* путь, но не кратчайший — выбор обхода диктуется тем, нужна ли тебе именно
**длина/расстояние** ответа.

### Очередь срезом

`queue = queue[1:]` не освобождает начало нижележащего массива (как и в
[графах](graphs.md)) — на огромных деревьях веди индекс головы по фиксированному срезу.

## ⚠️ Типичные ошибки

1. **Не зафиксирован размер уровня** — `levelSize` нужно взять до внутреннего цикла,
   иначе добавленные дети попадут в текущий уровень.
2. **Добавление nil в очередь** — проверяй `node.Left != nil` и `node.Right != nil`
   перед `append`, иначе при снятии с головы получишь разыменование nil.
3. **Не обработан пустой корень** — при `root == nil` возвращай `[][]int{}`, не входя в цикл.
4. **Извлечение не из того конца** — BFS требует FIFO (`queue[0]`); чтение с конца
   превратит обход в DFS.
5. **DFS вместо BFS для уровней** — рекурсия с передачей уровня тоже даёт группировку,
   но BFS нагляднее и гарантирует порядок слева направо без лишней логики.

## 📝 Разбор задачи

Перебор и наблюдение — в [«🧭 Откуда берётся обход по уровням»](#-откуда-берётся-обход-по-уровням-выведем-его-сами):
обычная очередь склеивает уровни в одну ленту, а снимок `levelSize` ставит засечку на границе.
Здесь — код и трасса задачи на шаг дальше: из каждого уровня нужен один узел.

> **Задача (Right Side View).** Дан корень бинарного дерева. Вернуть значения узлов,
> **видимых справа**, сверху вниз — то есть по одному с каждого уровня: самый правый.
> Пример: дерево `[1, 2,3, null,5, null,4]` →
>
> ```text
>        1
>       / \
>      2   3
>       \   \
>        5   4
> ```
>
> Ответ — `[1, 3, 4]` (с правого бока видно `1`, `3`, `4`).

Снимок `levelSize` снимает уровень слева направо, поэтому последний снятый узел уровня
(`i == levelSize-1`) — самый правый, его и видно: он приходит сам, ровно когда уровень
закрывается. (Ту же задачу решает и обход в глубину: он копит в словаре «глубина → последнее
значение» и собирает ответ вторым проходом по глубинам — попробуй его, когда пройдёшь
[Tree DFS](tree-dfs.md).)

Идти только по правым ссылкам нельзя: убери узел `4` — ответ станет `[1, 3, 5]`, ведь `5`
(правый ребёнок `2`) — самый правый на своём уровне, а проход `1 → 3` по правым ссылкам на нём
оборвётся. Смотреть надо на весь уровень — его и снимает `levelSize`.

**Код: обход по уровням, берём последний узел каждого уровня — O(n).**

```go
func rightSideView(root *TreeNode) []int {
    if root == nil {
        return []int{}
    }
    res := []int{}
    queue := []*TreeNode{root}

    for len(queue) > 0 {
        levelSize := len(queue)               // снимок размера уровня!
        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]                 // снимаем с головы
            if i == levelSize-1 {             // последний на уровне = видимый справа
                res = append(res, node.Val)
            }
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
    }
    return res
}
```

Один проход, память — `O(w)` под очередь, ответ копится сразу в нужном порядке.

Прогони обход по уровням: очередь набирает всех детей уровня, и последний снятый с
уровня узел — это и есть видимый справа:

<div class="algo-viz" data-viz="tree-right-view" data-tree="1,2,3,null,5,null,4"></div>

**Трассировка** на `[1, 2,3, null,5, null,4]` (жирным — узел, который уходит в ответ как последний на уровне):

| Уровень | Очередь в начале | Извлекаем (слева→направо) | Последний (`i==levelSize-1`) | Дети в хвост | `res` |
|---------|------------------|---------------------------|------------------------------|--------------|-------|
| 0       | `[1]`            | `1`                       | **`1`**                      | `2, 3`       | `[1]` |
| 1       | `[2, 3]`         | `2`, `3`                  | **`3`**                      | `5` (от 2), `4` (от 3) | `[1, 3]` |
| 2       | `[5, 4]`         | `5`, `4`                  | **`4`**                      | —            | `[1, 3, 4]` |

Очередь опустела — ответ `[1, 3, 4]`. На каждом уровне в `res` уходит ровно один узел,
взятый из хвоста снимка; именно его и видно справа.

## 🔗 Связанные шаблоны

**Не спутай с соседом** (вся таблица — в [руководстве по выбору](pattern-selection-guide.md#путаемые-пары-что-обязано-быть-верно)):

- если нужны уровни дерева, минимальная глубина или ближайший к корню узел — Обход дерева в ширину, а не [Обход дерева в глубину](tree-dfs.md): обход вглубь узнаёт минимальную глубину, лишь обойдя всё дерево, а очередь по уровням останавливается на первом листе.
- если ответ узла собирается из ответов детей, как высота, сумма или диаметр поддерева — [Обход дерева в глубину](tree-dfs.md), а не Обход дерева в ширину: по уровням узел обрабатывается раньше своих детей, а подсчёту снизу вверх он нужен после всех потомков.
<!-- pairs:end -->

- **[Tree DFS](tree-dfs.md)** — обход в глубину; память O(h) вместо O(w), удобен для
  задач на пути и свойства поддеревьев.
- **[Topological Sort](topological-sort.md)** — BFS по графу (алгоритм Кана).

## 🧱 Как устроен узел

Один узел бора — это **массив ссылок на детей** (по одной на каждый символ алфавита) плюс
**флаг конца слова**. Никаких символов внутри узла не хранится: символ закодирован *позицией*
ребёнка в массиве (`children[0]` — это `'a'`, `children[25]` — `'z'`). Сам символ — это ребро,
а не вершина.

```go
type Trie struct {
    children [26]*Trie // ребёнок по индексу c-'a'; nil — ребра нет
    isEnd    bool      // здесь заканчивается вставленное слово
}

func NewTrie() *Trie { return &Trie{} }
```

Корень — пустой узел, не несущий символа: путь к нему — это пустой префикс. Вот как выглядит
бор с уже вставленными `cat`, `car`, `card`, `do`, `dog` (★ — узлы с `isEnd`):

```
        (root)
        /     \
       c       d
       |       |
       a       o ★────┐
       |       |      │
   ┌───┤       g ★    │
   t★  r★             (do — конец слова, и при этом
       |               у него есть ребёнок g: один узел
       d★              может быть и словом, и префиксом)
```

Три факта, которые видно прямо на картинке и которые держат всю структуру:

1. **Общий префикс — общий путь.** `cat`, `car`, `card` делят узлы `c→a`; дальше ветка
   расходится. Память не дублируется — в этом вся экономия бора.
2. **Слово может быть префиксом другого.** `do` помечен `isEnd`, но у него есть ребёнок
   `g` (`dog`). Поэтому конец слова — это флаг, а не «лист»: лист и конец слова — разные вещи.
3. **Глубина = длина слова.** Путь до `card` — ровно 4 ребра. Сколько ещё слов в боре —
   на эту глубину не влияет. Отсюда и `O(L)`.

## 🔨 Строим бор: `Insert` символ за символом

Вставка — это спуск от корня по символам слова: на каждом шаге берём ребёнка по индексу
`c-'a'`, **создавая его, если ребра ещё нет**. Дойдя до конца — ставим `isEnd`.

```go
func (t *Trie) Insert(word string) {
    node := t
    for i := 0; i < len(word); i++ {
        c := word[i] - 'a'
        if node.children[c] == nil {
            node.children[c] = &Trie{} // ребра нет — создаём узел
        }
        node = node.children[c]        // спускаемся в ребёнка
    }
    node.isEnd = true                  // отметили конец слова
}
```

> 💡 **Интерактивная демонстрация вставки.** В боре уже лежат `cat`, `dog`, `do`. Вставляем
> `car`: шаги `c` и `a` **переиспользуют** общий с `cat` префикс (узлы не создаются), а на
> символе `r` бор **растёт** — новый узел подсвечивается. В конце узел помечается `isEnd`.
> Призрачные (пунктирные) узлы — те, которых ещё нет на текущем шаге. Подставь свои слова и
> вставляемое слово. (Виджет работает в собранной книге `mdbook serve`/`mdbook build`.)

**Трассировка** `Insert("car")` в бор, где уже лежит `cat` (то есть путь `c→a→t` существует):

| `i` | символ | `children[c]` до шага | действие | где `node` после |
|-----|--------|------------------------|----------|-------------------|
| 0   | `c`    | есть (от `cat`)        | переиспользуем узел | `c` |
| 1   | `a`    | есть (от `cat`)        | переиспользуем узел | `c→a` |
| 2   | `r`    | **nil**                | **создаём** узел `r` | `c→a→r` |
| —   | —      | —                      | `node.isEnd = true`  | `c→a→r` помечен |

Ключевой момент — шаги 0–1 **ничего не создают**: ветка `c→a` уже проложена словом `cat`,
вставка `car` лишь дописывает развилку с шага 2. Это и есть «общий префикс — общий путь» в
действии. Вставь следом `card` — переиспользуются уже `c→a→r`, добавится только `d`.

## 🔎 `Search` и `StartsWith`: одна функция, два ответа

Обе операции — это один и тот же спуск по символам; различает их **только проверка `isEnd`**
в конце. Вынесем спуск в общий `find`, возвращающий конечный узел или `nil`:

```go
// find возвращает узел, соответствующий строке s, или nil, если путь оборвался.
func (t *Trie) find(s string) *Trie {
    node := t
    for i := 0; i < len(s); i++ {
        c := s[i] - 'a'
        if node.children[c] == nil {
            return nil          // ребра нет — такого префикса в боре нет
        }
        node = node.children[c]
    }
    return node
}

func (t *Trie) Search(word string) bool       { node := t.find(word); return node != nil && node.isEnd }
func (t *Trie) StartsWith(prefix string) bool { return t.find(prefix) != nil }
```

> ⚠️ Разница между `Search` и `StartsWith` — ровно в одной проверке. `find("do")` для бора
> выше вернёт узел, и `StartsWith("do")` → `true`, и `Search("do")` → `true` (флаг стоит).
> А вот `find("ca")` тоже вернёт узел (`car`/`cat`/`card` через него идут), поэтому
> `StartsWith("ca")` → `true`, но `Search("ca")` → `false`: на узле `a` нет `isEnd`, слово
> `"ca"` мы не вставляли.

> 💡 **Демонстрация поиска.** В боре `cat`, `car`, `card`, `dog`, `do`. Поиск `car` спускается
> по символам `c→a→r` и в конце проверяет `isEnd`. Попробуй запрос `ca` — путь существует, но
> `isEnd` нет: это префикс, а не слово. Подставь свои слова и запрос.

## 🧹 `Delete` и `WordsWithPrefix`: мутация и обход

Удаление — это не просто снять `isEnd`: иначе в боре накапливаются мёртвые узлы. После снятия
флага нужно **обрезать висячий хвост** — идя от конца слова к началу, удалять ссылку на ребёнка,
пока он не является концом другого слова и не имеет своих детей.

```go
func (t *Trie) Delete(word string) bool {
    node := t.find(word)
    if node == nil || !node.isEnd {
        return false            // такого слова нет — удалять нечего
    }
    node.isEnd = false
    t.prune(word)               // обрезаем висячие узлы на пути
    return true
}
```

> 🔑 Почему обрезаем «снизу вверх и только висячее»: узел нельзя удалить, если он `isEnd`
> другого слова (`do` при удалении `dog`) или если у него остались дети (`c→a` при удалении
> `car`, ведь там ещё `cat`). Остановка на первом таком узле — и есть корректная обрезка.

> 💡 **Демонстрация удаления.** В боре `cat`, `car`, `card`. Удаляем `card`: снимаем `isEnd` с
> узла `d`, потом обрезаем снизу вверх. Узел `d` висячий — **удаляется** (вспышка), но на узле
> `r` обрезка **останавливается**: `r` — это конец слова `car`. Видно, что `card` исчез, а `car`
> остался. (Виджет работает в собранной книге `mdbook serve`/`mdbook build`.)

`WordsWithPrefix` — это уже **обход** структуры, а не спуск по одному пути: находим узел
префикса через `find`, затем DFS-ом собираем все слова под ним (перебирая детей `a..z`, мы
получаем их сразу в лексикографическом порядке). Это та же рекурсия, что и обход дерева, —
Trie ведь и есть дерево.

> 💡 **Демонстрация обхода.** Собираем все слова с префиксом `ca` в боре `car`, `card`, `cat`,
> `dog`. Сначала спуск к узлу префикса `ca`, затем DFS по детям в порядке `a→z`: при каждом
> узле с `isEnd` накопленный путь падает в список `out` справа. Порядок выхода — лексикографический
> (`car`, `card`, `cat`). (Виджет работает в собранной книге `mdbook serve`/`mdbook build`.)

## 🧠 Почему это корректно

### Два независимых условия «слово хранится»

Инвариант бора: строка `w` **хранится** тогда и только тогда, когда выполнены *оба* условия —

1. **путь** из символов `w` существует от корня (значит `w` — префикс какого-то вставленного слова);
2. **финальный узел помечен** `isEnd` (значит вставлено именно `w`, а не только его продолжение).

Отсюда и разница операций: `Search(w)` требует `node != nil && node.isEnd` (оба условия),
`StartsWith(p)` — только существование пути (условие 1). Без флага `isEnd` нельзя отличить
«вставили `app`» от «`app` — лишь префикс `apple`»: `Search("app")` ошибочно вернул бы `true`.
Это не деталь реализации, а часть определения корректности.

### Почему `O(L)` не зависит от числа слов

Поиск проходит ровно `L` рёбер (по одному на символ запроса), каждый шаг — `O(1)` (индексация
массива детей). Сколько слов уже в боре — неважно: общие префиксы лишь делят узлы, но не
удлиняют путь. Число слов влияет на **память**, а не на время поиска.

### Сложность

| Операция            | Время | Память                              |
|---------------------|-------|-------------------------------------|
| Insert / Search / StartsWith | O(L) | —                          |
| Хранение N слов     | —     | O(ALPHABET · N · L) в худшем случае |

`L` — длина запроса. Время **не зависит** от числа хранимых слов. Для разреженных алфавитов
используют `map[byte]*Trie` вместо массива.

## ⚙️ Цена на практике

### Массив `[26]` против `map` детей

- `children [26]*Trie` — доступ за `O(1)`, плотная память, дружелюбно к кэшу, но
  **ALPHABET указателей на каждый узел** (расточительно для разреженного или большого
  алфавита, например Unicode);
- `map[byte]*Trie` — память пропорциональна реальному числу детей, но хеширование на
  каждом шаге медленнее.

Выбор — по размеру и плотности алфавита. Для ASCII-задач LeetCode массив почти всегда лучше.

### Trie или хеш-множество?

Для **точного членства** хеш-сет проще и тоже `O(L)` (хеш строки и так считается за `O(L)`).
Бор берут, когда нужны **префиксные** операции: автодополнение, `startsWith`, поиск самого
длинного префикса, поиск слов на доске. Доставать trie ради обычного «есть/нет» — лишняя сложность.

### Память и погоня за указателями

Главная цена бора — **память**: `O(ALPHABET · N · L)` в худшем случае. Прикинь порядок: при
`children [26]*Trie` каждый узел — это 26 указателей × 8 байт = **208 байт накладных**
независимо от того, сколько детей реально занято. Плюс обход прыгает по указателям (промахи
кэша) в отличие от непрерывной структуры. Для огромных словарей помогает **сжатый (radix)
бор** — слить цепочки узлов с единственным ребёнком, это режет и узлы, и прыжки.

### Бор не только по буквам: бит-trie для XOR

Если «алфавит» — это **биты** числа (0 и 1), бор становится инструментом для запросов на XOR.
Вставляем числа от старшего бита к младшему (фиксированная ширина, скажем 32 — дерево глубины
32 с двумя детьми на узел); чтобы максимизировать `x ⊕ y` по всем сохранённым `y`, на каждом
бите **жадно идём в ребёнка с противоположным битом** — так ставим `1` в самый старший разряд
результата, где это возможно. Запрос — `O(32)` независимо от размера множества. Та же
структура — другой алфавит (применение — задача *Maximum XOR* в следующей главе).

## ⚠️ Типичные ошибки

1. **Забыли флаг `isEnd`** — тогда `Search` неотличим от `StartsWith`.
2. **Массив фиксированного размера для большого алфавита** — для Unicode берите `map[rune]*Trie`.
3. **Не проверяют `nil`-ребёнка** перед переходом — паника.
4. **Удаление узлов** реализуют небрежно: нельзя удалять узел, у которого остались дети или который конец другого слова.
